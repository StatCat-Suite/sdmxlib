## Summary

- \`DataflowBinding.materialized_at\` / \`bound_at\` now require tz-aware datetimes via a converter that raises on \`tzinfo=None\` (no silent coercion — per CLAUDE.md "no default tz: the call site decides UTC, not us").
- Storage stays \`TIMESTAMP\` (DuckDB's \`TIMESTAMPTZ\` Python path requires \`pytz\`, which we don't want as a hard dep). Writer normalises to UTC + strips tzinfo; reader re-tags with UTC. Round-trip is exact for UTC inputs and instant-preserving for any tz-aware input.
- Sweeps the 16 \`# noqa: DTZ001\` sites in binding fixtures.
- Cookbook + module docstring updated.

The original issue contemplated migrating the column to \`TIMESTAMPTZ\` and bumping \`SCHEMA_VERSION\`; investigation showed that path needs \`pytz\`. The model-layer-only fix is strictly cleaner: no schema bump, no migration, no new dep, same user-facing contract.

Out of scope per the issue: \`valid_from\` / \`valid_to\` and \`reference_period\` — those are spec-level SDMX fields tracked separately.

Closes #92.
