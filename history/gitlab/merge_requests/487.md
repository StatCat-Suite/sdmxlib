## Why the reader and not the writer

Re-measured before starting, because the numbers had moved a lot since #346 was
filed. Option 2's guard (!434) drove the fork to near-parity:

| | 3.0 | 3.1 | identical | differing | one-sided |
| --- | --- | --- | --- | --- | --- |
| `reader.py` | 30 | 30 | **30** | 0 | 0 |
| `writer.py` | 50 | 50 | 47 | 3 | 0 |

The reader needs **no** "what this generation omits" mechanism — the whole
difference is the three namespace URIs, which `ReaderHelpers` already takes as
constructor arguments and which already live in each package's
`namespaces.py`. That is what makes it the half worth doing first: the shared
core is a pure extraction with nothing to parameterise beyond what was already
parameterised.

The writer's three divergences are real wire-format differences
(`Categorisation` without `@version`, `DataConstraint` without `@role` and
`<ReleaseCalendar>`, `Dataflow` with `<DimensionConstraint>`) and still need
that mechanism. They stay forked, and the guard still documents them.

## A class, per #209

`ReaderHelpers` in `_common.py` is already a class for the recorded reason: the
closure-factory form scored 88 on C901 with 210 statements and erased every
signature behind `Callable[...]`. `V3Reader` is the same decision applied one
level up — it holds the namespace triple and the helpers derived from it, and
one instance per package serves every call.

## The conversion is verified, not eyeballed

Every function body was compared AST-to-AST against the 3.0 original after
unbinding `self`: **29 of 29 identical**, the only differences being docstring
indentation from moving into a class. Coverage is unchanged — the shared reader
measures 89% against the forks' 90% / 89%, and both thin modules are 100%.

## The guard now asserts the merge rather than the fork

`test_ml3_fork_drift.py` compared function bodies, which after this says
nothing about the reader: two modules holding one forwarding `read` are
trivially identical, so every assertion would pass while the reader could be
re-forked in a two-line change.

Two new tests replace that: each reader module defines **only** `read` and
imports the shared class, and `V3Reader` actually carries the implementation
(≥25 methods) rather than being an empty shell a thin pair would also satisfy.
Both sabotage-checked — adding one function to `sdmx_ml31/reader.py` fails
naming it, and gutting `V3Reader` fails with the method count.

The body-comparison tests are now scoped to `writer.py`, and
`test_the_fork_is_still_overwhelmingly_a_copy` is renamed for what it now
measures.
