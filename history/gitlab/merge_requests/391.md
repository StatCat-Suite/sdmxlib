# Merge request !391: fix(api)!: the session records how completely a URN resolved, not whether

| | |
| --- | --- |
| State | merged |
| Opened | 2026-08-19 |
| Merged | 2026-08-19 |

Closes #344. `partial=False` was ignored for a pinned URN: the caller
asked for untrimmed codelists and was handed the trimmed ones, silently.

`Session._resolved_map` recorded *that* a URN had been fetched with its
references and not *how completely*, so a `detail=referencepartial` fetch
and a `detail=full` one set the same flag and the second call was a cache
hit on the first. `latest` escaped only incidentally — it is a pointer,
so #338 re-asks it every time and the `detail=full` request happened on
the way past, for reasons unrelated to `partial`.

Replaced with an ordered `Completeness` (`UNRESOLVED < PARTIAL < FULL`)
and `Session.get_at_least(urn, level)`. Ordering is the point: `FULL`
must satisfy a request for `PARTIAL` — a full answer is more than was
asked for, not less — while `PARTIAL` must not satisfy `FULL`. That also
settles the reverse direction, which previously worked by accident: a
`partial=True` after a `partial=False` is a cache hit rather than a
second request.

Not a second cache keyed on detail. The session interns one object per
URN and a fuller fetch *fills that object in* — so this is a record of
what has been learned about it, written with `max` because learning is
monotonic: an all-stubs sweep must not downgrade a URN already held
untrimmed.

`completeness_of` keys on `references` before `detail`, because
`detail=full&references=none` is a complete artefact with nothing
followed — the commonest unresolved fetch in the library, and reading
`detail` alone would mark it the most complete thing there is.

`tests/unit/test_rest_partial.py` is now parametrised over pinned and
`latest`. Three of its four tests failed against a pinned URN when
finally asked — the file was written for #338 and used `latest`
throughout, so it read as coverage while guarding only the case that
passed for a different reason. `docs/design/caching.md` gains a section
on this failure mode, since #338 and #344 are the same mistake twice:
a boolean where the real question is ordered.

`Session.get_resolved` / `ingest(resolved=)` are gone. Internal API — no
`sdmxlib.*` export changes.

Also deletes `test_partial_reaching_the_wire_is_a_latest_only_guarantee`,
the placeholder !390 left behind, as its own message instructed.
