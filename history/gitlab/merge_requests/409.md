Nineteen endpoints probed across OECD, ECB, BIS, IMF and the Global Registry.

## Real examples found

| Field | Where |
|---|---|
| `Attribute.related_measure` | BIS, ECB, IMF DSDs |
| `Attribute.related_group` | BIS DSDs |
| `ConstraintAttachment` (non-dataflow) | BIS content constraints |

No provider in reach publishes `Group.uri`, `Dataflow.dimension_constraint`,
`Agency.parent`, `Level.coding_format`, `Category.uri`, `Codelist.extensions`,
`Measure.concept_role`, `DataConstraint.reference_period` or
`release_calendar`. Those stay synthetic-only, which is now a measured statement
rather than an assumption.

## Finding them disproved twenty register entries

SDMX types `AttributeRelationship` and `ConstraintAttachment` as **choices** —
dimensions *or* measure *or* group *or* dataflow; dataflow *or* structure *or*
provision agreement *or* provider. The fixture set every member of both at once,
chasing maximality. A writer given that can only emit one, and does, correctly.
The census read the rest coming back empty and registered five losses × four
formats.

BIS publishes both shapes for real and round-trips them with **zero**
differences. That contradicted the register, so one of them was wrong — and it
was the fixture.

Fixed: one attribute per relationship kind, one constraint per anchor. Both BIS
sources joined the corpus, so this is now held by real data rather than only by
a fixture I wrote.

## One real limit was hiding behind a false one

In 3.0/3.1 and SDMX-JSON, an attribute related to a measure loses the measure's
*identity*. `AttributeRelationshipType` offers Dataflow / Dimension / Group /
Observation, and `<Observation/>` is `common:EmptyType` — the type has no
measure reference at all. 2.1 carries it fine. Declared in `gaps.py`.

The reader then reports `related_measure="OBS_VALUE"`, which is fabricated
rather than read, and wrong for any DSD whose measure is named otherwise. #360
asks what it should do instead; not decided here because it is a semantics
choice.

## `constraints` left the not-covered list

It was excluded as a 95 MB Global Registry response. BIS publishes the same type
in 90 KB — so the exclusion was about one endpoint, not about the type. That is
precisely what writing exclusions down is for.

## Third time

"Maximal" has to mean maximal *within the grammar*. Same mistake as
`Level.coding_format` (a restriction of the ordinary facet type) and the
`date`/wildcard-URN pair in #354. **Any `<xs:choice>` is a place the fixture can
lie** — #359 notes the remaining register deserves a sweep for that shape.
