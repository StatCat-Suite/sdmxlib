# Merge request !440: An absent reference is NULL, not the empty string

| --- | --- |
| State | merged |

Prerequisite for #372 stage 2, but a defect on its own merits.

## The hole

Eight columns were `TEXT NOT NULL` while every model field behind them is `Optional`. The writer squared that circle by storing `''` — so the constraint enforced nothing, and "required" held only because absence was smuggled through as a value.

The cost landed in the query language. Asking for absence found none of it:

```python
reg.query(q.hierarchy_association).filter(q.context_object.urn.is_null()).ids()
# []          ← and yet HA_STD genuinely has no context object
```

An unscoped `HierarchyAssociation` is the **default** hierarchy for a dimension, so "which associations apply to any flow" was unaskable. Same hole for a `Dataflow` with no structure, both ends of a `Categorisation`, both of a `ProvisionAgreement`, a `Metadataflow`'s MSD, and both ends of a `MetadataProvisionAgreement`.

## The change

Schema **2.17** drops the eight `NOT NULL`s; the writers store `None`. Readers are untouched — they already tested truthiness, and NULL is falsy where `''` was.

## Three things it surfaced

**The optionality guard earned its keep.** Relaxing the columns failed `test_optionality_matches_the_schema` on exactly the eight edges whose `optional=False` had been true only of the empty-string convention. They join LEFT now, which is what a nullable FK means.

**Ref rows were being written for absent references.** Every guard read `if flow.structure is not None` while appending the *local* — so an absent ref inserted a row pointing at `''`. Now guarded on the local: the value actually appended, one source of truth, and it narrows for the checker (this is what basedpyright caught when the locals became `str | None`).

**The sweep had to be able to fail.** `test_the_sweep_would_notice` writes an empty string by hand and asserts the guard catches it — otherwise a green sweep means "no rows" rather than "no empty strings".

## Coverage shape

The sweep reads `information_schema`, so a new `*_urn` column is covered the day it lands. The nine columns this change touched are *also* named individually: a writer that quietly stopped emitting one of those rows would pass a derived sweep with nothing left to inspect.

## Breaking

Only for code reading `sdmx.*` directly and comparing against `''`. Stores rebuild on the version bump, as ever. pinaxlib's descent SQL is the known consumer — its `NULLIF`-free comparisons want a look, though `IS NULL` there was already never matching.
