The `m11` note in #423: the bare wire gate (`test_wire_conformance_gate.py`) holds every artefact kind to *valid or refused*, but only with its identity set. #416 and #417 shipped past it because both are values, and a bare artefact carries none.

## What it adds

`tests/unit/test_wire_conformance_populated.py` puts the same question to 20 populated states, in all four formats:

- the **#423 §B rows**: organisation-scheme versions, every version grammar (`1.2.3.4`, `1.03`, `1.0.0-draft`, `1.0.0`, and one valid in neither), reference versions (`latest`, a draft, 2.1-only, a wildcard), the measure shapes, two include regions, and annotation values;
- what the **registry sweep** (!516) found written invalid: a code `Parent` of `_T`, and a `KeyValue` with no values.

Each case applies one state to an artefact taken from `tests/support/maximal.py`, so every other field is populated.

Two checks keep the cases honest:

- **`test_every_base_is_valid_everywhere`**: each base is valid in every format, so a refusal or an invalid document is caused by the state the case sets. The DSD base drops `enumeration_format.decimals` and `measure_dimension`, which are refused everywhere; left in, every DSD case would be refused for them.
- **`test_every_case_changes_its_base`**: no case may reproduce its base. This already caught one of mine (`organisation_scheme_final`: the maximal scheme is final already).

Sabotage-checked:
- a stale `KNOWN_INVALID` entry fails;
- a base that is not valid everywhere fails.

## One question, raised on #420

A version one grammar cannot carry is refused with `VersionFormatError`, which is deliberately not a `ValidationError` (`model/version.py`). The bare gate's rule is that a refusal is a `ValidationError` with `.issues`. The two never met before, because bare artefacts all use `1.0`. This gate accepts both as a refusal and says why. Whether a version refusal should carry `.issues` is asked on #420.
