`query_stream` was the last capability the SQL-text API had and the typed
path did not, so it blocked that API's removal. `stream()` is its
counterpart on both frame-shaped terminals: to `frame()` on a query, and
to `collect()` on a projection.

It reaches the structural side too, which was not the goal but is where
the need was already filed — #154's 700k-node hierarchy is a
materialisation this makes optional.

**Both spellings work, and the reader decided that rather than us.**
`pa.RecordBatchReader` is an iterator *and* a context manager:

    for batch in query.stream(): ...
    with query.stream() as batches: ...

The second is worth preferring for a stream abandoned part-way — a
break, an exception, a client that hangs up — because the cursor is then
released at a defined point rather than whenever the reader is collected.
This is the one place in the language a context manager earns its keep:
a query is a value and owns nothing, a reader holds a cursor.

Arrow rather than polars because a writer wants Arrow — CSV, parquet, an
HTTP body — and `pl.DataFrame(batch)` is cheap for a caller who wants the
other thing. Converting here would force it on everyone.

**The memory claim is measured, and the old one was wrong.** 4M rows of
three columns: 443 MB peak RSS materialised, 214 MB streamed at
chunk_rows=50_000. That is a halving, not a reduction to batch size, so
`query_stream`'s "peak stays roughly proportional to chunk_rows" did not
hold — DuckDB's scan buffers are the floor and no chunk size gets under
them. The docstring says so, because sizing a container on the old
sentence would have been a mistake. First attempt at measuring this used
tracemalloc, which sees only Python allocations and reported 0.02 MB for
both; Arrow allocates natively, so peak RSS in separate processes is the
measurement.

`RecordBatchReader` joins `DataFrame` in the public-surface guard's
`foreign` set: pyarrow is a baseline dependency, so naming it commits a
caller to nothing they do not already have — which is what that set
encodes, rather than "is it ours".
