Design §5.17, resolved — **and the section's premise was wrong on all three counts, so no new type is needed.**

## What §5.17 claimed

That `observations()`, `write_observations()` and `browse()` need a lake, so on a plain `LocalRegistry` they must *raise* — which §2 says only a type can prevent — and therefore `BundleRegistry` might have to be a type after all.

## Measured

| claim | reality |
|---|---|
| `write_observations` must raise | **not on `LocalRegistry` at all** — it belongs to the data store |
| `browse()` must raise | answers on a plain registry, with an empty list |
| `observations()` must raise | answers on a plain registry whose binding points at a local table — which `test_registry_data_plane.py` has relied on since §6 step 6a |

What needs the lake is a **binding**, when its `database_role` names one. That is *data*, and data cannot be checked by a type — so §2's rule was never in tension. A method that answers for one binding and refuses for another is not a method that should be absent.

## What was actually wrong

The refusal. A bundle's binding read through a plain registry reached DuckDB as:

```
Binder Error: Catalog "lake" does not exist!
```

True, and useless to a caller who does not know that `lake` is what `bundle()` attaches. Now:

```
urn:...Dataflow=AG:DF(1.0) is bound to lake.data.obs, but no catalog named 'lake'
is attached here (attached: memory, system, temp). A bundle's observations live in
its DuckLake, which `LocalRegistry.bundle(path)` attaches and `LocalRegistry(path)`
does not — open it as a bundle, or rebind the dataflow to a table this registry can see.
```

Same shape as §5.8 and §5.9: the failure was never the refusal, it was a refusal that did not say what to do.

Raised when the binding is read rather than at the terminal, so a caller who builds a filter first does not see it attributed to the filter.

## Evidence

Mutants killed: no check (3 tests), check never refuses (3), **check always refuses (2)** — the last one matters, since a check that refused *every* binding would pass any test that only asserted the error message. `test_observations_answers_on_a_plain_registry` is what stops that, and it is also the test that decides §5.17.
