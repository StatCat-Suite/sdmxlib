## Summary

Small serialize hot-path optimisation found while benchmarking the #159
serialization changes for regressions.

**Context.** A before/after benchmark showed no *algorithmic* regression:
serialize of the ESTAT HICP fixture (3.8 MB) went 70 → 154 ms only
because the pre-#158 build silently dropped ~10.7k code annotations
(output 1.25 → 3.56 MB). Stripping annotations from the current build
reproduces the old time exactly. The extra time is the honest cost of
correct output.

**Optimisation.** Profiling that path showed `_emit_istring` dominating
via `dict(value.items())` — a dict built from the `items()` generator on
every name / description / annotation-text emit. Add
`InternationalString.as_dict()` (direct `dict(self._data)` copy) and use
it in both SDMX-JSON `_emit_istring` sites; drop the now-redundant
emptiness recheck.

## Numbers

- Inner istring extraction: ~0.34 µs → ~0.23 µs (**~31% faster**).
- SDMX-JSON serialize, ESTAT HICP: ~18.3 → ~16.2 ms median (**~11%**).
- SDMX-ML path is lxml `SubElement`-bound (creating the ~40k annotation
  elements) — no comparable Python-level win, left as-is.

No behaviour change; full unit suite green (2388 passed, 1 skipped,
2 xfailed).
