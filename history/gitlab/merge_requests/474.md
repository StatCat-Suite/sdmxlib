## Two storage decisions, both from precedent already in the schema

* **One parent table per kind**, not a shared one with a discriminator, for
  the reason `metadata_provider` states in its own comment: they are separate
  artefacts, and an edge resolving to "a map" resolves to nothing in
  particular.
* **One `item_map` table for both scheme maps** — `ConceptSchemeMap.maps` and
  `CategorySchemeMap.maps` are both `tuple[ItemMap, ...]`, the same class, the
  way `organisation_contact` serves `Agency` and `DataProvider`.
  `StructureMap.maps` is `ComponentMap`, a different class mapping components
  rather than items, so it gets its own.

The issue expected `StructureMap` to be the expensive one ("plus a
`component_map` child table"). It is not: `ItemMap` and `ComponentMap` are
both `(source_id, target_id)`, so the three writers differ only in table
names.

Both child tables carry `ordinal` and read back `ORDER BY` it — `maps` is a
tuple and its order is part of the artefact. The round-trip fixtures are
deliberately unsorted (`ZULU` before `ALPHA`) so a reader that lost the order
and re-sorted fails rather than coincides.

## Three things the existing guards caught

* **Two edges to `artefact` from the shared `item_map` collide** — both are
  named `artefact.item_maps` and the reverse hop is ambiguous.
  `organisation_contact`'s pair works only because its owners are *different
  tables*; both scheme maps live in `artefact`. One edge serves both, and each
  accessor's `__constraint__` on `artefact_type` tells them apart. Declared in
  `_POLYMORPHIC` with that reason.
* **`test_the_cascade_precondition_holds_for_every_writer` reads each
  dispatched writer's own source**, so the shared helper keeps cascade and
  spine in the three writers rather than folding them in. Said in the helper's
  docstring so it is not "tidied" back later.
* **`test_storage_query_bounds`'s refusal tests were on `StructureMap`** —
  picked when the containers became storable, and carrying a comment warning
  about exactly that risk. They are on `AttachmentConstraint` now, and the
  drift is guarded directly rather than by comment.

## Two stale `_NOT_PERSISTED` entries removed

`StructureSet` and `HierarchicalCodelist` became storable in #395's first step
and stayed listed as refused. Dead today — `put_artefact` finds a writer first
and never reads the table — but one dispatch change away from printing a
reason that is not true.

`test_the_refusal_table_matches_the_dispatch` now compares the table against
both dispatch tables in **both** directions, so it cannot drift again.
