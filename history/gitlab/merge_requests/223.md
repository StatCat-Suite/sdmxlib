#216. The round-trip property, stated over *generated* artefacts for SDMX-ML 2.1/3.0/3.1, SDMX-JSON and DuckDB storage, with the official XSD or JSON schema validated **on every example**.

`KNOWN_GAPS` is imported from `test_roundtrip_property_guard`, not restated. Two lists of known gaps would drift, and the first symptom would be a property failing on a gap somebody already understood.

There is also a **cross-format** property, because a round-trip alone cannot catch a field that *both* sides of one format drop symmetrically — precisely the blind spot `KNOWN_GAPS` exists to record. Any two serializers must also agree with each other.

## Three findings

**1. The SDMX-JSON writer emitted `[]` where the schema requires `minItems >= 1`.** Fixed here. An empty `ConceptScheme` produced non-schema-valid SDMX-JSON while all three XML writers accepted the same artefact.

Rather than fix the one case, I swept the writer against **every** `minItems >= 1` property in the official schema — 107 of them — and found 12 candidate call sites. Of those:

- **3 were real** (`concepts`, `categories`, `agencies`) and are fixed;
- **6 were rejected by basedpyright** — those DTO fields are *required*, so an empty one is an invalid artefact rather than a writer bug;
- **3 were caught by ruff** as single-element literals that can never be empty.

Both checkers narrowing the sweep is why this is a 3-line change and not a 12-line one.

**2. Concept ids are `NCNameIDType`; Code ids are `IDType`.** Easy to assume identical, so verified against the vendored XSDs:

```
id=OK       Code=valid    Concept=valid
id=0LEAD    Code=valid    Concept=INVALID
id=A@B      Code=valid    Concept=INVALID
```

Concept ids can become component ids, and component ids become XML names in structure-specific schemas. The strategies now model all three id types, including `NestedNCNameIDType` for agency ids.

**3. `validate()` accepts maintainable and agency ids the XSD rejects** — filed as #221, since it is a `validate()` semantics change rather than a test concern. `serialize(validate=True)` is the default and can currently emit non-schema-valid SDMX-ML.

## Two test-side fixes worth recording

**`compile_json_schema` was recompiling on every call** — ~100 ms, called once per example. Cached, and the properties went from **8m40s to under 2 s**. Schema compilation was the entire cost; the round-trips themselves are cheap. Every other test using that helper benefits too.

**`_XML_SAFE_TEXT` now derives its alphabet from `validation._XML_FORBIDDEN`** instead of restating it by Unicode category. My category-based version missed **U+FFFE**, which is `Cn` rather than `Cc`, and a property failed inside lxml saying nothing useful. Deriving from production is safe *here* specifically because that set is itself anchored to lxml's real behaviour by `test_validation_xml_charset` — otherwise it would be the circularity #215 warns about.

That one only surfaced under the full suite, not in isolation: `pytest-randomly` reseeds Hypothesis per run, so the property found an example the isolated run had not. Confirmed stable across three randomly-seeded full runs afterwards.
