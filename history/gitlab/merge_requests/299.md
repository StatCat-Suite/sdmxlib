## What was actually missing, and what it hid

The **structure binding**. `metadata_sets` only ever drew a `Metadataflow`, so the other arm of `MetadataSetType`'s choice was never generated. Extending it to both arms immediately found two bugs.

### 1. A MetadataStructure binding serialised to an invalid document

Validation accepted it and the 3.0 writer emitted `<md:Metadataflow>` holding an MSD URN:

```
Element '...metadata/generic}Metadataflow': [facet 'pattern']
  The value 'urn:sdmx:org.sdmx.infomodel.metadatastructure.MetadataStructure=...' is not accepted
```

SDMX-JSON rejected it too. The rule conflated two different things: the message **header**'s `<mes:Structure>` *does* carry an MSD, while the **set's** binding offers only `MetadataProvisionAgreement` or `Metadataflow` and has no third option. `_HEADER_URN_CLASSES` is now `_SET_STRUCTURE_CLASSES` and applies to both wire forms, since both reject it.

### 2. An unresolved MetadataProvisionAgreement had no 3.0 form and did not refuse

`_HEADER_ELEMENT` keys on `"ProvisionAgreement"`; the artefact class is `"MetadataProvisionAgreement"`. So it fell through the `.get(..., "Structure")` default into `<com:Structure>`, whose facet demands an MSD URN.

`GenericMetadataStructureType` is a choice of three, and an MPA URN matches none of their patterns — `ProvisionAgreementReferenceType` is `.+\.registry\.ProvisionAgreement=.+`, which `...registry.MetadataProvisionAgreement=` does not satisfy. The writer walks MPA → Metadataflow → MSD when the graph is resolved; when it is not, there is no valid document, so it now refuses. It writes fine as JSON, which is why the refusal is 3.0-only and why the round-trip property branches per format rather than excluding the case — excluding it would drop the MPA arm from JSON coverage too.

The writer's own comment claimed `check_metadata_serialisable` "refuses the kinds with no header slot at all". It did not.

## The gate now covers the second envelope

`test_wire_conformance_gate` was `StructureMessage`-only. It now also runs the binding × wire cross product for `MetadataMessage`, asserting valid-or-refused, that refusals are `ValidationError` rather than any escaping exception, and that an MSD binding is refused outright.
