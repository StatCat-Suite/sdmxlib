2.1 names a hierarchical code by a full `<Code><Ref>`, or by `<CodelistAliasRef>` + `<CodeID><Ref id=…/>`: the code's id alone, plus an alias for one of the HCL's `<IncludedCodelist alias=…>`. OECD writes every 2.1 HCL the second way. The reader took the code only from a `Ref` that also carried agency and parent, so **all 8,297 OECD codes came back as none**, and every writer then emitted nodes that no format accepts.

## Changes

- **Reader.** Each HCL builds an `alias → codelist` map, and `CodelistAliasRef` + `CodeID` resolve to the full Code URN. `isFinal` is read too; it was being dropped.
- **Writer.** `IncludedCodelist` is now emitted. It has been read since #239 but never written.
- **Store.** `included_codelists` is a container ref beside `hierarchies`.
- **A node with no code** is refused at the write, in every format (`check_serialisable`), instead of being emitted invalid. It is not a `validate()` rule: a code-less node is legal to hold, store and query (`test_a_node_without_a_code`). Whether such rules move to ingest is #419's question.

## Why nothing caught it

`tests/support/maximal.py` had no `HierarchicalCodelist`, so neither field census, wire or store, had ever looked at one. It now holds a populated one, and both censuses check it.
- **Sabotage-checked:** removing `included_codelists` from the store's container refs fails the store census.
- **`StructureSet` has the same blind spot.** It is still listed as absent in `test_storage_cascade.py`, untouched here.

## Tests

`test_hcl_alias_form.py` reads OECD's alias shape and asserts:
- the resolved code URNs;
- `included_codelists` and `isFinal`;
- schema-valid 2.1 output that reads back equal;
- the store keeping `included_codelists`;
- a code-less node refused in all four formats.

Disabling the alias branch fails it.

## Docs

The hierarchies cookbook's fixture wrote `classifications.xml` from nodes with no code, which made it a schema-invalid 3.0 file. The docs tier caught it once the write refused. Every node now references its code.
