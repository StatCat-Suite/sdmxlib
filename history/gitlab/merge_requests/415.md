Steps 1–3 of #364. The #354 census compares a round-trip, which is blind to
output wrong in a way our own reader forgives — the class #345, #356 and #357

Pointed at it: **23 XSD errors in 3.0 and 3.1, 13 in 2.1, 7 in SDMX-JSON.**

## Four were real

**`enumerationFormat` carried `decimals` and `isMultiLingual`** in all four
writers. It constrains the *codes* of an enumerated representation, and codes
are strings — SDMX-ML types it `CodedTextFormatType` (decimals prohibited,
isMultiLingual absent from the restriction) and SDMX-JSON closes the branch.
Invalid output, not a quiet drop. Filtered per-tag on the XML side; the JSON
serialiser is separate and needed the same. Declared in `gaps.py`.

**A Level's `startValue`/`endValue` went through `str()` in the 3.0 and 3.1
writers** — `1.0` into a slot typed `xs:positiveInteger`. #354's 2.1 bug
verbatim, in the two writers #346 is about. `minValue`/`maxValue` went in with
the fix; they are `use="optional"` and were never emitted, which is #230's other
half.

## The rest were the fixture, for the fourth time

Maximal beyond the grammar: a TimeDimension with a general facet where
`TimeTextFormatType` allows only textType/startTime/endTime; a categorisation
targeting a CategoryScheme where the pattern pins `…categoryscheme.Category=`;
a measure named `MEAS` where 2.1 fixes `PrimaryMeasure/@id` to `OBS_VALUE`; a
2.1 metadata target with a general facet where four target-object types are
legal; a provider URN built from `DataProvider` because `MetadataProvider` is
unmodelled (#315).

## Vendored the right schema

Only SDMX-JSON **2.1**'s structure schema was in the tree, and 2.1 describes
SDMX 3.1 — it closes every object with `unevaluatedProperties: false` where 2.0
leaves them open. Validating our 2.0 output against it reports version
differences as defects, which is precisely the mistake I made on #358. 2.0.0's
structure and metadata schemas are now vendored, from tag `v2.0.0`.

## Two corrections to my own work, both recorded in place

**`tests/support/json_schema.py` already existed** and I overwrote it, breaking
six modules that import it. It was better than my replacement and already
documented the format-checker subtlety I had presented as a discovery. Restored;
the real change is `_KINDS_BY_VERSION` gaining structure and metadata for 2.0.
#364's premise is corrected in a note there.

**One register entry went quiet rather than fixed.** Renaming the measure to
`OBS_VALUE` (2.1 requires it) means the id the 3.0 reader *fabricates* (#360)
now matches the real one, so that round-trip looks clean. One conformant fixture
cannot both satisfy 2.1's fixed id and expose a fabrication of it — the register
says so where the entry used to be.
