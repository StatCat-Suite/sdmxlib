The audit's third item — closing the aggregation surface. Three of its
four points held; one did not, and the correction is below.

**`having()` — predicates over groups.** "Agencies with more than one
dataflow" had no spelling: the root is a dataflow, the group is an
agency, and `filter` refuses after `group_by` because a row predicate
stops being meaningful once rows are groups. That refusal is right and
stays; the missing thing was the other question.

    group_by(q.dataflow.agency).agg(n=q.dataflow.id.count())
        .having(q.dataflow.id.count() > 1)

The aggregate is written out rather than named by its output alias,
because `HAVING` runs before the result exists and dialects disagree
about whether the alias is visible there. `having()` without a
`group_by()` is refused and points at `filter`, where a row-grain
aggregate does belong — `filter(q.codelist.codes.count() > 3)` already
works and means the correlated-subquery reading. Same `AggCompare`, two
readings, decided by the clause: the split `.over()` makes for windows.

Binds are spliced in clause order rather than appended to the
projection's. DuckDB matches `?` positionally, and getting that wrong
bound every value one slot out — it surfaced as a cast error naming an
unrelated column, which is pinned by a test.

**`Agg.__canonical__`.** Two textually identical programs behaved
differently: `Frame.order_by` matched columns structurally and
aggregates by `is`, so holding the aggregate in a variable worked and
writing it twice was a `TypeError`. `__eq__` is spoken for — it builds a
predicate — so an aggregate had no way to say it means the same thing.

**`order_by("n")`.** By output name, which SQL and polars both accept
and which is the only spelling available when the projection was built
elsewhere.

**The audit was wrong about windows.** It reported them usable only in
`qualify`, making `lag`/`lead` dead and "rank within agency"
unexpressible. Both work in `select` today — `Win` is a `Col` — and the
query it named runs. What was actually wrong is the *message* for an
unframed `WinFn`: "takes a column, got WinFn" sent people looking for a
column they already had, where the fix is `.over()`. Now it says so.

`AggPred` is exported as the vocabulary `having()` names — abstract, for
the reason `WinPred` is: `test_public_surface` holds both that every
type in a public signature must be importable *and* that no concrete
expression node may be, and those two together decide it. The concrete
`AggCompare` stays private, so reshaping it stays free.

Three inventory guards fired on the new type and each was answered where
it belongs rather than exempted: a sample in the expression surface, the
vocabulary set in `test_public_surface`, and `_concrete_predicate_kinds`
learning that `AggPred` is a third abstract base — those are abstract by
intent, not by ABC machinery, so `inspect.isabstract` cannot see them.

`just test-properties` clean at 20x.
