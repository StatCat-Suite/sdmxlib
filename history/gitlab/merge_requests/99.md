Pre-release XML perf audit. Two micro-optimisations that net ~7% on parse across every fixture size.

## Wins

### 1. Precompute clark-notation tag strings

Replace ``c(\"Name\")`` / ``c(\"Description\")`` (~43 ns each — the f-string ``f\"{{{ns}}}{tag}\"`` builds per call) with local-variable accesses (~10 ns) in the hot read/write helpers (\`read_istring\`, \`read_annotations\`, \`write_istring\`, \`write_annotations\`).

Bench:
\`\`\`
f-string ``c(\"Name\")``: 43 ns/call
cached dict lookup:     31 ns/call
local var access:       10 ns/call  ← 4x faster
\`\`\`

The 8 hot tags get pre-built once per ``make_reader_helpers`` / ``make_writer_helpers`` call and the closures reference them directly. The ``c()`` / ``s()`` / ``m()`` builders stay for cold paths.

### 2. Empty value-type singletons

Module-level ``_EMPTY_ISTRING`` and ``_EMPTY_ANNOTATIONS`` returned from ``read_istring`` / ``read_annotations`` when there's no language data or no annotation block. Avoids per-call attrs construction in the (very common) no-data case.

### 3. Tried + rejected: batched ``SubElement(parent, tag, attrib={...})``

Made serialize ~10% **slower** across every fixture. lxml's attrib-dict path is more expensive than two C calls. Reverted; documented in the commit message so future contributors don't try it again.
