## The gate was broken, and had been since #284

**`just mutate` did not run at all.** mutmut copies `src/`, `tests/`,
`pyproject.toml` and `uv.lock` into `mutants/` — not `tools/` — so the
`from tools.count_any import …` I added in #284 aborted the whole run at
*collection*. Not one mutant: all of them.

Nothing caught it, because mutation testing is deliberately not in `just ci`
(eleven minutes), so the only signal was the next person to run it. That was
this issue.

Fixed, and guarded: `test_no_test_imports_a_repo_tree_mutmut_does_not_copy`
AST-scans `tests/` for imports of repo directories outside the copied set. It
costs milliseconds, runs in `just ci`, and was verified to fire on exactly the
import that broke things. The cheap half of an expensive gate.

## The measurement, before anything else

**`collections.py`: 179 mutants — 145 killed, 27 survived**, 3 timeout, 3
segfault, 1 no-tests.

27 is *exactly* the #213 pilot's figure. Everything that landed in between
killed none of them — the calibration #253 wanted on how much four aggregate
properties pin. The answer: they pin aggregate claims. Every survivor sat in a
lookup, a sort, a projection or a message — *"which one did you get back"*, not
*"is the result a subset"*.

**`validation.py` did not complete.** 1000+ mutants, 129 survivors and 75
timeouts after ~25 minutes, 739 unchecked, timeout count still climbing. That
is the reportable result #253 anticipated, and the timeouts are the signal:
cost per mutant is unbounded there, not merely high. It needs its own bounded
run before triage, and #213's figure of 123 is neither confirmed nor refuted —
it should stop being quoted until a run finishes.

## Triage: 27 → 15

Twelve killed. **Every survivor is recorded** in
`docs/design/mutation-testing.md` as equivalent or won't-fix with its reason —
the artifact #218 asked for and never got — so the next run does not re-triage
them.

Real gaps closed, all in `ArtefactList`: a `SdmxRef` wildcard whose sense could
invert, version matching that could compare `!=`, a bare-id miss that raised
`TypeError` instead of returning `None`, `descending=True` as a silent no-op,
`to_dict` collapsing every key to one, and two messages reduced to
`KeyError(None)`.

Two rules kept the equivalents honest rather than chased — message *content* is
pinned, message *format* is not; same for `repr`. Both measured: a content
assertion on `repr` killed exactly **one of nine** mutants. The other eight only
move punctuation, and killing them needs a golden test on debugging output.

## A defect the triage found

`ItemList.__hash__` / `ArtefactList.__hash__` **raise for every domain item
type** — `_items` holds attrs `@define` items, which are unhashable, so only an
*empty* list hashes. The classes advertise hashability they cannot deliver, and
that is precisely why the mutant survives: no test can call `hash` on a
populated list. Filed as **#290**; current behaviour pinned here, which does
kill the mutant.
