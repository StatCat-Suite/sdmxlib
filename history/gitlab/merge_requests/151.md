# Merge request !151: perf(serialize): decouple validation from serialize (validate=False default)

## Motivation

Profiling the serialize path against sdmx1/pysdmx showed the dominant *avoidable* cost was **validate-on-every-write**. `serialize()` ran `validate_message(msg)` unconditionally. `orjson.dumps` itself is only ~3% of JSON serialize; **validation was 55% of it** (13% of XML). pysdmx's JSON/serialize edge was almost entirely us paying validation they don't.

## Change

Serialisation and validation are separate concerns. `serialize()` / `to_xml` / `to_json` now take `validate: bool = False` and only validate when asked. `validate_message` stays public for the explicit pre-flight check. Output is **byte-identical** either way — validation is a pure guard, never fed to the writer. Matches sdmx1/pysdmx (neither validates on write). SRP + removes a hidden per-call cost.

## Measured

Code-heavy synthetic (500 dataflows):

| | before (validated) | after (default) | Δ |
|---|---|---|---|
| JSON serialize | 2.22 ms | **0.99 ms** | **−55%** |
| XML serialize | 10.0 ms | **8.70 ms** | **−13%** |

Competitive `test_compete` (ecb-490k): JSON **1.49 → 0.96 ms (−36%)**, XML 5.96 → 5.48. The win is O(artefacts) — big on many-artefact messages, smaller on few-large-artefact ones (so the 3.8 MB compete fixture, being data-volume-bound, moved less).

## Also

- Small XML win: pre-build the `str:`-namespace `Code`/`Parent` tags (`_s_code`/`_s_parent`), mirroring the existing `_c_name` block — avoids a per-code f-string rebuild.
- **Deliberately NOT done:** an `attrib`-dict merge in `write_istring` — A/B'd it and it was **~38% slower** (per-call dict alloc > the saved `.set()` C-crossing). The plain `.set()` form stays (faster *and* clearer). The remaining pysdmx XML edge is architectural (they string-concat; we build a DOM for auto-escaping, guaranteed well-formedness, XSD-validated round-trips) — not worth trading that quality.
