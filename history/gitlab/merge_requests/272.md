## The finding: NULL attributes

An attribute filter does **not** match rows whose value is NULL, because
`NULL IN (…)` is NULL rather than false. So `GEO_LEVEL IN ('FED','PROV')` —
naming every non-null value that exists — still drops a third of the table.

The library had not written that down anywhere, and a reader would reasonably
expect otherwise. It is now stated in the oracle's docstring and pinned by a
named test, so a future change to `to_where_clauses` (say, emitting
`col IS NULL OR col IN (...)`) is a **decision** rather than a drift. Same
three-valued-logic trap the structural side already met, where `parent_id != x`
excludes roots.

#258 predicted this shape would be here. It was.

## Design notes

- The fixture is a **cartesian product** on purpose: any filter's expected
  result is trivially computable, and no accidental correlation between
  dimensions can mask a bug that ignores one.
- Relations are **executed, not modelled** — whether a `CodeQuery` computes the
  right set is `code_query`'s problem with its own property. This tests the
  splice.
- The oracle is not a recursive ADT interpreter. The IR is AND-across,
  OR-within; modelling more would model expressiveness the library lacks.
- The fixture is module-scoped because Hypothesis rejects function-scoped
  fixtures under `@given`. Nothing mutates it, so widening the scope is the
  honest fix — suppressing the health check would assert the same thing without
  making it true.
