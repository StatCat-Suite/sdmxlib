Closes #276. Part of %15.

The survey found **76 hand-written SQL sites across fourteen tables**, and the
question behind most of them has no in-memory answer: "across 800 dataflows,
which use REF_AREA" is a join, not 800 `resolve()` calls.

```python
reg.artefacts(sl.Dataflow).filter(sl.artefact.uses_concept("REF_AREA")).urns()
```

One statement, no resolution.

## The decision this issue was held open for

**One generic spine query, not fourteen DSLs.** The issue framed fourteen
tables as fourteen missing DSLs. The schema says they are one relation plus
thirteen thin extensions — `sdmx.artefact` carries the whole maintainable
surface for every artefact, and `sdmx.dataflow` is two columns:

```sql
CREATE TABLE dataflow (urn TEXT PRIMARY KEY, dsd_urn TEXT NOT NULL);
```

The consumer SQL agrees: the dominant shapes are spine-with-a-filter and
spine-with-a-correlated-EXISTS, the latter structurally identical to what
`annotation_exists` already emits.

**This is not a reversal of #267.** That kept `code` and `node` apart because
their columns genuinely differ. Across artefact types the field surface is
*identical* — it is the `MaintainableArtefact` surface by definition — so there
is nothing to keep apart, and thirteen more row kinds would be thirteen copies
of one. Type safety comes from the artefact class instead:
`reg.artefacts(Dataflow)` → `ArtefactQuery[Dataflow]` → `list[Dataflow]`.

Joins that are not fields become predicates, exactly as `code.descendants_of`
already does: `uses_concept`, `uses_codelist`, `in_category`.

## Worth a look in review

**Labels compile to a correlated scalar subquery, not an `EXISTS`.** Artefact
labels live in `sdmx.localized_text`, not a MAP column. The primary key makes
the subquery single-valued, and it buys two things `EXISTS` cannot: the label
is **projectable**, and it is **testable for absence** —
`name["fr"].is_null()` answers "which artefacts are missing a translation".

**`uses_concept` works from both sides of the dataflow/DSD edge.** A
DataStructure carries its components directly; a Dataflow reaches them through
`dsd_urn`. Both are asserted, and so is the non-match — the asymmetry is a trap
that looks correct against whichever fixture the author happened to write.

**`RowKind` trimmed to the one member the compiler reads.** It declared
`table`, `scope_column`, `key_column`, `parent_column`, `urn_column`; both DSLs
set all five and **only `urn_column` was ever read**. The spine has no parent
and no enclosing scope, so implementing them meant assigning two meaningless
strings to satisfy a promise nobody checks.

**`select` / `group_by` / `SqlRelation` came free from #275.** The new module
is a row kind, its fields, three predicates and a query class — no new compiler
machinery. That is the payoff from the last two MRs.

## Protected file

## Found on the way

rather than fixed here.

## Tests

- **22 unit tests.** Two spy tests assert `urns()` and `len()` are one
  statement and resolve nothing — an implementation that hydrated every match
  would pass every value assertion in the file and hand back exactly the cost
  consumers wrote SQL to avoid.
- **4 differential properties against `Registry.get_all`** — an unusually good
  oracle: a shipped code path answering the same question by a completely
  different route, so unlike a test-only oracle the two cannot drift silently.
  Deliberately restricted to unfolded matching; restating `code_query`'s
  folding rules would be a second copy able to be wrong the same way.
- **`docs/cookbook/discovery.md`** + driver executing every block (#278).

## Deliberately not in scope

- **`dsd_component` as its own query** — "which dimensions does this flow have"
  as a catalogue-wide frame. `uses_concept` / `uses_codelist` cover the
  discovery half; the component surface is a second row kind.
- **`metadata_target`** — a tree of reported values, a different shape from the
  artefact spine. Worth its own issue, as #276 anticipated.
