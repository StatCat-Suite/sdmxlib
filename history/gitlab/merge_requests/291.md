## The premise, re-measured

The issue’s code citation is stale (#255 restructured `_emit_string_match`) and so is its “Not affected: label fields”. After #255 removed the *implicit* label folds, labels case-fold exactly as ids do. It was never an id-field quirk: **every string match, on every field, in all four DSLs**, with no way to ask for a case-sensitive one.

Which reframes it — case is not a separate question from #255, it is the rung #255 left out. `Fold.NONE` folded case, so the floor of the ladder was not a floor and its name was a lie.

## Why this shape

Peers are unanimous on the default, but the *mechanism* decided the API. SQLAlchemy has two:

```
(a) i-prefixed op       c.icontains(x)                   -> ILIKE
(b) .collate(modifier)  c.collate("NOCASE").contains(x)  -> (v COLLATE "NOCASE") LIKE
                        c.collate("NOCASE") == x         -> (v COLLATE "NOCASE") =
```

(a) is what everyone uses **when case is the only axis** — polars `(?i)`, Django `__icontains`, pandas `case=`; none of them has an accent or punctuation fold at all. When strength is multi-valued, SQLAlchemy switches to a modifier chained before the op, which is structurally our `.unaccented.contains(...)`. So the chain shape is precedented for exactly our situation, and it settles `==` too.

Equality compiles to `COLLATE NOCASE =`, not `ILIKE`. An equality operand is not a pattern: the shortcut is silently wrong because `_` and `%` in a caller’s id become wildcards, so `id.caseless == "CL_FREQ"` would also match `CLxFREQ`. SDMX ids contain `_` constantly.

The accent rungs still refuse `==` — #255’s call, left standing rather than swept along. `is_in` stays exact; no peer offers a caseless membership test.

## Two pre-existing defects found on the way

1. **The oracles were already wrong about case.** They modelled `ILIKE` with `str.casefold`, which claims `Straße` matches `STRASSE`. DuckDB’s `ILIKE`, `COLLATE NOCASE` and `lower()` agree with each other and all three disagree. It never failed because a generated needle is a slice of the generated value, so the fold cancels on both sides. Now `str.lower`, with the residual `İ` divergence pinned as examples rather than modelled.
2. **`code_query`’s differential had no power over case.** A probe reverting the default to `ILIKE` left it green — only the *hierarchy* property and hand-written tests caught it. The two suites were not equally strong and nothing said so. Both now draw case-mutated needles.
