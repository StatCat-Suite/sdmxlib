Closes **#99**. The audit reported \"Contact multi-field untested\"; adding a fixture that exercises every \`ContactType\` field surfaced **three bugs at once**.

## Summary
7 files, +87 / −6. CI: **1825 unit + 71 docs** (was 1823; +2 reader tests).

## Bugs found

1. **\`Contact.x400s\` missing from the model entirely.** The XSD \`ContactType\` includes \`<X400>\` as a sibling of Telephone / Fax / URI / Email; we never modelled it. Read-only inputs that carried \`<X400>\` silently dropped the value.

2. **3.0 reader looked for \`<com:Department>\` / \`<com:Role>\`.** The XSD places these in the **structure** namespace (since \`ContactType\` is defined inside \`SDMXStructureOrganisation.xsd\`, whose target namespace is \`str:\`). \`_read_istring\` defaults to the common namespace — wrong namespace for these two fields, so any \`Department\` / \`Role\` value parsed as an empty \`InternationalString\`.

3. **3.0 writer emitted \`<com:Department>\` / \`<com:Role>\`.** Same bug, mirror image. XSD validation rejects this the moment a Contact actually carries one of those fields.

(2) and (3) cancelled out on round-trip when no fixture exercised them, so this stayed latent until now.

## Changes

- **Model**: \`Contact.x400s: tuple[str, ...] = ()\` — new field.
- **3.0 writer**: \`X400\` emission alongside Telephone / Fax / URI / Email. Department / Role now emit as str-namespace elements with \`xml:lang\`, bypassing \`_write_istring\`'s common-namespace target.
- **3.0 reader**: X400 collection. Inline str-namespace istring read for Department / Role.
- **SDMX-JSON writer + reader**: \`x400s\` field added symmetrically.

## Fixture extension

The existing single-field Contact stays so the bench covers both the minimal and the full shape.
