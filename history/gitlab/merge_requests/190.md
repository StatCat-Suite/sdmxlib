Builds on !189 (merge that first). Makes the reader **fail** on a reference whose URN class contradicts the element carrying it, instead of returning an unresolved Ref.

## Why the read boundary and not the writer

I initially proposed doing this at the write boundary, where `validate()` already lives. That was wrong for a concrete reason: **`Ref[T]`'s type parameter is erased at runtime.**

```
type(Ref[Codelist] instance)      -> <class 'sdmxlib.model.ref.Ref'>
type(Ref[ConceptScheme] instance) -> <class 'sdmxlib.model.ref.Ref'>
same runtime class?               -> True
```

A writer holding `RepresentationMap.source` sees a bare `Ref` and cannot recover what it was *supposed* to be, so it would need its own field→class map and would still have less context than the reader — which knows the element name, and the element name is what the XSD constrains. Checking at read is also the only placement that keeps the invalid state out of the model at all.

## What is and isn't an error

* **Error** — the URN names a class the element cannot carry. No schema-valid message contains one. Raises `SdmxConformanceError`.
* **Not an error** — a *dangling* reference: right class, artefact simply absent from this message. Normal for partial payloads and for refs resolved later against a registry; still yields `Ref.unresolved`.

The check lives in `resolve_ref`, so all ~10 call sites get it uniformly. Sites that genuinely accept any artefact pass `object`, which disables it by design. Every representation call site now passes its witness **explicitly** — the default was removed, so a new site cannot silently inherit `Codelist`.

## It found three real defects

**1. `MeasureDimension` is enumerated by a ConceptScheme, not a Codelist.** The XSD types it `ConceptSchemeReferenceType`, and our own 2.1 writer docstring says so — but the reader, the model field, and `storage/readers.py` all said Codelist. `md.codelist` was returning something semantically a ConceptScheme.

**2. The ml30 hierarchy fixture emitted non-conformant XML.** It built a `HierarchicalCode` whose `code` was a bare *codelist* URN. XSD-validating its own output confirms it:

```
Element 'Code': [facet 'pattern'] The value
'urn:sdmx:org.sdmx.infomodel.codelist.Codelist=T:CL(1.0)' ...
```

`<Code>` requires `.codelist.Code=`. Reader and writer agreed with each other, so the round-trip was green — the exact failure mode CLAUDE.md says XSD validation exists to catch, in a test file that doesn't run it.

**3. The ml21 measure-dimension fixture** enumerated over a Codelist, same root cause as (1).

## BREAKING: `MeasureDimension` drops `RepresentationMixin`

pyrefly rejected narrowing the mixin's mutable `representation` in a subclass — correctly; it is an LSP violation. So `MeasureDimension` carries its own field and accessors named for what they actually hold:

| removed | replacement |
| --- | --- |
| `md.codelist` | `md.concept_scheme` |
| `md.codes` | `md.concepts` |
| `md.resolved_codelist` | `md.resolved_concept_scheme` |

**No aliases.** Those names were wrong on this class. `pivot()` and the polars bridge follow; `_to_concept_scheme_ref` also rejects a non-ConceptScheme `Ref` at construction, so the bad state cannot be built directly either.

The alternative — a generic `RepresentationMixin[T]` — was rejected because it drags `codelist` returning a `ConceptScheme` through the public API of every component.
