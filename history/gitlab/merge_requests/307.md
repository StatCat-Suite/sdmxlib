Closes #317.

Writing an artefact cost **8.4 ms** and 43 SQL statements, ~36 of them a `DELETE` per table in the schema run for every artefact whatever its type. On a fresh materialisation every one matches nothing.

| payload | before | after |
| --- | --- | --- |
| ECB dataflow catalogue, 183 artefacts | 8.5 ms/artefact | **3.2** |
| CL_CURRENCY + descendants, 142 artefacts | 14.0 ms/artefact | **8.9** |

Two thirds of the saving is not the deletes themselves — each binds `urn` as a parameter, and DuckDB probes every parameter *value* for a pandas null with a lazy `import pandas`. Not a dependency here, not installed, and Python does not cache failed imports, so each probe re-walks `sys.path`. Measured in isolation on 20,000 four-column rows: `executemany` 4.90 s / 160,000 lookups, Arrow 0.03 s / 1 lookup. So `_put_artefact_localized_text` — the last `executemany` in the writer — now uses `_execute_bulk_insert` like everything else.

## Why the skip is sound

Every writer cascades *before* `_put_spine`, so child rows never exist behind an absent spine row. `test_the_cascade_precondition_holds_for_every_writer` reads that ordering off the source of all 18 writers rather than trusting the docstring — a transposed pair in a writer added later makes the skip silently wrong, and the symptom is stale rows nobody looks for.

## Gates

- Re-add contract per artefact kind: add three times, row counts never move. Three rather than two because #309 grew by one set per add — a third distinguishes "duplicates once" from "duplicates every time".
- Replacement still drops removed children (the delete path, when the artefact *is* present).
- The skip is guarded by a statement **count**, not a duration.
- Full suite green; it also runs 131 s → 111 s, since tests write artefacts constantly.

## Follow-up not taken here

The re-add path still issues all ~36 deletes. Making the cascade type-aware would cut that too, but it needs the per-kind table set *derived* in a test rather than enumerated twice — noted on #317.
