I found this while writing `obs.pivot()` (step 4 of #516).

**The bug.** `DataflowBinding.from_dsd` mapped `dsd.dimensions` and the time dimension. A 2.1 `MeasureDimension` isn't in `dimensions`, so on a cross-sectional dataflow:
- the measure column was missing from every observation frame and from the key (and so from paging's tiebreak);
- `obs.col("MEASURE")` was an unknown component;
- each series' one-row-per-measure looked like duplicates.

`RestRegistry.observations` binds its fetched table through `from_dsd`, so every such flow read over REST was affected.

**The fix.** `dim_map` is now `dsd.key_slot_ids("3.0")`: dimensions, then the measure dimension, then time. That is the 2.1 DimensionList order. `DataStructure.role_of` already gave the measure dimension `KEY_DIMENSION`, so pushdown needed no change.

**Tests:**
- the key order;
- a DSD without a measure dimension maps as before (discrimination check);
- an observation frame carries `MEASURE`, and a filter on it works.

Without the fix, 2 of the 3 tests fail.
