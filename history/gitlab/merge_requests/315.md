Closes #311. Relates to #319.

`artefact.version` is text, so every ordering over it was lexicographic: `1.9` sorted after `1.10` and "the latest version" — the headline example in `cookbook/discovery.md` — returned the wrong artefact for any catalogue whose minor version reached double digits.

Fixed by baking a sortable key at write time, which is what `caching.md` prescribes for an input immutable within an artefact version, and the same shape as `code.depth`. Schema 2.8 → 2.9.

## The grammar came from the vendored XSD, not a guess

The cassettes were checked first and hold exactly **one** distinct version string, `1.0` — so real data had nothing to teach. `SDMXCommonReferences.xsd` supplied the rest.

## Three sites, built by different code

Only the first is obvious, and fixing it alone leaves the bug:

- `order_by(version)` — `_Scope.order`
- `rank().over(...)` — the window's own ORDER BY in `_window`. Still returned `1.9` after the first fix, which is the exact query #311 names.
- `after()` paging — `_order_terms`, which must agree with `_Scope.order` or the cursor compares one column while the sort used another and rows are skipped, silently and only past double digits.

`lag`/`lead` needed the source rendered twice: the *value* reads `version`, the ORDER BY reads the key.

Comparison is deliberately unaffected — `version == "1.10"` matches what the registry published.

## Two defects found in this branch's own work

- **The SQL corpus caught a regression.** `sort_column` first defaulted to the private `_column` slot; `Label` overrides the public `column` (a localised value is a MAP, read as `name[?]`), so every label's sort key diverged from its own reference and `ORDER BY name` lost its language bind. Corpus diff went from 6 lines to the 2 intended.
- **Three parts was too few.** 2.1 permits unlimited parts and `_check_version` implements 2.1, so `1.2.3.4` and `1.2.3.9` tied. Now eight, with the new boundary pinned.

## Stated limits rather than implied ones

- Prerelease ordering is lexical, not full SemVer precedence (`alpha.10` before `alpha.9`).
- Beyond eight numeric parts, versions collide.
- An unparseable version sorts *before* every real one, so a malformed artefact looks old rather than newest.

## The page and its guard

`test_version_ranking_is_lexicographic_as_the_warning_says` was written to fail "after someone fixes it and forgets the page". It did. Renamed, inverted, and the admonition is now a note.
