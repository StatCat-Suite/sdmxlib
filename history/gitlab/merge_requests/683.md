Step 5a of #516, per the decisions recorded on the issue. **`reg.scan_csv(source) -> ObsQuery`** is on both `LocalRegistry` (new) and `RestRegistry`; on `RestRegistry` this is a breaking change, since it used to return a `Dataset`.

**What it does:**
- The registry resolves the file's `STRUCTURE` / `STRUCTURE_ID`, or 1.0's `DATAFLOW`. `LocalRegistry` reuses the CSV reader's `_resolve_structure`, which handles all three kinds. `RestRegistry` keeps its single "dataflow + descendants" fetch.
- A **path** becomes a DuckDB view over `read_csv`. The file is read in place on every query.
- **Bytes** are loaded into a table once, the way a REST fetch is.
- Both go into an attached `:memory:` catalog, `sdmx_scans`. A `TEMP` view would be invisible to the store's cursors, and the attached catalog means a file-backed store is never written to (there is a test for this).
- Each scan gets its own relation, so two files of the same dataflow are two independent queries.
- `_column_types` moved from `api/registry.py` to `local/_scan.py` as `column_types`; REST fetches and scans now share it.

**The one literal in a DDL.** DuckDB refuses `CREATE VIEW … read_csv(?)` because that statement "can't be prepared". So the path and the column types are written into the view as quoted literals through `_sql_string_literal`, the precedent set for `CREATE SECRET`. A path containing `'` is tested.

**Refused: a file whose `STRUCTURE` is `datastructure`.** A binding is over a dataflow, and a structure alone doesn't say which one. `slpl.scan_csv` accepted these files, so retiring it (5c) drops that case. I'm flagging this on the issue.

**Tests** (`test_scan_csv_registry.py`, 16):
- the envelope columns are dropped, and typing is applied;
- a code DuckDB would read as BIGINT (`10`) stays text, for both a path and bytes. With the view's `types=` removed, this test fails, and it is the only one that discriminates the typing;
- the view reads the file in place;
- the store is untouched;
- the terminals (`validate`, `pivot`) work on a file;
- the 1.0 and provision-agreement kinds work;
- `RestRegistry` makes exactly one request.

Three doc blocks (`cookbook/data.md`, `data_tutorial.md`, `llms.txt`) are updated to `.frame()`. The misuse refusal from !674 named the fix in each case.
