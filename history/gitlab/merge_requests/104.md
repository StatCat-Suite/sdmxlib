## Summary

Each `sl.code` predicate (`_Eq`, `_StringMatch`, `_IsDescendantOf`, …) now exposes `to_sql(ctx: CompileContext) -> (sql, params)` via a single method on the `Predicate` base. Foreign-SQL embedding goes through `sl.CompileContext` (already public, already exported), aligning the public surface with the cross-library `Predicate` Protocol that was already designed in `sdmxlib/sql.py`.

## Motivation

`pinax`'s catalog filter layer (`pinax.query.has_code`) wants to accept `sl.code.descendants_of("CA", hierarchy=h)` so that *catalog-level* queries can use SDMX 3.0 Hierarchy descent without enumerating the descendant set first:

```python
store.query(pk.StatisticalDataset).filter(
    q.has_code("REF_AREA", sl.code.descendants_of("CA", hierarchy=h_admin))
)
```

The first iteration of this MR added a procedural `sl.compile_code_predicate(pred, *, row_alias=...)` top-level helper. Review surfaced that `sdmxlib/sql.py` already documents the cross-library contract for exactly this use case — a `Predicate` Protocol with `to_sql(ctx: CompileContext)` and a `CompileContext` carrying `row_alias`, join accumulators, alias dedup, and a logical→physical schema map.

Adding the procedural helper would have created a parallel API surface and split future enhancements (logical-schema mapping, alias dedup across cross-library predicates in one query) across two seams. Protocol-aligned design instead:

- `pinaxlib` predicates and `sdmxlib` code predicates share **one** `CompileContext`, so JOINs dedup and aliases stay unique across a query containing both.
- Schema mapping is one `ctx.schema('sdmx')` lookup away — no API change needed when a downstream consumer wants to remap tables.
- The protocol stays single-seam: every predicate, in every library, has `to_sql(ctx)`.

## Public surface

```python
pred = sl.code.descendants_of("CA", hierarchy=h)
ctx = sl.CompileContext(row_alias="c")
clause, params = pred.to_sql(ctx)
# ctx.join_sqls / ctx.join_params carry any LATERAL JOINs the
# predicate needs (annotation predicates only, today).
```

`sl.CompileContext`, `sl.Predicate` (Protocol), and `sl.SqlRelation` are all already exported from `sdmxlib/__init__.py`.

`compile_code_predicate` is **not** exported — `pred.to_sql(ctx)` is the load-bearing API.

## Schema contract

`Predicate.to_sql`'s docstring now documents the required columns on the relation aliased as `ctx.row_alias`:

- `code_id` (TEXT)
- `parent_id` (TEXT, nullable)
- `depth` (SMALLINT)
- `name` (MAP(VARCHAR, VARCHAR))
- `code_urn` (TEXT)
- `codelist_urn` (TEXT)
- `ancestor_ids` (TEXT[])

Hierarchy-aware predicates (`descendants_of(..., hierarchy=h)`, `hierarchy(h).level(...)`) additionally reference `sdmx.hierarchy_node`. Schema names are resolved through `ctx.schema('sdmx')` so consumers can remap if needed.
