Closes #177.

## Problem

The `type[T]` witness threaded through `resolve_ref` / `_resolve_urn` (!145)
**documented** an assertion but didn't **enforce** it. The resolved branch built
`Ref.of(urn, obj)` from `obj: object` (a `dict[str, object]` value) and returned
it as `Ref[T]` — an unbacked downcast that typechecked only under basedpyright's
`Any`-unification (via the `SdmxUrn[Any]` argument). pyrefly, inferring honestly,
saw `Ref[object]` and rejected the `Ref[T]` return (`bad-return`). The witness was
decorative.

## Fix

Make the witness a **runtime guard**: resolve into the Ref only when the indexed
object is actually a `cls` instance (`isinstance` narrows `object` → `T`). A URN
pointing at a wrong-typed artefact now falls through to an **unresolved** Ref
(policy (a) from the issue) instead of a mistyped resolved one — safer, and it
connects the assertion to the payload so `Ref[T]` is honest under any checker.

The guard is `obj is not None and isinstance(obj, cls)`, **not** bare
`isinstance(obj, cls)`: `isinstance(None, object)` is `True`, so for the
heterogeneous `cls=object` sites a *missing* URN would otherwise resolve to a
`None` payload.

## Effect

- pyrefly `bad-return` **3 → 0** (the witness gap is closed); basedpyright still 0.
- The `# noqa: ARG001` witness-unused suppressions are gone (`cls` is now used).
- **No behavior change for valid input** — the resolution index stores each
  artefact/item under its own URN, so `isinstance` always passes. All 2405 unit
  tests green.

## Test

`tests/unit/test_reader_ref_witness.py` covers the policy: type-match resolves,
wrong-type falls through to unresolved, `object` witness accepts any type, and the
missing-URN-with-`object`-witness sharp edge.
