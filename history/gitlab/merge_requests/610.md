## The defect

#436 (elements) and #446 (attributes) close each *artefact's* subtree. The frame around the artefacts was never checked: the message header, and the containers between `mes:Structures` and the artefacts. Measured on the maximal message in 2.1, 3.0 and 3.1:

| Injected | Before |
|---|---|
| an empty unknown container, a foreign-namespace element in `Structures`, a stray header element, an attribute on a container | **silently ignored** |
| `<str:Bogus>` in `str:Codelists` | refused, as "sdmxlib does not model Bogus" |
| a `ConceptScheme` misplaced in `str:Codelists`; a codelist inside an unknown container | refused, but blamed as "**a reader defect**" |

## The fix

- **`frame_refusals`** (`_closed_world`). It checks the header through `check_children`, then one level of containers and their children against the table, and never re-enters an artefact, since `check_artefact` walks those when they are built.
  - A stray element outside any artefact is refused **by its place**, e.g. `mes:Structures/str:Codelists/str:Bogus[1]`. That's the outcome you chose, matching how 3.1's identity-less availability constraints are refused.
  - An unknown container, or one carrying an attribute it does not allow, is refused whole.
  - The reason is the schema table's: "not allowed in <str:Codelists>; the SDMX-ML 3.0 schema allows str:Codelist there".
- **`account()`** runs it first, and does not account for what it covered a second time.
- **The generator** reaches `mes:Header` as well as `mes:Structures`.

## The header is checked, not read: #480

The SDMX-ML readers do not read the header at all, and `StructureMessage` has none. Sender, Receiver, Source and the rest are dropped silently. Modelling it is a separate decision, so I filed **#480**, which I also added to the #460 tracker. Once the table reached the header, the element and attribute censuses asked why ~20 allowed header pairs per version are never written. They now set those pairs aside against #480. The rule is derived (`tests/support/header.py`: elements reachable from `mes:Header` and not from `mes:Structures`) rather than listed, and a guard checks that it sets something aside, so it can't go vacuous.

## Evidence

- **Real data:** 0 frame refusals over the **167** cached registry documents (raw, or as chunks for the largest). That matches the earlier full-XSD validation of the same cache. No false positives from the header table.
- **No over-catch in our own output:** every vendored fixture and the maximal round trips still read with nothing refused.

## Guards

- `test_the_frame_refuses_by_place`: six shapes × 2.1/3.0/3.1. Each asserts exactly one refusal, its class, its place, and the schema's reason.
- A strict `parse` raises, naming the stray.
- Sabotage: replacing `frame_refusals` makes the unknown container vanish again, as it did before.
