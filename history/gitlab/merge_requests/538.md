## What changes

2.1's version grammar has no form for an extension, so a draft (`1.0.0-draft`) cannot be written there. Writing one raised; now the artefact is **left out** of the 2.1 document. Stripping the suffix was rejected in #424: it makes a draft look final and can collide with a real `1.0.0`.

**Cascade, transitive within the message:** an artefact referencing a draft (a reference 2.1 cannot name) is left out, then anything referencing an artefact left out, until nothing changes. A reference to an artefact never in the message is left alone.

- `sl.dropped(msg, "2.1") -> tuple[DroppedArtefact, ...]` — each with `urn`, `cause` (the draft behind it, even through intermediate artefacts) and `reason`. This is how a server tells "asked for this artefact by name" (refuse, e.g. 404) from a listing (add a note); `serialize` cannot tell them apart.
- `serialize` / `to_xml` / the 2.1 writer called directly all leave out the same artefacts, with or without `validate`. 3.x and SDMX-JSON still write drafts.
- `sl.unrepresentable(artefact, "2.1")` gains two rows: `version` (a draft) and `references` (a reference to one).
- Late-binding references (`1.0+.0`) stay refused — #422.
