Two bits of drift found while auditing the open issues against current `main`.

**Four dead constants.** `_BROWSE_PARAMS`, `_FETCH_PARAMS`, `_RESOLVE_PARAMS` and `_RESOLVE_FULL` in `api/client.py` are referenced nowhere in `src/`, `tests/` or `docs/`. Left over from the pre-`a8ef0e8` API when browse / fetch / resolve were separate calls; `get(urn, resolve=…, partial=…)` derives its own wire parameters now.

**A stale CLAUDE.md example.** The "Browse" snippet was wrong in both halves — `query()` takes a path root and returns a `Query`, which has no `browse()`. The REST-side browse is gone; the surviving one is `LocalRegistry.browse()` over dataflow bindings. Replaced with the current form, matching `docs/cookbook/catalog.md`.

That second one is the reason this is worth an MR rather than a note: CLAUDE.md is what tells an agent what the API looks like, so a stale example there is an instruction to write code that does not run.
