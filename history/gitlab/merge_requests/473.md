## Nine `src/` changes, each a declaration that did not describe the code

* **`Num.__add__/__sub__/__mul__/__truediv__` omitted `Win[R]`** — so
  percent-of-total (`col / col.sum().over(...)`), #297's feature with its own
  regression test, type-checked nowhere while working everywhere.
* **`Observations.__getitem__` declared `Col[ObsRow]` and returns `Untyped[ObsRow]`.**
  Its docstring claimed comparisons and ordering were "on the base" — they are
  on `Untyped`; `Col` carries `__eq__` alone. So `obs["TIME_PERIOD"] >= "2019"`
  was undeclared.
* **`Frame.order_by` omitted `str`**, though `_position_of` explicitly designs
  for `order_by("n")` — "what SQL and polars both accept".
* **`formats.parse(registry=…)` declared `InMemoryRegistry`** but calls only
  `add_all`, so passing a `LocalRegistry` — which these tests do — type-checked
  nowhere. New `SupportsAddAll` Protocol beside its three siblings.
* `Query.get` / `__getitem__` still returned `object` (#396 propagation I missed).
* `storage.readers.code_map` is declared as the re-export its comment says it is.

## A regression this pass found in #397

`reg.get(SdmxUrn.parse(text))` types as `LazyCodelist | None` whatever the URN
names — `Any` matches every overload and the first one wins. I checked both
orderings:

| ordering | `SdmxUrn[Codelist]` | `SdmxUrn[Any]` |
| --- | --- | --- |
| generic first | `Codelist` — the lie #397 removed | `Any` ✓ |
| specific first (current) | `LazyCodelist` ✓ | `LazyCodelist` ✗ |

Neither is right for both. The ordering stands — the explicit spelling is the
common one, and the `Any` case at least fails *loudly*, on the first attribute
that is not on a codelist — and `LocalRegistry.get`'s docstring now says so.
