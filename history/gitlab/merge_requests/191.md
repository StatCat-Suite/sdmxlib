Closes #205.

## The gap

`test_roundtrip_property_guard` round-trips every structural field through json / ml21 / ml30, but never validated the emitted XML. It could only ever catch *"the reader undoes the writer"* — never *"the writer emits XML the schema forbids and our reader happens to accept it"*. That is precisely the class CLAUDE.md says XSD validation exists for.

Four lines in `_roundtrip_structure` — validate `writer.write(msg)` against the vendored XSD before re-reading — took the file from **2 failures to 25**. All 25 are now fixed; the guard is green at 85 passed.

## Three genuine writer bugs

These affect anyone consuming sdmxlib's XML, not just tests.

**1. `assignmentStatus` omitted (2.1).** The XSD marks it `use="required"` on Attribute; we emitted it only when `usage` was set. Now unconditional, with absent usage mapping to `Conditional` — the weaker of the two, which is what "unspecified" means to a consumer.

**2. `ConceptRole` emitted in the wrong shape (3.0 + 3.1).** SDMX 3.x types it `common:ConceptReferenceType`, a **simple** type restricted to `.+\.conceptscheme\.Concept=.+`. Both writers emitted the 2.1 child-`<Ref>` form, which the schema rejects twice over — element content on a simple type, *and* an empty string against the URN pattern. Now emits URN text.

**3. `<MeasureList>` is mandatory in 2.1.** `DataStructureComponentsType` requires it, and `MeasureListType` requires a `<PrimaryMeasure>` inside ("Only a primary may be defined"). A measure-less DSD therefore **cannot be expressed in SDMX-ML 2.1 at all**.

## Two fixtures building schema-impossible artefacts

**4. A `Code` with no name.** `<com:Name>` carries no `minOccurs`, so it is required. This is what the 13 baffling `Element 'Parent': This element is not expected. Expected is one of ( Annotations, Name )` errors actually were — not an ordering bug, as it first appeared. The writer emits `Parent` in the right position; with `Name` absent the parser reported the *next* element it saw.

**5. `Level.coding_format` used `textType="String"`.** `CodingTextFormatType` restricts it to `SimpleCodeDataType` — **Alpha, AlphaNumeric, Numeric** only. `String` is valid for `CodeDataType` but not here.

## Behaviour note

An Attribute with `usage=None` now round-trips through 2.1 as `OPTIONAL` rather than `None`. That loss is **inherent to the format** — 2.1 has no way to encode "unspecified" — and the alternative was continuing to emit invalid XML. Worth knowing if you compare a DSD before and after a 2.1 round-trip.

## Deliberately not in scope

Two real gaps this uncovered, both needing their own decision rather than being folded in:

* **`validate()` checks no names, and `serialize()` has `validate: bool = False`.** So nothing stops a nameless `Code` reaching the wire — finding (4) is a symptom. Note `model/validation.py`'s module docstring claims *"Validation is invoked at every write boundary (`serialize`, …)"*, which is not what the default does. There are 68 nameless-item constructions in `tests/`, so making names required is a sizeable, separate change.
* **The 2.1 writer's `if dsd.measures:` guard** can still emit an invalid document for a measure-less DSD. Given (3), the honest options are to refuse the write or to require a measure in the model — a user-facing behaviour decision.

I'll file both unless you'd rather fold them somewhere.

## Comments

### 2026-08-05

Two follow-ups pushed, both closing paths that let invalid output reach the wire.

## `serialize()` now validates by default

`serialize()` / `to_xml()` / `to_json()` flip to `validate=True`. The old default rested on *"messages built through the typed model or read back by the parser are already well-formed"* — this MR disproved that five distinct ways.

The cost argument does not hold either. Measured against live registry payloads, median of 60 runs:

| payload | validate | serialize | ratio |
| --- | --- | --- | --- |
| ECB dataflows — 38 KB, 104 artefacts | 0.07 ms | 0.77 ms | **9 %** |
| SDMX CL_AREA — 240 KB, 899 codes | 0.13 ms | 3.54 ms | **4 %** |

The *larger* payload is relatively cheaper, because the item-id checks vectorise above 64 items. `validate=False` stays for deliberately round-tripping a non-conformant message in order to repair it.

Only 4 tests broke, and all 4 were pinning the old default (`test_serialize_default_does_not_validate`). Replaced with a pair asserting the new contract and that the opt-out still works.

## The 2.1 writer refuses a measure-less DSD

`DataStructureComponentsType` requires `<MeasureList>`; `MeasureListType` requires a `<PrimaryMeasure>` inside it. So a measure-less DSD has **no valid SDMX-ML 2.1 encoding**. It previously emitted a document the schema rejects — and which sdmxlib's own reader now refuses after !190. It raises `ValueError` instead, naming the DSD and pointing at 3.0. Zero test fallout; two tests added.

## Deliberately still out

Requiring `name` on nameable artefacts — the thing that would have caught this MR's nameless `Code`. I spiked it: requiring a name on **codelist codes alone fails 21 tests**, before touching Concept / Category / Agency / components. Interacts directly with the new `validate=True` default, since each becomes a serialise-time failure. That is an API tightening worth its own decision rather than a rider here.
