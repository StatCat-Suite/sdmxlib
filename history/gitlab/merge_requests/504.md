# Merge request !504: docs: cast OBS_VALUE before aggregating it — polars 2 refuses a string mean

| | |
| --- | --- |
| State | merged |
| Opened | 2026-10-06 |
| Merged | 2026-10-06 |

Two examples averaged `OBS_VALUE` straight off `ds.lazy()`:
`data_tutorial.md`'s summary statistics and `cookbook/data.md`'s aggregation.
A `Dataset` types its columns from the DSD, and ECB declares `OBS_VALUE` as
`textType="String"` (both recorded EXR structures in the integration cassettes
say so), so the column is a string.

- polars 1.x: `mean()` of a string column is null, silently. The tutorial
  printed `f64` means and extremes that this code could never have produced
  against ECB's real structure.
- polars 2.0: `mean()` of a string column is an error. `polars>=1.39.3` has no
  upper bound, so a fresh install of sdmxlib now gets 2.0, and `just ci` in a
  fresh environment failed both doc tests.
- Both versions: `min()` / `max()` compare as text, so `"1.10" < "1.9"`.

Each example now casts to `Float64` first and says why. Making the docs' test
DSD numeric instead would have hidden the real ECB shape the reader will meet.
