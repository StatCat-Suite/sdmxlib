The audit's remaining cluster. Five things that looked unrelated and
share a shape: the library did something other than what it said, or said
it in someone else's voice.

**A predicate from another root reached DuckDB.**
`reg.query(q.dataflow).filter(q.code.id == "A")` came back as
`BinderException: Table "s0" does not have a column named "code_id" ...
Candidate bindings: : "fetched_at"` — an alias the caller never wrote, a
column they never wrote, and a suggestion of `fetched_at`. Statically
caught, so a typed codebase never saw it; a notebook is the audience a
query DSL actually has.

Deliberately narrow, and it took three tries to get there. A path is
fine (`q.dataflow.dsd.id` reads `artefact` through a hop — the commonest
traversal in SDMX). A side table is fine (`q.dsd.name["en"]` reads
`localized_text` by correlated subquery with no path). The observation
plane is fine — it roots at a *binding's* table and joins a sidecar,
neither of which `_edges` knows. What is left is a column read directly
off another accessor root, which is exactly the mistake.

**`frame(labels=)` on a structural query died inside the label builder.**
The guard was `getattr(root, "dsd", None)` — and `_Dataflow.dsd` is a
declared edge, so the duck-test passed, an accessor went to `label`, and
it failed on `'_Dsd' object has no attribute 'measure_dimension'`. The
`hasattr`-cannot-narrow hazard CLAUDE.md names, found in the wild rather
than by a checker. Now `isinstance`, with the two cases kept apart: no
DSD at all still says "build it from a catalog"; a structural root says
labels are an observation thing and names what to project instead.

**`valid_from` / `valid_to` were stored and unreachable.**
`design/query-language.md` lists them as part of the hoisted maintainable
surface and reasons about as-of queries from them. They were columns; they
were not in the language. `Num`, because a TIMESTAMP compares and orders
like one — a `Temporal` class is worth having when something needs date
arithmetic, not before.

**`sl.union` is specified in two design documents and did not exist.**
Only `from sdmxlib.query import union` worked. Exported; same function,
not a second one.

**Version ranges had no spelling.** `>=` was left out on the sound
grounds that comparing the raw text makes `1.9 >= 1.10` true — but that
made "every artefact at 2.0 or later" unaskable in a domain where
versions are first-class, and the refusal arrived as a bare Python
message about `Version` and `str`. Nothing new was needed: `version_sort`
is already baked and already what `order_by` and `rank()` compare, and
the same `sort_key` maps the literal. So the comparison is exact and
agrees with the ordering by construction. Equality still reads the
published text — only ordering ever diverged.

`columns_in` widens to `AnyPred`, which is what that base is for: it
matches on node kinds and never touches the row kind.

`just test-properties` clean at 20x.
