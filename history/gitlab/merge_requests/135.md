## Changed

- **`SdmxUrn[Any]` → `SdmxUrn[object]`** on pure-consumer params — the URN is only `str()`'d or read for its *concrete* `str` attributes (`.agency`, `.artefact_class`, …), never the phantom `T`:
  - `ref.py` `UnresolvedRef.__init__`
  - `local/registry.py`: `codelist`, `metadata_for_target`, `metadata_report`, `_parent_scheme_urn`, `_load_parent_scheme` (`sample`), `drop`, `replace`, `code_map`, `dsd_code_map`
- **`Any` → `object`** on the reflective validation entry points (`isinstance`-dispatch / attrs-reflection, no direct attribute access): `validate`, `_collect_issues`, `_collect_refs`.

The litmus (per CLAUDE.md): `object` unless the value flows into a position that recovers the erased type. Every site above only stringifies the URN / reflects over the artefact, so `object` is strictly the honest type and body-checking is now on.

## Deferred (need thought/design — a later change)

- **Phantom-recovery sites that must stay `Any`:** `SdmxUrn.parse -> SdmxUrn[Any]` (feeds `Ref.unresolved -> Ref[T]`, needs bivariance), `_canonical_ref`, `artefact_urn` (also blocked on #174).
- **`validation._walk` helpers** — access `.id` directly; want a `HasId` protocol.
- **`message.all_artefacts() -> list[Any]`** — element-type choice (`Maintainable`?) affects callers.
- **Resolver caches** (`_FIFOCache`/`_CallScopedMemo`) + resolution-walker `memo`/`frontier` — cached-value type design.
- **`Ref[Any]`/`AnyRef` + `MetadataSet` target unions** — belong to the covariant-`Ref` spike (#173).
