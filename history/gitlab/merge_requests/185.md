## #192 — `_maint_fields`: Protocol + TypedDict (21 suppressions)

One signature in `_structure_dto.py` accounted for 45% of every type-ignore in the codebase:

```python
def _maint_fields(m: object) -> dict[str, object]:
```

`m: object` made `m.id` / `m.agency_id` / `m.version` unreadable (3 ignores) even though the *other* fields were already `getattr`-probed — the signature disagreed with itself. And `-> dict[str, object]` made every `**_maint_fields(x)` splat fail all eleven field assignments at once (18 ignores).

Now the existing `Maintainable` Protocol + a `MaintFields` TypedDict. Runtime behaviour is unchanged; the optional fields stay `getattr`-probed because not every artefact reaching the helper carries validity or annotations.

## #193 — `id` shadows a builtin by design, so say it once (21 suppressions)

`id` is what the SDMX information model calls the identifier field. That one project-wide fact was written out as 35 directives (21 in `src`, 14 in `tests`). `builtins-ignorelist = ["id"]` states it where it can be reviewed once.

RUF100 confirmed the count in both directions: adding the option made exactly those 35 dead, and the fix removed exactly them — the diff carries no other suppression token, so nothing was riding along on a shared `# noqa` line.

## #194 — the registries were `object` because of a *parameter name* (2 suppressions)

Two helpers took `registry: object` then called methods on it. `binding.py` documented why: *"typed as object rather than the RegistryReader Protocol so the overloaded RestRegistry.get and similar registries satisfy it."*

The actual cause: protocol conformance matches positional-or-keyword parameters **by name**. `RegistryReader.get` names its parameter `urn`; `RestRegistry.get` names it `urn_or_type` because it is overloaded. A probe pins it exactly — named parameter → RestRegistry fails; positional-only (`/`) → it conforms, and so does `local.Registry` with its extra keyword-only `eager`.

So: `SupportsGet` / `SupportsGetAll` with positional-only first parameters, `RegistryReader` extends `SupportsGet`, and each helper is typed to the one method it needs rather than the wider reader interface. Typing them propagated to two public wrappers that were `object` for the same reason — that cascade is the point.

Verified structurally and at runtime: `InMemoryRegistry`, `local.Registry` and `RestRegistry` all satisfy the Protocols via `isinstance`.
