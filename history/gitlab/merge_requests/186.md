Closes #196.

Removes the worst suppression-to-error ratio in the codebase: one `# type: ignore[arg-type]` on `httpx.Client(**httpx_kwargs)` that was silencing **17 distinct errors**, one per httpx parameter that `object` cannot satisfy.

## This does not do what the issue proposed

The issue said `**kwargs: Any` + `flake8-annotations.allow-star-arg-any = true`. Both halves were reconsidered during review; both were wrong.

**The config flag is not worth its surface.** It looks like the `builtins-ignorelist = ["id"]` decision from !185, but the two differ in kind. `id` shadowing is a *closed* fact about the SDMX model — identical at every occurrence, now and in future — so config states it once. `**kwargs: Any` is *open-ended*: right at an httpx boundary, wrong in `model/`, and the option cannot distinguish them. It would silently pre-approve every future star-kwarg `Any` in the codebase, including where CLAUDE.md says `Any` must not reach, and unlike a `noqa` it leaves no trace in the diff that relies on it. Not set; `ruff.toml` now records why not.

**And `Any` turned out to be unnecessary.** PEP 692 types the pass-through exactly.

## What it does instead

```python
class HttpxOptions(HttpxTransportOptions, HttpxAuthOption, total=False): ...

def __init__(self, ..., **httpx_kwargs: Unpack[HttpxOptions]) -> None:
```

The whole chain — `FmrRegistry → RestRegistry → SdmxClient → httpx.Client` — now type-checks with **no `Any` and no suppression anywhere in it**. Strictly better than either option in the issue:

* Callers get their httpx options checked. `folow_redirects=True` is now a static *"No parameter named"* error instead of a runtime `TypeError` deep inside httpx.
* `headers`, `timeout` and `base_url` are deliberately **excluded** — `SdmxClient` owns them, so smuggling one through used to be a runtime duplicate-keyword `TypeError` and is now caught at the call site.
* The supported surface is written down for the first time. Nothing previously documented what `**httpx_kwargs` accepted.

## Why three TypedDicts

Both splits were forced by checker findings, not taste:

1. `FmrRegistry` exposes its own richer `auth` (it also accepts a `BearerToken`, which becomes a header rather than an httpx auth object). An `auth` keyword alongside an `Unpack` shape that also carries `auth` is a static conflict.
2. The two `**` unpackings at its `super().__init__` call must have provably disjoint key sets.

Hence transport options, auth, and their union.

## One finding worth recording

**pyrefly caught a subtlety basedpyright did not.** The first attempt merged the shapes with `httpx_kwargs: HttpxOptions = {**kwargs}`. That is unsound — a TypedDict is *open*, so a runtime value may carry keys its declared type does not — and `open-unpacking` rejected it. Restructured into two disjoint unpackings rather than suppressed. Second time `preset = \"all\"` has paid for itself since !184.

`event_hooks` is omitted from the shape on purpose: httpx types its hooks `Callable[..., Any]`, which would put `Any` back into the signature for a rarely-used option.

## Verification

Runtime as well as structural — transport options reach `httpx.Client`, basic-auth tuples become httpx auth, and `BearerToken` still becomes an `Authorization` header:

```
FmrRegistry basic-auth set: True | follow_redirects: True
FmrRegistry bearer header: Bearer tok | max_redirects: 4
```

`just check` clean across all three checkers; 2471 unit + 72 docs tests pass.

## Follow-up, deliberately not done here

`HttpxOptions` lives in `sdmxlib.api.client`, which is not re-exported from the top-level package (neither is `SdmxClient`). It now appears in public constructor signatures, so if users should be able to write `def f(**kw: Unpack[sl.HttpxOptions])` it wants exporting — left alone rather than widening the public API as a side effect of a lint fix.
