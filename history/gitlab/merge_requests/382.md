Closes #334 (design §5.11) — **one** of the seven relations it named, not all seven, and the one that was left was worse than the issue described.

## The defect

`Request.path` said `structure/` for every resource:

```python
return f"structure/{self.resource}/{self.agency}/{self.resource_id}/{self.version}"
```

SDMX-REST routes three ways, and a `metadataset` is served from `/metadata`. pysdmx's `RefMetaByMetadatasetQuery` renders `/metadata/metadataset/{provider}/{id}/{version}`, which this now matches segment for segment.

## Six of the seven were already correct

Checked before building:

| relation | why it was fine |
|---|---|
| `msd`, `metadataflow`, `metadata_provision_agreement` | **definitions** — SDMX-REST serves these from `/structure`, confirmed against pysdmx's `StructureType`, which lists `metadatastructure` / `metadataflow` / `metadataprovisionagreement` among its structure resources |
| `metadata_attribute`, `reported_attribute`, `metadata_target` | **items** within an MSD or MetadataSet. The planner already refuses them as roots exactly as it refuses `q.code` — items come back inside the artefact that owns them. Behaviour, not a gap |

"metadata" appearing in a resource name says nothing about its plane, which is why the exception is a **named set** rather than a prefix test — `metadataflow` and `metadataset` differ.

## And the remaining one was worse than filed

#334 said there was "no request to issue". There was — a **wrong** one. Since #338 a 404 comes back as "not here" rather than raising, so against a real provider `reg.query(q.metadata_set).ids()` returned an **empty result and said nothing**.

## Evidence

Guarded in both directions:

- reverting the plane fails **2** tests;
- the plausible over-reach — routing anything named `metadata*` to `/metadata` — fails **4**, because the three definitions are pinned to `/structure`.

An inventory test asserts the metadata plane serves exactly `{"metadataset"}`, so a new maintainable (which arrives on `/structure` by default, correctly) has to be listed to move.
