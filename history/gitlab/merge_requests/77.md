## 3.1 divergences from 3.0

Surveyed up front against the vendored 3.0 vs 3.1 XSDs — only **three** real wire-format differences:

### Categorisation (#103)
\`@version\` is prohibited per the 3.1 XSD. The writer overrides \`_write_categorisation\` to emit only \`agencyID\` + \`id\` (plus \`validFrom\` / \`validTo\` when set); never \`@version\`.

### DataConstraint (#104)
- \`@role\` attribute removed in 3.1. The 3.1 DataConstraint is allowed-only by definition (the Actual semantic moved to the new \`AvailabilityConstraint\` artefact, which we don't yet model). Writer silently drops the model's \`constraint_type\` on emit.
- \`<ReleaseCalendar>\` removed from the DataConstraint sequence in 3.1 (also moved to \`AvailabilityConstraint\`). Writer silently drops the model's \`release_calendar\` on emit.

Doc-only changes in other XSDs (typo fixes, comment updates) don't affect emission. Out of scope: \`AvailabilityConstraint\`, Geographic / GeoGrid codelist subtypes, etc.

## Format dispatch wiring

\`sdmxlib.formats.__init__\`:
- \`_detect_version\` checks \`v3_1\` namespace before \`v3_0\` (since 3.1 is newer and supersedes).
- \`parse()\` routes auto-detected \`\"3.1\"\` through the 3.1 reader.
- \`serialize(version=\"3.1\")\` routes through the 3.1 writer.

\`tests/fixtures/sdmx_ml31/minimal.xml\` — copy of the 3.0 minimal with \`v3_0\` → \`v3_1\` namespace swap, plus the three divergences applied. Validates against the v3.1.0 XSD as both input and round-tripped writer output.
