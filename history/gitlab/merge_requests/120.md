## Summary

Fixes the `slpl.label()` thundering herd by moving the label-map cache to its **source** — `LazyCodelist.code_map` — and guarding it with a per-instance, per-language **single-flight build lock**.

### Before

`polars._component_label_map` cached results in a module-global weakref dict with an unsynchronised read → build → write. N concurrent first-time callers for the same codelist each missed the cache, each ran the `code_map` SQL projection, and each wrote back — ~5× redundant work (measured **0.55s → 2.48s** for 5 cold callers). The cache also only covered `label()`; other `code_map` callers raced independently.

### After

The first caller builds the map under the lock; concurrent callers for the same lang block, then return the hot cache (double-checked locking). The cache lives on the `LazyCodelist` instance, so a fresh ingest yields a new instance with a fresh cache — re-ingestion stays correct. **Every** `code_map` caller now dedups, not just `label()`.

This makes `performance.md`'s long-standing claim that `code_map` is "memoised at the lazy level" actually true, and establishes the read-side contract: **concurrent reads are safe and do not duplicate work**.

## Scope note (see #155 discussion)

The original "58s" framing was a mis-attribution — `code_map` SQL is ~8ms; the 58s was LLM round-trip / pinax `open_bundle` startup. The real, in-scope defect is the ~5× herd, which this fixes. Follows the caching decision framework added in `docs/design/caching.md`.

## Changes

- `storage/lazy.py`: per-instance, per-lang `code_map` cache + single-flight lock.
- `polars.py`: drop the redundant `_LABEL_MAP_CACHE` / `clear_label_cache` (neither was a public export); `_component_label_map` defers to the source cache, in-memory `Codelist` fallback stays uncached (no SQL, cheap).
- `tests/unit/test_perf_regressions.py`: cache assertions point at the new per-instance cache; **new count-based** test asserts one SQL build under 5 concurrent callers (not wall-clock).
- `docs/design/caching.md`: example updated to reference the new cache.
