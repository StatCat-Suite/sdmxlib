A tier the gate never runs cannot fail. #386 proved it: renaming
`resolve_cache_size` to `resolve_cache_items` passed `just check`, passed 6,284
unit tests, and left this tier with 19 errors nobody would have seen. I only
ran it because that MR was about the cache.

That is `_bundle.py`'s own argument — *a finding that cannot fail is a finding
nobody acts on* — arriving from the other side.

## Split by what the halves are for

`bench-bundle-assertions` runs `-m "bench and bundle" --benchmark-skip`, and
`ci` gains it. The line is **purpose, not cost**, as the issue required:

| | tests | in `ci` |
| --- | --- | --- |
| asserts a property | 15 | yes |
| reports a number (takes the `benchmark` fixture) | 8 | no |

`--benchmark-skip` happens to draw exactly that line, because the measuring
tests are the ones taking the fixture. Nothing new to mark and nothing to drift.

Measured: **15 passed, 8 skipped in 123 s**, and `just ci` end to end is 5:52
on the machine holding the bundle. (The 96 s I quoted when choosing this was
the tier run alone on an idle machine; the same pass also took the unit suite
from 143 s to 188 s, so that is load rather than the tier.) On a machine
without the bundle it is ~0 s.

What now gates that did not: the per-item calls/bytes budget (%18), the
collect-vs-frame ratios (#382), and the pruned-join and declined-order ratios
(#391).

## A skip has to read as a gap

`pytest_terminal_summary` already printed the skip reason on its own line. Now
that these are part of the gate, a green run that skipped them is a green run
that checked less than it looks like it did, so the banner says **"the gate did
not check it"** and names what is unguarded.

It also prints the reasons it actually found rather than a canned one. Two
things were wrong there:

- It always printed `skip_reason()` — the "no bundle at all" message — even
  when the env var *was* set and the skip was something else. A structural-only
  bundle reported "$SDMXLIB_BENCH_BUNDLE is unset", which was false.
- **#391's own data-plane skip was invisible to it.** That reason did not
  mention `$SDMXLIB_BENCH_BUNDLE`, and the hook matches on that name, so a
  bundle with no `lake.ducklake` skipped eight tests silently. `data_plane_skip_reason`
  now names the variable, which is both better advice and what makes the hook
  fire.

Verified on a structural-only bundle: 7 structural assertions pass, 8
observation tests skip, and the banner names `lake.ducklake` as the missing
file.
