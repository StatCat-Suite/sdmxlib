## `_serialise_key`

Interleaved three jobs — validate the spec, decide which positional slot each dimension occupies, format the string — and its two arms duplicated the same build loop.

Now `_validate_key_spec` (every `raise`) and `_key_slots` (the layout rule), with the caller down to four lines.

**The point is not the branch count.** SDMX's measure-dimension rule — a *formal* `MeasureDimension` trails every regular dimension, whereas a `measure_dim` hint occupies its own dimension's slot — was a branch the reader had to reconstruct. It is now a named function with a docstring, testable without the string handling around it.

## `_resolve_refs`

Its docstring numbered three phases the code did not name:

> 1. **Collect** … 2. **Resolve** … 3. **Assign**

That is a reliable tell — the reader was doing structural work the code could do. `_pending_urns` and `_assign_resolved` now exist and the walk body is six lines that read as collect → resolve → assign.

The risk was shared mutable state (four pieces threaded between phases). It turned out mild: both extractions take what they need and return a value.
