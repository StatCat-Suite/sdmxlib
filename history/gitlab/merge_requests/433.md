## The ratchet

A suppression written in an unchecked directory is aimed at a checker that never runs there. It cannot be validated and — the part that matters — it cannot be **invalidated**: when the code beneath it changes and the finding goes away, nothing says so.

The %17 review found **59** dead suppressions in `tests/`; !392 removed them. Measured today: **4**. A hole that refills on its own is an argument for a gate rather than another cleanup.

`tools/check_dead_ignores.py` pins it at zero and joins `just check`. No baseline file, unlike `count_any.py` — a dead suppression is never the right answer, so there is nothing to ratchet down from.

## tests/support, fully checked

19 files of library-shaped fixture code: **393 findings → 0**, and `just typecheck` now covers it.

Most of it was one annotation:

| change | findings |
| --- | --- |
| start | 393 |
| `maximal._maintainable` → `dict[str, Any]` | 130 |
| `sql_corpus` `Query[object]` → `Query[Any]` | 16 |
| the individually-real remainder | 0 |

`_maintainable` is splatted into twenty different constructors, so a `dict[str, object]` return erased every value's type and produced **250 argument mismatches in one file**, none of them real. That is the "one annotated boundary where the `Any` dies" case CLAUDE.md describes. `Query[R: RowKind]` is *bound*, and `object` does not satisfy a bound — `Any` does.

The last 16 were each real:

- **`sql_ast.parse` over-claimed its return type.** Declared `list[exp.Expression]`; `sqlglot.parse` promises `list[Expr | None]` and `Expression` is a **subclass** of `Expr`. basedpyright also named the correct import (`sqlglot.expressions.core`) and was right.
- **`field_census` narrowed one side of a two-sided union.** `isinstance(before, dict) or isinstance(after, dict)` narrows *neither* for the `dict(x or {})` calls that follow — two suppressions replaced by narrowing each side.
- The fixture passed `list` where `tuple` was declared, and `"A0"` where `Agency | None` was.

## What it found that is not fixed here

That last item generalises, and both of these are public-API questions that should not be settled as a side effect of a test-tooling change:

- **#371** — 30 model fields declare `tuple[...]` with no converter, so a list handed in stays a list. The annotation is wrong and the immutability it implies is absent.
- **#370** — `LocalRegistry.get` is declared `urn: SdmxUrn[T]` but accepts a plain `str` at runtime; 20 test sites rely on it, the docstring is silent, and `RestRegistry.get` declares `SdmxUrn[T] | Ref[T]`, so the two entry points already disagree.

Full adoption (option 1) stays open on #347: 2560 findings, of which 774 are unannotated pytest fixtures (deliberate style) and ~712 are the same erasure pattern fixed at its source here.
