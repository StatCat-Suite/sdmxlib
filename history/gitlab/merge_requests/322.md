Closes #316.

Three bugs of one shape had shipped — `Facet.is_multilingual`, `Concept.parent_id`, `DataProvider.contacts` — where the field existed in the model and storage silently dropped it. All three were found by someone reading an inventory, not by anything going red, because **an absence does not fail a test**.

Two things make this different from the round-trips that missed them:

- **The field list is derived** from `attrs.fields()`, so a field added tomorrow is covered the day it lands.
- **The values are distinguishable, not merely valid.** `is_final=False` round-trips perfectly through a reader that never populates it — which is how `is_multilingual` survived 4,882 passing tests. `test_the_sentinels_differ_from_the_defaults` asserts that property rather than trusting it.

## Four defects on the first run

| issue | defect |
| --- | --- |
| #320 | `is_final` and `uri` kept for some maintainables, dropped for six others — same six for both |
| #321 | a tz-aware `valid_from` returns **naive and shifted**: DuckDB `TIMESTAMP` has no zone, so it converts to the session's local time. A different instant, and a different one per reader's machine |
| #322 | `annotations` lost on `Codelist` and `Hierarchy`; and `LazyCodelist.uri` returns the right value while `materialize().uri` returns `None` — the two read paths disagree |
| #323 | `Hierarchy.has_formal_levels` and `Dataflow.dimension_constraint` read back as their defaults |

Every one defaults to something falsey, which is why no fixture caught them.

## What the guard refuses to hide

- `KNOWN_LOSSES` entries each cite an issue, and a test asserts they do. They are **defects**, not the by-design gaps `formats/gaps.py` declares — recording one there would tell an author the loss is permanent.
- The guard fails on an **unexpected pass**: fix a defect and its entry must be deleted.
- `CANNOT_BUILD` names the three types no full instance can be built for, with reasons. An unbuildable type is uncovered, and uncovered silently is the condition this exists to end.

One harness bug worth naming: the lazy proxies hold the registry's connection, so materialising after the block closes raises "Connection already closed" — which reads as a storage bug and is not one.
