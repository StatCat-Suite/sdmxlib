Closes #292.

Every annotation predicate compiled to `EXISTS(… annotation_type = ? AND <condition on the value>)`, so all of them meant "an annotation of this type exists **and** its value …". That left "has no annotation of this type" unreachable. On a codelist where `A` has a note with a title, `B` a note with no title, `C` no note:

```
annotations["note"].is_null()      -> ['B']       a note whose title is NULL
annotations["note"].is_not_null()  -> ['A']       a note that has a title
~annotations["note"].is_not_null() -> ['B', 'C']
wanted: no note at all             -> ['C']       unreachable
```

`exists()` reads no value: the subquery tests the type and stops, with **no trailing AND**. Not cosmetic — `AND TRUE` would select the same rows while reading as though a value were examined. `NOT EXISTS` is total, so `exists()` and `~exists()` genuinely partition the rows (asserted in both differential properties) — the one place in these DSLs where `~` is a real complement.

`annotations[type,lang].exists()` keeps the `annotation_text` join and drops only the value condition; the join *is* the language test, so this answers "carries a translation at all".

`is_null` semantics unchanged, as the issue proposed. Docstrings now say which question each predicate answers.

One shared node overriding `to_sql`, like #262's combinators — the only per-relation fact is `RowKind.urn_column`, so all four DSLs get it unwired.

## The nesting hole this found

`.any(...)` compiled its sub-predicate through the module `_EMITTERS` table rather than `pred.to_sql(ctx)` — the same seam mistake #262 fixed in `_where` and did not look for one level in. **`.any(a | b)` and `.any(~a)` raised `NotImplementedError` on `main`**, and a downstream pinaxlib predicate had never worked there. One line per DSL.

Nothing caught it because both `.any(...)` properties hardcoded `sub = code.id == target`. Both now draw a `_paired_tree` with `nullable=False`, so `~`, `&` and `|` are in the pool inside the subquery.

The first version of the discovery doc-driver was **vacuous** — that fixture has no annotations, so every assertion passed on empty sets. The fixture now gives two artefacts a `tier` annotation, one with French text, plus an explicit "fixture no longer discriminates" guard.
