## Why

`lxml-stubs` 0.5.1 declares attributes with **legacy PEP 484 type-comment
syntax**:

```python
text = ...  # type: Optional[str]      # lxml-stubs/etree.pyi:220
```

basedpyright reads the `# type:` comment; **pyrefly ignores it and infers from
the `...` RHS as `EllipsisType`**, producing a **154-error cascade** across the
entire `formats/sdmx_ml*` layer (`EllipsisType has no attribute strip`, `str not
assignable to text with type Ellipsis`, …) — the dominant noise source in the
pyrefly editor pass. (lxml 6.x ships no native `py.typed`, so the stub package is
the only type source.)

`types-lxml` is the modern, actively-maintained replacement (latest `2026.2.16`,
"Complete lxml external type annotation") — complete, real `@property def
text(self) -> str | None` declarations, drop-in on the `lxml-stubs` import
namespace.
