Closes #263.

`hierarchy_query`'s module docstring opened with a worked example that raised:

```python
h.nodes.filter(node.depth <= 2).collect()
# TypeError: '<=' not supported between instances of '_DepthRef' and 'int'
```

`_DepthRef` inherited only `__eq__` / `__ne__`, so depth — the one genuinely ordered field either DSL exposes, and the reason the column is baked at all — supported equality alone. "Everything down to level N" needed three equality filters unioned in Python.

Both DSLs now have `<`, `<=`, `>`, `>=` on depth, via a new `_Cmp` predicate whose operator comes from a closed set chosen by the ref's dunder, never assembled from caller input.

## Depth-only, deliberately

Ordering identifiers is collation-dependent, and "every id after `CA_`" is not a question anyone asks of SDMX codes. Narrower is the reversible choice. The absence of the dunder on string refs is how the API states that, and `test_ordered_comparisons_are_depth_only` pins it.

## The docstring is now executable

Pinned by a test that asserts both that the example is still *in* the docstring and that it builds a predicate. A claim in prose is exactly the kind that drifts — this one drifted into being false.

## Properties

Differential against a freshly walked depth, so it checks the bake as well as the comparison. Plus three identities needing no oracle: `<= n` ≡ `< n+1`, `>= n` ≡ `> n-1`, and `< n` / `>= n` partitioning the rows — that last one is worth its keep because a NULL depth would leave a row in neither half.

## Retires the last complexity suppression in `src/`

Adding two predicate kinds (this and `_InSet` from #261) pushed `hierarchy_query._emit_predicate` over C901. The obvious move was a second `# noqa`, and `code_query`'s twin already carried one whose stated reason was:

> A `dict[type[Predicate], emitter]` table needs one uniform signature, but only three emitters take `join_sqls` / `join_params` / `annotation_join_aliases`. The other eight would carry three dead parameters apiece to satisfy the table.

**#254 deleted that plumbing.** Every emitter now has the same signature, so the objection is gone. Both chains became table lookups and the existing suppression went with them — rather than a second one being added to match it.

The one wrinkle: the table is a module-level dict, so it has to be defined *below* every emitter it names. It sits just before the row-construction section in both files; `_emit_predicate` resolves it at call time.
