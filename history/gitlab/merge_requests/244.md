**Closes #245 by its option 2.** SDMX-ML 2.1 requires `MetadataStructureComponents` to carry a `<MetadataTarget>` and a `<ReportStructure>` — the reporting layer SDMX 3.0 deleted. sdmxlib followed 3.0, so it could *read* a 2.1 MSD (#236) and not write one back: the layer had to be invented, and inventing it means a round-trip returns something the caller never supplied.

Both are now modelled, and **a 2.1 MetadataStructure round-trips losslessly**. Same treatment as `StructureSet` and `HierarchicalCodelist` (#239), for the same reason.

## The design decision, unchanged from #239

A `ReportStructure` holds attribute **ids**, not attributes. They stay single-sourced in `MetadataStructure.attributes` — the 3.0-shaped view this model is built around — because copying them would denormalise one fact into two places and let the copies disagree. That was the design mistake rejected for `StructureSet`, and it applies here unaltered.

The refusal becomes *conditional* rather than disappearing: an MSD with no reporting layer — which is what a 3.0-shaped one is — still has no 2.1 form, and is refused with a message naming what to populate.

## Three schema details that only surface once you write it

- **A target has two ids.** The `<MetadataTarget>` carries one, which report structures reference; the kind element inside carries another. Collapsing them made the round-trip come back referencing the wrong thing.
- **`TargetObjectTextFormatType` allows four text types**, not `DataType`'s forty-four — a target names what *kind of thing* is described, not a value domain. Now enforced.
- The strategy generates the layer unconditionally. 3.x ignores it, and without it every 2.1 case would be a refusal exercising none of the new writer.

## The cross-version hop stays blocked — and that is the answer, not a gap

`2.1 → 3.0 → 2.1` still fails. The intermediate 3.0 document cannot carry the layer, so the return leg has nothing to write. **No amount of modelling fixes that**: the wire format is the bottleneck, not the model.

The harness now records those four hops as *fundamental* rather than *tracked*, alongside the grouping containers — which is what #245 predicted when it said no option makes the cross-version case exact.

| | before | after |
|---|---|---|
| 2.1 MSD, same version | refused | **lossless** |
| 2.1 → 3.x → 2.1 | blocked (pending) | blocked (**settled**) |
| 3.x MSD → 2.1 | blocked | blocked, with a message saying what to populate |

## Controls

Five mutations verified to fail: dropping the targets, dropping the report structures, collapsing the two target ids, omitting the report's target references, omitting the target's `objectType`.
