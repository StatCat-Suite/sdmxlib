## The position was already real

Measured rather than assumed. A new registry opened over an existing store answers from it with the remote dead, in **one request**:

```
1st get: requests=1
2nd get (new session, dead remote): requests=1 -> LazyCodelist
```

That is what "a position in the chain" means, and nothing had to be built for it. Worth stating plainly rather than shipping a change that pretends otherwise.

## What was actually missing

§1.3's second rule promises that every result records *which source answered*. `source_registry` was threaded through every path. `fetched_at` — declared **directly beside it** in the DDL — was written by nothing: always NULL, in every code path. A schema promising provenance it did not keep, unnoticed because nothing read it either.

The two now travel together:

| | `source_registry` | `fetched_at` |
|---|---|---|
| from a source | set | set |
| added locally | NULL | NULL |

A timestamp without a source would imply a fetch that never happened; a source without a time answers only half the question. Stored UTC-naive per `storage/_time` (#321), since a zoneless column hands an aware value back as a different instant per reader's machine.

## Two stale claims in §1.3, found by building against them

- **`structural_version` was named as "set inconsistently".** It is not — a required field on `DataflowBinding`, written and read on every path. The parenthetical was stale.
- **Rule 3 said "a miss is an error naming what was tried, not `None`"**, which contradicts §5.8's "`None` means every source answered *not here*" — the later, settled rule that !374 just implemented. Both hold once the kinds of miss are separated:
  - no source routed for the agency → `KeyError` (the chain cannot even attempt it)
  - routed and absent → `None`
  - routed and unreachable → `RegistryUnavailable`
