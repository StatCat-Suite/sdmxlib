Housekeeping from the %17 review. No `src/` behaviour changes; each item
is a guard that was not guarding.

**`strict = true` for pytest.** A typo'd marker was silently deselecting:
`pytestmark = pytest.mark.uint` made a whole file vanish from `just test`
(which selects `-m unit`), so an always-failing test in it passed the
gate by never running — measured, not hypothetical. pytest warns, but
that is the exact shape CLAUDE.md describes for the two ruff warnings
that survived three milestones: a finding that cannot fail is a finding
nobody acts on. pytest 9 exposes this as an ini option rather than the
old `--strict-markers` flag, and `strict` is the umbrella.

Turning it on surfaced **four sets of duplicate parametrisation ids**,
each of which made a failure report ambiguous:

- `test_query_edges.py` gave all four annotation edges the id
  `annotation.None` — they differ only by target, so a failure named an
  edge nobody could identify and `-k` could not select one.
- `test_query_accessors.py` dropped the accessor root from its id, so
  every artefact-rooted `annotations` hop collided. The root is now in
  the id *and* in the assertion message, which previously could not say
  which accessor exposed the bad hop.
- `test_query_slice_guard.py` and the new `test_coerce.py` had bare
  lambdas reading as `<lambda>`.

**`_coerce.py` went from 53% to 100%.** Every uncovered line was an
`except` branch — that is, the entire reason the module exists. Its
docstring says fuzzing found the cases one family at a time
(`minOccurs=""`, a non-numeric `maxLength`, a `startTime` of `""`) and
not one of the conversions from `ValueError` to `SdmxParseError` was
tested. The new file asserts the type, that the message names both field
and value, and that the original is kept as `__cause__`; removing one
conversion fails 9 of them.

**59 dead suppressions removed from `tests/`.** basedpyright reports
them itself when pointed at the directory — it just never is. See #347,
which is about the hole rather than this instance of it.

**21 deprecated `-> Iterator[...]` returns on `@contextmanager`** in the
doc-test fixtures, now `Generator[...]`. `src/` was fixed for this in the
pyrefly `preset = "all"` pass; the fixtures I added last week reintroduced
it where no checker runs.

Filed, not fixed: #345 (SDMX-ML 3.1 drops RepresentationMap data-type
endpoints and Level/CodingFormat, and `gaps.py` denies it), #346 (the
3.1 fork that makes such bugs cheap), #347 (`tests/` is unchecked).
