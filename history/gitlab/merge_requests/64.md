## Two new enums

### \`AttributeUsage\` ∈ {\`MANDATORY\`, \`OPTIONAL\`}
Canonical 3.0 / 3.1 vocabulary per \`SDMXStructureDataStructure.xsd\` \`UsageType\`. 2.1's \`AssignmentStatusType\` was {\`Mandatory\`, \`Conditional\`}; we collapse \`Conditional\` → \`OPTIONAL\` on read. The enum has a \`.parse()\` classmethod that accepts either spelling so callers can construct an \`Attribute\` without manual coercion.

### \`ConstraintType\` ∈ {\`ALLOWED\`, \`ACTUAL\`}
Per \`ContentConstraintTypeCodeType\` (2.1) and \`ConstraintRoleType\` (3.0). **These are the only two valid values in either spec** — the audit agent's \"Forbidden\" guess was a misread; the include/exclude distinction is actually encoded by \`CubeRegion.@include\` in both versions.

Both enums live where their fields live (\`model/datastructure.py\` / \`model/constraint.py\`). Public-API exports updated.

## Serializer migration
- **2.1 writer**: emits \`Mandatory\` / \`Conditional\` mapped from the \`AttributeUsage\` value (the 2.1 element name is \`assignmentStatus\`).
- **3.0 writer**: emits \`attr.usage.value\` directly. Dropped the legacy \`_USAGE_3_0\` translation dict — the model now holds canonical vocabulary so the writer can be a one-liner.
- **SDMX-JSON writer**: same \`.value\` pattern for both fields.
- **Storage writer**: serialize \`usage.value\` into the DB column; reader hands the raw string back and the model converter re-parses. No schema migration.

## \`ProvisionAgreement.is_final\` added
PA was the only \`MaintainableArtefact\` subclass missing \`is_final\`. \`is_final\` is a 2.1-only \`MaintainableType\` attribute (dropped in 3.0 and 3.1), so the field defaults to \`False\` and the 3.0 / 3.1 writers continue ignoring it cleanly. Verified per #112.
