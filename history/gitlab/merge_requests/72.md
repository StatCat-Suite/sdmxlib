## Latent bugs (Group attachment)

Until this MR, all three serializers emitted \`<Group/>\` as an empty marker element. Per the XSDs:

- **v2.1** \`LocalGroupKeyDescriptorReferenceType\`: \`<Group>\` wraps a nested \`<Ref id=\"...\"/>\` pointing at the GroupDimension descriptor.
- **v3.0+** \`AttributeRelationshipType.Group\`: \`IDType\` text content carrying the descriptor's id.
- **SDMX-JSON**: \`\"group\": {}\` (the empty-object form had no id slot).

None of those matched what the writers emitted, and the readers never tried to extract the id. Consequence: a Group-attached attribute round-tripped with the level but **no way to know which group it belonged to**.

## What changed

**Model**: \`Attribute.related_group: str | None = None\` — the missing discriminator the audit didn't realise was missing.

**Writers**:
- 2.1: \`<Group><Ref id=\"...\"/></Group>\` per the XSD wrap.
- 3.0: \`<Group>id</Group>\` as IDType text.
- JSON: \`\"group\": \"id\"\` as plain string.

**Readers**: 2.1 / 3.0 / JSON \`_read_attachment\` now returns a **4-tuple** (level, related_dims, related_measure, related_group). All call sites updated.
