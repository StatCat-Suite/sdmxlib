Closes #93 (the high-severity item from the XSD audit). The 3.0 writer was silently dropping every StructureSet on the floor — real ECB mapping documents would round-trip with all maps lost.

Per discussion: the right answer wasn't \"the 3.0 serializer translates 2.1-shaped model objects.\" It was **\"the model goes 3.0-native and both serializers translate.\"**

## Summary

- Model now uses 3.0-native types: \`RepresentationMap\` (← \`CodelistMap\`), \`StructureMap\` (← unifies \`DataStructureMap\` + \`DataflowMap\`), \`ItemMap\` (← \`ConceptMap\` / \`CategoryMap\`), \`ValueMap\` (← \`CodeMap\`). \`ConceptSchemeMap\` and \`CategorySchemeMap\` promoted to \`MaintainableArtefact\`.
- \`StructureSet\` removed from the model. Maps are top-level on \`StructureMessage\` (\`representation_maps\`, \`structure_maps\`, \`concept_scheme_maps\`, \`category_scheme_maps\`).
- 2.1 serializer: writer wraps maps in synthetic \`<str:StructureSet>\` groups (one per agency+version) at the schema-correct position; reader unwraps.
- 3.0 serializer: writer emits per-kind containers (\`<str:RepresentationMaps>\`, \`<str:StructureMaps>\`, \`<str:ConceptSchemeMaps>\`, \`<str:CategorySchemeMaps>\`) with 3.0 inner shapes (\`<str:ItemMap>\`/\`<str:RepresentationMapping>\` with \`<str:SourceValue>\`/\`<str:TargetValue>\`); reader mirrors.
- SDMX-JSON layer: retains the 2.1-style \`structureSets\` wire envelope (which SDMX-JSON 2.0 still uses) but synthesizes / unwraps it.
- Storage layer: \`structure_set\` / \`codelist_map\` / \`code_map_entry\` tables → \`representation_map\` / \`value_map\`.
- Shared \`_common.py\` helper: \`_write_id_pair_maps\` accepts either \`source_id\`/\`target_id\` or \`source_value\`/\`target_value\` so one helper serves both id-pair and value-pair shapes.
