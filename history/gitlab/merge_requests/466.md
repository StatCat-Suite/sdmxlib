`StructureMessage.all_artefacts()` yielded 21 of 23 slots, and its two callers
want opposite things from it. Both were being failed.

## The omission was a silent drop, not a safeguard

`structure_sets` and `hierarchical_codelists` were absent, so
`parse(xml, registry=…)` **dropped them without a word**:

    >>> msg = StructureMessage(hierarchies=[h], hierarchical_codelists=[hcl])
    >>> [type(a).__name__ for a in msg.all_artefacts()]
    ['Hierarchy']
    >>> reg.add_all(msg.all_artefacts())   # the container simply ceased to exist

A `HierarchicalCodelist` named "Geographic hierarchy" vanished on ingest —
which is the name #239 added the container to stop losing.

`validate_references` was blind to the same two, and they carry four of the
five container-of-`Ref` fields #392 taught the walkers to read. #392's test had
to assert on `_collect_refs` directly for this reason; it can stop.

## Completing it makes a refusal visible where a drop was silent

Six of the 23 now yielded have no `ArtefactKind`, so `add_all` refuses them —
four already did, and this makes it six. That is the right direction:
`formats/gaps.py` states the rule this follows, *dropping is the one that burns
an author; a refusal is visible, a drop is not*, and filtering `all_artefacts()`
down to the storable set would have been that drop.

The refusal now says which and why:

    HierarchicalCodelist is not persisted by this registry — an SDMX 2.1
    container; 3.0 promoted Hierarchy to top level (#395). It was parsed and is
    valid; only storage cannot hold it. Refused rather than skipped so the
    artefact is not lost silently: read the message without `registry=` to keep
    it in memory, or drop it from the message before adding.

against `Unsupported artefact type: HierarchicalCodelist`, which reads as
*malformed* and is not. Whether those kinds should exist is #395; the message
is right either way, and `_NOT_PERSISTED` is where a kind's arrival deletes a
row.

`add_all` is one transaction, so the refusal is atomic — a caller who catches
the `TypeError` is not left with half a message. Asserted, not assumed.

## What is *not* in this commit

The issue asked for the 2.1-only artefacts to be recorded in `gaps.py` so
`unrepresentable()` answers for them. That is wrong, by the module's own
contract:

> Does **not** report what would be *refused* … This is for the losses that
> make no sound.

Writing a `StructureSet` to 3.0 *refuses* — verified — so `unrepresentable`
correctly returns nothing. And after this change no storage drop remains to
record either. Noted on the issue rather than forced into the table.
