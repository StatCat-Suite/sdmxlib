# Merge request !437: The index guard cannot scan its own fixtures

| | |
| --- | --- |
| State | merged |

Follow-up to !436, which left `main`'s gate red.

## What happened

!436 was verified while `tools/check_indexes.py` and its test were still **untracked**. The scanner reads `git ls-files`, so it never saw them, and `just check` went green on a tree that did not include the thing being checked. The first run after the merge produced **eleven findings** — all of them the `mirror.example.invalid` fixtures the scanner needs in order to be tested against anything but public hosts.

A scanner cannot scan its own fixtures. Exempting them is what every linter does; the question is only how tightly the exemption is bounded.

## The fix

`SELF_EXEMPT` skips exactly two paths, and only in `survey`. Three tests keep it there:

- the set is exactly those two paths;
- both still exist — an exemption for a moved file is a silent hole, not a stale string;
- `scan_text` still reports a leak labelled with an exempt path, so the skip stays a property of `survey` and never reaches the scanner.

The docstring on `test_the_repository_itself_is_clean` now records why it passed when it should not have: a test that only runs against tracked files proves nothing on the commit that first tracks them.

## Verification

`just check-indexes` clean at 739 tracked files (was 737 — the two new ones), 23 tests pass, `just check` green.
