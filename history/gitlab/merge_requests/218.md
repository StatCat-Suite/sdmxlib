Mechanical audit for #212. The deliverable is **verdicts**, so most of this is measurement; the code changes are the cases where measurement showed something was broken.

## The headline: two of three test recipes were lying

Every file in `tests/integration/` was marked `live`. All six replay from VCR cassettes and touch no network — **56 tests in 2.9 s offline**. So:

| | Claimed | Actually did |
| --- | --- | --- |
| `just test-integration` | replay from cassettes, no network | **selected 0 tests** |
| `just test-live` | real SDMX endpoints, requires network | replayed cassettes |
| `just record-cassettes` | re-record from live | worked |
| `test_sdmx_live.py:6` | `re-record: pytest -m integration ...` | selected 0 tests |
| `CLAUDE.md:175` | "live endpoint tests (requires network)" | wrong on both counts |

The recipes encoded the right design — `integration` replays, `live` hits the network — and the marker on the files never matched it. The files are now marked `integration`, and `test-live` passes `--disable-recording` so it genuinely bypasses VCR (verified: `--record-mode` defaults to `none`, which is why the old recipe silently replayed). The `live` marker had no remaining users; `slow` replaces it in `pyproject.toml`.

**The ml30/ml31 gap is a single missing test area.** I predicted the same branches were untested in both and checked it by mapping uncovered lines to function names: **13 of ~14 uncovered functions are common to both readers** — `_read_structure_maps`, `_read_item_scheme_maps`, `_read_scheme_map`, `_read_value_maps_30`, `_read_component_maps_30`, `_read_groups`, `_read_concept_role`, and friends. The mapping family. One set of tests would close both.

## The 19 assertion-free tests are all correct

Every one is a "must not raise" (`validate(x)`, `reg.add(cl)`) or "must not warn" (`warnings.simplefilter("error")`) test — the absence of an exception *is* the assertion.

That is only sound if paired negative tests exist, otherwise a no-op `validate()` would pass all of them. **Checked by mutation**: stubbing `validate()` to `return` immediately fails **44** tests in `test_validation.py`. The positive half is backed by a negative half. **No change needed** — recorded so a future audit doesn't re-derive it.

## The slow tests are marked, not removed

Two tests in `test_concurrent_reads.py` were **33 s of a 50 s** unit suite. They are worth keeping — concurrency invariants cannot be tested any other way — so they are now `slow`:

```
-m unit                  50.1 s
-m "unit and not slow"   16.5 s
```

That 16.5 s is the number that decides whether the #213 mutation pilot is tractable, which is why #212 runs alongside it.
