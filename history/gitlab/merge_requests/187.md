Follow-up to !186.

## The defect

!186 introduced `HttpxOptions` and, for two of its fields, wrote a type narrower than httpx's own:

| field | httpx | !186 |
| --- | --- | --- |
| `params` | `QueryParams \| Mapping[str, PrimitiveData \| Sequence[PrimitiveData]] \| List[Tuple[str, PrimitiveData]] \| Tuple[Tuple[str, PrimitiveData], ...] \| str \| bytes` | `QueryParams \| Mapping[str, str]` |
| `cookies` | `Cookies \| CookieJar \| Dict[str, str] \| List[Tuple[str, str]]` | `Cookies \| Dict[str, str]` |

So `RestRegistry(endpoint, params={"limit": 100})` was a static error against a call httpx accepts happily. Same for a raw query string, a list of pairs, or a `CookieJar`.

## Why there is no SDMX-level justification

Two facts, both checked:

* **sdmxlib never reads these values.** `params`/`cookies` enter via `**httpx_kwargs` and are forwarded to `httpx.Client(...)` untouched — grep for `httpx_kwargs` finds only the two forwarding sites. Per-request params are built separately in `SdmxClient`.
* **httpx normalises at construction.** `Client.__init__` does `self.params = QueryParams(params)`, and every request goes through `_merge_queryparams` → `QueryParams(self.params).merge(...)`. By the time anything SDMX-specific happens, all accepted spellings have collapsed to the same `QueryParams` object.

There is therefore no input form httpx accepts that could behave differently for an SDMX request. The narrowing bought nothing and cost callers.

## The fix

Both fields now mirror httpx in full, plus `_PrimitiveData` mirroring httpx's private `_types.PrimitiveData` (spelled out — `httpx._types` is not public API).

The list/tuple members are spelled exactly (`list[tuple[...]] | tuple[tuple[...], ...]`) rather than collapsed to `Sequence[...]`: httpx's alias names the concrete types, so a `Sequence` here would type-check at the call site and then fail at the forwarding call — reintroducing exactly the suppression !186 removed.

`HttpxOptions.__doc__` gains the general rule, since !186's "supported surface" framing is what made the narrowing look deliberate: **options may be dropped from the shape (`headers`, `timeout`, `base_url`, `event_hooks` are), never narrowed within it.**

## Tests

Three tests in `test_rest_registry.py` cover every spelling of each field, asserting the value reaches `client._client.params` / `.cookies` intact.

They are separate literal call sites rather than a `parametrize` list on purpose: `parametrize` erases the argument type to `object` and would need a `# pyright: ignore[reportArgumentType]` per call — a suppression to test that a *suppression* was removed. As literals they type-check against the declared shape under `basedpyright tests/unit/test_rest_registry.py`. Note both checkers are scoped to `src` in the default gate, so CI enforces the runtime assertions; the static half needs an explicit invocation.
