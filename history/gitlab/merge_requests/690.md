#511 item 9, option 2 as decided: design §6.3's two halves.

**`obs.col(id)` checks at runtime.** Its static type is still `Untyped`. It now carries a `ColumnKind`: what the column holds, and how that is known. A literal of the other kind is refused as the predicate is built (`==`, `!=`, `<`…`>=`, `is_in`):

```
REF_AREA is enumerated by CL_AREA, so its values are text; it is compared with int 1,
which would compare text with a number. Compare with "1".
```

**Where the kind comes from:**
- **The DSD first, read from the representation.** An enumerated component holds codes (text), resolved or not. A measure dimension holds concept ids. A `Facet` maps through `sdmxlib.polars`' facet→dtype table, the same one `_typed` uses. It does not go through `schema(dsd)`, which would list every code to type one column (the census codelist has 580k).
- **The store second, only for a component the DSD leaves untyped**, read lazily. When the table exists, the type comes from `DESCRIBE`: the `SchemaInspector` cache now keeps types beside names, still one `DESCRIBE`. A table not yet fetched gets the types its fetch will create (`column_types`, moved from `_scan.py` into `data_store.py` to avoid an import cycle).
- **Unknown** (no DSD type, no stored type, or a date or boolean): nothing is checked, as before.

This catches the silent `obs.col("REF_AREA") == 1` (no rows) as well as the binder error.

**`obs.text(id)` / `obs.num(id)`** return exact `Str[ObsRow]` / `Num[ObsRow]` and refuse the wrong kind when asked for, naming the other accessor. They are implemented by private `ComponentStr` / `ComponentNum`, which project under the component id as `Untyped` does. `sl.Str` / `sl.Num` / `sl.ColumnKind` are exported. The expression-privacy guard admits `Str` / `Num` to its vocabulary on #413's own argument: a public accessor hands them back.

**Tests** (`test_obs_column_kinds.py`, 19 tests):
- every kind source is refused and answered: code, time, stored text, stored `DOUBLE` under a renamed column, declared Double;
- a table not yet created;
- a query with no DSD;
- `text` / `num` answers, projection names, and refusals.

Sabotage checks: with the check off, 8 fail; with no store fallback, 5 fail. `just test-properties` (20×) is green.

Before this change it was a raw binder error, so nothing regresses. Fixing it is a typing decision for fetched tables. The `llms-dsl.txt` example says so rather than pretending.
