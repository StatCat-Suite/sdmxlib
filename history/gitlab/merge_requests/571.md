## What changes

- **`parse` runs `add`'s rules.** Every artefact a reader builds goes through `collect_issues` — the same rules `Registry.add` enforces since !570. One that breaks them is refused into `StructureMessage.refused` (reason: each broken rule, by path), like an element that contradicts the schema; the rest are read. `strict=True` still raises. The 2.1-only-version check stays at `add`: a 2.1 document read and written back as 2.1 never needs a 3.x version (`model/version_rewrite.py`).
- **References into a refused artefact are withdrawn.** A reader resolves in-message refs before the rules can run, so `refuse_invalid` (`formats/_refuse.py`) unresolves any ref whose target is the refused artefact or an item inside it — matched by identity, since a `latest` ref names no version. Nothing is refused by cascade. Withdrawal goes through `_interning.withdraw_resolution`, the sanctioned write seam.
- **`RestRegistry` reads on.** The client parses non-strict; `_absorb` ingests the rest and keeps refusals on `reg.refused`; `get` of a refused artefact raises `SdmxConformanceError` naming the reason (a `latest` URN matches any refused version). `FederatedRegistry` lets it through rather than treating it as unavailability. `load()` of a local file stays strict.
- Sweep: `refusal_key` drops item ids from refusal reasons; `issue_key` handles the nested-agency `Class:agency:id` labels `add` now writes.
