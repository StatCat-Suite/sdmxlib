Closes #446.

## The defect

#436 closed the world for child *elements*: one the schema allows nowhere under its parent refuses the artefact. Attributes were still read past. A misspelt optional attribute, such as `validfrom` for `validFrom`, lost its value silently. One a version prohibits (3.0 removes `version` and `isFinal` from organisation schemes, and Eurostat ships both) was ignored.

## The fix

- **The generator** (`tools/generate_allowed_children.py`) now also emits `ATTRIBUTES` and `OPEN_ATTRIBUTES`: per element name, the attributes some schema context allows on it. Attributes resolve differently from content models:
  - an `xs:extension` adds to its base's attributes;
  - an `xs:restriction` *inherits* its base's attributes and removes one only by redeclaring it `use="prohibited"`, which is how 3.0 strips `version`/`isFinal`;
  - `xs:attributeGroup`s resolve through the symbol table;
  - `xml:lang` resolves by its fixed namespace, since the prefix is implicit and never in an `nsmap`;
  - `xs:anyAttribute` opens an element (only 2.1's `str:Key`).

  It is lenient like the element table: the union over every declaration of a name.
- **The walk.** `check_children` checks attributes in the same walk, with no second pass. `xsi:` attributes are always allowed. The refusal names the attribute, the element, the line, and what the schema allows there.
- **The policy** was your decision: refuse the artefact, like an element.
