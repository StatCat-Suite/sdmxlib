## Why pyrefly is scoped, not a full gate (evaluation)
A full pyrefly run = ~58 findings. Two root causes account for ~52, both at the attrs `field(converter=…)` boundary:
1. **Generic converters** (`to_itemlist[T]`): attrs sets the `__init__` param to the converter's input `ItemList[T] | list[T]`, but pyrefly doesn't re-solve `T` against the field's declared type — it leaves `T` unbound, so nothing is assignable. basedpyright solves `T` from the field annotation.
2. **Classmethod converters** (`Enum.parse`): pyrefly treats the bound classmethod as unbound and reads its `cls` as the value param, so the `__init__` param becomes `type[Enum]`. basedpyright sees the bound method.

Both are pyrefly attrs-integration gaps, not code defects — "fixing" them would inject `Any` or churn every artefact's fields. So they stay basedpyright's domain; pyrefly keeps `implicit-any`, which basedpyright only approximates.
