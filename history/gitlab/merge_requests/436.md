Audit for leaked private-mirror configuration, plus a gate so it stays that way.

## The audit found nothing

Reported first because it changes how you read the rest: there was nothing to clean up.

- **Every tracked file** (737) scanned for `artifactory`, `index-url`, `extra-index`, and `user:pass@` URLs. One hit — the `.gitignore` comment explaining why `uv.lock` is not committed. It names the concept, not a host, path or token.
- **All 5229 blobs reachable from all 1316 commits.** Six matching lines, all six that same comment across its versions. Pickaxe over `index-url` / `extra-index` returns zero commits: no such line has ever been added or removed here.
- **`uv.lock` has never been tracked.** It is the classic vector, since a lockfile records whichever index resolved it.
- **Every URL host in tracked files**, reviewed as a list — all public (sdmx.org, ECB, W3C, IMF, GitHub/GitLab, `example.invalid` fixtures). The one StatCan host is `www150.statcan.gc.ca` in `examples/codr.py`, their public WDS API. Left alone; say if you want it gone.
- **Config surfaces**: no `uv.toml` / `pip.conf` / `.netrc` / `.pypirc` tracked, no `[tool.uv]` index config, and `.gitlab-ci.yml` installs from default PyPI.

So this is a guard against a future mistake, not a fix for a past one.

## Why an allow-list

The obvious guard greps for the mirror's hostname — and writing that guard *is* the leak: the pattern would name in the gate the exact thing the gate exists to keep out, committed and searchable forever.

Inverted, the rule reads: **an index directive may point at a public index and nothing else.** A mirror nobody has heard of yet is caught with no update here. Nothing in this MR names the real mirror, including the tests.

## What it checks

1. A directive assigning a non-public host — `index-url`, `extra-index-url`, `find-links`, `trusted-host`, `publish-url`, `UV_INDEX*`, `PIP_*_INDEX_URL`, and uv's `[[tool.uv.index]]` tables.
2. A tracked file that carries index credentials by nature: `.netrc`, `.pypirc`, `pip.conf`, `pip.ini`, `uv.lock`.
3. `uv.lock` not being ignored — catching the state *before* a commit rather than after.

Every tracked text file is scanned, not just config: a README telling a contributor to install from a private mirror leaks the same host a `pyproject.toml` would. `just release-5-pypi` gets a matching preflight, since a shell configured for a mirror redirects `uv publish` silently.

## The part worth reviewing

Matching directives is easy; *not* matching English is not. The first pattern allowed a single dash and reported five leaks in this repo — four of them sentences about a DuckDB ART-index, one about a `source-index` mapping. Requiring both dashes fixed those; requiring an assignment separator fixed two more, both in this MR's own prose.

`tests/unit/test_check_indexes.py` (20 tests) pins all five real lines as must-not-match, alongside the leaks that must match. One accepted limit is documented in `directive_value`: a single-label value (`--trusted-host mirror`, no dot) reads as an ordinary word and is not reported. Requiring a dot is what keeps the scan off prose; `uv.lock` staying ignored is the backstop.
