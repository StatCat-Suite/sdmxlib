## What it models

SDMX 3.1 \`DataflowType\` adds optional \`<DimensionConstraint>\` with one or more \`<Dimension>id</Dimension>\` children. Supports the *evolving DSD* pattern: a DataStructure can grow new dimensions in minor versions, and a Dataflow with a wildcarded minor-version pin to that DSD declares which dimensions it commits to so future DSD additions don't silently appear in datasets.

Modelled as \`dimension_constraint: tuple[str, ...] = ()\`:
- Empty tuple = no constraint (the Dataflow accepts the full DSD dimensionality).
- Per the XSD docs, the time dimension must not be listed (it's always implicitly included). We document that constraint but don't runtime-validate it — the eventual 3.1 writer's job.

## No serializer changes

- 2.1 / 3.0 \`DataflowType\` have no equivalent element; serializers silently ignore the field (the default empty tuple emits nothing).
- We don't have a 3.1 writer yet; that work picks up the field when it lands.
