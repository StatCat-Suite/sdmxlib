Closes the last hole #205 left open.

!191 made `serialize()` validate by default — but `validate()` **checked no names at all**, so the check that would have caught #205's original nameless `Code` simply did not exist. A nameless artefact could still reach the wire.

## What the schema actually requires

Verified per type against the vendored XSDs rather than assumed:

| type | Name |
| --- | --- |
| `Code`, `Category`, `Agency`, `DataProvider` (via `ItemType`) | **required** |
| `Concept` (via `ConceptBaseType` → `ItemType`) | **required** |
| every maintainable (via `MaintainableType`) | **required** |
| `MetadataSet` (`MetadataSetBaseType`) | **required** |
| `Dimension`, `Attribute`, `Measure` (via `ComponentType`) | **no Name element exists** |

`<com:Name>` carries no `minOccurs` in any of the required cases, so it is mandatory.

**Components are deliberately excluded.** They are *identifiable*, not *nameable* — the XSD gives them no Name element at all. "Validate everything" would have been the easy wrong answer, so there is a test pinning that a component-only DSD passes.

## A gap the checker found

`MaintainableArtefact` declared `id`, `maintainer` and `version` but **not** `name` — the one NameableArtefact field missing from the base, with every subclass redeclaring it independently. The generic check did not typecheck until that was fixed, which is how it surfaced. Now declared alongside the others, with the XSD rationale recorded.

## Test fallout

**87 failures**, all fixtures that had simply never needed names — 147 constructions across 9 files, fixed mechanically.

Worth flagging: I estimated **21** when we discussed this. That was measured on codelist codes alone; maintainables dominate the real number (39 of the failures are `Codelist.name`). The 4× miss was mine, and the work was larger than I quoted, though still mechanical.

Two of the 87 were **deliberately** nameless and were restored, not "fixed": the SDMX-JSON `serialize_code` / `serialize_concept` id-only tests. Those exercise the low-level DTO path, not the validated write path, and asserting id-only output is exactly their point. A blanket script would have silently broken what they were testing.

## BREAKING

`validate()` — and therefore `serialize()` — now rejects an artefact or item with an empty name:

```
ValidationError: 1 validation issue:
  error: Codelist.name — name is required (SDMX NameableArtefact)
  error: Codelist.codes[A].name — name is required (SDMX NameableArtefact)
```

Combined with !191's `validate=True` default, code that previously emitted nameless artefacts now raises.
