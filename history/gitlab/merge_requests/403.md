# Merge request !403: fix(query)!: union across two databases is refused, as intersect already was

Found by tracing `sl.union` end to end rather than trusting that
exporting it in !401 finished the job — the same question that turned up
the timestamp zone bug one MR ago, asked of the other two "promises".

Two registries holding disjoint codelists:

    a holds: ['A1', 'A2']       b holds: ['B1', 'B2']

    union(a.filter(id=='A1'), b.filter(id=='B1'))  -> ['A1']
    intersect                                      -> CrossSourceError
    difference                                     -> CrossSourceError

`union` dropped a whole operand and returned a plausible-looking set.
`b`'s compiled SQL is spliced into `a`'s connection, where the same table
names resolve to `a`'s rows and `B1` does not exist — §5.9's defect, and
the one `test_query_cross_source.py` was written for.

The check lives in `_membership`, which `intersect` and `difference` go
through and `union` does not, because it is a free function — for the
refinement reason its own docstring gives. So the guard covered two of
the three set operations, and its test parametrised over exactly those
two, which is why nothing looked.

`test_a_set_operation_across_databases_is_refused` now covers all three,
and a second test keeps the *answer* the refusal is protecting against,
because the fixture that exposes it — two stores that disagree — is the
part worth preserving. Verified both fail with the guard removed.

The other two promises traced clean, and one is worth recording as the
contrast. Version comparison has no hole of this shape because
`version_sort` is `NOT NULL` in the DDL: the invariant is enforced by the
database rather than by a convention a read path can skip, which is
exactly what the timestamp case lacked. Checked across paths too —
comparison agrees with `order_by`, `rank`, `qualify`, `agg(max)` and
paging, works through a joined path, and holds for prereleases,
`1` == `1.0` == `1.0.0`, and `10.0 > 2.0`.
