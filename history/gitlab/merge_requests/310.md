## Evaluation is local, so there is no interpreter to write

§12 concluded materialise. Follow it through and the REST backend needs no local predicate evaluator, sort, projection, or artefact-to-row layer: it fetches, writes into a scratch DuckDB at 2.6 ms/artefact, and runs the *original* query through the compiler that exists.

    183 artefacts materialise   0.51 s
    then the original query     1.6 ms

So for a backend that cannot compute, **pushdown is fetch planning**. `Residual` and `Membership` stop being work the executor performs and become the reason a particular fetch is enough.

## The failure this caught

Running the headline query against the materialised catalogue returned **zero rows and no error** — because the fetch was short:

| fetch | returned | concept ids resolvable |
| --- | --- | --- |
| `/dataflow/ECB?references=datastructure` | 102 flows + 81 DSDs | **0** |
| `/dataflow/ECB/EXR?references=descendants` | 1 flow + subtree | **31** |

`references=datastructure` brings the DSDs but not the concept schemes they reference, so `dsd.dimensions.any(concept.id == …)` evaluates over an empty `concept` table. That is the failure this design exists to prevent, arriving through the back door.

§11 said "projection drives prefetch". True and too narrow — a locally-evaluated *filter* needs the joined values just as much, and for this backend every filter is local. §11 now points here.

## The inversion worth knowing

Fetching everything locally does **not** make the §9.1 rewrite pointless. It is how the closure stays small: without it, closing `dataflow.dsd.dimensions.concept` means `/dataflow/ECB?references=descendants` — every dataflow dragging its subtree. With it, the inner scan is `/datastructure/ECB?references=children` over 81 DSDs and the outer scan needs no references at all. The N+1 argument and the closure argument coincide; they are different arguments, and that matters when one stops applying.

## What 4b becomes

Push → URL (assembly, not compilation); a `references=` per Push from the closure; fetch/parse/materialise; run the original query. No local evaluator, no row-shaping, no second compiler. The §8 differential gate gets cheaper — both sides run the same SQL over stores populated differently.
