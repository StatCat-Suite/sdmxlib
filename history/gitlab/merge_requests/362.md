## The leak

An unprojected `frame()` handed back the binding's **physical** columns:

```python
store.observations(binding).frame().columns
# before: ['f', 'geo', 't', 'v', 'st']
# after:  ['FREQ', 'REF_AREA', 'TIME_PERIOD', 'OBS_VALUE', 'OBS_STATUS']
```

Every filter, projection and label in this language names a *component*. A
result that used the producer's column names was the one place they escaped
into a caller.

## Which is why labelling was broken

`sdmxlib.polars.label` matches components **by id**. While a frame carried
physical names, labelling a binding whose columns are not already ids matched
nothing — silently at first, and by raising once that was found. That raise
treated the symptom; this removes the cause:

```python
store.observations(binding, dsd=dsd).frame(labels="en")
# REF_AREA | OBS_VALUE | REF_AREA_label_en
# ON       | 1.0       | Ontario
```

on a binding that maps `REF_AREA` to `geo`.

## How

`Cols.__projection__` lets a root declare its output as `(table, column, name)`
triples. Empty keeps the old `s0.*`, which is right for a structural relation
whose column names *are* what a caller asked about.

`_Scope.declared_projection` renders it. The split is deliberate: the root
knows which column carries which component and which table it lives on, and
only the scope knows what that table is *called* here — so the two meet at one
method rather than either guessing. That is also what makes a **sidecar** column
come back under its component id, so which side a column is stored on can no
longer change the name a caller sees.

## Breaking

`frame()`, `collect()` and `stream()` over observations return component ids
where they returned physical columns. An explicit `select()` is unaffected — it
names its own outputs, and the default applies only where a caller named
nothing.

## Guards

Mutation-checked: dropping the declared projection fails 3 tests, reading
sidecar columns through the root alias fails 1, and aliasing to the physical
name rather than the component id fails 3.

Prerequisite for step 7 — once a result speaks component ids, a format writer
needs a DSD rather than a binding.
