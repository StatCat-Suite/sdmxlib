## The defect this found in !358

`_fetch_data_for` handed `scan_csv` a `bytes` object — and that reader has two
branches:

```python
lf = pl.scan_csv(...)                          # a path  — lazy
lf = pl.read_csv(io.BytesIO(source)).lazy()    # bytes   — EAGER
```

So the whole slice sat in RAM, twice, before DuckDB was involved. **A
file-backed `store=` would not have fixed it** — that decides where the table
lands, after the peak has already happened.

## Measured on both axes, because optimising one can surprise the other

2M rows, separate processes, fixture built once outside the measurement:

| route | time | peak RSS |
| --- | --- | --- |
| bytes → polars → duckdb (before) | 0.30 s | 660 MB |
| file → Arrow IPC → duckdb | 0.27 s | 608 MB |
| **duckdb reads the file** | **0.21 s** | **307 MB** |

The middle row is what this branch implemented first, on the assumption that
reusing `scan_csv` was worth a modest cost. Isolating the stages showed
`sink_ipc` to be the most expensive step in that route — so there was no
trade-off to make, and the assumption was simply wrong.

## Typing is replaced, not dropped

Leaving `scan_csv` costs its DSD-driven typing, so `ingest_csv` takes an
explicit `types=` map. It is a **partial** override, which is what makes it
robust: components are forced, and the SDMX-CSV envelope is left to inference
because which columns arrive depends on whether the provider sent 1.0
(`DATAFLOW`, `KEY`) or 2.0 (`STRUCTURE`, `STRUCTURE_ID`, `ACTION`).

Every dimension and attribute is `VARCHAR` **without exception**. A code column
of `0100`, `0200` inferred as an integer loses its leading zeros, still looks
like a code, still joins, and is wrong everywhere. Measures take their type
from the DSD facet — guessing wrong there is recoverable, since a caller sees a
binder error rather than corrupt data.

## Also in here

**`explain()` says when a query fetches.** It showed only SQL, so a remote
query read as a local table scan and the request filling that table was
invisible. Structural queries too, not only data.

**`stream()`'s measured promise is scoped.** Its 5 MB figure is measured
against rows already in the store. Fetched into a `RestRegistry`'s own
in-memory store — the default when no `store=` is given — the slice is
materialised in RAM first. The docstring now says which configurations hold,
and names `explain()` as what tells them apart.

## Guards

A fetch of `0100` / `0200` proves the leading-zero case end to end.
Mutation-checked: inferring component types fails 9 tests, typing measures as
`VARCHAR` fails 2, and the earlier `explain()` line is checked to appear only
where something is actually fetched.
