## Phase 1 bug fix

\`test_registry_lookup\` was calling \`a.urn\` which returns the unbound classmethod (since \`urn\` is \`@classmethod\` on \`MaintainableArtefact\`, not a property). The InMemoryRegistry was getting bound-method objects as lookup keys, missing silently, and the bench was measuring dict-miss cost instead of dict-hit cost.

Fixed by using \`artefact_urn(a)\` and adding a sanity assertion so future regressions surface immediately. Real lookup numbers are now slightly slower than what Phase 1's MR !79 reported (130-160 ns/lookup vs the reported 15 ns), but credible.

## Real findings from running it

- **Lazy vs eager codelist read is 3-4× apart**: 600 µs lazy vs 1.6-2.2 ms eager for the same codelist. Confirms the LazyCodelist design pays off when you only need the spine.
- **\`code_map\` scales sublinearly**: 0.3 ms @ 100 codes → 1.5 ms @ 1k → 2.0 ms @ 10k. SQL pushdown working.
- **\`put_codelist\` per-row cost ≈ 6.5 µs/code** at the 10k size. Linear, no surprises.
- **\`put_data_structure\` at 10×200 takes 106 ms** — but most of that is the 10 backing codelists. The DSD-component portion is ~30 ms.
