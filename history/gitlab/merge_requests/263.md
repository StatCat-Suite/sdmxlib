Closes #282, #283, #284. First three of %16.

An audit after %13/%14/%15 asked whether those milestones had added `Any`. **They
had not** — net +1 across 4,297 added lines of `src/`, zero new `-> Any`, zero
new casts, zero `# type: ignore`, and pyright/pyrefly suppressions flat (six
added, six removed by #267's dedup).

The interesting finding was not in the diff. It was that **the audit could not
have failed**.

## The gap

CLAUDE.md says `src/` carries "zero `Any`-annotated parameters or locals, and an
`Any` parameter anywhere is a finding". `ANN401` enforces that — for *bare*
annotations. It does not look inside generic arguments:

```python
def f(x: Any) -> None: ...              # ANN401 finding
def f(x: dict[str, Any]) -> None: ...   # silent
```

**112 of the occurrences are the second form.** The documented rule covered
about four sites while reading as though it covered all of them.

## Three findings (#282)

| | |
|---|---|
| ``# noqa: C901`` inside a **doc comment** | ruff scans raw text, parses a malformed directive, warns on every cold run — and inflates the `noqa` count so a suppression audit reads wrong |
| `text_by_ann: dict[Any, dict[str, str]]` | key is only ever a lookup — pure-consumer, so `object` by CLAUDE.md's own litmus |
| `table = getattr(_thread_local, "table", None)` | unannotated → implicit `Any` local, three functions above the correctly-annotated `lang: str \| None = getattr(...)` |

The last two are **pre-existing** — both were in *both* query modules at the
pre-%13 baseline; #267 halved them and moved them somewhere visible. Fixing
them takes `_query_common.py` to **zero** `Any`.

## Two guards, because the findings were not the point (#283, #284)

**Ruff warnings now fail `just lint`.** Ruff exits 0 on a `warning:` line, so
those two survived three milestones — and they survived *because* they were
noisy and got filtered out of check output as routine. I filtered them myself,
repeatedly, during the work that introduced them. A finding that cannot fail is
a finding nobody acts on. ruff 0.16 has no native flag; the wrapper says to
revisit when it does.

**A ratchet on `Any`.** No linter in the stack has a rule for the
generic-argument case, so `tools/count_any.py` carries a measured number
instead — the same technique as pyrefly's deny-list. It fails in **both**
directions: rising means one slipped in; falling means the baseline needs
tightening, because a ratchet nobody tightens stops ratcheting.

Baseline recorded at **117**. The 171 I first reported was a raw grep inflated
by prose, imports and `AnyRef` — the tool's number is the honest one, and the
per-category breakdown in %16's issues is scaled to it.

## Both guards were verified by breaking them

Not asserted — reintroduced the defect and watched the gate fail:

```
$ just check-any          # after adding one dict[str, Any]
error: `Any` in src/ rose to 118, above the baseline of 117.

$ uv run ruff check src   # with a prose noqa present
warning: Invalid `# noqa` directive on .../urn.py:164
All checks passed!        # ← ruff exits 0
$ just lint               # ← now fails
```

## Notes for review

- The counter is a **text scan, not an AST walk**, so it agrees with what a
  reader greps for and sees string annotations the way this codebase writes
  them under `from __future__ import annotations`.
- It is **tested**, because a gate tool breaks *open* — a counter that
  undercounts reports green forever and nobody investigates a passing check.
- One test **records a known limitation rather than asserting it away**: `Any`
  inside a string *value* is counted. That over-counts, which can only cause a
  false failure and never a false pass, and `src/` has no such string today.
- **CLAUDE.md corrected** — it stated a guarantee `ANN401` does not provide.
