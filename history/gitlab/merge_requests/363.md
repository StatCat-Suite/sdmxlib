## Four entry points, one axis

`get(type, agency=…, id=…)` returned a `GetQuery` whose `.fetch()` and
`.resolve()` were two settings of *how far to follow references*; `fetch()` and
`resolve()` on the registry were the same two again, by URN. All four collapse:

```python
reg.get(urn)                                # skeleton — what fetch() meant
reg.get(urn, resolve=True)                  # every reference
reg.get(urn, resolve=[sl.Codelist])         # only those types
reg.get(urn, resolve=True, partial=False)   # and untrimmed
```

Two of the handle's other jobs went elsewhere rather than away: building a URN
from coordinates is `urn_for` (step 2, !361), and accepting a `Ref` from graph
traversal stays on `get`, since making a caller unwrap one would be ceremony.

Selective resolution survives as a **list** rather than a single type, because a
list can be — and is sorted, so the same question cannot produce two URLs and
therefore two cache entries.

## Defaults differ between registries, deliberately

`RestRegistry.get` does not resolve — a reference is another round trip.
`Registry.get` does — locally it is a join. Each states the default its cost
implies rather than agreeing on a number neither would pick. That was already
true before this change; it is now visible on the signature instead of split
across two method names.

## Tests moved rather than went

What `GetQuery`'s tests covered is real, so it is asserted against the **wire**
— which `detail` and `references` reach the request — since that is what a
caller is choosing between. The two are checked together because they move
together: asking for references and asking for them trimmed are different
questions, and pinning one would let the other drift.

## A stale page, found by the change

`docs/cookbook/resolution.md` documented three "modes", and **one of them had no
implementation left anywhere in `src`**: `.browse()`. The collection side had
already moved to the path language in an earlier milestone, where the planner
picks its own request from what the query reads (`detail=allstubs` when a
projection is served by stubs) — so there is no mode to choose there at all. The
page's code examples had been migrated; its prose had not.

Rewritten around the one parameter, with collections pointed at the query.
