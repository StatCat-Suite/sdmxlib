## #383 — every hierarchy node was walked twice

`walk_fields(Hierarchy)` included `_codes`, which is `_flatten_nodes(self.tree)`
— *the same objects*. Never wrong (the `walked` set caught it), just 499,138
wasted calls.

A `derived_view()` field marker. Its contract is **reachability, not privacy**:
a marked field must hold nothing an unmarked field does not already reach.
`_`-prefixing implies no such thing, and a marker on an independent edge would
hide it from resolution, interning *and* validation simultaneously — silently,
since the objects stay and only their refs stop resolving. So it is checked on
a parsed graph, with the case that would pass if the check were decoration.

**This forced a real decision in #376's differential**, which asserts the static
shape is never narrower than reflection. Derived views make it legitimately
narrower. The exception is *subtracted explicitly*, with a pointer to the test
that carries the burden — rather than the assertion being loosened, which would
have turned the marker into a way to hide an edge.

## #384 — the converter re-ran on a value we had just built

10.2x on the assignment. `_assign_ref` bypasses `on_setattr` behind an
`isinstance` check — the check is why it is a function and not an inline
`object.__setattr__`, stating the assumption once for ~0.04 us against the
0.33 us saved.

Both halves pinned: the bypass converts nothing, the public API still does. The
converter spy is a purpose-built class, because **attrs captures converters by
reference** when it generates `__setattr__` — patching `attr.setters.convert`
intercepts nothing, which the first version of that test found by passing for
the wrong reason.

## #154 item 2 — one URN parse per node

499,138 on every path. `SdmxUrn.parse_item` splits at `").."`, caches the scheme
half, builds the rest directly: **0.85 us → 0.55 us** over 500,000 URNs from
two *interleaved* codelists, so a single hoisted prefix would not have done.

It is a second implementation of the grammar's item case, so `parse` is the
oracle — Hypothesis plus the hand-found shapes, green at
`HYPOTHESIS_PROFILE=deep`, and two mutants caught (a cache keyed too coarsely,
a mangled item id).

## What was declined, and why that is a result

**#385.** Its stop condition was set before any code: abandon under ~150 ms.
Fairly measured, `__new__` + `object.__setattr__` on `HierarchicalCode` is
0.69 → 0.48 us — **105 ms** projected, ~68 ms for `Code`. Below the line;
recorded and closed.

The first attempt measured the bypass as *slower* (1.05 µs). The harness filled
remaining fields through a `hasattr` loop attrs does not pay for. Worth naming:
attrs' generated `__init__` is fast enough that a naive bypass loses to it, and
the version that wins is the one most likely to drift when a field is added.

**#154 item 3** (memoising `materialize()`). A per-instance memo of a 1.1 GB
`Hierarchy` is precisely the bounded-in-the-wrong-unit problem #386 is open
about. Deferred until that decides, rather than adding a second cache measured
in objects.

## Notes for review

- The `Any` ratchet goes 39 → 40, reason in `tools/any_baseline.txt`:
  `parse_item -> SdmxUrn[Any]` mirrors `parse`, which CLAUDE.md names as a
  legitimate site — the phantom is recovered by `Ref.unresolved(urn) -> Ref[T]`.
- `_assign_ref` raises rather than asserts: S101 bars `assert` in `src/`, and
  the rule is right — this is a hot path where a stripped assert would silently
  remove the one check the bypass depends on.
- `parse_item`'s scheme cache is `lru_cache(maxsize=512)`. Bounding by **count**
  is correct here for exactly the reason it is wrong in #386: the entries are
  uniform and tiny.
