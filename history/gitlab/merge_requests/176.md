Follow-up to the msgspec migration (milestone #8): a fresh design pass on how we handle `InternationalString` and the wire DTOs, prompted by "why aren't we as fast as pysdmx now that we both use msgspec?"

## The finding

Profiling the migrated writer showed **msgspec encode is only ~6% of serialize time**; ~90%+ is the domain-model → wire-Struct conversion — and **pysdmx has the identical conversion step** (`from_model`, called the same number of times as our `to_*`). So the gap was never "we convert and they don't." It was:

1. **They're lossy, we're lossless.** pysdmx stores one best-match `name: str` and emits only `name`; we model a full `InternationalString` and emit `name` + the `names` lang-map (proof: for one code we emit `de`/`fr`, pysdmx drops them). Their `from_model` is a pointer copy; our `to_*` splits every istring. That's real work — the price of a lossless round-trip, which we **want**.
2. **Two msgspec knobs we hadn't used** — both fixed here.

## Changes

- **`WireStruct` base** carrying `gc=False` (+ `omit_defaults`), inherited by every SDMX-JSON DTO (structure / metadata / 1.0). Wire DTOs are transient, acyclic **trees** — built per-serialise, encoded, discarded — so the cyclic collector scanning millions of them is pure overhead. Reference counting still frees them promptly (**no leak** — the only leak mode is a reference *cycle*, which our tree-shaped DTOs never form; documented as an invariant on `WireStruct`). **~40% of build+encode.**
- **`InternationalString.emit_pair()`** — collapse the `(best, full-map)` istring split into one method with direct backing-map access, dropping the `__bool__`/`as_dict`/`iter`/`next` calls `emit_istr` made 677k times on the large fixture. **~6%.**

## Result

3.8M-obs ESTAT HICP fixture, SDMX-JSON 2.1 serialize (median): **~5.9 ms → ~4.0 ms**. Head-to-head on the competitive harness:

| | median |
|---|---:|
| **sdmxlib (now)** | **4.02 ms** |
| pysdmx | 4.64 ms |

**~16% faster than pysdmx — while emitting every language pysdmx discards.**

## Safety

- `gc=False` disables only the *cyclic* collector; refcounting (which can't be turned off) still reclaims every DTO immediately on scope exit — demonstrated with the cyclic GC fully disabled. Better for long-running serialize loops, not worse.
- New `test_wire_dtos_are_gc_untracked` guard (`gc.is_tracked`) samples a DTO from each wire module so a stray `msgspec.Struct` base can't silently re-track one and undo the win.
- Full unit suite **2427 passed**; `just check` clean.

Design verdict: the `name`/`names` two-field split is **not** debt — it's forced by the wire (two sibling keys), so no `enc_hook` can replace it. The real debt was the two unused msgspec knobs, now adopted.
