Closes #476.

## The defect

An SDMX-ML 2.1 `<Ref>` without `@version`, or an item ref without `@maintainableParentVersion`, was read as version `latest`, a late-bound pointer to whatever is newest. Every concrete ref type in `SDMXCommonReferences.xsd` declares `default="1.0"`; only the abstract `RefBaseType` has none. So `<Ref agencyID="ECB" id="CL_FREQ"/>` names `CL_FREQ(1.0)`. It's the same class of defect as #475: the schema's default is the standard's own answer.

The rest of the library already knew. `_check_latest_refs` refuses to write a `latest` reference to 2.1, and its docstring says why: *"its XSD documents an omitted `version` and `maintainableParentVersion` as defaulting to 1.0"*. Only the reader disagreed.

## The fix

Three reads now default to `1.0`:
- `ref_el_to_urn`: `version` and `maintainableParentVersion`;
- 2.1's hierarchical-code reference: the parent version, still read through `@version` first as before.

The writer's omit-for-`latest` branch (for callers writing directly, #429) stays. Its comment now says what a reader makes of the omission, and why `serialize` refuses first.

All the version-less refs are local (`<Ref id="FREQ"/>`), which carry no version by definition. The fix is correctness only, not a change in what any live document reads as.

## Guards

- `test_an_omitted_2_1_reference_version_names_1_0`: refs are written at version 2.0 and then stripped, which covers the dataflow's structure ref and two concept item refs. A reader that kept the written version or took `latest` fails it.
- The #474 census (`test_reader_defaults_census.py`) had these four reads pinned to #476. They're now classified as the XSD's default, and `maintainableParentVersion '1.0'` is cross-checked against the vendored 2.1 schema.
- Sabotage: putting `latest` back for either attribute fails both tests.
