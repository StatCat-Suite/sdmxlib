Fixes a measurement fault introduced by !625.

**The fault.** !625 kept mutmut 3.8's default `forkserver_warmup = "collect"`. The fork server collected the suite before any mutant was chosen, and every child inherited the imported modules. Code that runs at import was therefore never mutated:
- the 3.x readers' and writers' module-level instances;
- `gaps.py`'s predicate table.

The first `_v3_writer.py` run booked 282 survivors. One is an `__init__` that sets `self._helpers = None`, which a fresh process kills. !625's check measured the import-time credit, not whether the credited mutants were ever active.

**The fix:**
- `forkserver_warmup = "none"`, and `tools/mutmut_forksafe.py` refuses any other value.
- A mutant that breaks an import-time table fails collection, and pytest exits 4. The fork server turns the exception into exit 255, which 3.8 books as a **timeout**. `CreditingRunner.run_tests` books it as a kill, as 3.7 did. A clean or forced-fail run still raises.

**`gaps.py`**, 622 mutants, 4 children:

| runner | killed | survived | timeout | wall |
| --- | --- | --- | --- | --- |
| !625 (warm-up collect) | 317 | 302 | 2 | 79 s |
| warm-up none | 490 | 118 | 13 (11 exit 255) | 290 s |
| this MR | 501 | 118 | 2 | 296 s |

Twelve sampled survivors survive a fresh process too. The 2 timeouts are the real infinite loops in `_follow`.

Installments 1–5 and !626 were measured on 3.7 and are unaffected. The `_v3_writer.py` run is discarded and is re-run after this merges. `docs/design/mutation-evidence.md`'s runner section is corrected.
