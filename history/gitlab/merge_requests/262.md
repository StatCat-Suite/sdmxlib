## The premise in #276 was wrong, and that made this cheap

#276 deferred this as "a tree of reported values, a different shape from the
artefact spine". That is true of the **model** — `ReportedAttribute` recurses —
and false of the **storage**:

```sql
CREATE TABLE metadata_value (
    set_urn, attribute_path, sibling_index, value_kind, scalar, i18n,
    PRIMARY KEY (set_urn, attribute_path, sibling_index)
);
```

The tree is reconstructed on read from the dotted path. So this is an ordinary
relation, subtree questions are `starts_with`, and it needed **no new compiler
machinery** — a row kind, its fields, an accessor.

## Two defects avoided because the codebase had already paid for them

**Fan-out (#254 again).** Every consumer writes the target lookup as an inner
join from `metadata_target`. That table is keyed `(set_urn, ordinal)`, so a set
may list the same artefact twice and the join then returns each value row
twice — silently, and only for sets shaped that way. This uses a correlated
`EXISTS`, and the duplicate-target case is asserted.

**LIKE metacharacters (#222 again).** `has_metadata(path, subtree=True)`
compiles to a prefix match, and SDMX attribute ids routinely contain `_`, which
`LIKE` reads as "any single character". Routed through
`ilike_pattern`/`ESCAPE`, with a test that adds an underscore on purpose —
the bug is invisible on a fixture whose ids have none.

## Worth a look in review

**`collect()` routes through `metadata_report`** rather than re-deriving the
MSD join, so the typed view has one implementation. A `MetadataSection` does
not carry its owning set, so results are indexed by full key and re-emitted in
the *query's* order — otherwise a caller's `sort_by` is silently replaced by
the report's own `(path, sibling_index)` ordering.

**`RowKind.urn_column` may now be `None`.** A reported value has no URN, so
annotations are unreachable from it. `None` states that, and `field_condition`
raises a clear error rather than emitting a join to nothing. Declared as a
**read-only property** so it is covariant — a plain Protocol attribute is
invariant, which would force every row kind that *has* a URN to redeclare the
type just to accommodate the one that does not.

**`meta.target` is filter-only.** A set may describe many targets, so there is
no single value to project into a cell. Refused rather than guessed at.

**No public `keys()`.** The cheap terminal is `paths()`. `keys()` reads as the
dict protocol — `for k in query.keys()` is what every linter and every reader
takes for a mapping, and ruff flagged exactly that in the tests before it could
reach a user.
