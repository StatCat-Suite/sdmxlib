# Merge request !215: typing: one way to build a Ref from an artefact — Ref.to()

| | |
| --- | --- |
| State | merged |
| Opened | 2026-08-06 |
| Merged | 2026-08-06 |

Closes #219. One way to build a `Ref` from an artefact, and it is the typed one.

## Before

```python
urn: SdmxUrn[T]                       # what the field declared

def __attrs_post_init__(self):        # what the constructor accepted
    if isinstance(self.urn, MaintainableArtefact):
        self.urn = SdmxUrn.make(...)  # rewrite the field in place
        self._resolved = obj
```

Two forms, one declaration. No checker can model a post-init that replaces a field with a different type, so the gap was carried by **three suppressions inside `ref.py`** — and every caller passing an artefact wrote an expression that could not typecheck anywhere.

The two forms were **identical at runtime** (verified: `Ref(cl) == Ref.to(cl)`, same URN, same resolved object), so the artefact form bought nothing except a shape the checkers reject.

## After

| Form | |
| --- | --- |
| `Ref(urn)` | URN only. Typed. |
| `Ref.to(obj)` | Artefact. Typed. Does the derivation itself. |
| `Ref.of(urn, obj)` / `Ref.unresolved(urn)` | unchanged |

`Ref(obj)` is now **refused**, not silently accepted, and the error names the replacement:

```
TypeError: Ref expects a SdmxUrn, got Codelist. Use Ref.to(codelist) instead.
```

Child items keep their own message, since passing a `Dimension` was never valid and is a different mistake.

**`ref.py` now has zero suppressions**, down from three.

## The library was recommending the untypeable form

Not merely permitting it. `polars.py` raised a `ValueError` whose text told the user to write the expression that fails type checking:

```
"...Construct the Dataset with dataflow=Ref[Dataflow](flow) and retry."
```

`ref.py`'s module docstring (`allows Ref(cl_freq) instead of ...`) and the class docstring's Construction block did the same. All three now say `.to`.

## Rejected alternative, and why — worth not re-deriving

The obvious fix is an attrs `field(converter=...)`, exactly the pattern `maintainer: Agency = field(converter=_to_agency)` already uses in this codebase. **It cannot work here.** Prototyped, and basedpyright says:

```
error: Type "SdmxUrn[MaintainableArtefact]" is not assignable to return type "SdmxUrn[T@_to_urn]"
```

Narrowing `SdmxUrn[T] | MaintainableArtefact` with `isinstance` lands on the *union member*, so `T` is lost and `SdmxUrn.make(type(v))` yields `SdmxUrn[MaintainableArtefact]`. In `Ref.to` the parameter is declared `T`, so narrowing gives `T & MaintainableArtefact` and `T` survives. That asymmetry is precisely why the classmethod works and the converter cannot.

A converter also cannot set `_resolved`, so it would not have preserved the interning half of the behaviour anyway.

## Migration

**38 call sites across 9 test files.** `Ref(<artefact>)` now appears nowhere in `src/`, `tests/` or `docs/` — except inside the docstring of the test that pins its removal.

## Two tests were coupled to the message text

`test_ref_construct_with_non_urn_raises_type_error` and its sibling asserted `match="MaintainableArtefact"`, which the new message no longer contains. They were checking the right *behaviour* through an unstable *string* — the over-detection pattern #214 is about — so they now match on `expects a SdmxUrn`. This is the second time this session a correct improvement collided with an error-text assertion; #214 has the evidence.

## Verification

- `just ci` green — **2513** unit (up 2), 72 docs, basedpyright 0, pyrefly 0.
- New tests pin both halves: that `Ref(artefact)` is refused with a message naming `Ref.to`, and that `Ref.to` still derives the URN and interns the object.
- **Non-vacuous by mutation**: restoring the permissive post-init makes the guard fail. A test asserting a `TypeError` that the old code also raised would have been worthless here, so this needed checking rather than assuming.
