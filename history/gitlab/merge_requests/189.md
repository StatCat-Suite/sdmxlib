Part 2 of #200 — the leaky `-> Any` returns. **#200 stays open** for part 1 (known-shape `dict[str, Any]` → TypedDict), which is a separate sweep and carries its own "re-scope #176 first" caveat.

## The reader helpers were a duplicate of a better one

`_resolve_ref_text` existed twice — byte-identical in ml30 and ml31 — returning `Any`, taking no type witness, and skipping the `isinstance` guard. Meanwhile `_common.resolve_ref`'s **"Style 2: direct URN text content"** branch is the same lookup, done properly.

So this doesn't annotate the duplicates. It deletes them, adds a None-tolerant `resolve_ref_text[T]` to `_common.make_reader_helpers` that delegates to `resolve_ref`, and binds it in both readers alongside their other shared helpers. The None-tolerance is the only thing the private copies had that `resolve_ref` lacks — callers pass a bare `el.find(...)` — so that is the only new code.

The 18 call sites now pass a witness:

| Endpoint | Witness |
| --- | --- |
| `SourceCodelist` / `TargetCodelist` | `Codelist` |
| `linked_hierarchy` | `Hierarchy` |
| scheme-map `Source` / `Target`, `linked_object`, `context_object` | `object` |

`object` is the documented spelling for genuinely heterogeneous refs — `resolve_ref`'s own docstring and `docs/design/phantom-generics.md` say so, and existing call sites already use it.

**`Any` is now absent from both reader modules entirely** — the `from typing import Any` import went with it.

## This is a behaviour fix, not only a typing one

The missing guard meant a URN naming a **wrong-typed artefact** produced a Ref claiming type `T` while actually holding something else. `<str:SourceCodelist>` pointing at a ConceptScheme URN gave you a "resolved" `Ref[Codelist]` holding a ConceptScheme. It now falls through to *unresolved*, matching `resolve_ref`.

Two tests, both directions. The negative one is verified **non-vacuous** — against the same index, the same URN resolves under an `object` witness and does not under `Codelist`:

```
witness=object   -> resolved: True
witness=Codelist -> resolved: False
```

Without that check the test would have passed even against the old unguarded code, since an absent index entry also yields an unresolved Ref.

Delegation is behaviour-preserving otherwise: `resolve_ref`'s Style 2 uses `isinstance(obj, cls)` where the old code used `obj is not None`, and with `cls=object` those differ only when `obj is None` — where `Ref.of(urn, None)` and `Ref.unresolved(urn)` are indistinguishable, because `resolved` is `_resolved is not None`.

## Caches

`_FIFOCache` and `_CallScopedMemo` were `dict[str, Any]`. They hold heterogeneous artefacts that every consumer narrows, so they are now `dict[str, object]` — including the `get` overrides the issue flagged as inherited-signature pressure. No generic was needed. One consumer had already annotated its receiving local `object | None` (`local/registry.py:1015`), which is the type the base class should have carried all along.

## The sixth site the census counted but never listed

#200's table says **6** `-> Any` returns; the body enumerates 5. The missing one is `readers.get_artefact -> Any | None`.

I did **not** change it. It is a dynamic dispatch over the stored artefact-type string with **66 call sites** (14 in `src/`, 52 in tests), it sits in the ANN401-exempt shell, and the typed seam already exists above it (`Registry.get[T]`). Narrowing it to `object | None` would mean adding a narrowing step at every one of those call sites — a redesign of the storage read seam, not a leak fix. Verdict is document-and-keep, so it belongs to #204; I'll add it there.
