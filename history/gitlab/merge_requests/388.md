## Three design points

**The names come from a setup, not the page.** 300 blocks across 23 pages, and only **6** are self-contained — the rest use `reg`, `cl`, `ds`, `q` without defining them, which is how the pages read. A fenced `import` block existing only to satisfy a test would be noise for the reader, and hiding one would be worse, so `tests/docs/pages/` supplies the vocabulary.

**The HTTP is patched at the client.** Every provider-facing page opens `with sl.RestRegistry(sl.Provider.ECB) as reg:` as its *first line*, so a `reg` in the namespace is shadowed and the block goes to the network anyway. Patching `SdmxClient` leaves the page exactly as written.

Deliberately **not cassettes**: one would tie a page to a recorded response, so editing an example to fetch a different codelist would fail as a cassette miss rather than a wrong answer — and re-recording needs a network the gate does not have.

`answer_to_any_name` re-stamps the fixture with whatever identity was asked for. The pages name real artefacts (`BIS:WS_CBPOL`, `ESTAT:NAMAIN_10_GDP`) and the identity is not what they demonstrate; the shape is. Without it every page needs a fixture differing in two strings, or the examples get rewritten to fetch `AG:DSD_X`, which no reader wants to see.

## Two directives, invisible in the rendered page

```markdown
<!-- test: skip -->      a fragment, or an illustration in another library
<!-- test: raises -->    a block whose point is the error it produces
```

Four of each. The skip count is budgeted for the same reason as the page count: a skip is the easy fix for a failing block, and would quietly stop running the documentation this exists to run.
