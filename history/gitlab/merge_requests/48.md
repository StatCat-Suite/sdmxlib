## Summary
6 files, +734/−1126 (net −392 lines).

\`src/sdmxlib/formats/sdmx_ml/_common.py\` hosts the namespace-bound reader and writer helpers that were previously duplicated byte-for-byte between SDMX-ML 2.1 and 3.0. Each version's reader/writer calls a factory once at import time and rebinds the closures under their existing private names, so all downstream call sites inside each version's module work unchanged.

### What moved into common
**Reader helpers** (closures over the namespace triple): \`_c\`, \`_s\`, \`_m\`, \`_read_istring\`, \`_read_annotations\`, \`_read_datetime_attr\`, \`_resolve_agency\`, \`_ref_el_to_urn\`, \`_resolve_ref\`, \`_index_artefact\`, \`_index_item\`, \`_read_text_format\`, \`_read_representation\`.
**Higher-level readers** (byte-identical): \`_read_codelists\`, \`_read_dataflows\`, \`_read_categories\`, \`_read_category_schemes\`, \`_read_categorisations\`, \`_read_provision_agreements\`, \`_read_reference_period\`, \`_read_release_calendar\`.
**Writer helpers**: \`_c\`, \`_s\`, \`_m\`, \`_write_istring\`, \`_write_maintainable_attrs\`, \`_urn_to_ref_el\`, \`_write_ref\`, \`_write_text_format\`, \`_write_representation\`, \`_write_concept_identity\`.

### Behaviour notes
The 3.0 superset is used everywhere (e.g. \`_resolve_ref\` handles the URN-text fallback that only 3.0 producers emit; 2.1 messages still parse correctly because the extra branches don't trigger).

### Out of scope
Near-duplicates that still have substantive version differences — \`_read_concept_schemes\` (62-line diff), \`_read_constraints\` (22-line diff), \`_read_hierarchical_code\` (60-line diff because 3.1 adds Level support) — stay version-local. Same for the high-level writers (\`_write_codelist\` etc.) which are also byte-identical and would yield ~100 more lines. Those are candidates for a follow-up MR if we want to push further.
