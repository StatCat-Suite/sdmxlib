# Merge request !240: fix(sdmx-ml 2.1): read MetadataStructures instead of discarding them

| | |
| --- | --- |
| State | merged |
| Opened | 2026-08-07 |
| Merged | 2026-08-07 |

**Closes #236.** A schema-valid 2.1 document containing `<str:MetadataStructures>` parsed "successfully" and yielded **zero** metadata structures — id, name and attribute tree gone, no exception, no warning. The 2.1 reader had no handling for the section at all; it was never written rather than deliberately skipped.

That was the only unread 2.1 section whose artefact sdmxlib models. The other eight are types with no model counterpart (Process, Ruleset, Transformation, …), where ignoring the section is defensible because there is nowhere to put the result — which is what made this a bug rather than a scope boundary.

## What reading recovers, and what it does not

2.1 groups attributes into `ReportStructure`s naming the `MetadataTarget`s they describe. SDMX 3.0 deleted that layer and this model follows 3.0, so the attributes of every report structure are concatenated in document order, with nesting, cardinality and ConceptIdentity preserved.

The targets and the grouping are **not** represented, so writing back to 2.1 still refuses rather than inventing them (#235). That is the intended end state under #237's rule: an explicit refusal naming what cannot be represented, where the previous behaviour was a silent drop of the whole artefact.

## A third outcome in the fidelity harness

`test_document_fidelity` now distinguishes three results rather than two:

| outcome | meaning |
|---|---|
| lossless | `D → model → D` returns `D` |
| **declared refusal** | writing back raises, naming what is missing — asserted with `pytest.raises` |
| known-lossy | recorded in the burn-down with its tracking issue |

All three are *asserted*, not tolerated: a document that starts round-tripping forces its entry out, and one that starts silently losing fails.

## A second defect found on the way

The new fixture initially omitted `package` on its `<Ref>` elements. Every attribute came back with no ConceptIdentity, and the write boundary then refused for a reason unrelated to the real defect.

`ref_el_to_urn` requires `package` and returns `None` without it — but the schema declares it **optional on 81 of the 2.1 ref types**, and `fixed` on the typed ones, which is XSD's way of saying "you may omit this". A producer relying on that emits valid SDMX-ML and sdmxlib silently loses the reference. Filed as **#240**; the fixture now carries `package`, matching what real producers emit.

## Controls

Five mutations verified to fail: ignore the section, read only the first ReportStructure, drop nested attributes, drop the ConceptIdentity, remove the 2.1 write refusal.
