Closes #332. Unblocks #329's deletion of `query`/`query_stream`.

## What

A binding with `series_attributes_location` set was refused by
`observations()`. It is now a **root join** — a `LEFT JOIN … USING (keys)`
that every query over that dataflow gets, reached through
`AnyCols.__joins__` rather than through a path, because there is no
relation for a caller to name.

## Why it is a plan change and not a spelling one

An SDMX attribute attached at series level is constant across every
observation of that series. The attachment level is declared by the DSD
and is the same wherever the value sits; whether there is a sidecar is a
producer's layout choice. So `obs["GEO_NAME"]` reads the same either
way, and the query language never surfaces the split.

## Two load-bearing details

- `USING` merges only the **join keys**. A non-key sidecar column read
  through the root alias is a binder error rather than a wrong answer —
  which is why `_table_of` exists and why a column carries the table it
  lives on.
- A join **key** is correct through the root alias, since `USING` has
  already merged the two sides. Reading it through the sidecar would be
  noise.

The join keys are derived by `SchemaInspector.plan` from the two tables,
not declared on the binding — a declared key that drifted from the
schema would plan a join that silently dropped rows.

## Tests

`tests/unit/test_query_observations.py` gains a sidecar fixture: the
join is emitted, the sidecar column is aliased to the join's alias, a
key reads through the root, filtering crosses the join, group-by still
works, and a binding *without* a sidecar plans no join at all. The old
test asserting the refusal is gone with the refusal.

`test_empty_attribute_filter_returns_no_rows` now runs through
`observations().filter_components(...)` rather than `store.query` — the
last acceptance criterion #329 was waiting on.
