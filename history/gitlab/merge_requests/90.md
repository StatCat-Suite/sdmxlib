## Summary

Both \`hierarchy_query\` and \`code_query\` DSLs now support indexing into the annotation's localised text payload with a language tag — mirrors the existing \`node.name[lang]\` / \`code.name[lang]\` accessor shape:

\`\`\`python
# title (plain string) — as before, backwards-compat
code.annotations[\"geo_level\"] == \"City\"
node.annotations[\"geo_level\"] == \"Province\"

# text (InternationalString) — new
code.annotations[\"geo_level\",\"en\"] == \"Province\"
node.annotations[\"geo_level\",\"fr\"].contains(\"ille\")
\`\`\`

## Why

The title field was the only thing the existing predicate saw. Real SDMX payloads put their meaningful annotation values in \`text={\"en\": \"...\"}\` per convention. Filtering by them used to silently return empty — surfaced in the milestone-6 audit.

## Implementation

- New \`_AnnotationTextField(type, lang)\` FieldExpr in **both** modules (the same gap existed in both per the #127 audit note).
- \`_AnnotationRef\` gains \`__getitem__(lang)\` returning a new \`_AnnotationTextRef\`. Backwards-compat: the existing \`_AnnotationRef._field\` still returns the title-field, so all existing \`annotations[type] == ...\` predicates keep working.
- New \`_ensure_annotation_text_join()\` helper joins \`sdmx.annotation_text\` on \`(annotation_id, lang)\`. Shares the annotation-table join with title-based predicates when both target the same type — only one ann-table JOIN per type, plus one text-table JOIN per (type, lang).
- \`_emit_eq\` and \`_emit_string_match\` handle \`_AnnotationTextField\` by emitting \`<text_alias>.text {op} ?\`.
