First slice of #223. The matrix had **20 artefact classes with serialisers and 2 with generative, schema-validated coverage**. This adds DataStructure — the centre of the model and the most structurally constrained artefact — and Dataflow.

## Extending the oracle to one new type found six real bugs

All silent: every writer emits the document, and `validate()` accepts the artefact. Filed as **#224**.

| | Finding | Rejected by |
| --- | --- | --- |
| 1 | **`ConceptIdentity` is required and no writer supplies it** | all four formats |
| 2 | `DataType` has four members in no schema enumeration — `Attachment`, `ReportingHour`, `URL`, `Year` | all |
| 3 | `XHTML` valid in 3.0/3.1, invalid at 2.1 component level | 2.1 only |
| 4 | Facet numeric bounds use `str()`, emitting exponent notation `xs:decimal` rejects | all SDMX-ML |
| 5 | `decimals`/`maxLength`/`minLength` are `xs:positiveInteger`; `0` is emitted | all SDMX-ML |
| 6 | `isMultiLingual` not allowed on a 2.1 component `TextFormat` | 2.1 only |
| 7 | 2.1 fixes the primary measure id to `OBS_VALUE`; a 3.0 DSD with any other cannot downgrade | 2.1 only |

**#1 is the consequential one.** This is unserialisable in every format:

```python
DataStructure(id="DSD", maintainer="AG", version="1.0", name=...,
              dimensions=[Dimension(id="FREQ")], measures=[Measure(id="OBS_VALUE")])
```

`concept` defaults to `None`, nothing requires it, and the element is simply omitted. A DSD assembled in code without concepts looks fine and cannot be given to any consumer.

**#3 and #7 are version-downgrade hazards** — perfectly valid SDMX 3.0 that cannot be expressed as 2.1, with no signal at write time.

## Attribution discipline

Every one was **confirmed by hand against the vendored XSDs** before being called a library bug rather than a strategy bug. That mattered: the same investigation turned up a genuine *strategy* bug — component ids must be unique **across** dimensions, measures and attributes, not merely within each list, because the XSD enforces a DSD-wide unique-component identity constraint. Three of the initial failures were mine, four were the library's, and telling them apart was most of the work.

## The strategies generate the conformant subset

So these properties can land while #224 is open. Every restriction carries a comment naming the reason and pointing at the issue:

```python
# Rounded to 4dp: the XSD types these xs:decimal, which forbids exponent
# notation, and Python's str() switches to it below ~1e-4 … (#224)
```

Those comments are the regression handle. When #224 is fixed, the restrictions relax and the properties then cover exactly what is broken today. That is deliberate — narrowing a generator to make a suite green is how a property test quietly stops testing anything, so each narrowing is recorded rather than absorbed.
