## Library issues found along the way (not fixed here)

1. `sl.LocalRegistry(conn)` silently ignores a DuckDB connection and opens a file named after its repr.
2. A `TimeDimension` without a concept passes construction, and is then written to SDMX-ML without the `ConceptIdentity` the XSD requires.
3. `to_json` writes a DSD that its own reader refuses: a time dimension with no representation has no `localRepresentation`.
4. Two things that `add` accepts are refused by every writer: a sentinel on an `enumeration_format`, and `Attribute.attachment=None`. That contradicts #419.
5. `write_sdmx_json_data(lang="en")` has a default language.
6. `ObsQuery.ids()`/`urns()` fail inside DuckDB rather than being refused, and other errors tell users to call `.ids()`.
7. The data plane's REST bounding isn't enforced: `_fetch_data_for` drops the leftover predicates without calling `is_bounded`.
8. `PushdownError`, `SliceError`, `CrossSourceError`, `PathError` and `SdmxConformanceError` aren't exported from `sl`, although the docs name them.
9. Several clean refusals are missing; each of these fails with a raw DuckDB or `PathError` message instead:
   - a column compared with a column;
   - `qualify(Pred)`;
   - a parent-rooted predicate inside `.any()`;
   - an aggregate `where=` rooted at another relation;
   - a window inside `group_by().agg()`.
   Also, `filter(WinPred)`'s message doesn't name `qualify`.
10. `AncestorMap.ancestors()` returns a private type.
11. `reg.data()`/`DataQuery` are still public, despite `registry-and-catalog.md`'s "no eager query" decision.
