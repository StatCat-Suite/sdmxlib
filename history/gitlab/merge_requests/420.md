Three more groups off #355 — and again the split is two real bugs plus a limit
that had been sitting in the bug column.

## `dimension_constraint` was unwritable everywhere, including by 3.1

`DataflowBaseType` extends `StructureUsageType` with `<DimensionConstraint>` in
SDMX-ML **3.1 only**. It carries the dimensions a flow commits to, so a DSD that
grows one in a minor version does not silently widen the flow's key — a real
feature, and the 3.1 writer never mentioned it.

Now emitted after `Structure` (where `DataflowType` sequences it) and read in
the shared reader: 2.1 and 3.0 documents have no such element, so that needs no
version branch.

Declared a limit for 2.1, 3.0 and SDMX-JSON, which genuinely lack it. The model
docstring had said so since the field was added — nothing had put it in
`gaps.py`, so it read as a defect on four formats instead of a fact about one.

`KNOWN_LOSSES["3.1"]` now **subtracts** it from 3.0's set. 3.1 is not simply
3.0-with-more-gaps, and deriving one from the other without saying so would have
hidden that.

## A Level's `uri` was dropped by the JSON writer

`LevelJson` has carried a `links` field all along and its builder never filled
it — the one artefact whose constructor forgot the call every other one makes.
`IdentifiableType` permits links in both 2.0 and 2.1, and the output still
validates against both.

## MSD `targets` / `report_structures` are 2.1 constructs

They appear in **no** 3.0 or 3.1 schema. SDMX 3.0 replaced the target/report
layer with a flat `MetadataAttributeList` — the same simplification that dropped
`MetadataReport` from the message side. Declared for 3.0, 3.1 and SDMX-JSON
rather than carried as a defect.
