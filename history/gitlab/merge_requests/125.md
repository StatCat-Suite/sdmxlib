## Summary

Closes a class of **silent serializer round-trip data loss** — model
fields that one side of a reader/writer pair handled while the other
dropped them. Surfaced from #157 (SDMX-JSON dropping annotations),
audited across every serializer pair, and fixed. Three commits, one per
issue, each independently tested.

## Commits

- **#157 — `fix(sdmx-json): emit annotations on all artefacts and items`**
  The SDMX-JSON structure writer never emitted an `annotations` array on
  any artefact (bundle-baked `DEFAULT` / `LASTNOBSERVATIONS` caps on a
  Dataflow were silently dropped). Adds a shared `emit_annotations`
  helper emitting the 2.0 shape (`id`/`title`/`type`, `text`+`texts`,
  url as a `links` `rel:"self"`), wired into every maintainable and
  item/component writer; makes the reader schema-conformant to match.

- **#158 — `fix(sdmx-ml): emit annotations on items and components`**
  The SDMX-ML 2.1/3.0 writers emitted `<com:Annotations>` on
  maintainables but dropped them on codes, concepts, categories,
  dimensions, attributes, measures, hierarchical codes, levels, and
  metadata attributes — the readers parse all of these, so annotations
  on a component were lost on round-trip. Emits them (first child, per
  XSD ordering) from every item/component writer.

- **#159 — `fix(serializers): close asymmetric round-trip field drops`**
  From the full audit:
  - SDMX-JSON: emit `isFinal` on all maintainables (reader parsed it,
    writer never did).
  - SDMX-JSON: preserve RepresentationMap regex/index value-map
    discriminators (was collapsing every mapping to literal equality).
  - SDMX-JSON + SDMX-ML 3.0 metadata: parse `MetadataSet`
    validFrom/validTo (writer emitted, reader dropped).
  - SDMX-ML 2.1: emit `MeasureDimension` (reader parsed, writer omitted).
  - SDMX-ML 2.1/3.0: emit Agency/DataProvider item annotations.
  - DuckDB storage: read back `valid_from`/`valid_to` on all
    maintainables (persisted but only HierarchyAssociation
    reconstructed them); expose them on the Lazy facades too.

## Scope note

Symmetric gaps (fields **neither** side handles — e.g. storage attribute
relationships, `concept_role` in JSON, various validity bounds) are
tracked as follow-ups in #159, not fixed here. #159 also recommends a
generic per-format "every field survives round-trip" property test as
the durable guard.
