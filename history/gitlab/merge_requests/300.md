Closes #305 — **by correcting it**. The issue as I filed it was wrong, and the way it was wrong found something worse.

## The report was wrong

#305 said a DSD holding a `MeasureDimension` "cannot be serialised at all — AttributeError, every version". The reproduction put the component in `dimensions`, which is typed `ItemList[Dimension]`. There is a dedicated `measure_dimension` slot, and used properly the component wrote **valid 2.1 and round-tripped the whole time**:

```
correct slot, 2.1  ->  XSD VALID, round-trip measure_dimension=M1
```

That is asserted first in the new test file, so nobody has to re-derive it.

## Two real defects were behind it

### 1. The misuse crashed instead of explaining

`MeasureDimension` is deliberately not a `Component`: its representation is a ConceptScheme, and 2.1's `MeasureDimensionRepresentationType` is a restriction permitting only `<Enumeration>` — no `EnumerationFormat`, no `TextFormat`. So the field genuinely has no meaning on it, which is why the walkers now use `getattr(..., None)` rather than the class growing one.

Misplacing it used to surface as `AttributeError: 'MeasureDimension' object has no attribute 'enumeration_format'` from deep in validation, naming a field the caller never touched. Now it is a `ValidationIssue` naming the slot to use, in **every** version — the check sits before the 2.1 early return, because below it a 2.1 write skipped validation and crashed in the writer instead. That is precisely what the issue hit.

### 2. The 3.x and JSON writers dropped it silently

The serious one, and invisible from the crash. SDMX 3.0 removed the cross-sectional measure dimension; the 3.0 and 3.1 schemas contain **no** `MeasureDimension` element. The writers responded by emitting nothing:

```
serialize(msg, version="3.0")  ->  valid document, component gone
parse(that)                    ->  measure_dimension is None
```

Valid output, one component short, no error anywhere. That is the exact failure class %11 existed to remove, found after it closed. It now refuses, the way other downgrade hazards do.

## Two false starts, recorded because they cost time

- An `isinstance(d, Dimension)` check for the misplacement flagged **74 tests**: `TimeDimension` is *also* not a `Dimension` subclass and *does* legitimately sit in `dimensions`. Narrowed to `MeasureDimension`.
- That same run masked a missing import — an unbound `MeasureDimension` name fails identically on every DSD, so the failure count did not move and looked like the narrowing had not worked.

## Verified

Removing the rule fails **9 of the 12** new tests. One of them writes with `validate=False` and asserts the old silent drop still reproduces, so the refusal is anchored to a real behaviour rather than asserted against nothing.
