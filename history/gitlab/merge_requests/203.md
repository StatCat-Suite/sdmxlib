Spotted while reading the SDMX-ML writer. Two table-driven dispatch tables typed their writer slot as bare `Any`:

```python
sdmx_ml21/writer.py   _SECTIONS: list[tuple[str, list[tuple[str, Any]]]]
sdmx_json/writer.py   _SECTIONS: list[tuple[str, str, Any]]
```

## Why nothing flagged them

`ANN401` covers **parameters**. These are module-level variable annotations, so the sweep that took `src/` to zero `Any` parameters (#202 / #203 / #204) never looked at them. Container-level `Any` belongs to **#200 part 1**, which is still open — these are just the two noticed in passing.

## The narrowing

```python
list[tuple[str, list[tuple[str, Callable[[etree._Element, Any], None]]]]]
list[tuple[str, str, Callable[[Any], WireStruct]]]
```

The residual `Any` is **genuine**: both tables are heterogeneous in their *item* type — each writer takes a different artefact (`AgencyScheme`, `Codelist`, `Dataflow`, …), which no single type parameter expresses. But everything that *is* fixed now gets checked: arity, the parent-element parameter, and on the JSON side the `WireStruct` return.

## Verified it bites

A narrowing that only annotates is worth little, so I checked with a control — replacing one entry's converter with a string:

```
error: Type "Literal['not-a-callable']" is not assignable to type "(Any) -> WireStruct"
```

Under bare `Any` that would have passed the checkers and surfaced as a runtime `TypeError` inside `write()`.
