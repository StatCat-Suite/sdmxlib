Closes #299.

## What was wrong

The guard for this already existed — `test_every_type_in_a_public_signature_is_importable_from_sdmxlib`, added in #265. It reads signatures off a hand-written list of **four** classes (`Query`, `Frame`, `Grouped`, `Page`), out of the ~150 names `__all__` carries.

Its docstring claims to be "derived rather than hand-listed". That is true of the *types inside* a signature. The *classes whose signatures get read* were the list nobody revisited.

`DataStructure`, `Session`, `LazyHierarchy`, `InMemoryRegistry`, `DuckDBDataStore` and `RestRegistry` were never looked at. Between them they named **twelve** types a caller could not import.

## The fix

Derive the class list from `__all__`. The twelve split three ways:

| Category | Names | Resolution |
| --- | --- | --- |
| Genuinely unexported | `ReportedAttributeRow`, `ObsRow`, `AncestorMap`, `ApiVersion`, `ComponentRole`, `ObsQuery`, `SupportsUrn`, `ValueSet`, `RowKind` | exported |
| Exported under another name | `PathQuery`, `QueryCols`, `ArtefactQueryRow`, `QueryRowKind` | aliases dropped |
| Defined nowhere importable | `WriteSource` | made public in `data_store.py` |

The aliases collided with nothing in either registry module — they only made the rendered signature name a spelling that does not exist. `WriteSource` appears in a `Protocol` method, so anyone implementing `DataStore` out-of-tree has to name it; it existed only under `TYPE_CHECKING` in two modules, spelled identically in both and importable from neither. It is now runtime (duckdb/polars/pyarrow are baseline deps; the comment calling pyarrow optional had been wrong for a while).

## Two decisions, not bookkeeping

**`Win` / `WinFn`.** `test_the_expression_types_stay_private` forbade exporting these as compiler detail, while they are the return types of `.rank()` and `.over()`. The window chain is typed by stage — `Col` → `WinFn` → `Win` → `WinPred` — and the first and last were exported and the middles were not. That was not a principle. All four are vocabulary now, so a caller can annotate a variable or write a helper that holds a mid-chain value. Polars settles nothing here: every stage there is `Expr`, so it has no intermediates to publish.

**`Agg.desc`** moved down from `AnyAgg` instead of overriding it, so the key names the row kind. `Descending` is `@frozen` over one read-only field, so covariance would be sound — but attrs declares `key: K` as a plain mutable attribute and PEP 695 therefore infers `K` invariant, making the narrowing an incompatible override. Moving the declaration down is what `Col.desc` already does.

## The guard gains two things

- **PEP 695 bounds are scanned.** `def query[R: RowKind](self, root: Cols[R])` renders as `(self, root: Cols[R])` — the bound is invisible to `inspect.signature`, while being exactly the name a caller writing their own `def helper[R: RowKind]` needs. That is how `RowKind` was found.
- **`foreign` maps each allowed name to its owning module, checked at test time.** A flat set of bare names cannot tell "polars owns `DataFrame`" from "one of ours happens to be called `DataFrame`", so a real export regression could hide behind an allow-list entry meant for someone else. Stale entries now fail.

## Verification

Each export was planted back out individually and the guard confirmed to fail — including the pre-existing `DataStructure`, to check the widened walk really reaches the classes it now claims. `foreign`'s module check was verified the same way. `just ci` green.
