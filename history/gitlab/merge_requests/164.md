Replaces the per-call `ResolveCodelist` callback (from the concept/category read slice) with a **shared `resolve_urn`** both the reader and ingest import directly.

## What & why
`_resolve_urn` was already a pure function over `(urn, index, cls)` with no reader state, so it factors out with no import cycle *and* no callback. Moved to a new `_resolve.py`; the reader imports it as `_resolve_urn` (its ~15 dict-path call sites unchanged), and the ingest `from_*` functions take `index` and call `resolve_urn(urn, index, cls)` directly.

The callback bound a single target type (`Codelist`). As more read families migrate they resolve to **different** targets (Concept from `conceptIdentity`, DataStructure from a dataflow's `structure`, …), which would force either a proliferation of typed callbacks or a generic callback that's just `resolve_urn` with `index` pre-bound. One shared generic `resolve_urn` handles them all via `cls` — simpler now and as the DSD/dataflow etc. slices land.

Drops the `ResolveCodelist` type + the lambda in `_read_concept_schemes`. Behaviour identical: roundtrip + conformity green; `just check` clean; **2426 tests pass**.

Part of #181. (Prompted by review of the callback choice — the shared module is the cleaner, better-scaling design.)
