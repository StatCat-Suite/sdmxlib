A reference is written as its URN's package and class, unchecked. BIS categorises Fusion Metadata Registry artefacts SDMX does not define: 135 `publicationtable.PublicationTable` and 74 `pdq.PreDefinedQuery`. The reader keeps them faithfully, as it should, but writing them produced 209 categorisations that every format rejected.

## Fix

`check_serialisable` refuses such a reference, per target, naming it. It is refused rather than dropped: there is no valid form to write, and dropping the reference would change what the artefact says.

The tables in `model/_referenceable.py` are the schemas' own:

| target | source |
|---|---|
| 2.1 | `ObjectTypeCodelistType` (`Ref@class`) and `PackageTypeCodelistType` (`Ref@package`), checked separately as the schema checks them |
| 3.0 / 3.1 | `UrnClassesPart`, 69 `package.Class` pairs, identical in both |
| SDMX-JSON | the `urn` pattern, as both 2.0 and 2.1 allow it (the output is validated against either) |

`tests/support/referenceable.py` reads them out of the vendored schemas, and a test requires equality. A 2.1 container's members (StructureSet maps, HierarchicalCodelist hierarchies) are nested on the wire rather than written as refs, so they are not checked.

## On real data

Every source × target pair of BIS's cached categorisations: **exactly the 209 refused** (135 + 74), and the 13 dataflow categorisations written.

## The Any ratchet (decided: teach the counter)

SDMX defines a class named `Any` (`base.Any`). The tables name it three times, and `tools/count_any.py`'s text scan counted those as `typing.Any` (37 → 40).

- **The exclusion.** The counter now skips `"Any"` as an *element of a tuple, list, set or dict literal*, where it is data and never a type.
- **It fails closed.** A quoted `"Any"` annotation, `cast("Any", …)` and a `TypeAlias` still count.
- **Tested both ways.** The baseline stays 37.
