## Conformance bugs fixed

### 1. Section ordering in \`_SECTIONS\` was wrong
The v2.1 \`StructuresType\` has a strict child sequence (per \`SDMXStructure.xsd\`):
\`\`\`
OrganisationSchemes → Dataflows → Metadataflows → CategorySchemes
→ Categorisations → Codelists → HierarchicalCodelists → Concepts
→ MetadataStructures → DataStructures → StructureSets → ... → Constraints
→ ProvisionAgreements → ...
\`\`\`
The writer was emitting Codelists / Concepts / DataStructures **before** Dataflows / CategorySchemes / Categorisations, which the schema rejects. \`_SECTIONS\` reordered.

### 2. \`_urn_to_ref_el\` emitted both \`version\` and \`maintainableParentVersion\` on item Refs
Per \`SDMXCommonReferences.xsd\`, item Refs (Concept, Code, etc.) carry \`maintainableParentID\` + \`maintainableParentVersion\` only — no \`version\` attribute. The helper was setting both. Split the maintainable vs. item branches cleanly.
