Part of #462.

**The cost: a quadratic lookup.** The SDMX-JSON writer and validation call `wildcard_misfits` for every codelist in a message, each time passing all of the message's codelists. It built a URN index of all of them before looking at the codelist's extensions. So a write was quadratic in the codelist count: BIS's 105 codelists formatted about 11,000 URNs per write, and 1,000 codelists would format a million. The default `serialize(..., validate=True)` paid it twice.

**The change.** The index is built only for a codelist that has a wildcarded member. None of BIS's has one.

**Measured against `main`** (three alternating runs each, BIS codelists):

| write | main | this MR |
| --- | --- | --- |
| to JSON | 14.4 ms | 6.2 ms (**−57%**) |
| to JSON, validated (the default) | 32.6 ms | 16.0 ms (**−51%**) |
| to 2.1 / 3.0 XML | unchanged (they don't call it) | |

For reference, this write took 4.3 ms before milestone 20, and pysdmx takes 5 ms.

**Guard** (`tests/unit/test_write_cost.py`): it counts URNs formatted while writing 10, 20 and 30 codelists, with validation on and off, and asserts the two steps are equal. A linear cost gives exactly that; a quadratic one can't. It was watched to fail against the change reverted, and it has a check that a per-codelist index is seen.

**Still open in #462:** the remaining per-code write cost (links and annotations). It needs measuring at scale first.
