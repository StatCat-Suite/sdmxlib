One query language over the SDMX information model, replacing the four
hand-written SQL DSLs. Paths are typed expressions over a **declared edge
graph**; cardinality is derived from key constraints rather than enumerated,
which is the shape this milestone kept re-learning.

## Why

The %15 consumer survey found **113 hand-written SQL sites** across six
applications — they exist because the DSLs could not express what callers
need. The worst shape, "every dataflow × dimension × codelist as one frame"
(21 sites), cost **265 ms by resolution against 1 ms as one statement**, and
`FrameQuery[R]` was parameterised on a single `RowKind` so it could not be
written at all. It is now one `select()`.

- `sdmxlib/query/` — 10 modules: the edge graph, the planner, the compiler,
  the expression layer, `Query[R]` / `Frame` / `Grouped` / `Page`, the raw-SQL

- **33 accessor roots, 72 edges.** Every relation in the storage schema is

- **Five DSL modules deleted** — `code_query`, `hierarchy_query`,

## Things worth a reviewer's attention

**Trimming.** A hop whose terminal column is the key it was reached by is
rewritten to the local column, so `q.code.parent.id` and a `parent_id` column
produce the *same object* — planner, compiler, `canonical_key` and `explain`
cannot tell them apart. That is why there is no `parent_id` accessor: the
`parent_id`/`parent.id` pair was a footgun one bad autocomplete away, and the
fix was to delete one spelling rather than document the difference.

**No recursion anywhere.** Ancestry is a stored fact — the writer bakes
`ancestor_ids` / `depth` — so `ancestors` / `descendants` are array containment,
not recursive CTEs. The four tree names are two edges read both ways.

**Fan-outs never join.** A to-many hop compiles to a correlated `EXISTS`, so no
path can multiply rows; `list()` collects instead, and several columns in one
`list()` produce structs because two separate collections over one fan-out
align only by accident.

**The escape hatch is a terminal.** `reg.sql()` does not splice back into the
DSL — raw text carries no row kind to check against the column it would land
beside, and one splice would pin a whole query to DuckDB.

## Breaking

- `sl.code` / `sl.node` / `sl.artefact` → `sl.q`.
- `sdmxlib.sql` no longer publishes `Predicate`, `CompileContext`, `RowKind`
  or `ColumnSql`. A downstream library can no longer inject a *predicate*;
  it can still inject a `SqlRelation`, which is the composition that had
  consumers and which works because a subquery carries no row kind to
  disagree about.
- `Query[T].filter(lambda)` on the REST side is gone — it ran *after* the
  fetch, so `.limit(5).fetch()` read as a bounded request and was a full
  catalogue download trimmed in Python.
- `with_annotations` is gone; `collect()` hydrates whole artefacts in one
  batch.
- A localised column projects with its language — `name["en"]` is `name_en`,
  because `select(name["en"], name["fr"])` previously produced two columns
  both called `name` and one silently won.

## Testing

The two pure-Python oracles **predate** the compiler they now check and share
no code with it, so the migration deleted the old DSLs without deleting the
covered thing and re-deriving its coverage afterwards.

- `just ci` — 0 ruff / 0 basedpyright / 0 pyrefly, `Any` baseline 50→48,
  4,878 unit + 134 docs + 56 integration.
- `just test-properties` — 360 at 20× width.

Three defects fell out of the final retirement that no existing test would
have caught: the `name` column collision above; a grouped frame carrying the
row relation's *default* order into its `GROUP BY`; and `Str.is_in` checking
member types before its four specific refusals, replacing each with "not
iterable".
