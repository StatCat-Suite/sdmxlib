This is #518, option 1 as decided: **a measure the DSD leaves untyped is inferred, not forced to `VARCHAR`.**

**`column_types`:**
- `DOUBLE` for a numeric `Facet`.
- `VARCHAR` for a declared text type, or for an enumerated measure (codes stay text, so leading zeros are never lost).
- **Left out** when the DSD gives no type. DuckDB then infers it on a REST fetch or a `reg.scan_csv` view, so an `OBS_VALUE` of numbers is a number. `obs.num("OBS_VALUE") > 1.5` runs instead of being refused, and `frame()` returns it as a float. Dimensions and attributes are forced to `VARCHAR` as before.

**Cache:** an inferred column's type can change when a fetch replaces its table (numbers one time, `n/a` the next). The `SchemaInspector` now caches types, so `ingest_csv` invalidates the table it replaces.

**Kinds before a fetch (#511):** an untyped measure's kind is unknown until the table exists, so its comparisons are permissive. Codes are still refused before the fetch.

**Tests:**
- An untyped measure scanned from numbers holds a number and filters numerically.
- A not-yet-fetched table refuses codes and leaves the untyped measure open.
- A refetch that changes the inferred type is seen.
- The `test_scan_csv_resolve` round trip now reads `1.0` as a float, with its comment updated.
- Sabotage checks: forcing `VARCHAR` again fails 3 tests; dropping the invalidation fails the refetch test.

`llms-dsl.txt` goes back to showing `obs.num("OBS_VALUE")`, and `upgrading.md` gains an entry.
