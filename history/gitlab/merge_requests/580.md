## Decision (asked)

2.1 requires every MSD to carry a `MetadataTarget` and a `ReportStructure`, the layer SDMX 3.0 removed. Until now a 3.x MSD was refused for 2.1 (#245), which hit 37 live MSDs. It is now written with an invented layer:

- one `MetadataTarget` (`SYNTHETIC_TARGET`) holding an `IdentifiableObjectTarget` with `objectType="Any"`, whose text type `IdentifiableReference` the XSD fixes;
- one `ReportStructure` (`SYNTHETIC_REPORT`) holding every attribute.

Both carry an `sdmxlib:synthetic-report-layer` annotation, like our invented StructureSet. The 2.1 reader drops them, so 3.x → 2.1 → 3.x returns the MSD exactly. Any other 2.1 reader sees a valid MSD whose report applies to any object.

## Still refused

- **Half a layer:** targets without a report, or the reverse. The message names the missing half.
- **No attributes:** a 2.1 ReportStructure needs at least one, so the bare MSD in the wire-conformance gate is now refused there with that reason.

## Tests

- New `tests/unit/test_msd_report_layer_21.py`, with 4 tests:
  - a 3.x MSD is written XSD-valid with the marked layer and reads back equal;
  - a 2.1 MSD keeps its own layer;
  - the two refusals.
- **Sabotage:** keeping the layer on read, skipping synthesis, and allowing half a layer each fail it.
- **Fidelity:**
  - `2.1 → 3.x with_metadata_structure` moves from blocked to lossy: it comes back with the invented layer, not its own.
  - `3.x → 2.1 with_metadata` stays blocked, now on the metadataflow's targets, which 2.1 can't carry. That's the next MR's subject.
