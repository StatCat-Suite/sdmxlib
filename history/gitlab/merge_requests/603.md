Closes #475.

**The bug.** SDMX-ML 2.1 declares `ContentConstraint/@type` optional with `default="Actual"` (`SDMXStructureConstraint.xsd`). The reader used `cc_el.get("type", "Allowed")`. So a constraint relying on the default was read as **Allowed**, what data may be reported, where the document meant **Actual**, what data exists.

**The fix.** When the attribute is absent, the reader now uses each version's own rule:

| version | attribute | absent |
| --- | --- | --- |
| 2.1 | `@type` | `Actual`, the schema default (was `Allowed`) |
| 3.0 | `@role` | required, so a missing one is an assumption, #474's to record (unchanged here) |
| 3.1 | none | `Allowed`; Actual content moved to `AvailabilityConstraint` (unchanged) |

The version comes from the element's namespace via `BY_STRUCTURE_NS`, the pattern `_common` already uses for 2.1-only behaviour.

**Impact.** Latent: all 3,279 2.1 constraints across BIS, ECB, OECD and the SDMX registry state their type (2026-10-15 sweep).

**Test.** `test_a_constraint_without_type_is_actual_as_the_schema_defaults` reads one without `@type` and gets `Actual`. It fails against the old reader.
