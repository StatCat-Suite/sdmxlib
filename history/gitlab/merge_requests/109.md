## Summary

Follow-up to the validate() / validate_references() raise-by-default refactors. The same surface sweep flagged `validate_binding()` as another list-returning checker — but on closer inspection drift detection isn't really the same pattern:

- **Inspection** (\"what's stale?\") — iterate to display drift in a UI or log. The list IS the answer; there's nothing to forget to check. Forcing try/except here adds friction without preventing bugs.
- **Enforcement** (\"refuse to proceed if drifted\") — fail-loud contract identical to `validate()`.

Both are legitimate, so the API splits to match:

- `check_binding_drift(binding) -> list[DriftIssue]` — inspection, what callers actually do today.
- `validate_binding(binding) -> None` — raises `DriftError(issues=[...])` on any drift.

Added on all four registry surfaces: `InMemoryRegistry`, `RestRegistry` / `FmrRegistry`, `FederatedRegistry`, and the local `Registry`. The verb convention is now consistent across the codebase: **`check_*`** returns findings, **`validate_*`** raises on findings.

## Breaking change

`validate_binding()` no longer returns `list[DriftIssue]`. Either:
- use `check_binding_drift()` for the inspection pattern, or
- catch `DriftError` and read `e.issues` for the full accumulated list.
