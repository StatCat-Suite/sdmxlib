Closes **#96**. The audit reported \"annotations only tested on DataStructure\"; investigating revealed a wider gap: there was **no \`write_annotations\` helper at all**. Every maintainable's annotations were read on parse and silently dropped on every subsequent write across 2.1, 3.0, and SDMX-JSON paths.

The DataStructure annotation in the existing complete fixture wasn't actually exercising the writer — the input file carried it, but the round-trip just happened to ignore it on both ends. So nothing surfaced.

## Summary
5 files, +167 / −2. CI: **1820 unit + 71 docs** (was 1813; +7 reader tests). The pre-existing XSD-validation round-trip on \`complete.xml\` now also covers the new annotation paths because the fixture was extended.

## What was missing

- **\`sdmx_ml._common.WriterHelpers.write_annotations\`**: new helper emits \`<com:Annotations>\` with one \`<com:Annotation>\` per entry. Per the XSD sequence on every artefact, Annotations come **first** among the child elements (before Name / Description).
- Per-version writer modules bind it as \`_write_annotations\` and invoke it after \`_write_maintainable_attrs\` in every artefact-specific writer.

**3.0-specific overrides (\`sdmx_ml30/writer.py\`)** — the 3.0 writer overrides several of the shared helpers because of URN-text ref differences; each override needs its own annotations call: Codelist, ConceptScheme, Dataflow, Categorisation, ProvisionAgreement, AgencyScheme, DataProviderScheme, DataStructure, DataConstraint, Hierarchy, HierarchyAssociation, MetadataStructure, Metadataflow, ItemSchemeMap (Concept/Category), RepresentationMap, StructureMap.
