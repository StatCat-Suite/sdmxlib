#345, #346 and #354 were the same defect three times: a field reaches the wire
stripped of something, nothing fails, and it gets found by reading code rather
than by running it. Fixing them one at a time was not going to converge, so this
asks the question mechanically instead.

* `tests/support/maximal.py` — every attrs field of every artefact reachable
  from a `StructureMessage`, populated.
* `tests/support/field_census.py` — round-trip and diff the whole graph.
* `tests/unit/test_field_coverage.py` — compare against a register of known
  losses, **in both directions**. A new loss fails. A loss that stops happening
  also fails, because a register nobody prunes stops being read.

## Why this shape

The existing guard compares hand-written `Check`s over six of the twenty
artefact slots. A field is guarded only if somebody remembered to write a lambda
for it, and ten artefact kinds had nobody — which is precisely where all three
bugs were. Here a field is covered by *existing*, and
`test_the_fixture_populates_every_field` holds that line: it fails when the model
grows a field the fixture leaves unset, since an unset field makes every check
over it vacuous.

Verified it discriminates: planting a dropped `Codelist.description` in the
shared writer fails the test with `codelists.description: '<2 items>' -> '<0 items>'`.

## What it found

~50 losses per format. Registered, grouped by root cause, each labelled bug /
format limit / not-a-loss. Tracked in #355. Two fixed here:

* **2.1 Level coding format** emitted `startValue` / `endValue` via `str()`,
  producing `"1.0"` where `CodingTextFormatType` types them
  `xs:positiveInteger` — invalid per the XSD and rejected by our own reader.
  #243 found exactly this on `EnumerationFormat`; the fix never reached this
  path. Now goes through `xsd_num`.
* **`minValue` / `maxValue` never emitted there at all**, though #230's own
  docstring lists them as permitted. #230 half-landed — it restored minLength,
  maxLength and pattern, and left these two carrying the exact loss it was about.

Declared as a gap rather than fixed: `DataStructure.measure_dimension` into
3.0/3.1 — 3.0 replaced it with an explicit `MeasureList`, so there is nowhere
for it to go.

## #354 was wrong, and this is what showed it

I filed #354 claiming no writer emits `Category`/`CategoryScheme` annotations.
They round-trip correctly in all three formats. I had grepped the three
per-version `writer.py` files, but category writing is shared in
`WriterHelpers` in `sdmx_ml/_common.py` — the search could not have found what
it was looking for, and I read the empty result as evidence of absence. Closed
with that correction.

Three findings in the first census were my fixture rather than the library, and
each is now a comment where someone would trip on it again: value-map validity
is `date` not `datetime`, `Metadataflow.targets` is deliberately
`tuple[str, ...]` so it can hold a wildcard URN, and `Level.coding_format` is a
*restriction* of the ordinary facet type.
