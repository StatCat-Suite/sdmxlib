Document fuzzing covers the readers. The analogue for a query compiler is a
hostile **predicate value**, and nothing exercised that — #222 (an unescaped
`_` behaving as a LIKE wildcard, so `code.id.contains("REF_AREA")` silently
found nothing) was fixed with one targeted test covering one metacharacter in
one predicate.

## What the data side has to look like

SDMX ids are validated to `A-Za-z0-9_@$-`, so **an id can only ever hold one
LIKE metacharacter: `_`.** That is exactly why #222 was a live defect rather
than a theoretical one, and it means an id-only fixture cannot reach the rest of
the class. Labels are unconstrained on both sides, so `hostile_labelled_codelists`
puts the hostility there.

## Two independent assertions, both shown to discriminate

**Semantic** — differential against the oracle for every string position.
**Structural** — the emitted SQL must be byte-identical to the same query with a
benign value, across fifteen positions including the accessor *keys*
(`name[lang]`, `annotations[type]`, `annotations[type,lang]`) which flow toward
join positions and look safe because they resemble names.

## One defect found, at 20× width

`folded.ends_with("\x00")` raised

```
Syntax Error: Like pattern must not end with escape character!
```

which names the wrong cause. Isolated on DuckDB 1.5.3: it rejects a NUL-bearing
LIKE pattern when the **left** operand is a non-trivial expression — which every
folded match is, the column going through `strip_accents` — while the same value
against a plain `ILIKE` succeeds. **Our SQL was well-formed throughout**; the
behaviour is inconsistent as well as misleading.

#250 allows a driver-level rejection *if it is a clear error rather than silent
truncation*. It was neither, so `match_sql` now rejects NUL **where the pattern
is built** — the one place every string match passes through, per the issue's
own warning that a fix at the call site rots — and for every strength, so plain
and folded do not disagree about the same value.

**Default width did not find it.** Third defect in this codebase that only
appeared at 20×.

## The #222 regression test stays, deliberately

#250 required choosing rather than letting both accumulate. It stays: it names
the specific historical mechanism (the escape was applied but no `ESCAPE` clause
emitted, and SQL LIKE has no default escape character) and reproduces in a
fixed, fast case when a shrunk example needs interpreting. Cross-referenced in
both directions so the relationship is not left to be inferred.
