Part of #422. **Guard first, then model** (agreed): this MR makes the drops visible; modelling them follows in their own MRs.

## Why

The read-side register (`sdmx_ml._losses.LOSSES`) only reports constructs somebody listed. While starting the links / N:M ComponentMap work, injecting a StructureMap's `EpochMap` into a document showed it was read and dropped with **no** report — `lost == ()`, `refused == ()`, a lossless parse succeeded.

## The census

`tests/unit/test_element_census.py`, per SDMX-ML 3.x version: every `(parent, child)` element pair the schema allows (the closed-world table `_allowed_children`) is compared with the pairs the writer emits for the maximal fixture plus `_shapes()` — a small supplement of modelled variants the fixture does not write (an exclusive code selection, an open-ended time range, data-type map ends, a plain codelist holding geographic codes, a dataset-level attribute, a category scheme map). Every allowed-but-unwritten pair under an emitted element must be classified in `_UNWRITTEN`, in both directions:

- **loss** — a registered `LOSSES` construct (checked to exist for the version);
- **refused** — the container of a class sdmxlib does not model (checked against `sl`);
- **absent** — no valid document holds it: the closed-world table is keyed by element *name*, so it over-allows where types share one (the abstract `str:Component` head; a MetadataConstraint's attachment children; `MetadataAttributeUsage` children the XSD sets to `maxOccurs="0"`).

The shapes are asserted XSD-valid and read back field-for-field, so "written" means held. Sabotage-checked: dropping a `LOSSES` row, or stopping the writer from emitting `ExclusiveCodeSelection`, each fails it; the discrimination test strips `<str:Code>` and expects the census to report it.

## What it found — 17 silent drops, now registered

Classified by injecting each into the maximal message (held / reported / silent):

- **StructureMap:** `EpochMap`, `DatePatternMap`, `FrequencyFormatMapping`, `FixedValueMap`; **ComponentMap:** `RepresentationMap`
- **`com:Annotations`** on `DimensionList`, `AttributeList`, `MeasureList`, `Group`, `MetadataAttributeList`, `ComponentMap`, `ItemMap`, `RepresentationMapping`, `CubeRegion`, `Key` (one row)
- **Concept:** `ISOConceptReference`; its CoreRepresentation's `EnumerationFormat`
- a nested **`Level`**; a data key's **`Component`**
- (3.0) a `ConstraintAttachment`'s **`SimpleDataSource` / `QueryableDataSource`**

Each has a `LOSSES` row with an injection and a strict-xfail round trip in `test_read_losses.py`, as every row does — so `msg.lost` reports it and `parse(..., lossless=True)` raises. Note the XPath context: counters run on the artefact element, so a construct directly inside a StructureMap needs `descendant-or-self::` (the first draft's `.//str:StructureMap` found nothing — the injection tests caught it).
