## Why it stops at ~184 lines rather than ~600

The remaining ~411 lines are the predicate/ref class hierarchy, and sharing them would cost a real static guarantee. Each DSL has its own `Predicate` base, and basedpyright uses that to reject a cross-DSL predicate:

```python
q.filter(node.id == "A")
# error: "hierarchy_query.Predicate" is not assignable to "code_query.Predicate"
```

A shared base makes that call type-check and fail at *runtime* instead — the two emitter tables do not carry each other's predicate kinds. Deduplication is not worth losing that, and #267 anticipated the situation: *"if the parameterisation needs more than the table above, that is a signal the two are less alike than they look and the refactor should stop early rather than force it."*

Verified rather than asserted: the probe above still produces two basedpyright errors after the change.

The upshot is that the duplication is **less severe than the raw line count suggested**. Of ~600 shared lines, ~184 were incidental and are now single-source; the rest is a deliberate consequence of keeping the two DSLs' type surfaces apart.

## Two improvements made rather than carried across

- **`fetch_annotations_for` now binds `= ANY(?)` with a list** instead of generating a run of `?` placeholders. One parameter instead of one per URN, and the SQL becomes a static string with no interpolation to audit. Verified DuckDB handles the empty-list case correctly.
- **`hop_bound` returns its fragment without a leading space.** The two copies disagreed — one baked the separator in, one did not — which is exactly the low-grade drift this issue is about.

## The one config change

`ruff.toml` gains a single line exempting the new module from `S608`, under the comment that already explains the exemption for `code_query.py` and `hierarchy_query.py`. Asked and approved before making it: it is a protected file, and the alternative was letting the lint config dictate the file layout — the code being moved is precisely the code that exemption already covered.

The `= ANY(?)` change above removed the *other* S608 site on the way, so the exemption covers only `annotation_exists`, which builds an `EXISTS` from validated identifiers with every value bound.

## Follow-on

This was sequenced before **#262** (And/Or/Not) deliberately: that adds three predicate classes, three emitters and two dispatch-table entries. Those land in both modules either way — the class hierarchy is staying duplicated — but the shared helpers they will lean on (`in_clause`, `hop_bound`, `annotation_exists`) are now single-source.
