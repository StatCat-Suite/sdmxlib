Closes **#109**. SDMX 3.0 added \`CodelistExtension\` to \`CodelistType\` to support composing a derived codelist from one or more source codelists with include/exclude filters and an optional prefix. 3.1 keeps the same shape. Not modelled in 2.1.

## Four new value types

| Type | Role |
|---|---|
| \`InclusionMode\` ∈ {\`INCLUDE\`, \`EXCLUDE\`} | Discriminator for the XSD's \`<xs:choice>\` between \`<InclusiveCodeSelection>\` and \`<ExclusiveCodeSelection>\`. The XML layer is two element names with the same content type; semantically it's **one selection with a mode flag**. Modeling the flag explicitly prevents callers from accidentally populating both branches. |
| \`CascadeSelection\` ∈ {\`INCLUDE_DESCENDANTS\`, \`SELF_ONLY\`, \`EXCLUDE_ROOT\`} | The 3.1 \`CascadeSelectionType\` is a string union of \`xs:boolean\` and the literal \`excluderoot\` — three semantic values, one small enum. |
| \`MemberValue\` | A single code reference inside a \`CodeSelection\`. Value string may include the \`%\` wildcard per \`WildcardedMemberValueType\`. Optional per-member cascade. |
| \`CodeSelection\` | Inclusion mode + ordered \`MemberValue\` list. |
| \`CodelistExtension\` | Reference to the extended codelist + optional \`CodeSelection\` + optional prefix. |

\`Codelist.extensions: tuple[CodelistExtension, ...] = ()\` field added. Order matters per the XSD docs (precedence for conflict resolution). Empty tuple = no composition, matching XSD \`minOccurs=0\`.

## Serializer wiring (3.0)

- **3.0 writer**: extends \`_write_codelist\` to emit \`<CodelistExtension>\` AFTER all \`<Code>\` entries (the v3.0 \`CodelistType\` sequence position). The choice element is selected by the model's \`mode\` flag.
- **Shared 2.1/3.0 reader**: extended \`read_codelists\` in \`sdmx_ml._common\` with a new \`_read_codelist_extensions\` helper. The element doesn't exist in 2.1 messages so the helper returns \`()\` for 2.1 input naturally.
- **2.1 writer**: no change. The 2.1 codelist schema has no equivalent element; if a model carries extensions and is serialized as 2.1, the field is silently dropped (best the XSD allows). 3.0 round-trip preserves; 2.1 doesn't.
