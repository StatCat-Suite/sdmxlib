The authoring half of #319's discussion.

The model is a union of the 2.1 and 3.0 information models, so writing an artefact can **refuse**, **drop**, or **downgrade**. A refusal is visible; a drop is not — and until now the only record of the drops was `KNOWN_GAPS`, a table in this project's test suite, unreachable by the author it concerns.

```python
sl.unrepresentable(codelist, "3.0")
# (Gap(field='is_final', reason='SDMX 3.0 dropped isFinal from every maintainable artefact'),)

with sl.Registry("authoring.duckdb", target="3.0") as reg:
    reg.add(codelist)   # ValueError naming the field, the target, and the escape
```

**Per artefact, not per type**: a codelist with `is_final` unset loses nothing to 3.0, so nothing is reported. A check that fires on every artefact is noise, and noise is not read.

**`target=None` stays the default and has to.** A cache of a 2.1 registry must accept what that registry publishes; a target would refuse it. Declare one when authoring, leave it unset when mirroring.

## Promoting the table corrected it

`KNOWN_GAPS` keys by *test case*, so `is_final` — which 3.0 drops from **every** maintainable — was recorded once, under whichever case happened to exercise it. Declared against `MaintainableArtefact`, it now applies where it actually applies, and 3.1 inherits the 3.0 drops the guard never listed. 7 wire-format rows became 11.

## One table, two readers

`formats/gaps.py` is the declaration; the round-trip guard cross-checks its by-design entries against it, so the library cannot claim a write is lossless while the suite knows otherwise. The guard's `xfail(strict=True)` proves each row — fix a gap, the case XPASSes, the entry goes.

## Why not a constructor check

Decisive rather than a preference: the **readers build the same model classes** from wire data, so a `Codelist` refusing what 3.0 cannot express would refuse to *parse* a 2.1 document. Authoring and parsing share the model, so the model cannot be strict. Hence the store and the writer.

## Bug found

`Registry.from_connection` goes through `cls.__new__` and initialises every field itself, so `_target` was absent there — an `AttributeError` on the first `add`, caught by the shared-connection cookbook test.
