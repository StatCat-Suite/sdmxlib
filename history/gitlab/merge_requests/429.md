Closes #359 — which was a record of completed work plus one live action item: *"any XSD `<xs:choice>` is a place the fixture can lie — worth a sweep of the remaining register for the same shape."* This is that sweep, made standing.

## What the sweep found

The SDMX-ML 3.0 schemas declare **50** complex types with a multi-member `<xs:choice>`. Most are registry and messaging shapes this library does not model. Of the ones it does, almost all are *structurally incapable* of the lie, because the model collapses the choice into one field rather than mirroring it as siblings:

| XSD choice | How we model it | Can it lie? |
| --- | --- | --- |
| `MetadataSetType` | one `MetadataSet.structure` ref | no |
| `RepresentationMapType` | one `source`, one `target` | no |
| `CodelistExtensionType` | one `selection` + a `mode` enum | no |
| `ValueType` | one `ReportedAttribute.value` | no |
| `ComponentValueSetType` (`TimeRange \| Value`) | only `Value` modelled | no |
| `RepresentationType` | `representation` **+** separate `enumeration_format` | **yes** — checked by hand |
| `DataConstraintAttachmentType` | 4 nullable siblings | **yes** — declared |
| `AttributeRelationshipType` | nullable payload siblings | **yes** — declared |

`RepresentationType` needed checking rather than reasoning about, and a *flat* reading of the XSD gets it wrong: it is `TextFormat | (Enumeration, EnumerationFormat?)`, so `EnumerationFormat` is not a third branch but an optional companion **inside** the second. No fixture component sets one without an enumerated representation.

## The conclusion is about the model, not the fixture

The vulnerable shape is narrower than #359 assumed: **sibling nullable fields mirroring a choice, with no discriminator**. Exactly two exist, and they are exactly the two that bit. A choice carried as one field plus a mode enum cannot be lied about — worth remembering the next time one is modelled.

## Two guards, because the *fix* has its own failure mode

Splitting one over-set instance into honest ones is easy to do by **deleting** rather than distributing — which would leave three of the four attachment kinds written by nobody and checked by nothing. The register would go quiet for the same reason it went noisy, and look like progress. So:

1. at most one member set on any one instance, and
2. every member set by *some* instance.

Plus a third that keeps the register above from becoming ceremony: an entry earns its place only if the fields exist and the model can actually set them together.
