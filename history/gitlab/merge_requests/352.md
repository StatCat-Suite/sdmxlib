## The deletion

| gone | replacement |
| --- | --- |
| `DataStore.query` / `query_stream` | `DuckDBDataStore.observations(binding)` |
| `FederatedCatalog.query` / `query_stream` | `catalog.observations(flow_urn)` |
| `where=[...], params=[...]` | `obs.filter(obs.col("REF_AREA") == "CA")` |
| `columns=[...]` | `.select(REF_AREA=obs.col("REF_AREA"), ...)` |
| `order_by="V DESC"`, `limit=n` | `.order_by(obs.col("V").desc()).limit(n)` |
| `component_filter=cf` | `.filter_components(cf)` |
| `with_labels=True, lang="en"` | `.frame(labels="en")` |
| `_build_query`, `_fence`, `UnsafeQueryError` | — |

`with_labels` + `lang` is worth calling out: it was a two-argument state
that could disagree with itself, and had a runtime check to say so.
`labels="en"` cannot — the language *is* the request — so the check is
unstateable rather than merely removed, and its test went with it.

## Why the fence went too

There is no assembled statement left to inject a second statement into.
A caller who needs SQL writes a complete one through `catalog.sql()`,
which binds `$name` and checks the text against DuckDB's own parse —
the same rule `Registry.sql` uses.

## Two things that fell out

**`DataStore` is now write-side only.** Reading needs a compiler, which
a Protocol cannot require of an arbitrary backend, so
`FederatedCatalog.observations` narrows to the DuckDB store. A second
backend declares a `Capability`, not a frame-returning method.

**An unprojected result had to learn about root joins.** `to_sql`
defaulted to `s0.*` — right for a path hop, silently wrong for a
sidecar. `_Scope.star` now adds each root join's `* EXCLUDE (keys)`.
`test_query_joins_series_attributes_location` is what caught it: it
asserts an unprojected frame carries the sidecar's columns, which the
old `SELECT *` did by accident and the new default did not do at all.

## Migration

Every call site moved rather than being dropped, including the empty
OR-set cases (#256) — they now reach `is_in([])` instead of
`to_where_clauses`. The reading is unchanged; the compiler is not, which
is why the test moved rather than went. `to_where_clauses` itself stays:
`builders/contentconstraint.py` still uses it.

Docs updated: the REST-facade and federation cookbooks, both of which
showed the text API as the ordinary path.
