Extends the element census from !547 to SDMX-ML 2.1 (#422).

## Wrong readings, fixed
- **`<URN>` references.** 2.1 allows a reference to be a `<URN>` child instead of `<Ref>`. The reader only looked for `<Ref>`, so a schema-valid document using `<URN>` lost every reference without reporting anything. A test respells each `<Ref>` the maximal 2.1 document carries as `<URN>`, under exactly the parents the census lists, and asserts the read is identical.
- **Metadata constraints.** A 2.1 `ContentConstraint` or `AttachmentConstraint` that constrains metadata was read as a data constraint with its attachment emptied. It is now refused whole, as 3.x's `MetadataConstraint` is.
- **`StructureSet.related_structures`** was neither written nor read in 2.1, and `isFinal` was not read. StructureSet joins the maximal fixture, which is why no field census had caught this.
- **Text with no `xml:lang`** is now read as `en`, the default every SDMX-ML schema declares on `TextType`; the readers dropped it. This is the schema's default applied at parse time, not a library default language.

## Registered losses
- Fourteen 2.1 constructs that were dropped silently now have `LOSSES` rows, among them `AttachmentGroup`, `ReportingYearStartDay` and `HybridCodelistMap`; a `MetadataTarget` holding several target objects is one of them.
- New for every version: a constraint attached to several artefacts reports the ones it drops.

## Fixtures
- `maximal` adds a StructureSet and the four other 2.1 MSD target kinds.
- `shapes` adds a concept enumerated by a codelist, and `message_21()` adds an AttachmentConstraint. It can't go in `maximal` because the store refuses it (#395).

Each new guard was broken on purpose and failed. `just ci` is green: 7738 unit, 57 docs, 86 integration and 23 bundle tests. No storage schema change.
