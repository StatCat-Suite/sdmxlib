## The problem with grinding class by class

Every conformance bug this milestone was a constraint the XSD states and the model does not enforce. Every one was found the same slow way: generate an artefact, watch schema validation reject it, work out which side was wrong. `DataType.URL`, `NCNameIDType`, the fixed `AgencyScheme.id`, seven gaps in `DataStructure`.

That works — but a generated artefact only exercises the constraints it *happens to touch*. Fourteen classes remained, and the yield was already falling.

## Reading the constraints out instead

`tests/support/xsd_facts` extracts them from the vendored schemas. Per version:

| | 2.1 | 3.0 | 3.1 |
| --- | --- | --- | --- |
| enumerations | 59 | 26 | 27 |
| pattern facets | 20 | 161 | 161 |
| fixed attributes | 255 | 19 | 18 |

Nobody is going to state those by hand, and they are the reason the XSDs are vendored at all.

The checks:

- **Every sdmxlib enum's members must be accepted** by the XSD enumeration it serialises into, in every version.
- **A new enum must be mapped or explained** — `test_every_enum_is_classified` fails if one is neither, so the mapping cannot silently stop covering the model. The three unmapped ones carry reasons (`CascadeSelection` is an XSD *union*, not a named type; `InclusionMode` and `AttachmentLevel` are structural, not enumerated attributes).
- **The id regexes must accept exactly what the schema's do.** Compared over a corpus rather than as text: XSD facets are whole-value anchored and escape `-` inside character classes, so a textual comparison fails on differences that mean nothing. My first version did exactly that and reported nine false failures.
- **Every `fixed` id a caller can set must be enforced**, distinguishing those from the container ids the writer generates itself.
- **The extractor must keep finding constraints**, so the rest cannot go vacuously green if a schema directory moves.

**Three of this milestone's bugs would have been caught with no generation at all, in 0.05 s.**

## Why this is the better foothold

It is exhaustive where generation is opportunistic, and it **costs nothing to maintain**: refreshing the vendored schemas changes the facts, and these tests report the difference. That is exactly what you want to learn when SDMX-TWG publishes a new tag — and `tests/schemas/README.md` already documents that refresh procedure.

Generated round-trips are still the right tool for *structural* conformance — element ordering, required children, recursion — which is what the remaining classes in #223 will exercise. The two are complementary: this covers the constraint surface, generation covers the shapes.
