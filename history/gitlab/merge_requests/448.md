## Where a `collect()` went

`q.code…collect()` over `CL_GEOGRAPHY`, 579,951 codes. **SQL execution proper
was ~430 ms — 12%.** The query engine was never the problem:

| | before | after |
| --- | --- | --- |
| `fetchall()` — DuckDB → Python | 916 ms (750 of it the two `MAP` columns) | see #380 |
| annotation SQL + grouping | 1109 ms | opt-out, see #381 |
| building 579,951 `Code` objects | 642 ms | unchanged — this is the real work |
| **total** | **3336 ms** | **2508 ms**, or **1158 ms** opted out |

For scale on the same predicate: `.count()` 22 ms, `.ids()` 100 ms,
`.frame()` — all 579,951 rows into polars — **164 ms**.

## #380 — let DuckDB serialise the label maps

Selecting a `MAP(VARCHAR, VARCHAR)` makes DuckDB build a Python `dict` per
label per row inside `fetchall`, before any of our code runs. `to_json(col)`
plus a bound `msgspec.json.Decoder` is **2.3x cheaper end to end** for
byte-identical `InternationalString`s (1358 → 580 ms).

| | before | after |
| --- | --- | --- |
| `q.code…collect()` | 3336 ms | 2668 ms |
| `get(CL_GEOGRAPHY, eager=True)` | 3953 ms | 2722 ms |
| `LazyHierarchy.materialize()` | 3193 ms | 2835 ms |
| …its peak RSS | 1109 MB | 958 MB |

**This is not "use Arrow", and the helper's docstring says so** — because 71 ms
is the number someone will find first. `to_arrow_table()` fetches the same rows
in 71 ms, but `to_arrow_table().to_pylist()` costs 2430 ms, *slower* than
`fetchall`. Columnar wins only while the data stays columnar, which is why
`.frame()` is 164 ms and why a path that must produce a Python object per row
cannot use it.

Four bulk readers change. The other twenty `map_to_istring` sites read tens of
rows, where this is unmeasurable.

## #381 — `collect(annotations=False)`

The docstring justifying the eager read said annotations "were expensive, and
they are not any more." Measured, and true against the 10k fixture it was
written against; at 579,951 codes they are **32% of the collect — more than
building the `Code` objects** — and 98% of them carry no text.

`collect(annotations=False)`: 2508 → **1158 ms**, every id/name/description
identical, 579,951 annotations against 0.

Not a default and not silent. A silently empty `.annotations` is wrong data
rather than fast data — the reason `with_antions` was removed, and still
right. What changed is the size, not the argument, so the flag returns at the
*call site*.

`q.artefact` and `q.reported_attribute` **raise** rather than accept-and-ignore,
naming the roots that do support it. A flag silently ignored is worse than one
refused: no improvement measured, no way to learn why.

## Notes for review

- **The transport change is guarded differentially.** JSON adds an escaping
  layer the MAP path never had, so
  `tests/unit/test_istring_sql_agrees_with_maps.py` runs both paths over the
  same value *through DuckDB* and compares — the oracle is the code being
  replaced, not an expectation read off the replacement. Hypothesis draws the
  labels weighted toward `" \ newline / NUL é 🍁`; the nine hand-found cases
  stay as named regressions.
- **It was checked for discrimination before being trusted** (CLAUDE.md rule
  4): a mutant stripping backslashes fails 3 tests, one dropping the NULL guard
  fails the NULL case.
- **A malformed payload raises** rather than yielding an empty label. A
  swallowing decoder would turn a storage bug into missing names across a whole
  codelist with nothing to see.
- **The resolver signature became a `Resolver` Protocol**, because the keyword
  has to be in the type for a checker to catch a resolver that forgot it —
  which basedpyright then did, twice, on `storage/lazy.py`'s lambdas.
- **That retired a documented false positive.** `build(resolve)` sat in
  `test_query_misuse`'s reviewed-collection-parameter inventory only because
  the pattern matched the *return* half of its inline `Callable[[Sequence[…]],
  Sequence[object]]`. The Protocol removes the annotation and the false
  positive; the inventory's *stale* half is what noticed. Left as a comment,
  since "why is this not listed" is the next reader's question.
- **Counts, not clocks**, throughout — including that the non-opted-out path
  still makes exactly *one* batched annotation read covering all three codes,
  so #72/#73's batching cannot regress behind the new flag.
