Two of the three items in the audit's smaller cluster. Both were silent —
a query that looked right and returned something that was not an answer.

**Closed vocabularies.** `q.artefact.type` and `q.component.role` hold one
of a short fixed list the library itself writes, and comparing against
anything else returned an empty set indistinguishable from "this
catalogue contains none of those":

    q.artefact.type == "Codlist"      # typo -> []
    q.component.role == "dimension"   # case -> []

Now refused at construction, naming the language spelling rather than the
storage column, listing the legal values, and offering a "did you mean"
when only the case is wrong — which is the common form. `!=` is refused
too, with a different consequence in the message: that one matches
*every* row, and telling someone their filter is empty when it is a no-op
sends them to the wrong place.

A column class rather than a check at the call site, for the reason
`Version` is one: the divergence belongs to the column, so every operator
that compares one gets it and a new operator cannot forget. Members of an
`is_in` set are all checked, not just the first — a set is where a typo
hides best, because the others still match and the result looks plausible.

The values come from `storage._kinds`, which is what the *writer*
dispatches on, so the language cannot drift from what is in the column;
two tests hold the derived set against what a real write actually
produces. They arrive as a callable because `storage` imports `accessors`,
so naming that module at class-definition time is a cycle.

**It found a live one immediately.** `test_predicates_compose` had been
building `q.component.role == "dimension"` — lower case, matching nothing
— since it only asserted `.op == "and"`, so nothing noticed.

**Duplicate projection names.** Every maintainable's `id` reads
`artefact.resource_id`, so `select(q.dataflow.id, q.dataflow.dsd.id)`
named both columns `resource_id` and polars silently renamed the second
to `resource_id_1` — a frame whose columns do not mean what the query said
and whose second column is named after an artefact of the collision.
Refused, because only the caller knows which is which and the fix is one
keyword away.

Not done, and deliberately: the third item, `resource_id` / `component_type`
leaking storage names into every frame. That is a *renaming* of output
columns rather than a bug fix — it breaks every consumer reading a frame
by name, and there are two self-consistent conventions to choose between.
Worth deciding rather than assuming.

One checker disagreement worth recording: `isinstance(v, str | Mapping)`
is an `implicit-any-type-argument` to pyrefly and a subscripted-generic
error to basedpyright if you add the arguments. Three separate calls
satisfy both, as the bare `Mapping` already used in this file does.

`just test-properties` clean at 20x.
