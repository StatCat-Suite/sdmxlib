# Merge request !660: perf(storage): read the spine and annotation URLs without correlated subqueries

| | |
| --- | --- |
| State | merged |
| Opened | 2026-10-20 |
| Merged | 2026-10-20 |

A pre-release benchmark against v0.67.1 found **store reads 3–5× slower**. This is not from today's MRs, which measured flat (0.98–1.03×). It landed in the milestone work since the last tag, mostly #422.

## Diagnosis (A/B/A, profile-attributed, ablated)

- **Spine query:** a fixed **~1.1 ms per read**. Its two correlated link subqueries (the artefact's own links, and a count of its items') are planned badly by DuckDB for a single-row lookup. It takes 1,313 µs as written, against 140 µs for the row alone and under 200 µs for each part alone.
- **Annotation URLs:** **~320 µs per read**, as a correlated subquery per annotation. It's paid even when the store holds no annotations: 580 µs with it, 260 µs without.
- **Checked and left alone, with the maintainer's agreement:**
  - The DSD component query (~450 µs, 49 columns after #422) is the honest cost of what it carries.
  - DuckDB's pandas probe: every read statement already binds exactly one value, so code can't reduce it further. An upstream report is drafted.
  - The in-memory `add_all` 2.6× is #492's binding walk, about 3 µs per artefact, already skipped at class level. Detecting "no references" costs the same walk, so there was nothing cheaper to skip to.

## Fix

- **Spine:** one statement whose parts filter on `$urn` directly. Same answer, and the URN is bound once.
- **Annotations:** a shared `resolve.annotation_rows(cur, where, params)` reads them, then their URLs in a second statement under the same predicate, **only when there are annotations**. All four annotation readers use it, and the `ANNOTATION_URLS` correlated fragment is gone.

| lazy codelist `get` | 0.25 ms | 1.61 ms | **0.53 ms** (0.33×) |
| dataflow `get` | 0.63 ms | 2.55 ms | **0.93 ms** (0.36×) |
| DSD `get` | 1.1 ms | 4.3 ms | **2.9 ms** (0.67×) |
| eager codelist `get` | | | 0.56–0.60× |

- **No benchmark slower:** across the 93 benchmarks the median ratio against main is 1.00. Nothing is slower by more than 3% beyond its A/A drift.
- **Memory:** retained and peak, with `tracemalloc` over 50 held reads each of the maximal DSD, a dataflow and a lazy codelist, are unchanged (42.7 / 5.3 / 2.1 KiB per read retained; peaks within 3%).
- **What remains against v0.67.1** (1.4–2.7×) is the cost of what's been added since: links, the wider component query, and #492's store checks.

## Guards

- `test_get_statement_count`: the spine is recognised by its table (`FROM artefact`, not `artefact_*`), since the statement now opens with `WITH`. The old recogniser fell to zero matches here, so it can fail.
- A new annotated-dataflow case is pinned at exactly **5** statements, with a check that its URLs come back. The unannotated reads keep their counts.
