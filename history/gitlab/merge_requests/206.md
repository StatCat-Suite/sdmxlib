Completes #209. The readers now write lookups the way lxml documents them.

```python
el.findall(_s("Telephone"))        ->  el.findall("str:Telephone", namespaces=_NS)
structures.find(_s("Codelists"))   ->  structures.find("str:Codelists", namespaces=_NS)
```

**322 lookups** across the three readers and the shared `ReaderHelpers`.

## The argument is clarity

> the lxml with keyword reads clearer, and what it is doing is obvious, the `_s` requires someone to read that function

That is the right trade, and an earlier draft of #209 argued the opposite on call-site brevity — weighing line length above explicitness, which is the wrong priority for a library other people read.

`namespaces=_NS` repeats at every lookup and there is no avoiding it: lxml resolves prefixes **per call**, with no facility to bind a map to an element, a tree or a parser. It is the same token every time, so it reads as punctuation rather than content.

## What fell out of the conversion

* **`ReaderHelpers.c` / `.s` / `.m` are gone** — zero uses once the lookups were converted. `WriterHelpers` keeps its own, because `etree.SubElement` resolves no prefixes and genuinely requires Clark notation. That asymmetry is now real rather than incidental.
* **The eight pre-built `com:` Clark constants are gone.** They existed to avoid rebuilding f-strings on hot paths; a prefixed literal is already a constant. Measured at parity first — `findall` with a pre-built Clark tag **2.35 µs**, with a prefixed path **2.44 µs**.
* **`read_istring`'s three-branch dispatch** over those constants collapses to one `f"com:{child_tag}"`.
* **`_read_codelist_extensions`** took the tag builder as a `Callable[[str], str]` parameter; it now takes the prefix map.
