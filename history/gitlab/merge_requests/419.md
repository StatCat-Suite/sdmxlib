#355's "2.1 annotation drift" group. **The label was mine and it was wrong** —
this is not one drift but three causes, which is why counting
`write_annotations` call sites (the method that found #346) had not located it.

## 1. The scheme-map writers never emitted, and the reader never looked

A **symmetric** loss: write nothing, read nothing, and a round-trip comparing a
parsed document against itself agrees perfectly. Only a comparison against the
*model* sees it — which is exactly what the #354 census does and what the older
round-trip guard structurally cannot.

`StructureMap` had the same hole by a separate code path.

## 2. A Hierarchy's annotations went to the wrong element

2.1 has nowhere to put a bare hierarchy, so sdmxlib wraps one in a synthesised
`<HierarchicalCodelist>`. The annotations were written on that **wrapper**,
while the reader rebuilds the `Hierarchy` from the inner `<Hierarchy>`. They
were emitted, and arrived nowhere.

Now written on both — when the wrapper is a real container rather than a
synthetic one, its annotations belong to a different artefact.

## 3. A HierarchicalCode's were written all along

`_read_hierarchical_code` simply never passed `annotations`. The bytes had been
correct since forever.

## Ordering

`Annotations` goes before `Name` in each writer: `AnnotableType` sequences it
first, so emitting it after would have traded a silent loss for an invalid
document. All three SDMX-ML versions still XSD-validate.

## Result

Six register entries gone from 2.1. Each fix planted back individually fails the
census, so none is resting on the others.

`just ci` green: 5827 unit / 53 docs / 86 integration.
