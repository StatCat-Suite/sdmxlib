## Summary

Adds a small but load-bearing primitive to the shared CompileContext:

def next_alias(self, prefix: str = "f") -> str:
    \"\"\"Generate a unique SQL alias for use in a subquery or join.\"\"\"

Predicate compilers (sdmxlib's CodeQuery internals, pinaxlib's filter classes, future cross-library compilers) all need a way to generate unique SQL aliases for correlated subqueries. Lifting next_alias to the shared CompileContext means every predicate that takes ctx can use it without each library re-implementing the counter.

## Why now

Discovered while doing the pinaxlib refactor (the bundle architecture work). Pinax's filter classes were going to need their own \`_QueryContext\` subclass purely to add this method. Better to have it on the base — every other predicate compiler in the suite will need exactly this primitive.
