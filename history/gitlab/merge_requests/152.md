Two clean, quality-preserving wins on the JSON serialize hot path. (Profiling showed dict-building dominates; `orjson.dumps` is only ~5%.)

## 1. Dedup `_emit_istring`
It was copy-pasted in both `structure_values` and `writer`. `writer` already imports the rest of its istring/annotation helpers from `structure_values`, so it now imports `_emit_istring` too — one implementation, one place to tune.

## 2. Skip the defensive `as_dict()` copy
`_emit_istring` fed the full language map into the transient output dict via a shallow copy (75k copies on a large message). That copy keeps the model's internal map unshared — but here the output dict is built, handed to `orjson.dumps`, and discarded: it is never mutated and never escapes `serialize()`. So `InternationalString.as_dict` gains `copy: bool = True` (safe default — external callers still get a copy) and the serializer passes `copy=False` to share the backing map.

**Combined with the validation decoupling (!151), the pysdmx JSON gap is now ~19%** (estat: us 5.72 ms vs pysdmx 4.81 ms) — down from ~50% originally.

## Deliberately stopping here

The residual gap is architectural: pysdmx encodes `msgspec.Struct`s to JSON in C with no intermediate dict; we build a dict tree in Python then orjson it. Closing that fully means adopting `msgspec` (a heavy core dependency + a Struct-based writer rewrite), which isn't worth ~19% on a path where we already dominate both peers on **parse** (2.4–4.4× faster). Not chasing it.
