Relates to #312. **Breaking**: `reg.query(T)` and `api.query.Query[T]` are removed. Corpus byte-identical.

```python
reg.query(sl.q.dataflow).filter(
    sl.q.dataflow.agency == "ECB",
    sl.q.dataflow.dsd.agency == "ECB",
    sl.q.dataflow.dsd.dimensions.any(sl.q.component.concept.id == "REF_AREA"),
).ids()
```

Two requests, independent of catalogue size. Same language as `Registry.query`; only the fetch differs.

## The retirement was already argued

`query-language.md`'s convergence section decided this before it was executed: `Query[T]`'s only distinguishing feature was `filter(lambda)` evaluated in Python over everything fetched, and strict laziness bans exactly that — so once it is lazy and compiled it *is* the path language under another name. This MR executes rather than re-decides.

## How a fetch hangs off a lazy query

`Query` gains `_prepare`, called with the plan immediately before the first statement, with every terminal funnelled through one `_cursor()`. At the **terminal**, not construction: `reg.query(q.dataflow)` names no agency, so fetching there would fetch a registry. `eq=False` — wiring, not question — and `_fetch_for` memoises on `canonical_key`, so `count()` then `ids()` share a fetch, as do `filter(a).filter(b)` and `filter(b).filter(a)`.

Rows live in `materialise_to` when supplied, making the fetch a one-off for that store's life (§12); otherwise in a store this registry owns and closes. A caller's store is left open.

## Two guards earned their keep

- The step-1 structural test failed on the new field — exactly its job. `_prepare` is wiring, so it joins `_conn`/`_resolve`.
- `Registry.add` takes `SupportsUrn`, so the `Store` Protocol typed on `object` was *wider* than its only implementation. Narrowed with `isinstance` rather than catching `TypeError` around `add`, which would also swallow a store error — and a store quietly refusing every artefact presents as a query answering nothing.

## Docs

`catalog.md` loses its browse/fetch/resolve depth section: depth is now derived from what the query reaches. `reg.get()` keeps its explicit depths; only the collection form changes.

## Two gaps left visible rather than absorbed

- **`detail=allstubs` has no model** — every fetch is `detail=full`, so a listing that needs only ids downloads every component. Filed as #318 and noted on the field.
- **REST integration coverage is zero.** Four cassette-backed tests covered the retired entry point; the replacement issues different URLs, so new recordings need a network. Removed, with a skipped test naming the gap.
