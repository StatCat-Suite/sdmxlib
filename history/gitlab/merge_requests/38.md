### Two things worth noting

1. **Throughput decreases as workers increase** (915 → 863 ops/sec from 1 → 16 workers). That's the shared-cursor serialisation ceiling from #75. Post-fix, this should scale closer to linearly until DuckDB's connection-level serialisation dominates.
2. **Errors scale with worker count** (1 → 0, 4 → 1, 8 → 2, 16 → 4, 32-cache → 16). The bench catches silent-`None` returns from `reg.get(urn)` (dominant failure mode of the bug). After #78 these should drop to zero.
