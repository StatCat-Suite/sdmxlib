The planner emitted one join shape, because a declared hop only ever
needs one: the edge supplies an ON expression. The data plane's
series-attributes sidecar joins USING the columns common to both tables,
which `SchemaInspector.plan` already derives and the data store renders
as a string today.

`Join` now models both, with the invariant enforced rather than
documented — exactly one of `on`/`using`, and the error names the join.
Two mutually exclusive shapes on one class is the arrangement that
otherwise lets a caller set both and get whichever `to_sql` checks
first.

`qualify()` is now one function rather than two copies of the same
conditional, since the root and a join answer the same question about
their schema.

**The USING arm has no caller yet**, and that is the staging rather than
an oversight: step 4 is the binding-backed root that will build it, and
this lands first because everything it touches is structural code with
structural tests over it. If step 4 changes shape, this is three lines
to revise and nothing depends on it.

Existing behaviour is unchanged — the default schema and the ON
rendering are byte-identical, which the 5,219 tests already covering
this compiler assert by not moving.
