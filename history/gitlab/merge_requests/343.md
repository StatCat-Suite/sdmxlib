`ComponentFilter` was the one *typed* thing the SQL-text API took — a
dotted key plus `c[DIM]=…` parameters, parsed against a DSD — so it has
to survive that API's removal rather than go with it.

`filter_components` translates it: each constrained component becomes
`is_in`, which is exactly what `to_where_clauses` rendered by hand.

The three semantics that had to carry over, each now asserted:

* `None` is unconstrained and contributes nothing, so a wildcard filter
  does not narrow.
* `[]` is "the permitted set is empty" and matches no row — `is_in([])`
  already compiled to `1 = 0`, which is polars' and SQLAlchemy's reading
  and the one #256 argued from first principles. Keeping it distinct from
  `None` is the whole reason `ComponentFilter` has both.
* A `SqlRelation` value stays lazy, as a subquery.

A filter is parsed against a DSD and applied against a binding, so a
component in one and not the other now surfaces as a `KeyError` naming
what the dataflow has, rather than as a missing column at the database.

That clears step 2 of #329. Step 3 — delete `catalog.query` /
`query_stream` and `DataStore.query` / `query_stream`, add `catalog.sql`
taking a complete statement — no longer strands anything: with #328 the
typed path covers ranges, keys, membership and shares, and this covers
the REST key.
