The #276 headline query now plans to real URLs:

    GET /structure/datastructure/ESTAT/all/latest?detail=full&references=children
    GET /structure/dataflow/ESTAT/all/latest?detail=full

URL assembly is the dull half — a Push's predicates are equality on agency, id and version *by construction*, since the capability declares nothing else. The risk is entirely in `references=`.

## A modelling error caught by building it

The first cut computed `references=` from the push's own plan. The §9.1 sub-scan pushes `dsd.agency` and keeps the concept predicate **local**, so its plan mentions no crossing at all and the request came out `references=none` — the fetch that returns 81 DSDs, resolves zero concept ids, and answers nothing with no error. Exactly the silence §13 was written about, produced by the code written to prevent it.

The rule: a scan's `references=` must cover everything evaluated against its rows, and what it pushes is only part of that — the predicates the backend could *not* take reach the deepest paths precisely because it could not answer them. `requests_for` attributes each `Residual` to the most recent `Push` (the execution order the type already states) and unions their paths into the closure.

Which also shows why the rewrite is cheaper rather than merely different: the deep paths ride on the inner scan (`children` over 81 DSDs) and the outer scan needs nothing. Without it the same closure lands on the dataflow scan and drags every dataflow's subtree.

## Smaller decisions

- `all` and `latest` kept distinct: `all` means every id, `latest` the newest version rather than every version. Using `all` for a version would silently widen a query to an artefact's whole history.
- `references=none` is omitted rather than sent — it is the wire default, and sending it makes every cassette diff noisier.
- URLs asserted as whole strings: a segment in the wrong order is the bug a field-by-field assertion reads straight past.
