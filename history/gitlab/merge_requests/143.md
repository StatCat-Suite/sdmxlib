A standing design note capturing the rubric from the JSON-typing discussion, so future "how should I type this payload / should I parse it?" calls have a reference instead of being decided ad hoc.

Covers:
- The spectrum: `bytes -> Any -> object -> JSONRO -> TypedDict -> domain object`.
- **Rule zero**: mutable ⟹ invariant — you can't have a precise *buildable* JSON type, which is why the writers keep `dict[str, Any]` (SERIAL_DICT) and a recursive type belongs on the *read* side (#176).
- The core decision — **parse to a domain object** vs **stop at a strongly-typed tree** — with criteria and the two failure modes (over-parsing = #159/#160 round-trip gaps; under-parsing = navigation ceremony everywhere).
- Where sdmxlib sits: structural = domain objects; parse boundary = transient tree; the `index` = `dict[str, object]` (#169, not JSON); reference metadata = the hybrid zone.
