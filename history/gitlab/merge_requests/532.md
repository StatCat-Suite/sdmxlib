`TimeDimension.representation` is an ordinary `Facet`, so any `DataType` was accepted and written. That is schema-invalid in every format: 2.1, 3.0 and 3.1 all type the time dimension's format `TimeTextFormatType`, whose `textType` is the `TimeDataType` enumeration (`ObservationalTimePeriod`, `GregorianYear`, `ReportingQuarter`, `DateTime`, …). IMF publishes 54 DSDs declaring `String` there.

## Fix

The rule is format-independent, so `validate()` refuses it (`_check_time_text_type`) rather than each writer. Coercing the value to `ObservationalTimePeriod` would invent data.

## Tests

- **Schema differential.** The allowed set is a constant. `test_time_text_type.py` reads `TimeDataType` out of all three vendored schemas and requires equality; the enumeration is identical in all three.
- **Discrimination.** `String` is refused; each of the 17 time types is accepted, and so is no `textType`.
- **Every format.** Serialising IMF's shape is refused in 2.1, 3.0, 3.1 and JSON rather than written invalid.
- **Populated gate.** New case `time_dimension_text_type_string`.

Sabotage-checked: adding `String` to the set fails 12 tests.
