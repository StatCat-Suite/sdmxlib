Part of #200. Both SDMX-JSON readers decoded their outer envelope untyped and navigated it by hand:

```python
doc = msgspec.json.decode(data)          # -> Any, no type=
payload: dict[str, Any] = doc.get("data") or {}
...
dtos = msgspec.convert(data.get("codelists") or [], type=list[CodelistJson])   # x18
```

Adds `StructureMessageJson` / `StructureDataJson` (one field per top-level section, all 18) and `MetadataMessageJson` / `MetadataDataJson`, so a message decodes in **one** typed pass.

Every per-section DTO import in `reader.py` became unused, as did `typing.Any` — ruff removed all nineteen, which is the tidiest confirmation the conversion is complete.

## Two error-behaviour fixes

`[1,2]` and `{"data": [1,2]}` previously raised **`AttributeError: 'list' object has no attribute 'get'`** — an internal leak rather than a statement about the input. Both now raise `msgspec.ValidationError`.

Five other malformed inputs keep the same exception type but gain the full path:

```
Expected `str`, got `int` - at `$[0].id`
Expected `str`, got `int` - at `$.data.codelists[0].id`     <- now
```

## Preserved behaviour, now tested

Absent `data` key, explicit `"data": null`, and unknown sections (a producer emitting something sdmxlib does not model must not be fatal). msgspec ignores unknown keys, and both `data` fields are optional so the old `doc.get("data") or {}` tolerance is exact.

Every section field defaults to `None` rather than `[]`, keeping "the producer said nothing" distinct from "the producer sent an empty list".
