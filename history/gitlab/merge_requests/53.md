The audit flagged that several ruff and basedpyright disables had weak ("too noisy") or no rationale comments. Each entry now explains the trade-off so a future reader can re-evaluate it without reverse-engineering from the codebase.

### ruff.toml — expanded rationales
- **\`PLR2004\`** — every literal-in-comparison in this codebase is genuinely meaningless to name (HTTP 200, \`row[0]\`, \`len(parts) != 3\`, version checks). The rule has no severity dial, so naming each call site would mean hundreds of noqas.
- **\`ERA001\`** — false-positives on worked examples in docstrings (\`# >>> \`, \`# foo = bar()\`) and SQL fragments inside long docstring blocks. Genuine dead code is caught in review.
- **\`TC\`** — point at PEP 749 (accepted for 3.14) by name; until 3.14 is our minimum, eating a few non-\`TYPE_CHECKING\` annotations beats churning every import block twice.

### pyproject.toml — basedpyright config explained
- **\`typeCheckingMode = \"standard\"\`** (not strict) — explain that strict-only rules (\`reportUnknownMemberType\` etc.) fire on every \`duckdb\` / \`lxml\` / \`pyarrow\` touch. Strict-mode rules we *do* want are turned on manually via inline \`# pyright: ignore\` opt-outs.
- **\`reportUnusedCallResult = false\`** — explain it's off because \`pytest.raises\` is the only thing in this codebase that triggers it.
