Closes #510.

`Query.filter` compared a predicate's columns by **table**. Every maintainable roots at `sdmx.artefact`, so a predicate built from a sibling root passed the check and was planned from the wrong relation:

```python
reg.query(q.dataflow).filter(q.codelist.agency == "ZZ")       # answered for dataflows
reg.query(q.dataflow).filter(q.dsd.dimensions.id == "UNIT")   # [], silently
```

**Fix**
- Accessors and columns now carry their **origin**: the root accessor class they were reached from. It is inherited through hops and passed from `Localised` to the labels it makes.
- `filter` refuses a predicate whose origin differs from the query's root by table or by discriminator. The message names both in `sl.q` spelling.
- `q.artefact` has no discriminator, so it still fits any maintainable.
- The planner's own §9.1 rebase clears the origin of the columns it re-roots, because the caller's predicate has already been checked.

**Decision (yours):** refuse any sibling root, not just hops. This reverses `test_two_roots_over_the_same_table_still_compose`. The runtime now agrees with the row kind the type checker already enforced. It is breaking, so `fix!`, and recorded in `upgrading.md` and `llms-dsl.txt`.
