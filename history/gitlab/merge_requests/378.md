## §5.13 decided, filed as #340

A query over a `RestRegistry` scans the whole materialisation store, so rows from an earlier question — or a previous session with `store=` — answer alongside the current fetch. Measured on `main`:

```
provider serves: ['CL_LIVE']
query answers:   ['CL_LIVE', 'CL_RETIRED']    # store still holds a withdrawn artefact

request: version=latest  ->  CL_V(2.0)
query:   [CL_V(1.0), CL_V(2.0)]               # store holds both
```

**Decided:** a query answers only from rows its own fetch wrote; version behaviour follows.

**Not built here**, and the reason is structural rather than effort: the obvious `WHERE fetched_at >= <watermark>` needs a value that does not exist when the SQL is compiled. Terminals compile first and fetch second, and `to_sql()` is contractually non-executing with output documented as handable to another library — so neither triggering the fetch inside it nor emitting a sentinel parameter is acceptable. #340 records the two designs that do fit (a membership table keyed by `canonical_key`, compile-time knowable; or reordering terminals to fetch before compiling) and the trap either must avoid — a cached question re-runs without re-fetching, so a scope derived from "rows written just now" returns **empty**, the same silent failure `detail=allstubs` had in !377.

Worth noting what is **not** broken, since it narrows the fix: a *filtered* query is fine. The predicate re-applies locally over the materialised rows, so an earlier question's rows filter back out. The hole is unfiltered scans and projections.

## Cassette hygiene

Chasing §5.14's `allstubs` claim turned up two cassettes whose tests no longer existed — and they held the suite's **only** recorded `allstubs` requests, so they read as evidence against a design section that was right. A guard now fails when a cassette is neither replayed by a same-named test nor declared as evidence.

**The guard found two more on its first run** that my hand search had missed. **Then it produced a false positive that broke `test_query_closure.py`**: one of the four is not a replay at all but a *fixture* — a recorded ECB response that `test_the_depth_rule_matches_what_the_wire_returns` reads **by URL pattern** to pin the `references=` rule against what a provider really returns, rather than against a reading of the spec. No grep for its filename could have shown that.

It is restored, and the `_EVIDENCE` allowlist now states the dependency — which had been discoverable only by deleting the file and seeing what broke. That is the argument for the allowlist being the point of the file rather than an escape from it. A second test fails if a name is left in `_EVIDENCE` after its file is gone, so the list cannot decay in the other direction either.

Net: 3 cassettes deleted, 1 restored and declared.
