Closes #507. The issue was broader than filed.

A `TimeDimension` with no format was written **schema-invalid to every format**, not just SDMX-JSON:
- SDMX-ML 2.1, 3.0 and 3.1 all failed XSD validation, because `TimeDimensionType` has a mandatory `LocalRepresentation`.
- SDMX-JSON's reader refused what its own writer had just written.

Every format requires the time dimension's format and defaults its type to `ObservationalTimePeriod`.

**Decision (yours): the model holds the default.**
- `TimeDimension.representation` is now always a `Facet`. `to_time_format` turns `None` into `Facet(type=ObservationalTimePeriod)`, as #503 does elsewhere.
- **Writers:** SDMX-ML writes the minimal `<TextFormat/>`; SDMX-JSON states the type, because its schema gives `dataType` no default.
- **Readers:** a document that omits the format reads as the default, and a new `ASSUMPTIONS` row in each reader records it in `msg.assumed` (#474). The JSON reader now refuses a time dimension only for a missing concept.
- **Breaking:** `td.representation is None` no longer happens. Recorded in `upgrading.md`.

**Tests**
- `test_time_dimension_format.py` writes a time dimension with no format to SDMX-ML 2.1, 3.0, 3.1 and SDMX-JSON, validates each against its schema, and reads it back. All five tests fail on the old model.
- The assumption tests gain a removal for the new rows.
- Four tests that pinned `None` now pin the default.

**Checks:** `just ci` is green, including the bundle tier.
