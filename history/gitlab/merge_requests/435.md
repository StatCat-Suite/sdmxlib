# 1. Querying Structural Metadata

Sixteen sections, each building on the last:

> three parts of a query → filtering → terminals → **paths** → projection → localised text → text search → fan-outs → hierarchies → order and cursor paging → grouping → windows → subqueries and set ops → one-directional relations → seeing the SQL → the same query over REST → the raw-SQL escape hatch

Paths get the pivot position, because they're the idea everything else rests on: `q.code.codelist.id` is a hop, and by then the reader has written enough root-only filters to feel what it saves.

### Two things it teaches that are easy to get wrong

- **`.le(1)`, not `<= 1`, on a window.** `<=` there would have to return something that is both a predicate and a value.
- **`q.codelist.components` does not exist** while `q.component.codelist` does — the edge graph exposes each foreign key from the side that holds it. That gets its **own section**, because a reader who doesn't know it concludes the question can't be asked at all.

### The fixture

Small enough to hold in your head, shaped so every section has something real to find: a tree three levels deep, annotations on some codes and not others, two structures sharing codelists, and `CL_RETIRED` referenced by nothing — because "what is orphaned" needs an answer that isn't the empty set.

# 2. Querying Observations

The companion. Same path language rooted at a dataflow, so the overlapping sections are short and the space goes to what is genuinely different. Three things are only true on this side:

- **A binding is the link.** Structural artefacts live in the registry's tables; observations do not. Once you know the column map exists, every later example reads differently — `obs.col("REF_AREA")` is unchanged when the column is called `geo_code`.
- **Components are checked, columns were not.** The interface this replaced took SQL text, so a typo became a database error at the wrong layer. The page shows the `KeyError` and its list of valid ids, because that check is the reason the API exists.
- **Labels need the structure.** Names live on codelists, not in the observation table. The language is always in the column name — `area_label_en` even when you ask for one — so adding a second later cannot rename the first.

The `mean` example rounds in polars rather than in the query, and says why: the boundary between what runs in the database over rows you never materialise, and what happens after `.collect()`, is worth drawing deliberately. The fixture uses real inflation values so that section is a real boundary rather than ceremony.
