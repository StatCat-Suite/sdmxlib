Part of #422. Removes the `str:MetadataTarget` loss row.

## What changes

- **Model.** `MetadataTarget.target_objects: tuple[TargetObject, ...]` holds every target object of a 2.1 `<str:MetadataTarget>`, in document order. Each is a new `TargetObject(id, kind, object_type, representation, annotations, uri)`.
- **Breaking, with no compatibility shim.** `component_id`, `kind`, `object_type`, `representation`, `component_annotations` and `component_uri` move from `MetadataTarget` to `TargetObject`.
- **2.1 validation:**
  - A target with no target object is refused, as the schema requires.
  - A `ReportPeriodTarget`'s representation is now checked as a `TimeDataType`, which is what 2.1 types it as. Before, it was wrongly refused for not being one of the four reference types, so the maximal MSD couldn't be written to 2.1 through `serialize`.
- **No URN pair on `TargetObject`.** In 2.1 a target object's URN class depends on its kind, so there are five classes for one model class, and nothing in the model references one by URN. It is exempted in `test_item_urn_classes` with that reason.
- **No storage change.** The store keeps the 3.x MSD without the 2.1 layer, as already declared in `gaps.py` (#421).

## Decisions (asked)

- One `TargetObject` class, rather than a class per kind.
- The field is called `target_objects`.
