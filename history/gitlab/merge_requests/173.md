Swaps the SDMX-JSON 1.0/2.0 **data plane** from orjson to msgspec, completing the msgspec migration for the data-message path (`data_v1.py`, `data_v2.py`, `_data_common.py`).

## What changed

- `orjson.dumps(...)` → the shared `_dto.ENCODER.encode(...)`; `orjson.loads(...)` → `msgspec.json.decode(...)`.
- Dropped `orjson.OPT_SERIALIZE_NUMPY` on the batch hot path: per #179, Polars `.to_list()` already yields Python-native scalars (int/float/str/None), so no numpy encode hook is needed.
- The brace-splicing streaming strategy is unchanged — msgspec emits the same compact `{...}` shape orjson did.

## Correctness

Output is **semantically identical**. The one wire-format difference between the encoders is float formatting of extreme exponents (`1e+20` vs `1e20`) — the same JSON number, and the data writer tests decode-then-assert (not byte-compare), so it's invisible. Full data-plane suite (99 tests) + full unit suite (**2427**) pass.

## Performance (back-to-back on one machine, stash on/off)

| bench | orjson | msgspec | Δ |
|---|---|---|---|
| dot_stat json_v2 | 2.398 ms | 2.539 ms | +5.9% |
| **large_100k json_v2** | 30.44 ms | 29.89 ms | **−1.8%** |

The throughput-representative `large_100k` case is flat-to-faster. The sub-3ms `dot_stat` microbench moves +5.9%, but its stddev (~2.8 ms) exceeds its median — that's noise, not a regression. Meets the #179 ≤5% gate.

## Scope

Only `sdmx_json_1_0/writer.py` (the 1.0 ContentConstraint `/availability` downgrade writer, **#184**) still imports orjson. The entire SDMX-JSON **2.0** layer is now orjson-free.
