## Two findings worth calling out

**The storage helpers are not `MaintainableArtefact`.** My first attempt typed all five group-1 sites with the concrete base. basedpyright rejected it: `DataflowBinding` reaches `_put_spine` and is *not* a MaintainableArtefact, and `put_artefact` already declares `SupportsUrn`. The Protocol's own docstring names `DataflowBinding` and `MetadataSet` as deriving cases. So the storage seam is `SupportsUrn` and the XML writer's is the concrete base — a distinction the `Any` had hidden.

**A `getattr` guard that wasn't narrowing.** `write_maintainable_attrs` did:

```python
if getattr(obj, "valid_from", None) is not None:
    el.set("validFrom", obj.valid_from.isoformat())   # direct read
```

The guard lands on the `getattr` call, not on `obj`, so the direct read was unchecked. Now binds annotated locals.

## Why unions rather than Protocols

For groups 2 and 4 the members differ in *member types*, not in shape — `RepresentationMap.source` is `MapEndpoint | None` where `ConceptSchemeMap.source` is `AnyRef | None`; `maps` is `tuple[ValueMap, ...]` vs `tuple[ItemMap, ...]`. A Protocol would have to widen those to their join and would lose the concrete type at each branch. A union keeps `isinstance` narrowing working.

`polars.py` already spelled the component union inline. It keeps a **deliberately narrower** one — now commented — because the time dimension is Facet-only and handled by its own branch in `schema()`. Widening it to `Component` was a type error, which is the check doing its job.

## Group 7: matching the existing solution

#203 proposed a `TypeIs` helper for the `attrs.has(type(obj))` walkers. `InMemoryRegistry._walk_refs` had already solved it — bind `cls = type(obj)` once, take `obj: object` — and documented why the TypeGuard can't be carried from a discarded call expression. Introducing a second mechanism for one call site would be worse than matching the sibling.

## The one site left: `ingest_registry` (group 6)

Not done, and I don't think it should be typed. It has **zero callers** in `src/` or `tests/`, is not exported from any `__init__`, and appears only in `design/storage_schema_spec.md` and an archived spec. It is dead code whose body reaches into `registry._store` (also #198's SLF001 scope).

Typing it means typing code nobody runs. Deleting it is the honest option — pre-1.0, and CLAUDE.md's no-legacy stance supports it — but it is referenced in a live design doc as a planned batching point, so that is your call. Say the word and I'll delete it in a follow-up, or type it against `SupportsGetAll` + `ARTEFACT_KINDS` if it's wanted.

## Comments

### 2026-08-05

**`ingest_registry` deleted — #203 is now fully closed (13/13).**

I traced its history before removing it. `git log -S "ingest_registry("` across *all* revisions returns only the commit that added it (`140fc52`, April 2026, closing #34). **It was never called, in any revision — it was born orphaned.**

It came from `SHARED_STORAGE_SPEC.md`, which planned `LocalRegistry` as a thin wrapper delegating bulk import to the storage module:

```python
def ingest(self, registry: Registry) -> None:
    writers.ingest_registry(self._conn, registry)
```

What actually shipped was:

```python
def ingest(self, registry, *, source_registry=None) -> None:
    self.add_all(registry._store.values(), source_registry=source_registry)
```

`add_all` already batches and already threads `source_registry` — a parameter the spec's signature predates — so the wrapper had nothing left to do. The spec's other intended consumer, `ingest_sdmx()`, never materialised either.

**Stale spec line fixed.** `storage_schema_spec.md` still listed *"Batch `ingest_registry()` into a single transaction"* as Phase 7 work — planning for a function whose replacement had already shipped. Corrected with a note on why.

**What this does *not* fix:** the `_store` reach-in. `Registry.ingest()` does the same thing with a live `# noqa: SLF001`, on the public API path. That one is real and belongs to **#198**; `ingest_registry` was only an unused second copy of it.
