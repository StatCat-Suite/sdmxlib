# Merge request !615: fix(sdmx-json): carry the dataflow's annotations in data messages

| | |
| --- | --- |
| State | merged |
| Opened | 2026-10-16 |
| Merged | 2026-10-16 |

A data message wraps a dataflow, but the dataflow's annotations never reached it: `structure.annotations` held only component and value annotations (#366).

.Stat's Data Explorer reads `NOT_DISPLAYED` (attribute values to hide in the table) from that pool, and the .Stat NSI web service fills it from the dataflow, with the dataSet referencing the entries. Without it there's no way for a publisher to hide e.g. `OBS_STATUS=A` flags in the Explorer's table.

Both SDMX-JSON writers (1.0 and 2.0) now:
- pool the resolved dataflow's annotations **first**, so their indices are final when the dataSet head is written ahead of the observations;
- reference them from `dataSets[].annotations` (an integer array in both schemas).

An unresolved ref, or a dataflow without annotations, changes nothing (no new keys). Tests cover both writers, schema validity, interning against a value carrying the same annotation, and the unresolved case. `just check` clean; unit suite 6925 passed.

Motivated by the CSIP Explorer's per-cell `A.F` flags (srmd/sdmx/infra/test-census#8). Intended as a patch release (0.67.1) so consumers pinned `<0.68` pick it up.
