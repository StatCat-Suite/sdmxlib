## The re-scope

#198 proposed four per-file ignores, on the reasoning that these files legitimately reach into the package's own internals. That describes **7** of the 34 sites. The other **27** are a single different pattern:

```python
instance = cls.__new__(cls)
instance._uri = registry.uri    # noqa: SLF001
instance._conn = ...            # noqa: SLF001
```

An alternate constructor setting **its own class's** private state.

Writing "this file intentionally reaches into other objects' internals" over `data_store.py` and `catalog.py` would have been false — 100% of their suppressions are self-construction — and would have blanket-silenced any *future* genuine violation there.

## The insight that fixed it

`_x` is private to the **class**, not to the instance. That is why `self._x == other._x` inside `__eq__` is ordinary Python — and ruff already knows it. Probed directly:

| access | flagged? |
| --- | --- |
| `other._x` inside `__eq__` (same class, other instance) | **no** |
| `inst._x` inside a classmethod, on a local | **yes** |
| `c._x` from a different class | yes — correct |

So this was never a rule disagreement. It is a **type-inference gap**: ruff cannot tell that a bare `cls.__new__(cls)` local is an instance of the enclosing class. Tell it, and the finding goes away:

```python
instance: Self = cls.__new__(cls)
```

All 27 disappear. Applied to `catalog.py`, `local/data_store.py`, `local/registry.py`, plus `model/istring.py:41` — which #198 had already flagged as "arguably a ruff limitation" without connecting it to the other 27. That is 28.

Worth being explicit: this is **not** contorting code to appease a linter. It adds a type annotation, which this codebase wants regardless. The alternative considered — rewriting the constructors to take `self` — *would* have been contortion, and I'd have been changing correct code to satisfy a false positive.
