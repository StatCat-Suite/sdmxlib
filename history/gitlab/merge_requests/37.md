## Summary

Phase 1 of #75 — failing reproducer tests for the concurrent-read corruption. No production code changes.

Locks in two distinct failure modes (cursor race + cache-hit hot loop) before the fix in #78 lands, so we can demonstrate the bug today and prove the fix later.

## What this MR adds

- `tests/unit/test_concurrent_reads.py`:
  - `test_concurrent_get_identity_mixed_urns` — 16 workers × 800 mixed `reg.get(urn, eager=True)` calls released by a `threading.Barrier`. Asserts every returned artefact's `.id` matches the URN requested.
  - `test_concurrent_get_cache_hit_invariant` — 32 workers × 400 reads of the *same* warmed URN. Canary for the FIFO-cache change in #78.

## Failure on main

Suite fails **9/10** runs against `main` (v0.27.2). Dominant failure mode:

```
AssertionError: missing artefact for 'urn:sdmx:org.sdmx.infomodel.datastructure.DataStructure=SDMX:DSD_2(1.0)'
```

`reg.get(urn)` returns `None` for a URN that's definitively in the registry — the shared cursor's row buffer is clobbered by another thread's `execute()` between this thread's `execute()` and `fetchone()`. The identity-mismatch path (artefact populated from a different URN's rows) is guarded by the same assertion and would surface if DuckDB happened to leave a non-empty wrong-shaped buffer instead of an empty one.
