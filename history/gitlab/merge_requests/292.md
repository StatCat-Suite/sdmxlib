Follow-up to !291 (#222), fixing a defect that merge introduced and the suite did not catch.

`test_label_search_agrees_with_python` compares against a Python model that folds case on both sides:

```python
needle.lower() in label(c).lower()
```

Both the labels and the needles are drawn from `_WORDS = ["alpha", "beta", "gamma", "delta"]` — one case family — so the fold is a no-op and the assertion cannot distinguish `LIKE` from `ILIKE`. It went on asserting the **pre-#222** semantics after #222 removed them, and stayed green, including through a 20x `just test-properties` run.

This is the same trap `tests/support/oracle.py` documents for `casefold`, reached by a different route: the strategy only generates input on which the two candidate behaviours agree.

## Fix

- `_WORDS` is mixed case.
- Needles are case-mutated copies (`swapcase` / `upper` / `lower` / identity), the same device !291 added to the other two property files.
- Both rungs asserted — plain against an exact model, `.caseless` against the folded one.

## Verified

Reverting `Fold.NONE` to `ILIKE` now fails this property. Before this commit it did not — that probe is exactly what found the gap, and !291 ran it against `code_query` and `hierarchy_query` but not here.
