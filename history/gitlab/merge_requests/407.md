Follow-up to !406. That census asks "does every field survive" of a *synthetic*
message. This asks it of real ones — eleven sources from the OECD, ECB, BIS, IMF
and the SDMX Global Registry, 2.1 and 3.0, replayed from cassettes.

## Chosen for model coverage, not size

A 37 MB Eurostat dataflow listing is breadth of *dataflows*; a 7 KB registry
hierarchy is breadth of the *model*. Each source was picked by probing the
provider and measuring which message slots a response actually fills against
its byte size. Between them they cover thirteen artefact kinds: codelists,
concept schemes, DSDs, dataflows, agency schemes, category schemes,
categorisations, provision agreements, hierarchies, hierarchical codelists,
metadata structures, representation maps, data provider schemes.

Three things keep that honest:

* each source declares the slots it exercises, **asserted** — a provider
  quietly returning an empty document fails rather than passing over nothing;
* `test_the_corpus_covers_the_artefact_kinds_providers_publish` holds the union,
  so a source going dark is a coverage failure, not silently fewer assertions;
* a companion test names the eight slots the corpus does **not** reach and why
  (endpoint 404s, 2.1-only container, or a 95 MB `dataconstraint` response not
  worth a cassette), so "no provider publishes this" stays distinguishable from
  "we never looked".

## What it compares

`parse(x)` against `parse(write(parse(x)))` — model to model. A byte diff would
report attribute ordering and namespace prefix choice, which is not information
anyone lost, and would say nothing about what matters. Emitted bytes are
XSD-validated separately, which catches the opposite failure: non-conformant XML
our own reader happens to tolerate.

## It found a bug on the first run

**The 2.1 writer emitted `<MetadataStructures>` out of sequence** (#356). 2.1's
`StructuresType` fixes the section order — MetadataStructures belongs after
Concepts — and the writer had it third, right after Metadataflows. Any message
carrying an MSD *together with* a codelist, concept scheme, category scheme or
hierarchy was rejected by the XSD.

An MSD on its own was fine, which is why every fixture passed: they all had only
an MSD. A real `metadatastructure?references=all` response arrives with its
concept scheme attached — the ordinary shape from any provider. Not an exotic
field; just a combination no fixture author thought to build, which is precisely
what this corpus is for.

## Checked that it discriminates

Not assumed — planted against the recorded cassettes:

* reverting the section-order fix → `test_what_we_write_back_is_schema_valid[imf-msd]` fails;
* planting a dropped `Code.description` → three round-trip cases fail with
  `codelists.codes[].description  ('<1 items>' -> '<0 items>')`.

## Notes

* `field_census.generalise` strips collection indices, so one register entry
  covers a loss in every artefact of a message.
* The tolerated-loss list here is a strict subset of !406's register, tracked by
  the same issue (#355). It is shorter only because real providers do not
  populate every field a fixture can — a loss absent here means nothing in the
  corpus exercised it, not that it is fixed.
* Cassettes are 4.9 MB and replay offline in ~1 s. `sdmx.oecd.org` answers 403
  to urllib's default User-Agent, hence the explicit header.
