Design §5.14. #318 derived when a stub answers a query and **tested** the derivation — but `requests_for`'s `projection` argument defaulted to `None` and the only production caller supplied none, so **`allstubs` never once fired**. Coverage of a thing nobody ran.

## The rule

Already written in `request_for`'s own comment: `None` means the caller wants *artefacts*, and a stub has no items. So `Frame` — which **is** the projected query — supplies its columns, and every other terminal supplies `None`.

`ids()` could in principle narrow and deliberately does not: it is not a projection, the saving is small, and the failure mode is silence.

## Two things a test caught that §5.14 did not mention

**A projection's paths are not in the plan.** `closure(plan)` is derived from predicates and order, so `select(codes=q.codelist.codes.id.list())` reached `detail_for` with an empty path set and came out `allstubs`. It would have returned **empty lists, silently** — the exact failure `detail_for` documents, arriving by the one route nothing was checking. `_projection_columns` now refuses anything that is not a plain column on the root: keep the saving where it is obviously sound, give up rather than guess elsewhere.

**The derived detail belongs in the fetch key.** The key is `canonical_key(plan)` and the projection is not part of the plan, so a `select(id)` fetch marked the question done and a later `collect()` skipped its own fetch — resolving artefacts whose items never arrived. Keyed on the detail, with `full` subsuming `allstubs` (everything a stub carries is in a full artefact).

## The trade, stated rather than buried

A caller mixing a projection with an aggregate over one plan now pays a round trip that asking `full` throughout would not. `test_projection_and_aggregation_work_over_rest` asserted the old one-fetch behaviour; it now states the new one and why.

Taken because the payload difference runs the other way and is much larger. Measured on the recorded cassettes: one **full** codelist is 75,848 bytes, while an **allstubs** listing of *every* codelist is 96,609 — so a full scan carries every code of every codelist where the stub listing carries none.
