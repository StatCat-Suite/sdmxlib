## Summary

Bundle-architecture data-plane changes plus two integration-suite bug fixes.

### DataflowBinding
- New `database_role` field (default `"lake"`) and `from_dsd(dsd, *, dataflow, schema, table, ...)` classmethod that derives identity column maps from the DSD.
- Stored `table_location` no longer embeds the database alias; the resolver prepends `database_role` at query time as `<role>.<schema>.<table>`.
- Bindings schema gains a `database_role` column; writers/readers updated.

### DuckDBDataStore
- `write_observations(*, schema, table, source, mode, ...)` writes Polars / Arrow / DuckDB relations into a DuckLake-managed table via the ATTACHed lake. Auto-creates schema; supports `overwrite` + `append`.
- New `azure_credentials=` kwarg: installs+loads the azure extension on demand. Three credential shapes — `connection_string`, `service_principal`, `credential_chain`. `CREATE OR REPLACE SECRET` keeps re-opens idempotent.

### ATTACH grammar fix
- DuckDB requires options *after* `AS alias`: ``ATTACH '<url>' AS <alias> (<options>)``. The previous template baked everything into `spec` and produced invalid SQL.
- Widen the attach value type to accept `(url, options)` tuples; strings continue to mean URL-only. `FederatedCatalog.open()` switched to the tuple form.
- `FederatedCatalog.open()` now reads `<uri>/meta.duckdb` (was `registry.duckdb`).

### Storage bug fixes
- `_put_refs` failed with a PK constraint error when a DSD enumerated the same codelist from multiple dimensions (e.g. ECB's CURRENCY + CURRENCY_DENOM → CL_CURRENCY). Per-dimension ordinal info is recoverable from `dsd_component.position`, so collapse duplicates with `ON CONFLICT DO NOTHING`.
- Three integration tests still called `code_map("en")` / `column_labels("en")` / `dsd_code_map(urn, "en")` / `collect(with_labels=True)` / `ds.label("FREQ")` positionally, predating the keyword-only `lang=` tightening. Updated to current signatures.
