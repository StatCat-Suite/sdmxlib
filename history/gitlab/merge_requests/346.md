Asked while sizing `stream()`'s `chunk_rows`: if a query's `ORDER BY` is
what makes a stream unbounded, store the rows sorted so it is not needed?
Yes — and for none of the obvious reasons, which is why the measurements
are in the docstrings.

**Sorting at ingestion does not let DuckDB skip a sort.** No
read-in-order optimisation for base tables, so an `ORDER BY` over
already-sorted rows still sorts: 102 MB against 251 MB shuffled at 4M
rows. Cheaper, because sorting nearly-sorted input is nearly free; not
free. ClickHouse's table `ORDER BY` *is* its primary index and can serve
such a read with no sort at all; DuckDB is in Iceberg's and BigQuery's
group, where the layout prunes and compresses and the engine still sorts.

**A sorted scan comes back in order only by accident.** It does while
`preserve_insertion_order` is true — the default, and exactly the setting
a caller turns off for a large result. With it false the ordering goes
and the memory does not move. So this is a planning hint and never a
guarantee, `stream()` keeps dropping the `ORDER BY` rather than trusting
the layout, and a test pins it: it would otherwise hold everywhere except
the one configuration someone reaches for under load.

**It costs about 2.5x on the way in** — 82 ms against 33 ms and 342 MB
against 132 MB at 4M rows — so `sort_by` is opt-in. Paying once at write
for every read is usually right, and it is not right when ingestion is
the memory-constrained step.

`DataflowBinding.sort_order` declares it beside `partition_layout`, which
had no counterpart for ordering though Iceberg carries both.
SCHEMA_VERSION 2.11 -> 2.12.

`sort_by` takes physical column names, because this method holds a source
and a target and never a binding — an SDMX id would have nothing to
resolve against. Passing one anyway is the likelier mistake, so the
refusal says which it is rather than only that the column is missing.

An append sorts only what it inserts, leaving the table sorted in runs;
that is what every append-structured store does and why they all compact.
Said out loud in a test, because a reader of `sort_order` would otherwise
expect a global guarantee.
