Follow-up to #300. Two things wrong as merged, both found by asking whether there is now exactly one way to obtain a handle. There is not — there is one **handle**, reached four ways, and the fourth was under-described.

| how | releases? | who uses it |
| --- | --- | --- |
| `reg.session()` | yes (outermost block) | custom SQL |
| `reg.execute()` | yes (wraps `session()`) | one-shot custom SQL |
| `session.handle` | n/a — raw object inside a block | escape hatch |
| `cursor_for(base)` | **no** | **every DSL query** |

**`cursor_for` was in `sdmxlib.session.__all__`.** It hands out an *unmanaged* handle — no scope, no release. It must stay importable, since `_query_common` and `storage.lazy` resolve at execution and cannot wrap themselves in a block, but that is package-internal API and `__all__` is where the distinction belongs (CLAUDE.md rule 4, and the contract #265's guard reads). Removed from `__all__`; still importable.

**`open_sessions` counts handles, not `with` blocks.**

```
reg.open_sessions        # 0
codes.ids()              # 1   implicit, and not released
with reg.session(): ...  # 0   after the block
codes.ids()              # 1   a fresh one
```

Correct behaviour — one handle per live thread is the steady state #75/#80 wanted — but the name reads as "sessions currently open", so a caller would take it for requests in flight. The docstring now states what it counts and when the implicit one appears.
