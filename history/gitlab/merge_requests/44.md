## Summary

Prerequisite for the [Cleanup pass](../-/milestones/3) — updates the architecture rules to match how the library actually works today.

The previous CLAUDE.md said "sdmxlib.model depends only on attrs (no other external dependencies)" and "core never imports polars." Both predated polars and duckdb becoming core deps; pyproject already lists them as required. Code_query and hierarchy_query execute against duckdb, the polars bridge is the only blessed observation surface — the install-time justification for the original rule no longer applies.

## Changes
- Architecture-rules section in CLAUDE.md rewritten:
  - Lists \`attrs\`, \`httpx\`, \`lxml\`, \`duckdb\`, \`polars\`, \`pyarrow\` as baseline runtime deps that any module may import.
  - Keeps the layering invariants that still matter: model is pure data + behaviour, no XML/JSON/HTTP/I/O; format layer owns parsing.
  - Clarifies \`sdmxlib.polars\` is the user-facing bridge while model query DSLs may use polars/duckdb internally.
