Two groups off #355's register — and they turned out to be different kinds of
thing, which is the useful part.

## 32 entries were a real bug

`validFrom` / `validTo` survived on a Codelist and vanished on **eight other
maintainables in each of 3.0 and 3.1**: agency and provider schemes, all three
map types, hierarchy associations, MSDs, metadataflows.

`_write_maintainable_attrs` had always emitted them. Those eight writers set
`id` / `agencyID` / `version` by hand instead of calling it, so they never
reached the line that writes validity. The organisation schemes had a reason —
their version is schema-fixed — and the other six had none anyone recorded.

`_write_validity` now runs in all sixteen. Output still XSD-validates in both
versions, and dropping any single call fails the census.

## 16 were never a bug at all

#355 listed `HierarchicalCode.name` / `.description` as its **highest-value
fix** — "user-facing labels lost silently in all four formats". That was wrong,
and the schemas say so unambiguously: a `HierarchicalCode` is **Identifiable,
never Nameable**. `HierarchicalCodeType` derives from `IdentifiableType` in all
three SDMX-ML versions and in SDMX-JSON 2.0 and 2.1, declaring only Code /
HierarchicalCode / Level plus validity. There is no `Name` element to write to.

The displayed name belongs to the *code the node references*
(`node.code().name`), so no reader loses anything. We keep the fields because
the DuckDB store carries them and `q.hcode.name` queries them — a locally-built
hierarchy may name its nodes even though no SDMX document can. Declared in
`gaps.py` for all four targets.

Worth noting the references disagree and neither contradicts the schema: sdmx1
gives `HierarchicalCode` no name and reaches through `code`; pysdmx carries one
whose own docstring says it is the referenced code's.

## How to read progress on #355

The register's raw size is **not** a progress bar. It counts declared limits and
real bugs together, and it *grew* for SDMX-JSON during the release work as
limits were declared instead of emitted. What moves is the undeclared
remainder — 3.0 and 3.1 are each down sixteen.
