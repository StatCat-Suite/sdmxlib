`Accept` was hardcoded to `text/csv`, so a download's path extension was decorative and **SDMX-ML data could not be requested at all**.

## What lands

- **`sl.DataFormat`** — a `StrEnum` of the eleven data formats the standard defines, valued by media type. A member *is* its media type, so it goes straight into a headers dict.
- **`RestRegistry.download(flow, *, fmt, key=…, start_period=…, end_period=…, to=…)`** — byte-faithful passthrough. Nothing parses, validates or reorders the body; that is what separates it from `observations()`. Returns `bytes`, or the `Path` when `to=` is given (streamed in chunks, never held whole).

## Course correction: not a `(media type, version)` pair

The design said "an explicit `(media type, version)` argument". The vocabulary refuses that shape:

- SDMX-ML 2.1 carries data under **four** media types — generic / structure-specific, each plain or time-series — so `("xml", "2.1")` names no single format
- `application/vnd.sdmx.data+xml` did not exist before 3.0, so the pair cannot be normalised into one either
- `("csv", "3.0")` names nothing at all

An enum makes exactly the real formats expressible. pysdmx reached the same conclusion; our member list is compared **against theirs** rather than against itself. sdmx1's `MEDIA_TYPES` covers the same ground but omits SDMX-CSV 2.0.0 and 2.1.0 — the version our own writer emits — so it was the wrong oracle here. §2 of the design records the correction.

## The two checks that keep `fmt` from being decorative

**Extension vs format.** A destination whose extension contradicts `fmt` is refused *before* the request goes out — `.xml` holding CSV bytes misleads every later reader of that file. This is not inference: extensions sdmxlib does not recognise (`.dat`, `.gz`, none at all) are left alone, since refusing those would be inference wearing a refusal's clothes.

**Content-Type vs Accept.** A response that is not the format requested is refused. Providers that ignore `Accept` are common, and a download has *no downstream step* that would notice CSV 1.0.0 arriving where 2.0.0 was asked for — the columns simply differ. Tolerant of extra parameters (`charset`, `labels`), a padded version (`2.1` == `2.1.0`, since SDMX-ML 2.1's media type is registered unpadded), case, and an absent header.

## One request

A download needs no DSD — there is no key to widen and no columns to interpret — so it costs exactly one request. That is the sharpest statement of how it differs from `observations()`, and it is asserted rather than described.
