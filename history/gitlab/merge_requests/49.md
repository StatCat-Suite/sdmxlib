## Summary
17 files, +281/−317.

Four independent refactors in one MR — each one stands on its own.

### Single ARTEFACT_KINDS registry
New \`src/sdmxlib/storage/_kinds.py\` owns the (class, name) pair for every artefact kind:
\`\`\`python
ARTEFACT_KINDS: tuple[ArtefactKind, ...]
CLASS_TO_NAME: dict[type, str]
NAME_TO_CLASS: dict[str, type]
\`\`\`
Replaces three of the four hand-maintained dispatch tables (\`_CLASS_TO_NAME\` in writers, the duplicate import + derived \`_TYPE_REGISTRY\` in readers, and the second \`_TYPE_REGISTRY\` import in \`local/registry.py\`). The fourth (write/read function dispatch) stays next to the functions it dispatches to — those can't be hoisted without a circular import — but they no longer carry their own class/name entries.

### Table-driven writer scaffolding
The three format writers (\`sdmx_ml21\`, \`sdmx_ml30\`, \`sdmx_json\`) each had a ~50-line chain of \`if msg.X: container = ...; for x in msg.X: _write_X(...)\` blocks — 36 copies across the three files. Each writer now has a module-level \`_SECTIONS\` list-of-tuples that drives the single loop in \`write()\`. Adding a new artefact still means one new entry; it's just no longer duplicated.

### De-underscore local/
- \`src/sdmxlib/local/_data_store.py\` → \`src/sdmxlib/local/data_store.py\`
- \`src/sdmxlib/local/_registry.py\` → \`src/sdmxlib/local/registry.py\`

Both modules export classes (\`DuckDBDataStore\`, \`Registry\`) that are publicly re-exported from \`sdmxlib.__init__\`. The leading underscore was a lie — these are part of the public API. Imports updated across src/, tests/, docs/.

### RestRegistry.data simplification
~140 lines (C901, PLR0912) → ~50 lines, no suppressions.

- New \`_DataflowSpec\` (frozen attrs) holds \`(agency, id, version, structure, dataflow)\` in one place.
- \`_make_spec_resolver\` extracts the two-branch logic (resolve on every call vs. resolve once eagerly) into a single helper returning a \`Callable[[], _DataflowSpec]\`.
- \`_fetch_data\` + \`_fetch_data_to\` collapsed behind one \`_fetch_data(..., to: Path | None = None)\`. The branch on \`to\` reuses every other parameter via the spec.
- The four inner closures (\`_fetcher\` / \`_streamer\` × two arms) become one pair of one-liners delegating to a shared \`_run_fetch\`.
