Second pass on #211, after !213 took the round-trip harness. This one takes the DataStructure builders — and the interesting result is that **not all of them should be shared**.

## `_make_dsd` — 7 definitions, 2 shared, 5 deliberately left alone

Two (`test_registry`, `test_local_registry_duckdb`) were byte-identical. They are now `factories.minimal_dsd`.

The other five are genuinely different artefacts serving different features: a CPI DSD carrying concepts, one with a measure dimension, a bench DSD with tunable code counts, one with a time dimension. Collapsing those into a single factory would need roughly eight knobs and be harder to read than the duplication it removed. **Left alone deliberately** — a builder used by one test is not duplication, and sharing it would only make the shared module a dumping ground.

## `_build_dsd` — the audit's "all differ" verdict understated it

Three definitions across the SDMX-JSON data modules, ~45 lines each. They are **structurally identical** and disagree only on the codes:

| Module | FREQ codes | Named? | Status codes |
| --- | --- | --- | --- |
| `..._data_readers` | A, Q, M | **no** | unnamed |
| `..._data_v1_writer` | **A, Q** | yes | unnamed |
| `..._data_v2_writer` | A, Q, M | yes | **named** |

Three modules testing one feature family against three different DSDs, with nothing recording why any of it differs.

**The unnamed variant is not cosmetic.** With no name on a code, label lookup falls back to the code id — so the reader module exercises a different code path from the two writer modules. That may be deliberate coverage, or it may be that someone copied a neighbour and trimmed it. Nothing in the repo says which.

The shape now lives in `factories.data_dsd` and each module passes its own codes on one visible line:

```python
return data_dsd(
    freq_codes=FREQ_CODES_BARE,
    status_codes=STATUS_CODES_BARE if with_attribute else None,
)
```

Behaviour preserved exactly. Reconciling the three is a **separate decision** — I have not made it — but it is now a one-line change instead of an archaeology exercise.

## Found on the way: `Ref[X](artefact)` does not typecheck

`Ref(artefact)` is documented and supported — `__attrs_post_init__` derives the URN and interns the object — but the field is declared `urn: SdmxUrn[T]`, so the supported form is a type error for callers. The typed equivalent `Ref[X].to(artefact)` already exists.

**47 call sites across 9 files** use the untyped form. `src/` uses it once. The asymmetry is explained entirely by `src/` being typechecked and `tests/` not being.

The new factories use `.to`. Whether to widen the checkers to `tests/` — and thereby surface all 47 — is a real decision with real cost, and belongs to #212.
