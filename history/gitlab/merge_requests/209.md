## `local/registry.py` — 14 sites, zero code changes

The resolver's `memo`, `pending` and `frontier` were annotated `dict[str, Any]` / `list[tuple[Any, str, Ref[Any]]]` / `list[Any]`, while the concrete class behind the memo — `_CallScopedMemo` — **already subclasses `dict[str, object]`**. The parameters had simply never followed it.

Widening them produced **zero** checker findings. That is what inertia rather than necessity looks like.

## `formats/sdmx_json/structure_values.py` — 10 → 0

The module docstring says it exists so producers and consumers "share one source of truth for the `codelists[*].codes[*]` and `conceptSchemes[*].concepts[*]` entry bodies" — but the shapes were `dict[str, Any]`, so the claim wasn't checkable. Now six TypedDicts (`CodeJson`, `ConceptJson`, `AnnotationJson`, `LinkJson`, and the two `coreRepresentation` variants).

**A TypedDict is a dict at runtime**, so the public contract of the four exported `serialize_*` functions is unchanged.

Two helpers had to stop mutating a caller-supplied dict, since a TypedDict can't be written through a computed key (`obj[key] = ...`). `_emit_istring` became value-returning and `emit_annotations` became `_annotations`. Neither is exported.

Worth recording: **`_emit_istring` duplicated `_dto.emit_istr` exactly** — both reduce to `next(iter(d.values())), d`. Checked before reusing it, precisely because a different primary-language pick would have silently changed emitted JSON. It is now a reuse rather than a second implementation. (There were also two different functions named `emit_annotations` in the package; that collision is gone.)

## `formats/sdmx_json/_data_common.py` — 8 → 4

`components` is a `Component` map, `_codelists` a `Codelist` map, and `display_names` returns a known four-key shape — now `DisplayNamesJson`. The two `getattr` results carry annotations so the `Any` dies on the line, per the CLAUDE.md pattern.

## Verification

Every `Code` and `Concept` in all 22 XML fixtures re-serialised through the public entry points — **5163 entries across 76 groups** — identical to `main` **including nested key order**, plus hand-built edge cases covering every field of every new TypedDict: all 11 facet bounds, both `coreRepresentation` variants, `links`, annotations with all-None fields, and empty `InternationalString`s.

A note on that check: my first run used `json.dumps(sort_keys=True)`, which sorts *recursively* and therefore would **not** have compared entry key order at all — the thing most at risk when a dict construction is reordered. Redone sorting only the outer keys. Baseline runs verified non-vacuous (`git status --short src/` empty after stashing).

`just check` clean; 2496 unit tests pass, including the 23 existing `structure_values` tests.
