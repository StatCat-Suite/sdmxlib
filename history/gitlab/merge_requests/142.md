## #170 — the conversions where an existing type fits (no bespoke protocol)
- `storage.put_artefact(artefact: Any)` → **`SupportsUrn`** (already isinstance-checks it before dispatch).
- ml30/ml31 `_write_maintainable_attrs(obj: Any)` → **`MaintainableArtefact`** (every caller is a maintainable subclass; `valid_from`/`valid_to` are subclass-specific, read off the `getattr` result).
- ml30/ml31 `_write_urn_text` / `_write_concept_identity(ref: Any)` → **`AnyRef`**. The one polymorphic caller (`_write_representation_map`, whose `source`/`target` are `MapEndpoint = AnyRef | MapDataType`) **narrows to the `Ref` variant** — `MapDataType` carries no URN and isn't exercised, so this also removes a latent `AttributeError` (cf. #174).

**Deliberately left as documented `Any`** (per the agreed "high-leverage only" scope): the genuinely duck-typed writer internals — `_write_item_scheme_map`, `_serialize_reported_value`, the JSON `_emit_maintainable_meta`/`_maintainable_obj` (polymorphic over maintainable + scheme-map surfaces), `_write_categories`, `emit_annotations`, and the storage `put_*` spine helpers. Each would need a bespoke small protocol for marginal internal-typing benefit. #170 stays open for that remainder.

## Supports* protocol convention (closes #175)
Adopt the typeshed-style **`Supports<Capability>`** idiom — it reads as *a protocol, not a concrete class*, and drops the lone `_`-prefixed outlier:
- `HasUrn` → **`SupportsUrn`**, `HasId` → **`SupportsId`**, `_HasCodeMap` → **`SupportsCodeMap`**.
- `Maintainable` kept — it names a domain *role*, not a capability.
