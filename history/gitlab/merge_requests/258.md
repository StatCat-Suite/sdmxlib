The predicate AST and ref hierarchy are now generic in a **`RowKind`** — the relation a predicate filters. Named that rather than "dialect" because both DSLs emit DuckDB; what differs is the row shape.

The row kind rides on `CompileContext[R]`, **not** on the predicate, so predicates stay pure data and refs stay pure factories. Callers never name it:

```python
(sl.code.id == "CA").to_sql(sl.code.context())
```

## The guarantee this buys

Both checkers already rejected a cross-DSL *predicate*. They now also reject a mismatched *context* — something we never had:

```python
q.filter(sl.node.id == "A")                     # was an error
(sl.code.id == "A").to_sql(sl.node.context())   # now an error too
```

## Performance vs the !257 baseline (noise floor 1.84%)

| | main | after |
| --- | --- | --- |
| `is_in` × 5000 | 114.0 µs | 114.6 µs (+0.5%) |
| `is_in` × 100 | 6.7 µs | 6.8 µs (+1.3%) |
| predicate chain | 8.2 µs | 8.5 µs (+3.9%) |
| single predicate | 2.0 µs | 2.1 µs (+5.6%) |

The `is_in` numbers are **post-fix**. The shared `_coerce` hook cost **+88% at width 5000** — 5000 identity method calls — until `is_in` learned to skip it when unoverridden. Caught by the baseline; no test would have failed.

The residual 3–6% on the small compiles is real and stable across runs: two extra calls per predicate (`ctx.rows.emit` indirection, `_coerce` on `__eq__`). Left in deliberately and stated rather than hidden — compile is ~1% of a query whose execution is 216 µs, so +0.11 µs is **+0.05% end to end**, and removing it means unpicking the indirection the type safety rests on.

## Three checker findings fixed in code, not suppressed

- `AnnotationLike`, a non-generic base, so `isinstance` needs no type argument — a parameterised generic is not a valid `isinstance` argument at runtime.
- `type` carried on that base rather than redeclared on both subclasses (inconsistent-override).
- `_emit_predicate(pred: object)` — truthful, since it dispatches on `type(pred)` and raises for anything unknown.

## Breaking change

`sl.CompileContext` is generic and requires `rows`; the `sdmxlib.sql.Predicate` Protocol is generic to match. Build contexts with `sl.code.context()` / `sl.node.context()`. Ordinary DSL use is untouched. Per #268, the seam had one construction site in `src/` and four dead fields, so the blast radius is small — but pinaxlib composes against it and should be checked.
