Closes #171. The three near-identical map-reader helpers in the ml21/ml30/ml31 readers — `_read_id_pair_maps`, `_read_scheme_map`, `_read_item_scheme_maps` — took `cls: type[Any]` and returned `list[Any]`, erasing the constructed type for every caller.

Parameterized with **PEP-695 type params** so callers get concrete types — e.g. `_read_id_pair_maps(el, tag, RepresentationMap)` now infers **`list[RepresentationMap]`** instead of `list[Any]`.

## The interesting detail: `Callable[..., T]`, not `type[T]`
These helpers **construct** `cls(**specific_kwargs)`. Typing the param `type[T]` (the obvious choice) makes basedpyright check those kwargs against an *unbounded* `T`'s constructor — 46 "No parameter named …" errors. So the original `type[Any]` was **load-bearing**, dodging a genuine limitation (you can't type `cls(**kwargs)` for an arbitrary generic `T`), not lazy.

The fix: type the param **`Callable[..., T]`**. A class satisfies it (calling a class returns an instance → binds `T`), the `...` accepts any construction args, and the return `list[T]` is recovered — **no per-call `# type: ignore`s, no casts**.
