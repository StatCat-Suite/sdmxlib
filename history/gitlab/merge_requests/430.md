Closes #240.

## The drop

`ref_el_to_urn` required both `@package` and `@class`, and returned `None` without them. The caller stored that `None`, so the reference vanished — no exception, no warning, and a document that validates against the XSD. Reproduced before fixing:

```
dimension concept (no @package):  None
measure   concept (has @package): Ref(CS → resolved)
```

## Omitting them is not malformed

Measured against the vendored 2.1 schemas: `package` is **optional on 97 ref types and required on 10**, and **83 declare a `fixed=` value** — XSD's way of saying "you may leave this out, the schema supplies it". A producer relying on that emits valid SDMX-ML, and we dropped the reference.

## The fix

Supply what the schema would, from the artefact class the containing field already expects. That witness is not new — `resolve_ref` takes it as a *conformance guard* — so filling in the value it would otherwise have checked against cannot contradict it. Verified an explicitly wrong class still raises `SdmxConformanceError`: the guard is unchanged, only the silent drop is gone.

`Concept` and `Code` gain `sdmx_package` / `sdmx_class`, matching how maintainables already carry theirs. The pair describes the **item**, not its container — a concept URN is `…conceptscheme.Concept=AG:CS(1.0).CONTACT`, so the class is `Concept` while the id path names the scheme. Those two are the only *item* classes any reader passes as a witness; the rest are maintainables that already had the pair, and adding it to items nothing references would be untestable.

**Both call sites.** `resolve_ref` handles item refs; the `Enumeration` branch of `read_representation` calls `ref_el_to_urn` directly with its own `enum_cls`. A fix threading only the first would have left maintainable refs broken — and a test file covering only `ConceptIdentity` would have stayed green.

**A ref the reader cannot type keeps the old behaviour.** A categorisation source or metadata target passes `object`, which carries no pair. Deliberate and tested: those must self-describe, because nothing else knows what they point at.

## Testing

Per ref *kind* and per spelling — item vs maintainable, across all four schema-valid ways to write the attributes (`both` / `no-package` / `no-class` / `neither`).

Two choices worth naming:

- **The first assertion is that each document is XSD-valid.** The whole argument for reading these rests on the schema permitting them, and a fixture claiming so is not the same as the XSD agreeing.
- **One test compares the spellings against each other**, not just against `None`. A fallback supplying a plausible-but-wrong package would satisfy every non-`None` assertion and still file the artefact where no lookup finds it.

Reverting the fallback fails 8 of the 14. `just ci` green (5877 passed).

## Why it had not bitten

The checked-in ECB fixtures all emit `package`, and so do the registries tested against. Luck, not design — it surfaced while building a 2.1 MetadataStructure fixture for #236, where every attribute came back with no concept and the write boundary then refused the artefact for a reason unrelated to the actual defect.
