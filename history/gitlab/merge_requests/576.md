The hierarchies row of #421.

## Defect found on the way

A 2.1 hierarchy's id is unique only inside its HierarchicalCodelist. We promoted it to a top-level 3.x `Hierarchy` keeping the bare id. OECD names 210 of its 234 hierarchies `H`, one per codelist, so they collapsed onto **49 URNs**:

- the store silently kept one of each, which accounts for OECD's 166 `Hierarchy.name` store diffs;
- 167 3.0/3.1 writes failed the `UniqueHierarchy` key.

## Decisions (asked)

- **Id:** a hierarchy read from a 2.1 HCL is named `<inner>@<HCL>`, e.g. `H@HCL_AGE`. This is the Fusion Metadata Registry's rule (FMR 11.9 release note), and ECB and BIS already serve ids in this form. The id stays bare when the inner id equals the HCL id. `member_id` / `inner_id` in `model/hierarchy.py` implement it. pysdmx keeps the bare id and has the same collision.
- **Wrapper HCL:** an HCL that holds one hierarchy with the same id, uri, name, description and annotations, and nothing else, is read as the hierarchy alone. This covers all of ECB's 36, BIS's 48 and SDMX's 3. A standalone hierarchy written to 2.1 now reads back as itself.
- **HCL → 3.x / SDMX-JSON:** the hierarchies are written and the HCL is left out (declared, `sdmx_class` gap). This was a whole-message refusal.
- **HierarchyAssociation → 2.1:** left out the same way. This was also a whole-message refusal.

## How

- **2.1 reader:**
  - composes the id;
  - gives each hierarchy its HCL's validity and external-reference attributes (3.0 made them its own), so those 2.1 gap rows for `Hierarchy` are gone;
  - node `Ref`s with `containerID` use the same composition.
- **2.1 writer:**
  - writes `H@HCL` as `H` inside `HCL`, for both the element id and the node ref's `containerID`;
  - a new validation check refuses a hierarchy that an HCL would give back changed: its id, agency, version, validity or external reference. That only happens with a hand-built HCL; anything read from 2.1 always agrees.
- **`dropped()`** now covers every target. A `_NO_SUCH_CLASS` table drives it (ValueList and HierarchyAssociation for 2.1, HierarchicalCodelist for 3.0/3.1/json). `serialize` and the 3.x and JSON writers apply it, as the 2.1 writer already did.
- **The read-accounting guard** (`_losses.account`) counts a folded wrapper as accounted for.
