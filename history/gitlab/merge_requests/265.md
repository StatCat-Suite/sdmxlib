Closes #287. Part of %16. **Baseline 108 → 166 — all disclosure, no regression.**

#287 asked whether `AnyRef` was the intended spelling for the 15 `Ref[Any]`
sites, expecting the answer to be a rename. It was worse than that.

## The alias was a hole in the gate

`AnyRef = Ref[Any]` had **74 uses** against 15 spelled `Ref[Any]`, and the
ratchet from #284 counted **none of them** — a text scan cannot see an `Any`
hidden behind a name.

So the gate was watching a sixth of the real total, and "standardise on the
alias" — the outcome the issue anticipated — would have dropped the number by
15 while changing nothing at all.

The counter now discovers module-level names bound to a type mentioning `Any`
and counts their uses across the whole tree, so an alias defined in
`model/ref.py` still counts where it is used in a writer. Detection is
restricted to type *expressions*: a first, looser version matched
`_EMITTERS = {AnyAncestorMatches: ...}` and `__all__ = ["AnyRef"]`.

## The alias was also misdescribed

> `# Type alias for Ref[Any] — used in format layers and internal code where`
> `# the specific artefact type is not yet known or not relevant.`

That is not what it does. `Ref[T]` is **invariant** — the mutable
`_resolved: T | None` field forces it — so `Ref[Concept]` is not a
`Ref[object]`, and `Any` is the only spelling that accepts refs of differing
artefact types. Substituting `Ref[object]` produces **56 errors, every one
variance**, not one a genuine loss of type information.

So it was an escape hatch for a language constraint, wearing the name of a
gradual-typing boundary. Deleted in favour of spelling `Ref[Any]` out: it
reads more honestly, it is greppable, and it cannot hide from the gate.

**The finding it was concealing is filed as #289**, which reframes most of what
is left in this milestone — if `Ref` can be made covariant, ~56 of the
remaining occurrences evaporate mechanically; if it cannot, those 66 are
*correct as written* and should be documented rather than counted as debt.

## Deleting it revealed a second alias

`MapEndpoint` was `AnyRef | MapDataType`, invisible to the detector because
`AnyRef` is not the word `Any`. Now it is `Ref[Any] | MapDataType` and its uses
count — **an alias of an alias, hidden twice over.**

That one **stays**. Unlike a bare synonym, the name carries information the
spelled-out form does not, and it has a documented pattern-matching example on
it. A test pins the inventory at exactly this one, so the next is noticed.

## On the baseline jump

108 → 166 looks like a large regression and is the opposite. 52 were always
present and invisible; 6 more were doubly so. The number finally means what it
says, which is the only reason a ratchet is worth having.

## Review notes

- Breaking: `AnyRef` is removed from `sdmxlib.__all__` and
  `sdmxlib.model.__all__`. Per the project's pre-stability stance, no shim.
- 66 `Ref[Any]` in `src/` after the change, across 21 files — mechanical, and
  covered by the existing suite plus all three checkers.
- Ruff passed on `Ref[Any] = Ref[Any]` at one point during the rewrite
  (syntactically valid, semantically nonsense). Caught by importing the
  package. Worth knowing the linters do not cover that shape.
