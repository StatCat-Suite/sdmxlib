## A wrong answer, not an error

`SqlRelation` required the subquery's tables be visible on the consumer's connection, said so **only in prose**, and nothing checked it. So this composed silently:

```python
obs = a.observations(flow)
obs.filter(obs.col("REF_AREA").is_in(b.query(q.code)...))
```

Measured with two registries whose codelists disagreed about which codes are named "Ontario":

| | answer |
|---|---|
| `b` alone | `['ON', 'QC']` |
| composed against `a`'s observations | `['ON']` ← **`a`'s answer to `b`'s question** |

The other registry's SQL *text* was spliced into this connection, where the same table names resolve to this database's rows. Entirely plausible-looking output.

## The mechanism

`sdmxlib.sql.HasSource` — an **optional** companion to `SqlRelation` reporting an opaque token for the database a relation reads.

Optional deliberately. Required would break every existing producer, and a foreign relation that cannot answer is not necessarily wrong: Topology B puts `sdmx.*` and `pinax.*` on one connection precisely so cross-library composition is legitimate. So a producer that *can* identify its source is checked; one that cannot is trusted — the state before this existed.

Refused rather than repaired, per §5.9: splicing the other side's rows in as binds reintroduces the parameter explosion `InRelation` exists to avoid, and doing it invisibly is what §1.3's third rule forbids. Auto-`ATTACH` was rejected — the chain must not open connections the caller did not ask for.

## Three things a test caught, not review

- **The token must be the base connection.** `ObsQuery` runs on a per-thread cursor while a structural `Query` holds the base connection, so comparing what each *executes* on refuses the **same** registry. `test_a_relation_valued_filter_crosses_the_planes` failed the moment I got this wrong, which is exactly what it is for.
- **The walk covers boolean structure.** A cross-source relation sits under an `&` as easily as at the top — and that is the shape a caller reaches for when combining registries.
- **`intersect` / `difference` splice the same way** and needed the same refusal. Cheaper there: the argument *is* a `Query`, so there is no producer that might legitimately decline to answer.

A label rides alongside the token because `DuckDBPyConnection` has no useful `repr` — without it the message reads *"a different database (DuckDBPyConnection)"* twice, naming two sources and identifying neither.
