§6 step 9, part two — design §5.8. **Removes `sl.FailurePolicy`.**

`None` and "the source was down" were the same outcome. The caller's response differs — retry a dead source, fall back for a missing artefact — so reporting them identically makes the distinction unrecoverable.

## FailurePolicy is deleted, not re-scoped

§5.8 said it *"keeps its real job — whether a federation continues past a dead source"*. Building it showed **there is no such job**: `FederatedRegistry` routes each URN to exactly one source by agency, so there is no next source to continue to. `RETURN_NONE`'s only effect was converting an error into a silence — and the cookbook documented that as *"source down or artefact missing — same outcome to the caller"*, i.e. the conflation §5.8 forbids, sold as a feature.

Continuing past a dead source is now the caller's `except`, which cannot mislabel anything:

```python
for urn in urns:
    try:
        artefact = fed.get(urn)
    except sl.RegistryUnavailable as exc:
        log.warning("skipping %s: %s", urn, exc)
        continue
    if artefact is None:
        ...  # genuinely absent, and only that
```

## Three things the implementation turned up, none of them in §5.8

- **A bare `RestRegistry` named neither side.** A dead provider surfaced as `ConnectError: connection refused` — no source, no URL. The client wraps at the transport boundary, and `RegistryUnavailable` carries `source_id`, `tried` and `cause`.
- **`TransportError`, not `HTTPError`.** The latter includes `HTTPStatusError`, so the broader catch relabels a 500 as an unreachable source — telling the caller to retry a server that answered.
- **A 404 was an exception, so `None` was nearly unreachable.** SDMX-REST assigns 404 the meaning *"no results found"*, making it the commonest way a provider says "not here". It raised `HTTPStatusError`, which left `None` reachable only when a provider answered 200 with an empty message. A 404 is now `None`; a 500 still raises, because a server that answers at all was reached and its error is its own.

## Mutation testing earned its keep twice

**A surviving mutant found a real gap.** Swapping `TransportError` for `HTTPError` initially *passed*: on `get_artefact` the status check runs after `_reaching` closes, so the two are indistinguishable there. On the **streaming** paths they are not — `stream()` opens the connection inside the block, so `_raise_for_status` shares it — and no test covered that. `test_a_server_error_on_a_streaming_path_is_not_relabelled` closes it, and the mutant now dies.

**A self-inflicted one.** My first "a dead source is never reported as absent" test put the assertion inside a `pytest.raises` block, where it never runs — it pinned nothing. Rewritten as a bare `try` / `pytest.fail`, with a comment saying why.
