Decided after !519's review: #233's refusal of a versionless reference now applies to SDMX-ML 2.1 as well.

## Why

2.1 was exempt because its `<Ref>` makes the version optional, so a legal document exists. It does. But the 2.1 XSD documents an omitted `version` / `maintainableParentVersion` as **defaulting to 1.0**. So that legal document names 1.0 to any reader that follows the schema, which is the same silent change #233 refused for 3.0.

## Changes

- `_check_latest_refs` refuses in every format. The 2.1 message says why: *"SDMX-ML 2.1 reads a reference with no version as version 1.0"*.
- `test_21_still_accepts_it` asserted the old exemption. It is replaced by `test_21_refuses_it_because_its_schema_reads_no_version_as_1_0`, which also checks that a versioned reference still writes, so the test can tell the two apart.
- The property `…decides_whether_it_can_be_written` covers both branches in both formats.
- The building tutorial pinned no version on its cross-domain concept references; `just ci`'s docs tier caught it. They are pinned to 2.0, with one sentence on why.

## Breaking

Serialising a reference built without a version to SDMX-ML 2.1 raises `ValidationError`. Build the reference with an explicit version.
