CLAUDE.md already stated the rule for this shape — `SdmxUrn[object]` for pure
consumers, `SdmxUrn[Any]` only where the phantom is recovered downstream. What
it did not say is *which* of the sites were which, so the file read as guidance
while the code read as inconsistent: **23 `Any` against 17 `object`**, already
coexisting.

## Measured, not triaged by eye

Converting all 23 produced **25 errors**, every one of the form `Ref[object]`
not assignable to `Ref[Concept]` — the parameter needing to be **recovered**,
not widened. Covariance from #289 does not help here; it runs the other way.

Narrowing further, **two signatures accounted for 23 of the 25**:

```python
SdmxUrn.parse(...)  -> SdmxUrn[Any]
artefact_urn(...)   -> SdmxUrn[Any]
```

Both feed `Ref.unresolved`, whose `Ref[T]` return can only be satisfied by
`Any`'s bivariance. The other two survivors are the closure in
`_common.resolve_ref` that performs the same recovery, and the `ref_el_to_urn`
that feeds it.

## Outcome

**18 → `object`. 5 keep `Any`**, and each of the five now carries its reason at
the site, rather than relying on a rule in CLAUDE.md that a reader would have
to match against the code by hand.
