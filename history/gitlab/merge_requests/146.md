## Audit finding

`_duckdb.scalar(cursor, default: Any = None) -> Any` presented as a general
"first cell of first row, or default" helper. In reality all **5 call sites** are
`__len__` methods running `SELECT COUNT(*)`, always `default=0`, result consumed
as `int`:

```python
def __len__(self) -> int:
    cur = ....execute("SELECT COUNT(*) FROM ...", [...])
    return scalar(cur, default=0)
```

Smells:
- **Fictional generality** — the `default=None` branch was dead code.
- **`Any -> Any`** — a viral hole for a value that is always an `int`.
- **False justification** — the docstring claimed it avoids a
  `# type: ignore[index]`; the inlined idiom typechecks with **no ignore**.

## Change

Rename to `count(cursor) -> int` — drop the dead kwarg, return a real `int`,
name it for its one purpose. Migrated all 5 call sites.

**Kept at the package root**: it's genuinely shared by `storage/` and the model
query DSLs (`code_query`, `hierarchy_query`), and neither layer may import the
other — a root-level shared util is the correct layering answer. Docstring notes
how to generalise back to a typed `scalar[T](cursor, *, default: T) -> T` if a
non-count scalar read ever appears (chosen over keeping the unused generality now).
