The three storage gaps deferred from the #159 audit, all the same
shape: the model carries the field, the writer receives it, and the
schema has nowhere to put it.

* `Codelist.extensions` — SDMX 3.0 composition. Two tables, because a
  selection is an ordered list of member values each with its own
  cascade rule; a list column could hold the values but not the cascade
  beside them. The extended codelist also becomes an `artefact_ref` row
  under an `extends` role, so "what depends on this codelist" answers
  with its extenders rather than without them.
* `DataConstraint.reference_period` / `release_calendar` — five scalars,
  at most one of each per constraint, so columns. The two timestamps
  take the naive-UTC convention (#321).
* `Level.coding_format` — the facet group, interpolated into
  `hierarchy_level` from the same `_FACET_COLUMNS` the other three
  tables use.

SCHEMA_VERSION 2.10 -> 2.11.

That last one forced the other half of the change. The facet expansion
was written out three times on the write side — dsd_component, concept,
metadata_attribute — and a fourth copy is how the first three drifted
twice already, once leaving `metadata_attribute` without
`is_multilingual` entirely. `_representation_columns()` is now the one
definition, matching what `_FACET_COLUMNS` did for the DDL. Reading
levels was duplicated too, between the eager reader and the lazy proxy,
so that is `_read_levels()` — had only one grown coding_format,
`get()` and `get(eager=True)` would have disagreed, which is #322.

`LazyCodelist` grows an `extensions` property for the same reason.

`hierarchy_level.codelist_urn` is always NULL — a level's coding format
has no enumerated arm — and is recorded in NOT_EDGES rather than wired,
since an edge there would offer `.codelist` and answer NULL for every
row.

Two of the three now sit inside the derived guard (#316) rather than
only in hand-written tests: `sentinels.py` can build a CodelistExtension,
a ReferencePeriod and a ReleaseCalendar, so a future writer that drops
one fails there. Verified by deleting the extension write — the guard
goes red. `level.coding_format`'s strict xfail in the property guard
XPASSed, which is what confirmed that one.
