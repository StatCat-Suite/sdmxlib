**Two library findings came out of writing this.** Neither is fixed here.

1. On a root column, every aggregate silently ignores `where=`: `count`, `n_unique`, `sum` and `list`, in both `agg` and `group_by`. For example, `cl.codes.agg(n=sl.q.code.id.count(where=sl.q.code.depth == 0))` compiles to a bare `count(*)`. The fan-out form works, and it's the only one these docs show.
2. `RestRegistry.query`'s docstring says an agency is required on every scan. An unfiltered listing actually runs without one; only a filter that REST can't express raises `PushdownError`. The docs state the behaviour as it is.
