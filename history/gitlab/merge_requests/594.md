Closes #464.

**The cost.** Writing BIS's 27 DSDs as SDMX-ML 2.1 took 16.8 ms, against 4.9 ms for 3.0. Switching things off measured **9.5 ms** of it in `gaps.dropped`, the walk that finds what the target cannot hold. There were two causes of about equal weight:

| cause | cost | change |
| --- | --- | --- |
| it ran **twice**: `serialize` drops before validating, then called the writer's `write`, which did the same walk on the already-narrowed message | 4.7 ms | each writer has `write_kept`, its step after the drop. `write` is still "drop, then `write_kept`" for direct callers; `serialize` calls `write_kept` |
| each reference looked up walked every `MaintainableArtefact` subclass again: **1,116 walks per write** | 4.3 ms | cached on a count of subclasses defined, kept by `MaintainableArtefact.__init_subclass__` |

**On #405.** The walk was uncached on purpose: a cache that couldn't see a later import froze a partial answer, and one item class became silently unresolvable. The cache here can't freeze that way, because defining any artefact class changes its key. It's `lru_cache(maxsize=1)`, so it holds one tuple. One limit, stated in the docstring: a class *deleted* at run time stays listed until another is defined, and only a test does that.

**Measured against `main`** (three alternating runs each, BIS DSDs):

| write to 2.1 | main | this MR |
| --- | --- | --- |
| unvalidated | 16.8 ms | 9.9 ms (**−41%**) |
| validated (the default) | 19.4 ms | 12.4 ms (**−36%**) |

Every other write is unchanged. For reference, this write took 7.1 ms before milestone 20, and pysdmx takes 4 ms.

**Guards** (`tests/unit/test_dropped_cost.py`), by count:
- one drop per `serialize`, for every format;
- a writer called directly still drops (the discrimination check);
- one class walk per write;
- a class defined later is seen, which is the #405 case.

Each was watched to fail: `serialize` routed to `write` again, the cache removed, and a cache keyed on nothing.

**An existing guard caught this change.** `test_ml3_fork_drift` requires the 3.0 and 3.1 writer modules to define only their entry points (#346). `write_kept` is a second one-line forwarder into the shared `V3Writer`, so the guard now names both entry points exactly.
