One artefact contradicting the schema failed the whole document. registry.sdmx.org's 3.0 `datastructure` document is 23 DSDs; three enumerate a dimension with a ConceptScheme, and the reader returned **none** of them.

## The unit of failure is the artefact

- **One helper.** Every top-level loop in the SDMX-ML 2.1, shared 3.0/3.1 and SDMX-JSON readers goes through `formats._refuse.build_each`.
  - It catches **only** `SdmxConformanceError`. Anything else is a bug and still propagates.
  - A refused artefact is never partly built.
  - What references it keeps an unresolved ref.
- **`sl.Refusal`** records each one (class, URN, reason) on `StructureMessage.refused`. The URN comes from the element's own agency, id and version, so an artefact with a malformed id can still be named.
- **2.1 containers.** A StructureSet or HierarchicalCodelist is refused together with its contents, because the container is what the document published.

## API (decided: strict by default)

```python
try:
    msg = sl.parse(doc)                 # raises on any refusal, as before
except sl.SdmxConformanceError as e:
    e.refused                           # every refusal, not just the first
    e.message                           # everything that was read

msg = sl.parse(doc, strict=False)       # the partial message
msg.refused
```

- A strict call that raises interns nothing into `registry=`.
- `strict=False` interns what was read. `read()` takes `strict` too.

`refused` is a private attrs field behind a property, so code that iterates the message's artefact slots skips it. `query._execute` would otherwise have collected `Refusal`s as artefacts, and eight test sites were adjusted the same way.
