Closes #501.

## What changed

A hierarchical code naming a level its hierarchy doesn't define now reads with **no level**, and the read records a loss (`StructureMessage.lost`; `lossless=True` refuses). Before this, !626 (#458) refused the whole hierarchy, and before that the reference vanished silently.

- `_common.node_level` returns `None` for an undefined level instead of raising.
- `_losses.LOSSES` gains one row, `str:HierarchicalCode/str:Level`, for 2.1, 3.0 and 3.1. Its XPath counts the dangling references in both spellings both readers accept: 2.1's `<Ref id>` and 3.x's text.
- The row is permanent, because a reference to nothing can never be modelled. The round-trip xfail's reason says so.

## Why

The registry sweep re-run found **all 99 of IMF's 3.0 hierarchies (12,279 nodes) refused**:
- each has `hasFormalLevels="false"`, no defined levels, and a bare number (`0`–`5`) in every node's `<Level>`;
- the 3.0 XSD says `Level` references a level defined in the hierarchy, so the data is IMF's defect;
- only 3,417 of the numbers equal the node's depth, so nothing is derivable.

Refusing cost the whole tree for one unresolvable reference per node.

## Evidence

- `test_read_losses.py`: an injected dangling level is reported exactly once, with the hierarchy kept, in 2.1, 3.0 and 3.1. The existing "maximal reads back with nothing lost" test is the discrimination check, since valid levels count zero.
- The two reader tests that pinned the refusal now pin the loss. The 2.1 one is parametrised over `<Ref>` and text.
- Sweep summaries for BIS, ECB, IMF, OECD and SDMX are refreshed, in their own commit. IMF's 99 hierarchies read, and the 12,279 references are recorded as lost. One IMF codelist is refused for a blank name (#452/#492, correct). The other four are unchanged. ESTAT was not re-run (about 2.5 h).
