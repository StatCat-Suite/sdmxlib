Closes #503. Implements the 2026-10-19 decision on the issue: one canonical spelling per meaning, the minimal one, with identity and required attributes always written and no option to spell defaults out.

## The guard (watched failing first)

`tests/unit/test_minimal_output.py` fails on any non-identity attribute written at its schema default.

- **SDMX-ML:** every element's defaults are read off the vendored XSDs **in context** by `tests/support/xsd_defaults.py`. It walks the document from its root declaration through extension, restriction, groups and substitution groups. `fixed` counts as a default, and `use="required"` is exempt.
  - libxml2's `attribute_defaults` was tried first and measured to fill nothing in an SDMX document: it skips elements from an imported namespace.
- **SDMX-JSON:** a table of its six defaults, which a second test re-derives from the schema so a new one can't be missed.
- **Before:** against today's writers it failed in 2.1, 3.0, 3.1 and JSON, matching the issue's audit exactly, plus the 2.1 fixed metadata-target `textType`s it hadn't listed.
- The fidelity comparator (`tests/support/fidelity.py`) now strips defaults with the same resolver, in place of its name-keyed `_DEFAULTED` table. That table couldn't express `textType`, whose default depends on context.

## Writers

They omit:
- `usage="optional"` (3.x and JSON);
- `include="true"` and `isInclusive="true"`;
- `cascadeValues="false"`;
- a context's `textType`: `String`, `ObservationalTimePeriod` on a time dimension, and 2.1's fixed target types;
- `isMultiLingual` at its version's default;
- JSON's `minOccurs: 1`.

Identity (id, agency, version, parent id and version, class, package) and required attributes are always written. The context is read off the tree being built (`_common.text_kind` / `text_type_default`), so the reader and the writer share one table.

## The model holds what a default means

Omitting a default is only safe if reading it back gives the same model, so `None`-for-unstated goes:

- **`Facet.is_multilingual: bool = False`.** An absent `isMultiLingual` reads as its version's default where its type allows one: **true in 2.1 and 3.0, false in 3.1**.
  - This fixes a conversion bug: a 3.0 attribute with no `isMultiLingual` is multilingual, and converting it to 3.1 used to flip it silently to false.
  - 2.1 gives attributes the simple format, which can't say it. That's now a **declared gap** in `formats/gaps.py` rather than a `serialize` refusal, which would have refused nearly every 3.0 structure.
  - A multilingual **dimension** (no format can carry it) is refused as it's built: `_check_dimension_multilingual`.
- **A text format's `type`:** owners fill their context's default (`to_text_representation`, `to_time_format`, `TargetObject`), so a facet built in code compares equal to itself read back.
- **`RegionValue.cascade`** is never `None` (`SELF_ONLY`).
- **Storage** keeps writing `NULL` for these and reads `NULL` back as the default, so no migration is needed.
- **SDMX-JSON fix:** a metadata attribute's absent `minOccurs` was read (and omitted) as 0, where the schema says 1. It now matches SDMX-ML.

## Fixtures, censuses, oracles

- **The maximal fixture carries the non-defaults:** exclusive bounds, an excluded region with an after-period, a non-multilingual concept and map target, and a component cascade of `true`. That keeps the attribute and JSON censuses seeing each one written.
- **FMR:** re-recorded. The multilingual ledger adjustment is gone, because it now removes nothing. Two FMR behaviours are classified:
  - it drops a TextFormat stating only defaults;
  - its 3.0 output loses a measure's `isMultiLingual="false"`.
- **pysdmx:** re-recorded. It reads an absent attribute `usage` as **mandatory** (3.x defaults it optional) and drops a defaults-only TextFormat. Classified, and per the maintainer **not followed**: our output stays conformant and minimal, with the behaviour noted internally only.
- Tests that pinned the old spelling are updated. A census check is added for the new validation rule.
