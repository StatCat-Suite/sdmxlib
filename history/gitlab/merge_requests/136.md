Closes #174.

`sl.node.<code-field> == <Code instance>` routed through `_coerce_value`, which called `artefact_urn(code)`. `artefact_urn` reads `.agency_id`/`.version`/`.sdmx_package`/`.sdmx_class` — but a `Code` is a **child item, not a maintainable artefact**: it has only `id`/`name`/`description`/`parent_id`, no `agency_id`/`version` and no `.urn`. So the call **AttributeError'd at runtime**.

## Fix

A bare `Code` genuinely can't yield a URN — its identity needs the owning codelist's agency/id/version, which isn't reachable from the `Code`. Falling through would silently no-match, so we **reject it with an actionable `TypeError`** pointing the caller at `Ref[Code]`, a `SdmxUrn`, or the code's URN string. The `Ref` and `SdmxUrn` branches are unchanged.

## Tests

The `node.code == ...` branches were only partially covered (string only) — which is why the bug shipped. Added:

- `SdmxUrn` → coerces to string ✅
- bare `Code` → raises `TypeError` (the guard) ✅
