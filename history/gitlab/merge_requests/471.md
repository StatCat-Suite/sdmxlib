## The design

`R` is the **row kind**, a phantom that keeps roots apart. The artefact is a
different type, mapped per root — so `Cols` and `Query` gain a second parameter
`A`, defaulted to `object` and pinned by the accessor class:

```python
class _Code[R: RowKind](Cols[R, Code]): ...
class _Component[R: RowKind](Cols[R, Never]): ...
```

The default is what kept this small: an accessor that pins nothing behaves
exactly as before, and `Query[R]` still means what it meant. The map was filled
in per accessor rather than in one edit.

## The map is measured, not assumed

Every one of the 37 roots was run against a populated registry and its element
type recorded. **21 build something; 16 raise `TypeError`.** Two are worth
naming:

* **`q.codelist` and `q.hierarchy` build `LazyCodelist` / `LazyHierarchy`**, not
  `Codelist` / `Hierarchy`. Declaring the nominal type would re-introduce exactly
  the declared-vs-actual lie #370 removed, and `.codes` is where the two differ:
  `len(cl.codes)` type-checks against `Codelist` and raises at runtime.
* **`q.artefact` collects `Maintainable`.** It is polymorphic, and the five
  classes it returns share no base — `LazyCodelist` subclasses nothing at all.
  They do all satisfy the structural protocol, verified rather than assumed.

## What it cost, each measured before choosing

* **`A` is invariant**, so it is carried rather than dropped: `Frame` and
  `Grouped` declare the parameter without reading it. Covariance would have
  needed a phantom method on `Cols`.
* **`Plan` / `Push` / `Program` do not carry it.** Threading it through the
  compiler layer was tried and reverted — 8 further signatures, none of which
  would read it. `build()` erases it in one documented line instead.
* **One `cast`, at the resolver seam.** Resolvers are registered per *table* at
  runtime (`_RESOLVERS`), so nothing static relates one to the accessor that
  selected it — the same shape `storage.readers.get_artefact` has.

## The guard that makes the cast honest

`tests/unit/test_query_collect_types.py` is **differential**: the declared side
is read off `__orig_bases__`, the actual side comes from running the query, and
neither is written down twice. All 21 building roots return rows, so no
assertion is vacuous, and the counts (21 / 16) are asserted so moving one across
the line is a visible change.

Sabotage-checked in both directions: mispinning `_Dataflow` fails with
`q.dataflow declares Code but collect() returned ['Dataflow']`, and pinning a
refusing root as if it built something fails with `q.component refuses to
collect but does not declare Never`.

`tests/typing/probe_query_row_kinds.py` carries the static half.

## One correction to the issue

I claimed there that `Never` would make `collect()` on the 16 refusing roots a
**static** error. It does not — `list[Never]` is still a list, so the call is
silent and only *use* of the result is poisoned. The runtime `TypeError` (with
its existing message naming what to use instead) remains the refusal a caller
actually meets. The tests assert what is true rather than what the issue hoped.
