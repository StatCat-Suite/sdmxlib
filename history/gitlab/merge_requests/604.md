## What changes

A reader that met a schema-required construct the document omitted filled in a value, and the artefact held it as if the document had stated it. There are now two outcomes:

- **Assumed and recorded.** A meaningful value is kept and appears on the new `msg.assumed` (`sl.ReadAssumption`), declared once in `_losses.ASSUMPTIONS` beside `LOSSES`. `lossless=True` raises on these too.
  - attribute / metadata-attribute-usage / 2.1 `ReportingYearStartDay` with no `AttributeRelationship` → `DATASET`, the #421 tolerance (on IMF: 3,047 + 16 occurrences across 172 DSDs)
  - 3.0 `DataConstraint/@role` → `Allowed`
  - `EpochMap/@epochPeriod` → `day`
  - `Hierarchy/@hasFormalLevels` → `false`
  - **new, from the census:** a 3.x artefact with no `@version`. 3.x reads it as *un-versioned*, which the model cannot hold, so it is held as `1.0` (#478). Organisation schemes, and 3.1's `Categorisation`, are versionless by the schema (`use="prohibited"`) and are excluded.
- **Refused.** Where no value is worth assuming, `required()` refuses the artefact instead of building it with `""`. This covers link `rel`/`url`, sentinel and geo-code `value`, 2.1 `ReferencePeriod`, epoch/date-pattern map attributes, 2.1 `ValueMapping`, and every required `@id` / `@agencyID`.

## What the census found beyond the survey

The survey's class A ("an empty id is refused downstream") was wrong. I measured it by removing `@id` from every element shape in the maximal message, through `sl.parse(strict=False)`:

| Missing | Before | Now |
|---|---|---|
| a maintainable's `@id` / `@agencyID` | **whole document failed** (`Invalid artefact id: ''`) | that artefact refused |
| a 2.1 `<Ref>`'s `@id` / `@agencyID` | **reference silently vanished**, e.g. a dataflow with no structure | holding artefact refused |
| Group, Level, the three 3.x map kinds, ValueItem, MetadataProvider, 2.1 MSD targets / report structures, cube-region and key values | **kept with id `""`** | refused |
| a component's `@id` | refused, but the XSD says it defaults to the concept's id | unchanged → **#477** |

Also fixed: a refused 2.1 metadata provision agreement was refused twice (once again as a "reader defect"), because the account's fold check looked only at what was built.

Filed from the census: **#476** (a 2.1 `<Ref>` without `@version` reads as `latest`, but the XSD default is `1.0`), **#477**, **#478**.

## Guards

- `test_read_assumptions.py`:
  - every `ASSUMPTIONS` row is proved by removing its construct once (exactly one assumption back, artefact kept);
  - the maximal message reads with nothing assumed (the discrimination check);
  - every class D site refuses only its artefact;
  - a walk over all 209 `@id`-bearing shapes either refuses or, where the schema fixes the id, reads back unchanged;
  - strict xfails pin the #477 components.
- `test_reader_defaults_census.py`: every remaining `x.get("<attr>", <default>)` in the three SDMX-ML reader modules is pinned by exact count to the XSD's own default/fixed value (checked against the vendored schemas), to an `ASSUMPTIONS` row, or to its issue.
- Sabotage: each guard was watched failing. Reverting a `required`, a lossless check that ignores `assumed`, a ref that drops again, PA classification raising outside the catch, an assumption XPath that counts nothing, and the fold fix are each caught. A central maintainable-identity check proved redundant with the per-site reads, so it was removed rather than kept untested.

The first version cost **+4.5%** on the codelist chunk. An ablation (emptying `ASSUMPTIONS`) recovered it: three rows counted with a `.//` descendant search from every artefact, so each codelist's codes were walked for an `AttributeList` or `EpochMap` that cannot be there. The second commit names each row's exact path instead. The DSD's +3 ms is the cost of recording its 178 assumptions.
