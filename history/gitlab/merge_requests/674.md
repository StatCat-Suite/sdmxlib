Refs #511. This covers ten of the eleven checklist items; item 9 stays open.

Each of these misuses reached the database and failed with a raw DuckDB error. Each now raises a refusal that names the fix:

1. **Artefact terminals on observations.** `ids`, `urns`, `collect`, `first` and `page` on an `ObsQuery` now refuse; an observation is a row, with no id. The old refusal suggested `.ids()`, which also failed.
2. **`qualify()` with an ordinary predicate** is refused, naming `filter()`.
3. **`filter()` with a window comparison** is refused, naming `qualify()`.
4. **A predicate from the wrong relation inside `.any()` / `.every()`** is refused when it's built, using #510's column origins.
5. **A fan-out aggregate's `where=` from another relation**: same refusal, also when it's built.
6. **A window inside `group_by().agg()`** is refused.
7. **An aggregate compared with an aggregate or a column**: the message says this is not supported yet (query-language.md §13).
8. **A column compared with a column**: same message, instead of "Did you mean …?".
9. **`x in query`** is refused, naming `.exists()`.
10. **Internal route names:** a to-many route is shown as the caller wrote it, without the internal `spine` hop.

**Tests:** 14 tests in `test_query_misuse.py`, each failing on the old code, plus checks that the legitimate forms still build.

**Not here (item 9):** an untyped observation column compared with a number. Whether that column is numeric depends on the physical table, not the DSD, so refusing it needs the store's schema at plan time.
