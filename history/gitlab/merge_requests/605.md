Part 2 of #474: the SDMX-JSON readers. Part 1 (account plus SDMX-ML) was !604.

## How the cases were found

Every key of the maximal message's SDMX-JSON form (2,126 key shapes) was removed in turn. The document was validated against the vendored 2.0 schema, then read with `sl.parse(strict=False)`. The schema decides what is required; the read decides what happens.

| Removing a key | On main |
|---|---|
| **required** (439 shapes) | 104 **failed the whole document**: msgspec's typed decode stops at the first entry missing a key its struct requires. 201 were read with the artefact changed, 161 of them links. Only 13 were refused. |
| **optional** (1,687 shapes) | 37 **conformant documents were refused**, or failed whole: the reader required `version`, a dimension's `position`, an MSD's `metadataAttributeList`, and more. |

## What changes

- **The entry is refused, not the document.** The single typed pass stays the fast path. Only when it fails is each entry decoded alone; the ones that fail are refused, named by the id, agency and version they state (read untyped, since the identity may be what is wrong). `msg.lost` walks entry by entry for the same reason.
- **Schema rules the reader skipped now refuse the artefact.** Plainly required keys lose their DTO defaults. Each `oneOf` is a `__post_init__` through one helper, `one_of`, whose `ValueError` msgspec reports as the same `ValidationError`. The rules cover links (`rel`, plus `href` or `urn`), representations, attribute relationships, constraint attachments, time ranges, date maps, fixed-value maps, and representation-map endpoints. A time dimension is checked in ingest instead, because the writer builds that struct from a model whose concept and representation are optional.
- **Assumed and recorded**, matching SDMX-ML:
  - a missing `attributeRelationship` (on an attribute or a metadata attribute usage) is read as attached to the dataset;
  - a missing `epochPeriod` is read as `day`;
  - a missing `version` is read as 1.0 (#478). Organisation schemes are excluded: SDMX 3.0 does not version them, which SDMX-ML 3.0 states by prohibiting the attribute.

  These are declared in `sdmx_json/_losses.ASSUMPTIONS`, counted on the DTOs, and `lossless=True` raises on them.
- **Conformant documents are read.** `version`, `position` and `metadataAttributeList` are optional again. The reader still refuses three schema-optional keys, each for a stated reason:
  - a date map's or frequency-format mapping's `id`, and an item map's `targetValue`: the information model makes them mandatory, and SDMX-ML requires them;
  - a component's `id`: that is **#477**, now noted to cover JSON as well.

After the change, every required key refuses except the two recorded assumptions. Every optional key reads except the listed exceptions.

## Guards

- `test_json_read_assumptions.py` is the survey as a test. It walks all 2,126 key shapes, lets the schema say whether each is required, and asserts refuse-or-read. The exceptions are explicit tables, each with its reason, and `test_the_exceptions_are_each_what_they_say` fails if one goes stale. Each `ASSUMPTIONS` row is proved by removal, with exactly one assumption recorded and the artefact kept. Component ids are strict xfails on #477.
- Coverage is complete because `test_json_census.py` already fails on a declared DTO field the maximal message never writes, so every field is walked.
- Sabotage: each guard was watched failing.

  | Sabotage | Tests failing |
  |---|---|
  | link `rel` rule off | 110 |
  | per-entry fallback off | 398 |
  | representation rule off (both forms) | 1 |
  | organisation schemes counted as un-versioned | 1 |
  | epoch assumption not recorded | 1 |
  | `keys` defaulted again | 1 |
  | `position` required again | 1 |

## Memory / performance

`sl.parse(strict=False)`, best of 5 per run, three rounds interleaved main / branch. The IMF documents are the 3.0 DSDs and concept schemes, written to SDMX-JSON 2.0 by main.

| Document | main | branch | retained / peak memory |
|---|---|---|---|
| IMF DSDs (1.3 MB, 186 DSDs) | 30 ms | 30–31 ms | 5.9 / 8.2 MB, unchanged |
| IMF concept schemes (11.7 MB) | 122–125 ms | 117–123 ms | 23.6 / 46.1 → 46.2 MB |
| BIS codelists (5 MB) | 29–30 ms | 29–30 ms | 7.5 / 16.0 MB, unchanged |
| UNSD commodity (30 MB) | 182–187 ms | 180–183 ms | 38.1 / 91.5 MB, unchanged |

The first version cost about 5% on the DSD document and 2% on the concept schemes. Disabling every `__post_init__` recovered it, and the cost was `one_of` building its arguments on every representation. `Representation` now tests its rule inline and calls `one_of` only to raise, which brings it back within noise. A document with nothing wrong never takes the fallback path.
