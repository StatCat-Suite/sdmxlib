Third #422 MR: the SDMX-JSON half of the read-side register (!539 did SDMX-ML).

## Decisions (asked)

- **Detection:** read the raw keys of `data`, and declare the rest in the typed DTOs. No second full parse.
- **`include="false"`:** refuse the constraint until the model holds an excluded value set.

## What changes

**SDMX-JSON (`formats/sdmx_json/_losses.py`)**
- **Unread sections:** `data` is decoded again as `dict[str, msgspec.Raw]`, which reads the keys and leaves the values unparsed. Every entry in a section that no `StructureDataJson` field reads is refused. The unread list matches SDMX-ML 3.0's unmodelled list exactly, and a test checks that.
- **Losses inside a built artefact.** The constructs are declared on the DTOs and counted by typed checks over the decoded structs:
  - annotation links beyond the first, and a link's `hreflang`;
  - artefact `links` other than `describedby`, `self` and `metadata`;
  - N:M `componentMaps`;
  - region validity;
  - `cascadeValues`;
  - `removePrefix`;
  - a value's `lang`;
  - `sentinelValues`.
- **`reader.SECTIONS`** maps each section to its model class. It's asserted equal to the DTO's fields, so a newly read section also gets its losses counted.

**`include="false"` on a region KeyValue or Component** excludes those values. Every reader (SDMX-ML 2.1, 3.0, 3.1 and SDMX-JSON) read it as an inclusion, keeping a constraint that says the opposite of its document. That constraint is now refused.

**New SDMX-ML register rows:**
- `Value/@cascadeValues` (2.1, 3.0, 3.1);
- `@removePrefix` (3.x);
- `str:Value/@xml:lang` (3.x).

**Bug fixed on the way:** SDMX-JSON's object form of a region value (`{"value": "A", "cascadeValues": true}`) is valid per the schema. Our DTO typed values as `list[str]`, so a document using the object form failed to decode at all.

**The official SDMX-JSON 2.1 sample** now reports one loss: its dataflow's `rel="structure"` navigation link, which has an href and an hreflang the model can't hold. The sample's guard pins it.

## Tests (`test_read_losses.py`)

- **Every JSON row:** injected into the maximal message, reported once, and the artefact is kept. A strict xfail re-counts it after a write; all 9 currently fail on the count (`0 == 1`).
- **Discrimination:** the maximal message reads back from SDMX-JSON with nothing lost or refused.
- **Unread sections:** each of the 16 is refused entry by entry, and the rest of the document is read.
- **`include="false"`:** refused in all four formats.
- **Object-form region values:** a regression test that they decode.
