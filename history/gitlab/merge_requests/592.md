Closes #461.

**The cost.** An SDMX-JSON read found the keys its structs skipped (#422, #445) by decoding the document a second time, untyped, and walking every key of every artefact beside its struct. On BIS's codelists that was **22 of the 54 ms read**, measured by switching it off. Every caller paid it, whether or not it ever read `StructureMessage.lost`.

**The change.**
- The walk now runs the first time `lost` is read.
- `StructureMessage._lost` holds the losses, or the function that finds them. Its converter leaves a function as it is, so `attrs.evolve` carries it; the refusal pass relies on that. The property runs the function once, the same way `SdmxUrn` caches its string.
- Refusals of unread sections stay eager. They decide whether a strict `parse` raises, and finding them reads only the section keys.

**Two consequences, for review:**
1. Until `lost` is read, the message holds the document's bytes. That's the smaller of the two things the walk needs; the decoded structs are rebuilt when asked.
2. `_lost` no longer takes part in equality. A loss describes how a document was read, not what the message holds, and two equal reads must not compare unequal because one was asked for its losses.

**Measured against `main`** (three alternating runs each):

| | main | this MR |
| --- | --- | --- |
| parse, BIS codelists (5 MB) | 54.4 ms | 34.1 ms (**−37%**) |
| parse, BIS DSDs | 10.0 ms | 7.7 ms (−22%) |
| parse, then read `lost` (codelists) | 54.2 ms | 60.0 ms (+11%) |

Reading `lost` costs about 6 ms more than before, for the second typed decode.

**Guards:**
- `tests/unit/test_json_lazy_losses.py` counts walks: none during a parse, exactly one when `lost` is read. It also checks that `lossless=True` still refuses, that `evolve` keeps the pending losses, and that equality doesn't depend on whether `lost` was read. The count guard was watched to fail with the reader made eager again.
- **The existing guard `test_the_walk_caches_each_struct_class_once` caught this change.** Its subject moved: a read no longer walks. It now reads `lost` after each parse, so it exercises the walk again.
