#215, Phase 3. Hypothesis in the dev group with an upper bound, two settings profiles, a strategy module, and twelve properties on the core value types.

## The strategies come from the spec, not from the validator

This is the design decision the whole issue turns on. The alphabets in `tests/support/strategies.py` are transcribed from the SDMX Information Model's `IDType` and `VersionType` — **not** from `validation.py`'s regexes.

Derive them from the code under test and "every generated id validates" becomes a tautology: strategy and validator share one source of truth, so a *wrong* regex still produces a passing property. Derived from the spec, a disagreement is a real question about which side is wrong.

## It paid off on the first run

`test_generated_codelists_validate` failed immediately:

```
Codelist.codes[0].name — name is required (SDMX NameableArtefact)
```

**The strategy was wrong.** `Code` is an SDMX `Item`, hence a `NameableArtefact`, so a Name is required — and `codes()` was generating unnamed ones. Fixed there and in `concept_schemes()`, with the reasoning in the docstring so the next person doesn't relax it back.

Worth being clear about what happened: this is not a bug found in `sdmxlib`. It is the strategy/spec agreement check doing exactly its job on day one, and a strategy built from `validation.py` could not have raised the question at all.

## Profiles — and a correction

The first version of this MR rationed CI to 25 examples to save pipeline time. **That justification does not survive measurement**: on the heaviest property here, 25 → 100 examples costs **0.28 s**, against a pipeline that spends about a minute on `uv sync` before running anything. Trading exploration for that is false economy, and local runs have no constraint at all.

| Profile | Examples | This file |
| --- | --- | --- |
| `dev` (local default) | 100 | 2.70 s |
| `ci` | 100, `derandomize=True` | 2.80 s |
| `deep` (`just test-properties`) | 2000 | 63.50 s |

CI now explores exactly as much as dev. The one real difference — `derandomize` — was never about cost: `.hypothesis/` is gitignored and absent in CI, so a failure must reproduce from the report alone rather than from a database that does not exist.

`deep` exists because locally there is nothing to economise. It found nothing new on the current properties, which is worth knowing. Selected by `HYPOTHESIS_PROFILE`, defaulting to `ci` when `$CI` is set.

**Suite cost:** `-m "unit and not slow"` goes 16.5 s → 19.7 s.

## The twelve properties

- **URN** — `parse(str(urn)) == urn`, including item-level URNs carrying `item_id`.
- **InternationalString** — `emit_pair` splits into (primary, map) and the map reconstructs the value; the empty case returns `(None, None)`.
- **Version ordering** — antisymmetry and transitivity, i.e. `_version_key` really is a total order.
- **Collections** — indexing agrees with iteration; `filter` yields a predicate-satisfying subset; `partition` is a disjoint cover.
- **Validation** — the strategy/spec agreement check above.

Where a property overlaps a module the #213 pilot measured, the docstring records what the pilot found, so the #218 re-run has a baseline. Two of these exercise `ArtefactList._lookup_str`, which carried **11 of `collections.py`'s 27 surviving mutants**.

`urn.py` and `representation.py` had **zero** survivors, so the URN properties are not expected to find anything — they exist to keep it that way as the grammar grows.

## Deliberately not here

Serializer round-trips (#216) and query-DSL differential testing (#217). Those are where the value is, and both needed this to land first. The strategies already include `facets()` drawing all eleven bounds independently, which is what #216 needs to say something stronger than the 14 fixtures that happen to contain a `<str:TextFormat>`.
