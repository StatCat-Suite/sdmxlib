Closes #480. Implements the decisions recorded on the issue (2026-10-20): model the full header for the messages we read and write, and keep fixed placeholders when there is none.

## Model (`model/header.py`)

- **`Header`** (`StructureHeaderType`) holds `id`, `prepared` (held in UTC), `sender: Sender`, `test`, `receivers: tuple[Party]`, `name` and `source`.
- **`MetadataHeader(Header)`** (`GenericMetadataHeaderType`) adds `metadata_provider: Ref[MetadataProvider]`, `data_set_action: ActionType`, `data_set_ids` and `extracted`.
- **`Party`** (`PartyType`: id, names, contacts, reusing `Contact`) and **`Sender(Party)`**, which adds a `timezone`. `ActionType` is a new enum.
- The header is set with `StructureMessage(header=...)` / `MetadataMessage(header=...)` and read as `.header`. The field itself is private (`_header`), like `_refused`, because the code that walks the message's attrs fields treats them as the artefact slots.
- Ids, the time zone (`TimezoneType`) and the data set ids are refused as they are set.
- A metadata header's `Structure` elements are not modelled: the writer derives them from each set's `structureRef`, as before.

## Formats

- **SDMX-ML** (`formats/sdmx_ml/_header.py`, one module for every version): the full header round-trips **whole** through 2.1, 3.0 and 3.1 and passes XSD validation. The 3.0 `GenericMetadata` writer slots its derived `Structure` elements in through a callback.
- **SDMX-JSON** (`formats/sdmx_json/_header.py`): `meta` carries the id, test, prepared, parties and names. These are declared in `formats/gaps.py`, so `sl.unrepresentable(header, "json")` reports them:
  - no source, no sender time zone, and none of the metadata four;
  - in the other direction, SDMX-ML's message `ContactType` has no `@id`, which JSON's contact has.
- The structure reader still decodes `meta` in its single fast pass.

## Behaviour

- **No header:** every format writes the same placeholders (`SDMX_MSG`, `2000-01-01T00:00:00`, sender `sdmxlib`) and reads them back as `None`, so `write → read` round-trips.
  - **Output change:** SDMX-JSON used to write `SDMXLIB` and the current time, so its output differed on every write. It is now reproducible. This is in `docs/upgrading.md`.
- **A header the model cannot hold** (a party with no id, a `Prepared` that is no date) reads as `None` and is recorded on `msg.lost` (`mes:Header` / `meta`), so `lossless=True` refuses it. It never fails the read, because the header used to be ignored entirely.
  - All **104 real registry headers** in the sweep's raw responses (BIS, ECB, ESTAT, IMF, OECD, SDMX) read cleanly.
  - A `MetadataMessage` has no `lost` record, so an unbuildable metadata header there just reads as none, as other metadata read losses already do.

## Tests and guards

- **`test_message_header.py`, 32 tests:** whole round trip and schema validity per format, the declared JSON gaps, the placeholder read back as none, and a discrimination check (the placeholder values plus a receiver read as a header). Also the contact-id gap, date-only `Prepared`, the loss and the `lossless` refusal, metadata headers in 3.0 and JSON, and the construction rules.
- **Maximal fixture:** carries a full header. The element and attribute censuses replace their blanket "header set aside" rule with an **exact** per-pair classification (`tests/support/header.py`).
  - Writing that out exposed a hidden misclassification: `mes:Structure` names both the message root and a header's structure reference, so the blanket rule had also absorbed the message **footer** unexamined.
- **Oracles:** FMR 12.4.2 and pysdmx accept the documents with their full header, and both are re-recorded.
- **Classification guards updated:** model class count, Ref-field count, the enum↔XSD map (`ActionType`), the non-item list, the JSON read-assumption walk (a sloppy `meta` still reads) and the XML missing-id walk (a header party with no id is a loss, not a refusal).
- **No `Any` added** (`gaps.without_dropped` names `header=` rather than unpacking it) and **no suppressions**.

## Not in this MR

- The SDMX-JSON 1.0 `/availability` writer still takes its id, sender and time from its caller, not from a message.
- JSON `meta.contentLanguages` and `meta.links` are not read: they describe the document on the wire, not header content.
