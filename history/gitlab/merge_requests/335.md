`sdmx.` was written into three renderings — the root, each join, and the
label subquery — where it read as a formatting detail. It was an
assumption: that everything this compiler can reach lives in one schema
of ours.

A dataflow's observations do not. A binding names them
`<database_role>.<table_location>`, which is a two-part name of its own,
and `docs/design/data-plane-query.md` puts the same compiler over them.
Prefixing that root again yields `sdmx.memory.data.obs`, which parses
and names nothing.

So `JoinPlan` carries `root_schema`, `None` meaning "qualified already",
and the literal has one home in `STRUCTURAL_SCHEMA`. A *hop* keeps the
constant, and that asymmetry is deliberate: every declared edge targets
a table in `EDGES` and those are all `sdmx`, while only the root can be
elsewhere. A data-plane query has no hops at all, so it costs nothing.

First of the three staged refactors, all of which touch structural code
with structural tests already covering it — they land before any new
surface exists to get wrong. The 5,219 existing tests do not move; the
three new ones pin the behaviour that was previously unreachable, and
were checked against a reverted implementation.
