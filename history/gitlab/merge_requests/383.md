Closes #339. #338 settled the *rule* — a pinned URN caches forever, `latest` is a pointer and never a cache key — and left the *window* to this.

**The provider decides, with a caller override.** This is the one place HTTP cache semantics legitimately apply: a pinned artefact's lifetime is settled by SDMX versioning and no proxy header shortens it, but *how long ago someone last checked* is exactly what `max-age` and `ETag` are for.

## Behaviour, against the provider shapes in our own cassettes

```
no headers                    3 asks -> 3 requests   (invent nothing)
max-age=86400  (OECD)         3 asks -> 1 request
no-store       (ECB, IMF)     3 asks -> 3 requests
no-store + latest_ttl=300     3 asks -> 1 request
ETag only      (SDMX GR)      3 asks -> 3 requests, 2 of them 304s
```

`latest_ttl` is a **floor**: it rescues a provider whose `no-store` is appliance boilerplate — ECB sends it on *codelists*, and stamps `isFinal="false"` on all 2420 artefacts recorded — and can never shorten a window a generous provider granted. Wanting *less* is spelled with a pinned URN, which is not a pointer at all.

## Three structural points

- **Freshness lives in the client; artefacts do not.** Bodies are never stored — the artefacts are interned by pinned URN one layer up, and the only question here is whether the pointer moved, which validators answer without a body.
- **`latest → pinned` is back, with the opposite guarantee.** #338 deleted an index that answered from cache and *never asked*. This one is read **only after** the authority confirms — by a 304, or by a window it granted. Same shape; the difference is the whole point.
- **The query path must not take this route.** A `NOT_MODIFIED` there would write no artefacts, leaving #340's scope membership empty and the query answering nothing. So `get_artefact` stays unconditional — it is what `StructureSource` declares — and only the `get` path opts in, via `get_artefact_if_changed`.

## Mutation testing found two weak tests, not two benign mutants

- **Dropping `no_store` survived.** Every real provider that sends it also sends `max-age=0`, so the suite could not tell which one was doing the work. A contradictory `no-store, max-age=86400` — which no provider would send — isolates the flag.
- **Sending pinned URLs down the freshness path survived.** The session answers pinned repeats before the client is reached, so no conditional request is ever made whatever the rule says. Asserted on the client instead: a pinned URL gets no freshness entry at all.

Six mutants now die, including the bound on the freshness store.
