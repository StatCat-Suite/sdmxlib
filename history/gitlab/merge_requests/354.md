## The problem they solve

The structural capability is declared over **column names**: every maintainable
has `agency_id`, so `PredicateShape(column="agency_id")` means something. An
observation's columns come from a DSD, so `column="REF_AREA"` is a fact about
one dataflow rather than about a backend.

So capabilities are declared over **roles**, and `shapes_for(predicate, root)`
rewrites a predicate's columns into them. A structural root passes through
unchanged.

| predicate | normalises to | 2.1 | 3.0 |
| --- | --- | :-: | :-: |
| `obs["REF_AREA"] == "ON"` | `@key_dimension` | Y | Y |
| `obs["FREQ"].is_in([…])` | `@key_dimension` | Y | Y |
| `obs["TIME_PERIOD"] >= "2019"` | `@time_dimension` | Y | Y |
| `obs["TIME_PERIOD"].is_in([…])` | `@time_dimension` | **N** | Y |
| `obs["OBS_STATUS"] == "A"` | `@attribute` | **N** | Y |
| `obs["OBS_VALUE"] > 100` | `@measure` | N | N |
| any, on a root with **no DSD** | *unrewritten* | N | N |

## Three things worth reviewing

**`/data` pushes more than `/structure` does**, which is the opposite of the
usual assumption. The structural surface has no predicate slot beyond identity;
the data surface has a positional key and period parameters.

**The two versions differ on time, not only on attributes** — found while
working #337 through. 1.5/2.1 puts time outside the dotted key (sdmx1 skips it
for the same reason, commenting *"TimeDimensions handled by query parameters"*),
so there is no `+`-joined segment and `startPeriod`/`endPeriod` is one
*contiguous* range: `is_in(["2019", "2021"])` would silently acquire 2020.
Equality survives on both by different means, so it stays shared.

**Under-declaring is deliberate, twice, and asserted rather than commented.**
Strict `>` / `<` on time is absent because the period bounds are inclusive, so
pushing one returns a period too many. No measure filter, because `c[…]` is
defined over any component but a filter on an observation's *value* is not
something this can vouch for providers implementing. Under-declaring costs a
local filter; over-declaring costs correctness.

## Failing closed

A root without a DSD reports no roles, so shapes keep their physical column
names, no data capability declares one, and every predicate becomes a residual
evaluated locally. A binding alone knows a column is *a dimension*; only a DSD
knows whether it is in the key, where, or whether it is time — and guessing
builds a positional key with a wrong slot, which returns a different slice and
raises nothing.

## Tests

Every fixture column is *renamed* away from its component id, so a lookup that
skipped the binding returns `None` for all of them rather than passing by
coincidence.

Mutation-checked rather than trusted: failing open without a DSD is caught by 1
test, reporting time as an ordinary key dimension by 4, skipping the binding
inverse by 7, declaring measures on 3.0 by 2, attributes on 2.1 by 1, a strict
time bound by 1, giving 2.1 back `InSet` on time by 2.

The first cut of the sigil test caught **nothing** — it compared against
`ROLE_SIGIL` on both sides, so it passed for any value including `""`, and the
collision it claimed to test could not arise because a column with a role is
rewritten regardless of its name. Rewritten to assert through `accepts()` on a
column that keeps its raw name, which does catch it.
