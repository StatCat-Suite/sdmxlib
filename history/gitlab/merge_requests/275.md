## Two findings

**`ItemPredicate` has only `~`** — no `&`, no `|`. The composition laws #251
anticipated, and the De Morgan laws #260 explicitly deferred *to here*, have
nothing to apply to. Double negation does, and is asserted.

Taken with #260's own finding, **the codebase has no boolean-algebra surface
anywhere**: negation is a per-field flag or a single unary operator, never a
combinator tree. Both issues assumed otherwise, and each discovered it
independently — worth stating once so a third does not.

**`Query[T]` mutates.** `filter` appends to the receiver and returns `self`:

```python
base   = reg.query(sl.Dataflow, agency="ESTAT")
annual = base.filter(...)      # annual is base
other  = base.filter(...)      # also base
base.fetch()                   # [] — both predicates landed on it
```

Every other query class in this library is a frozen record that evolves. Filed
as **#291**; pinned here, and the properties build a fresh query per example
rather than branching — with a note to restate them in the branching form that
commutativity naturally wants, once it is fixed.

## Also worth having

`CompileContext.schema` was `sql.py`'s one *real* uncovered line, and it is the
documented remap point that #257's `assert_only_known_tables` exists to catch
going wrong. Now a property: total, defaults to identity.

Alias uniqueness is stated over **generated prefix sequences** rather than
`test_sql.py`'s two hand-written cases — including the case a hand-written test
does not think of, the same prefix requested repeatedly and interleaved with
others. Two subqueries sharing an alias produce SQL that runs and returns the
wrong rows.

The `item()` differential needs no oracle: the lambda *is* the oracle, since
the expression form exists only to be a more readable spelling of it. Every
operator it offers is checked, not the one or two a hand-written test would
have picked.
