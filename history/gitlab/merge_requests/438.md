`tests/docs/test_doc_blocks.py` executes every ```python fence on the page. Two of the three sections added for 0.60 could not run.

## The two blocks

**Unhashable collections.** The example raises by design — that *is* the new behaviour. It now carries `<!-- test: raises -->`, and the working replacement moves into its own fence: a `raises` block stops at the first exception, so anything after it would sit unexecuted while looking checked.

**`attachment`.** The block named a bare `attr` the page never binds. It builds one now — `sl.Attribute(id="OBS_STATUS", attachment=sl.AttachmentLevel.OBSERVATION)` is the shortest honest construction, since `Attribute.concept` wants a scheme-backed URN and is not what the section is about. Its `print` claim is checked against the real value by the same runner.

## How it got in

The pre-tag verification ran `just check` and `just test`, not `just test-docs` — so **v0.60.0 shipped with this red**. `just ci` is the gate precisely because it covers the suites the inner loop skips, and it is what should have run before the tag.

Nothing about the release is wrong: the guide's prose and the API it describes agree, and `test_upgrading.py` (which checks the removed/added names against `sl`) was passing throughout. What failed is the page's own executable examples.
