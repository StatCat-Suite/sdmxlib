## `_build_observations` hid a deliberate difference behind an accidental-looking one

Four modules created an identical `data.observations` table, then inserted three, four or five rows:

```
cookbook_federation        A/CA, A/US, Q/CA
federated_catalog          A/CA, A/US, Q/CA, M/US
component_availability     A/CA, A/US, Q/CA, M/US, M/NULL
contentconstraint          A/CA, A/US, Q/CA, M/US, M/NULL
```

The five-row variant ends with a **NULL `REF_AREA`** — which is exactly what the availability builders need, to check a missing dimension value is excluded rather than reported as a code. A real, load-bearing difference that read like someone had trimmed a copy.

`OBSERVATION_ROWS` now orders the rows so prefixes are meaningful and callers slice it, which makes "no NULL row here" a visible choice at the call site rather than an absent line.

The shared builder also **parameterises its INSERT** instead of formatting literals into SQL, per the project's SQL rule.

## Stopping here, deliberately

The remaining 37 definitions are not a backlog. They are:

- **Bespoke by design** — five `_make_dsd`, five `_make_msd`, four hand-built `_binding`, three thin `_build_dsd` wrappers. Each was assessed in an earlier pass and left because the difference *is* what the test is about.
- **Trivially small with genuinely different bodies** — `_dsd` (5 defs, 5 distinct, 2–25 lines), `_cl` (3/3), `_drain` (3/3), `_populate` (3/3, 5–37 lines).

Only `_codelist` has two identical definitions, and they are **three lines each**. Sharing those would cost an import to save a line.

Driving the count to zero would mean sharing things that should not be shared, which is how `tests/support/` becomes the dumping ground the earlier passes were careful to avoid.

## Verification

- **Zero assertion lines changed**, as in every pass.
- `just ci` green — 2513 unit, 72 docs.
- One migration bug caught before it hit disk: the `_make_mdf` call sites nest (`_make_mdf(footnote_msd())`), and a `[^)]*` regex cannot match balanced parens. The rewrite now parses its output with `ast.parse` before writing, so a broken transform fails loudly instead of landing.
