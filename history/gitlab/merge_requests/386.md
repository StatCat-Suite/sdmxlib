## The docs did not build

`api.md` still pointed mkdocstrings at `sdmxlib.local.registry.Registry` (renamed in !372) and `sdmxlib.api.query.GetQuery` (deleted when `get` absorbed the three entry points). **`just ci` never ran `mkdocs build`**, so nothing caught it.

It does now, with `--strict` — a dangling `:::` directive is otherwise a warning nobody reads, and that build is the only check that resolves every one.

## 13 design pages were unreachable from the site

~7,900 lines, including the entire registry and query-language reasoning. Now in the nav, grouped by subject.

## `docs/upgrading.md`

Every breaking change since 0.48 with a before/after: registry naming, one `get`, `None`-means-absent, `latest` as a pointer, four DSLs becoming one path language, observations moving onto the registry, writers taking a structure, `download`'s explicit format, stricter validation — and a closing section on what did **not** change, since most reading code needs nothing.

**Writing it found a defect in !383.** `latest_ttl=` was documented on `RestRegistry` and reached the client only by being smuggled through `**httpx_kwargs`: it worked at runtime while basedpyright rejected the call site. Documented, functional and unusable in typed code at the same time. Now a declared parameter, with a test that a documented constructor keyword is a real one.

`tests/docs/test_upgrading.py` asserts the page rather than trusting it — an upgrade guide is the one page a reader cannot verify for themselves, because they are reading it precisely because their code does not run yet.
