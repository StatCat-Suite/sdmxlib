`HierarchicalCodelist` and `StructureSet` get a storage kind. Step 1 of #395's
order, and it is not optional: **!466 broke 2.1 ingest and this is the fix.**

## The regression, and why the suite missed it

SDMX-ML 2.1 has no way to write a `<str:Hierarchy>` except inside a
`<str:HierarchicalCodelist>`, so every 2.1 document carrying a hierarchy
carries the container too. After #394 completed `all_artefacts()`, storage saw
the container for the first time and refused it — so
`parse(xml, registry=…)` refused the whole document:

    HierarchicalCodelist is not persisted by this registry — an SDMX 2.1
    container; 3.0 promoted Hierarchy to top level (#395).

Correct behaviour by #394's rule, and a worse outcome than the silent drop it
replaced. Both are now gone: the container is stored.

`tests/unit/test_parse_with_registry.py` never parsed a hierarchy fixture into
a registry — which is why `just ci` was green through the break. It does now,
against `tests/fixtures/sdmx_ml21/with_hierarchy.xml`, the shape a real 2.1
producer emits.

## No new tables

Each container is a maintainable plus lists of refs, and `artefact` and
`artefact_ref` already hold exactly that — so this is a kind, a writer and a
reader, and no schema change. `artefact_ref.role` carries the field name, which
is what lets one table hold both of `StructureSet`'s lists without them merging
on read; `ordinal` keeps the members in the order they were written, because
the model stores a tuple and a tuple that reshuffles between reads is a diff
nobody asked for.

Round-tripped: the container's own name survives — #239's case, which used to
be lost at parse and was then lost again at storage — and `StructureSet`'s two
ref lists come back separately.

## Typing

`_read_container[T](…, cls: type[T])` was the first shape and both checkers
refused it, from opposite directions: pyrefly called the `cls(…)` result an
implicit `Any`, and adding the generic then hid the constructor from
basedpyright, which could not see `description` or `annotations` as parameters.
Two explicit four-line constructors that both checkers can verify beat one they
cannot, so the shared part is the *ref reading* and each class is built where
its fields are known. No suppressions, and the `Any` ratchet is unmoved.

## Still refused, and still recorded

`StructureMap`, `ConceptSchemeMap`, `CategorySchemeMap` and
`AttachmentConstraint` keep their `_NOT_PERSISTED` entries. #394's refusal
tests moved onto `StructureMap`, since asserting the refusal on a type that
just became storable would have quietly stopped testing anything.
