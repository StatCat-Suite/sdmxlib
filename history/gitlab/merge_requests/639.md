Part of #492 (the "related bug" it lists; the two stages remain open).

`validate(message)` returned `None` without checking anything. It took `object`, no rule matched a message, and nothing looked at the artefacts inside.

## Change
- `validate` hands a `StructureMessage` **or** `MetadataMessage` to `validate_message`. `validate_message` now takes either, since both have `all_artefacts()`.
- Anything that is not a maintainable artefact raises `TypeError` naming what it got. Before, an item, component or str passed silently, as if it had been checked.
- The signature is now `MaintainableArtefact | StructureMessage | MetadataMessage`, so pyrefly catches a wrong argument statically. `bench/sweep/analyse.py:_validate` had widened its input to `object`, and is narrowed to `Iterable[MaintainableArtefact]` to match `all_artefacts()`.

## Tests
- Structure message: `validate` raises the same issues `validate_message` does, with exact paths, and a clean message passes (the discrimination check).
- Metadata message: a bad set's id is refused.
- Item, component, str and None raise `TypeError`. That call carries one **approved** `# pyrefly: ignore[bad-argument-type]`; it is a deliberate misuse, the same shape as `test_query_misuse.py`.
- Sabotage: without the delegation 2 tests fail; without the `TypeError` 4 fail.
