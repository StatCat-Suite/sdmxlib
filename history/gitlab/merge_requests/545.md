Part of #422, following !544 (geographic codelists). `ValueList` was refused as unmodelled, and a 3.x component enumerated by one was refused for naming the wrong class.

## Decisions (agreed)

- **Own class; `Ref[Codelist | ValueList]`.** `sl.ValueList` with `sl.ValueItem` values (not identifiable: no URN, id any string), in `msg.value_lists`. `Representation = Ref[Codelist | ValueList] | Facet | None`.
- **Enumeration protocol.** `sl.EnumerationLike` (id, version, `code_ids`, `code_map`, `len`) is what a Codelist, LazyCodelist and ValueList share; `CodelistLike` now extends it. On a component: `code_ids()`, new `resolved_enumeration`, and `dsd.code_map` answer for either kind (so polars labels and value checks work); new `value_list`; `codelist` raises TypeError naming `value_list`; `resolved_codelist` / `codes` are None for a value list.
- **2.1: dropped like drafts.** `sl.dropped(msg, "2.1")` leaves out every ValueList and, transitively, anything referencing a ValueList URN.

## Formats

- SDMX-ML 3.0/3.1: `str:ValueLists`; `<Enumeration>` and representation-map ends read as `Ref[ValueList]` when the URN names one (`read_enumerated_representation`). XSD-valid.
- SDMX-JSON: `valueLists`. **Schema quirk:** 2.0's generic `urn` pattern misspells the class `Valuelist` (2.1 fixes it), while both versions' `AnyCodelistReferenceType` spells it right. So a ValueList is referenceable in JSON only where an enumeration is (`_referenceable.ENUMERATION_PAIR_JSON`, applied in `_check_ref_classes`), and a value list is written without its `rel="self"` link. Output valid against 2.0 and 2.1.
- SDMX-ML 2.1: left out, as above; gaps.py declares `sdmx_class` on ValueList and `references` on what names one.

## Storage — schema 2.31

`value_item (value_list_urn, position, item_id, name, description)`; item annotations keyed `<list urn as ValueItem>.<id>`. A representation keeps its URN in `codelist_urn` and reads back typed by the URN's class (`representation.enumeration_ref`). Bundle migrated in place (dry run first); `.2.30.bak` kept until merge.

## Found on the way

- **`Concept.core_representation` had no converter and no URN-text refusal**, unlike every other `Ref` field. The ref-field census matched annotation *text*, and an alias-typed field (`Representation`) was invisible to it. The census now looks through `type` aliases (count 45 → 46) and the field has both.
- From a `LocalRegistry` a codelist resolves to a `LazyCodelist`, so the accessors exclude a ValueList rather than require a `Codelist`.
