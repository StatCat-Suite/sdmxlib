Follow-up to !249. The differential-oracle discipline that milestone %13 phase 1 established lived only in module docstrings, where the next person writing a query property would not look first.

Adds a `### Differential properties and the oracles (query DSLs)` subsection to the Testing section, stating four rules with the evidence behind each:

1. An oracle shares no code with the module it tests, **and the two oracles share no code with each other** — two oracles sharing a helper can be wrong the same way, the one failure mode differential testing cannot catch.
2. An oracle states what the library *does*, not what it should — model the surprise and cite the issue arguing about it (#222, the annotation JOIN's existence scoping).
3. Every predicate kind gets a property, and `test_every_predicate_kind_is_covered` asserts the count off the module.
4. A strategy that leaves a field unset makes every predicate over it vacuous — measure that a new strategy discriminates before trusting the green.

Plus two operational notes that cost real time during !249:

- **`just test-properties` is not in `just ci`** (~7 min at 20× for these two files) and the default width does not find everything. Both defects fixed in !249's second commit were invisible at default width; one surfaced via a filter fragment of `":"`, a needle made only of punctuation, which folds to the empty string and matches every non-null label.
- **Coverage must use `--cov=sdmxlib`**, not `--cov=sdmxlib.model.<module>` — the module-scoped form hits the `_duckdb` shadowing error already documented against `mutate_only_covered_lines` in `pyproject.toml`.

And the triage rule, which is the part that matters when a property goes red: *SQL bug* / *oracle bug* / *underspecified DSL*. All three have happened; the third (#255) was the most valuable outcome.

Docs only — no code, no test changes. `just check` clean.
