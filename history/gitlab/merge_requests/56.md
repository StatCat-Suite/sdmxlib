## Summary
10 files, +648/−445. CI: **1656 unit + 71 docs + 4 deliberate xfail**.

## Conformance bugs fixed in the 3.0 writer
- **\`OrganisationSchemes\` split** into \`AgencySchemes\` + \`DataProviderSchemes\` (v3.0.0 XSD removed the unified container).
- **\`isFinal\` removed** from every maintainable artefact.
- **\`AgencyScheme\` sui generis**: fixed \`id=\"AGENCIES\"\`, never versioned, no \`isFinal\`.
- **Cross-references → URN-text content** per v3.0.0 XSD — \`ConceptIdentity\`, \`Enumeration\`, \`Structure\` (in Dataflow), \`Source\`/\`Target\` (in Categorisation, scheme maps), \`ConstraintAttachment\` children, and Provision Agreement refs. (2.1 wrapped them as \`<Element><Ref/></...>\`.)
- **\`Code.Parent\`**: simple text element with the parent id as content (2.1 wrapped a \`<Ref/>\`).
- **Container renames**: \`Concepts → ConceptSchemes\`; \`Constraints → DataConstraints\`.
- **\`AttributeRelationship\`**: \`<Observation/>\` (was \`<ObservationValue/>\`); \`<Dimension>id</Dimension>\` simple-text (was wrapped Ref); \`<Dataflow/>\` for dataset-level (3.0 dropped 2.1's \`<None/>\`).
- **\`Attribute.usage\`** translated to the v3.0.0 enum \`{mandatory, optional}\`.
- **\`DataConstraint\`**: \`role\` attribute (was \`type\` in 2.1).
- **\`CubeRegion\` \`KeyValue\` + \`Value\`** in \`str:\` namespace (were \`com:\` in 2.1).
- **\`GroupDimension\`** uses \`<DimensionReference>id</...>\` — an earlier cleanup comment incorrectly claimed \`dimensionRef=\` was the 3.0 shape.
- **\`DataStructure\` annotations** come *before* \`Name\` (3.0 is strict on ordering).
- **\`StructureSets\` dropped**: 3.0 split into separate per-kind containers (CodelistMaps, ConceptSchemeMaps, ...). The writer no longer emits a non-conformant \`<str:StructureSets>\`.

## Reader compatibility
The 3.0 reader accepts both the conformant 3.0 shape and the legacy 2.1-style shapes for every change above — URN-text or wrapped Ref, nested DimensionReference or the transitional \`dimensionRef=\` attribute, KeyValue in either namespace, \`constraint_type\` from \`role\` or \`type\`. Files in either shape round-trip cleanly.

## Test changes
- \`test_sdmx_ml30_writer.py\`: \`_roundtrip\` calls \`assert_valid_sdmx_ml\` on writer output. New \`test_input_fixture_is_xsd_valid\` parametrized over the three input fixtures.
- \`test_sdmx_ml30_reader.py\`: updated assertions to match the conformant shapes (usage enum, no-\`isFinal\`-in-3.0, no \`StructureSets\` in 3.0).
- \`test_roundtrip_complete.py\`: 4 ml30 tests marked \`xfail\` with clear follow-up notes — \`complete.xml\` is still in 2.1-style shape; writer translations break round-trip equality with it.

## Fixtures rewritten
\`minimal.xml\`, \`with_groups.xml\`, \`with_categories.xml\` rewritten to be v3.0.0-XSD-conformant. \`complete.xml\` is deferred to a follow-up (281 lines, semi-independent).
