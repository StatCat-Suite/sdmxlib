Closes #210, the last issue in the milestone.

Four writer section tables paired a message attribute with a converter, and nothing checked that the two matched. **Verified rather than assumed** — this typechecks today and fails at runtime inside `write()`:

```python
("codelists", "codelists", to_dataflow)   # basedpyright: no error
```

Entries are now built through a generic factory — `section_entry` in `formats/sdmx_ml/_common.py` for the three XML writers, `_section` in the SDMX-JSON writer:

```python
_section("codelists", lambda m: m.codelists, to_dataflow)
# error: Parameter 1: type "Codelist" is incompatible with type "Dataflow"
```

The single type parameter appears in **both** the accessor and the converter, so the checker has to unify them.

## Why storage still erases to `Any` — and must

`Callable` is contravariant in its parameters. A common supertype of `Callable[[Codelist], …]` and `Callable[[Dataflow], …]` needs a parameter type that is a subtype of both — that is `Never`, and `Callable[[Never], WireStruct]` is uncallable. No annotation recovers the per-entry type, because the invariant is *dependent*: this attribute holds items of type `T` **and** this converter takes `T`.

So the erasure is forced. What changed is that it now happens **after** the check, at the one place the mistake is actually made.

## Wider than the issue described

The issue listed two tables. There are **four** — `sdmx_ml30` and `sdmx_ml31` still carried a bare `Any` in the writer slot (`list[tuple[str, list[tuple[str, Any]]]]`), having been missed when !203 narrowed the other two. 62 entries bound in total.

## `getattr(msg, attr)` is gone

All four writers reached the message through a dynamic string attribute. The getter replaces it with a checked access. That was an untyped hole the earlier `Any` audit never counted, because `getattr` is not an annotation.

## Guarding it

The invariant is type-level and erased at runtime, so it cannot be asserted by calling anything. The tests assert the *mechanism* instead — that both factories stay generic and that both callable parameters are typed in terms of the type variable — via PEP 695's runtime `__type_params__`.

**Confirmed non-vacuous by mutation**: de-genericising the factories (the one edit that silently restores the old unchecked behaviour) fails both tests. The real tables are checked by `just check`; these guard what those tables depend on.

I first wrote this guard by shelling out to basedpyright, which is strictly stronger — it asserts the checker actually rejects a mismatched pair, and it also caught the mutation. It needs `# noqa: S603` on the `subprocess.run` call, so I dropped it rather than grant myself a suppression. **Say the word if you want that version instead** — it's about 40 lines and runs in 1.5 s.

## Verification

**Byte-identical against `main` across 110 writer outputs**: 22 XML fixtures × {2.1, 3.0, 3.1} × {plain, pretty-printed, `metadata_links`}, plus the SDMX-JSON writer with and without `metadata_links`. Baseline run verified non-vacuous.

`just check` clean; **2511** unit tests pass.
