Step 5 of `docs/design/registry-and-catalog.md` §6 was "delete the aliases
`reported_attributes` / `artefacts` / `metadata_for_target`." Implementing it
turned up evidence against **all three**, so this records the reversal instead
of forcing deletions the codebase argues against.

## The evidence

- **`artefacts(type)`** is not row selection. It maps a Python class to the
  wire discriminator (`sl.Dataflow` → `"Dataflow"`) with a validating
  `TypeError`. `query(q.artefact).filter(q.artefact.type == "Dataflow")` makes
  the caller hardcode the wire string — the method does what the query language
  cannot do ergonomically. A prior milestone already kept it, with
  `test_reg_artefacts_still_narrows_by_a_runtime_type` pinning it.

- **`reported_attributes()`** is a documented, curated convenience: ~40 call
  sites, a whole `reference_metadata.md` cookbook section ("every QUALITY
  statement anywhere — use `reg.reported_attributes()`"), a `query-language.md`
  surface listing, and an explicit pairing with `metadata_report`
  (cross-catalogue vs per-set). Same category as `codelist()`, `code_map()`,
  `get_all()` — all kept.

- **`metadata_for_target()`** stays by consistency. I *verified* the query
  replacement is equivalent (target lookup, `structure_urn` filter,
  `order_by(urn)` all map), so a caller who wants the query form has it — but
  "possible to inline" is not the bar the other conveniences were held to.

The rule, corrected: **a named convenience over a common query earns its name
when it is documented and used**, exactly as a proxy like `codelist()` does.
"Row selection wearing a name" catches an *undocumented* duplicate, not a
curated entry point.

## What survives of step 5 — two open questions, not deletions

- **`scan_csv` on `RestRegistry`** auto-resolves the DSD from the `DATAFLOW`
  column. `slpl.scan_csv(source, structure=…)` takes an explicit structure, so
  this is not a "move" — it is a convenience that needs a registry. Leave,
  promote to the shared surface, or make it a free function?
- **`load(source)`** cannot become "ingest": `Registry.ingest` already exists
  and takes an `InMemoryRegistry`, not a file. `load_file` / `add_file` / leave?

## Also

Fixes a stale `CLAUDE.md` example — the common-patterns block still used
`reg.get(Type, agency=, id=).resolve()`, the API deleted in step 4. Now
`reg.get(urn_for(...), resolve=True)`.

Docs-only. `just check` and `just test-docs` green.
