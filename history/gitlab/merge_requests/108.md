## Summary

Follow-up to !147 — applies the same "raise instead of return a list" treatment to `validate_references()`. Same reasoning: a function that returns `list[ReferenceIssue]` invites silent bugs (callers forget to check). The new contract returns `None` and raises `ReferenceValidationError` with all accumulated broken-Ref issues attached.

## Why this isn't wired into `serialize()`

`validate_references()` is a closed-world check — every Ref in the message must point to an artefact also in the message. That's too aggressive for partial bundles (e.g. a Dataflow shipped without its DSD), which are legitimate over the wire. So unlike IDType validation in !147, this stays an explicit opt-in for callers who want the guarantee.

## Breaking change

`validate_references()` no longer returns `list[ReferenceIssue]`. Catch `ReferenceValidationError` and read `e.issues` for the full list.
