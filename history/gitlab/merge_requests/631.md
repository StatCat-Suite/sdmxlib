This requires Python 3.14: `requires-python = ">=3.14"`. 3.14 is what work runs, and its deferred annotations (PEP 649) and `annotationlib` are worth having.

## Measured before deciding

- **Every runtime dependency ships 3.14 wheels**: duckdb 1.5.6, polars 2.0, pyarrow 26, lxml, msgspec, attrs, httpx.
- **It is not faster here.** Six interleaved single-process runs of the parsing tests took 21.3 s on 3.14 against 20.7 s on 3.13; both interpreters are PGO+LTO builds. The DuckDB-bound unit tier was within noise.
- **It does not bring PEP 728's `closed=True` TypedDicts.** Those are in 3.15.

## Changes

- **Version pins:** `requires-python`, the classifier, `.python-version`, the pages image, CLAUDE.md, and the target versions in `ruff.toml` and `pyrefly.toml`. The two protected files were approved for this change, and only their version lines changed.
- **Lint:** ruff at `py314` removes 536 quoted annotations. That surfaced two findings the quotes had hidden, a boolean positional parameter and a loop that should `extend`, and both are fixed. Two `noqa: E501` became unused and are gone. No suppression is added.

## What 3.14 broke, each fixed

- **Reading an annotation evaluates it**, and a name imported for type checking alone then raises `NameError`. This was a real runtime bug:
  - `FederatedRegistry` read each source's `get` signature that way on every dispatch, so on 3.14 it raised. It now reads parameter names only (`annotation_format=FORWARDREF`).
  - `_refshape`'s maintainable field list failed at import. It now reads names through `annotationlib`.
- **attrs evaluates converter annotations when the class is built** ([attrs#1470](https://github.com/python-attrs/attrs/issues/1470), open). Two converters name a class that can't be resolved at that point. Each now annotates through a lazily evaluated PEP 695 `type` alias, with no suppression. Adding `from __future__ import annotations` to those modules was tried first: it turned their attrs field types into strings and broke runtime reflection (36 failures).
- **A class without the future import keeps no `__annotations__` in its namespace.** So `vars(cls).get("__annotations__", {})` returns `{}`. The query tests that read accessors that way worked only because `accessors.py` has the future import. They now read through `annotationlib`, as does `query.py`.
- **Tests that compare signature text** now read it as written (`annotation_format=STRING`).
- **Unicode 16.** Python 3.14 decomposes or drops 60 code points that DuckDB 1.5.6's `strip_accents` doesn't know and leaves alone. Both fold oracles model that, each restating it independently. A Unicode bump on either side fails `test_oracle_fold`.
- **Cassettes.** The JSON cassettes matched every header, including urllib's `User-Agent`, which names the Python version. They now match on `Accept`, through a registered matcher.

## Found, not fixed here

The fold oracles disagree with DuckDB on all 11,172 Hangul syllables, on 3.13 too. `test_oracle_fold.py`'s sweep stops at U+2FFF, so it never reached them. That's a separate follow-up.
