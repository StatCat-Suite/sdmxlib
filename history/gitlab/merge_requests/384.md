## And the obvious repair was also wrong

Asserting `full > partial` **fails against ECB**. Measured across every enumerated dimension of ECB_EXR1:

```
dimension         partial     full
FREQ                   10       10
CURRENCY              369      369
CURRENCY_DENOM        369      369
EXR_TYPE               36       36
EXR_SUFFIX              6        6
```

ECB does not trim. `referencepartial` *permits* a provider to return only the codes a structure uses; this one returns the whole codelist either way. So **`partial=True` — the default — saves nothing against ECB**, and the difference the parameter names cannot be demonstrated against this provider at all. `tests/unit/test_rest_partial.py` exercises it against one that does trim.

That finding condemned a neighbour: `test_resolve_partial_true_trims_codelists` claimed *"constrained FREQ codelist has fewer codes than the master"* — which ECB does not do, and which its `>= 1` assertion never checked either. Renamed to what it verifies.

## #312's gap is closed rather than documented

The placeholder recorded what was untested — response shapes, error statuses, and whether a real service honours `references=` the way the spec reads — and needed a network to fix.

**It does honour it.** A `dsd.dimensions.any(q.component.id == "CURRENCY")` crossing returns `ECB_EXR1`, which is only possible if ECB actually sent the components the closure asked for; a provider that ignored the parameter would return bare DSDs and the query would find nothing, silently. Three tests now cover the REST path language on the wire: a scan, a local-only predicate applied after the fetch, and that crossing.
