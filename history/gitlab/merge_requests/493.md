`reg.get(SdmxUrn.parse(text))` reads as `LazyCodelist | None` whatever the URN
names. #399 filed that as the price of `get`'s overload ordering and offered
four options, preferring to narrow `SdmxUrn.parse` to `SdmxUrn[object]` once
#286's cost was re-measured.

Re-measured both halves, and the diagnosis moves: the library has nothing wrong
with it, and the option it preferred is the expensive one.

## It is step 5, and one checker skips it for a nested Any

The typing spec's overload algorithm, step 5: when more than one overload still
matches and "the return types are not equivalent, overload matching is
ambiguous. In this case, infer a return type that is assignable to each of the
remaining return types". It applies to an argument type that *contains* `Any` —
the spec's own example is `list[Any]`.

`get` has two lazy-root overloads returning different classes, so the spec
answer for `SdmxUrn[Any]` is a gradual type. Measured on 25 lines with no
sdmxlib in them:

| argument | spec | basedpyright 1.39.9 | pyrefly 1.2 |
| --- | --- | --- | --- |
| `Box[Any]`, two specific overloads differing | gradual | **LazyA** — first match | `Any` |
| bare `Any`, same shape | gradual | `Unknown` | `Any` |

basedpyright applies the rule for an argument that *is* `Any` and not for one
nested inside a generic. That one line is the whole finding, and `SdmxUrn[Any]`
is the nested case. pyrefly already answers honestly; basedpyright is the source
of truth for `just check`, which is why the wrong type is the one a caller sees.

## What #399's option 2 costs

Narrowing `SdmxUrn.parse` to `SdmxUrn[object]`: **52 basedpyright + 27 pyrefly**
findings. #286 recorded 23; `tests/` entering basedpyright's scope in #347 is
the growth. Every one is the same fact — `Ref` is invariant by design (#289), so
`Ref[object]` does not go where `Ref[Codelist]` is wanted — at 52 sites of
correct code. That is ~50 casts to work around another tool's bug, so it stays
rejected with the number attached rather than with a four-milestone-old one.

Reordering does not help either, and the sabotage check for the new probe
demonstrates it: generic overload first gives `Any | None` for the ambiguous
case *and* `Codelist | None` for a codelist URN — the silent lie #397 removed.
#399's table was right about that trade-off; what it misattributed was the
`Any` case.

## What lands

Nothing in `src/` changes behaviour. Two guards and two corrected docstrings:

* `tests/typing/probe_urn_any.py` pins the declared types **including the wrong
  one**, says so in the first paragraph so no reader takes it for a claim, and
  lists the three deletions that come due when basedpyright conforms. Watched
  to fail: reordering the overloads breaks all four assertions.
* `tests/unit/test_overload_any_ambiguity.py` runs both checkers on the repro
  and pins each answer, plus a third test asserting they genuinely disagree —
  without it the file could quietly measure one thing twice, and a resolution
  in either direction would pass unnoticed. It is also the upstream paste.
* `LocalRegistry.get` and `SdmxUrn.parse` now carry the measurement, so the next
  reader does not re-litigate from #286's 23.

The runtime half of #397 is untouched and is what keeps this cosmetic: the lazy
classes refuse `codes` / `tree` / `descendants` by name, so a wrong static type
cannot become a wrong read.
