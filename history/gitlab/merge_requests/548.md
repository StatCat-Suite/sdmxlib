Part of #422 — the SDMX-JSON half of the guard-first work (!547 did SDMX-ML).

## The problem

msgspec structs silently discard keys they do not declare, so the JSON register only caught constructs a hand-written row named. A schema-vs-writer comparison found ~90 properties read and dropped unrecorded.

## Generic detector (agreed design)

`_losses.undeclared`: the reader decodes each read section once more, untyped (`list[object]`), and walks it beside the structs that decoded it. Any key a struct has no field for — at any depth — is a `ReadGap` named `<Struct>.<key>` on the artefact. Complete by construction for undeclared keys; no row needed.

**Cost, measured** (interleaved A/B/A, 100,000-code codelist, 12 MB): the untyped decode is 0.045 s; the walk was 8 s extra (16.8 s vs 8.7 s) because `msgspec.structs.fields` ran per object. Cached per struct class (`_declared`), the walk is within noise. Guarded by a count: a second read adds no cache misses.

**On the SDMX-TWG's official 2.1 sample** the reader reported one lost construct; it now reports 51 — `isPartial`, `isPartialLanguage`, `isExternalReference`, `x-extension` keys, `Link.type`, a component list's `id`/`links`. The test pins them exactly.

## Rows for keys a struct declares but ingest ignores

`annotations[].links[].urn`, `links[].hreflang|urn` (a held link's language; a `describedby` link's URN), `coreRepresentation.minOccurs|maxOccurs`, `coreRepresentation.enumerationFormat` — each with an injection and strict-xfail round trip.

## The JSON census — `tests/unit/test_json_census.py`

Per schema version (2.0, 2.1), every `(definition, property)` pair the structure schema allows under a read section, against what the writer emits for `maximal` + `tests/support/shapes.py`. The structs are followed **statically** from `StructureDataJson` along their field types, so:

- **detected** (no struct declares it) — derived, not listed;
- **covered** (below a detected key) — derived;
- **listed** — a struct declares it and nothing writes it: `_DECLARED` names its row, or why it is held/absent (the `ReportingYearStartOrEndDay` duplicates of `AttributeType`; a second hierarchy level; a 2.1 component value's validity, which validation refuses to write).

Sabotage-checked: disabling the walk fails 8 tests; declaring `isPartial` on `CodelistJson` without writing it fails the census.

## Shared shapes

`_shapes()` moves to `tests/support/shapes.py` (both censuses use it) and gains free-text components with full facets, an MSD, and regex/index value maps — classes no fixture held, so no census compared them.

## Defects found, pinned as strict xfails (next MRs)

- **SDMX-ML 3.x multi-level hierarchies:** the XSD nests each level in the one above (`Hierarchy` holds one `Level`); the writer emits siblings — XSD-invalid past one level — and the reader reads siblings, so a conformant document's second level is the registered `str:Level/str:Level` loss.
- **SDMX-ML 2.1 regex/index value maps:** written as a `Ref` whose id is the pattern (XSD-invalid), losing both variants' validity and the index bounds, unrecorded.
