Decided: refuse for 3.0, rather than dropping `<Parent>` or writing it anyway.

SDMX-ML 3.0.0 types `<Code><Parent>` as `SingleNCNameIDType` (`[A-Za-z,A-Za-z0-9_-]*`), while a code's own `@id` is any `IDType`. So `<Code id="_T">` is valid 3.0.0, and a child of it is not. This is a schema erratum; 3.1.0 types `<Parent>` as `IDType`, and 2.1 never narrowed it.

The 3.0 writer emitted such parents schema-invalid at every registry the sweep read: OECD 18,562 codes, FMR 1,479, IMF 433, BIS 50.

## Changes

- **`check_serialisable` refuses it for 3.0** (`_check_code_parents_in_30`). There is one issue per codelist, with a count and up to three examples, pointing at 3.1 or 2.1. One issue per code would be thousands.
- **Not dropped.** Losing `<Parent>` flattens the hierarchy, and 3.1 carries it.
- **Reuses `_NCNAME_RE`** rather than a second copy of the pattern.
