Closes #187.

## The finding

SDMX 3.0's information model — both the `SDMXMetadataGeneric` XSD (`MetadataSetType` xs:choice) and the JSON metadata schema — reports a MetadataSet against a **Metadataflow** *or* a **MetadataProvisionAgreement**, never a MetadataStructure directly. Our model allowed `Ref[MetadataStructure]`, which has **no conformant wire form** — both our JSON writer (`metadataStructure` key) and SDMX-ML 3.0 writer (`<md:MetadataStructure>`) emitted off-spec output.

Per the decision on the issue: **model MPA, then constrain.**

## Changes

- **New `MetadataProvisionAgreement` maintainable** (`model/metadata_provision.py`) mirroring `ProvisionAgreement` — references a `Metadataflow` + a metadata provider (`AnyRef`). Exported from `sdmxlib` / `sdmxlib.model`.
- **`MetadataSet.structure` → `Ref[Metadataflow] | Ref[MetadataProvisionAgreement]`.** Passing a `MetadataStructure` now raises a `TypeError` pointing at the fix (wrap in a Metadataflow). The non-conformant case can't arise.
- **Wire (JSON + SDMX-ML 3.0)** emit/read `metadataflow` / `metadataProvisionAgreement` (JSON) and `<md:Metadataflow>` / `<md:MetadataProvisionAgreement>` (XML).
- **Storage**: MPA persists to a dedicated table + reader (reconstructs its `metadataflow` ref), registered in the kinds/dispatch tables — so the **set → MPA → Metadataflow → MSD** resolution chain works through the DuckDB registry (`Registry.metadata_report` walks it).

## Bonus: fixed pre-existing SDMX-ML 3.0 metadata XSD non-conformance

Validating the MPA path surfaced that the **whole GenericMetadata envelope was off-spec** (2.1-style `<Ref>` containers + a data-message-shaped header). In SDMX-ML 3.0 all reference types are **simple URN strings**, so:
- header `<mes:Structure>` now uses `GenericMetadataStructureType` (only `structureID` — no `namespace` / `dimensionAtObservation`), MSD URN as `<com:Structure>` text;
- the set element is `<mes:MetadataSet>` (message ns) with `<md:…>` children;
- structure refs and `<md:Value>` are URN/text, not `<Ref>` / unnamespaced.

Locked with `assert_valid_sdmx_ml` conformity tests (metadataflow + MPA) against the vendored 3.0 XSD, and a JSON `metadataProvisionAgreement` conformity test.

## Tests

Rewrote the ~15 tests that relied on MSD-direct to use a Metadataflow/MPA; added MPA round-trip (JSON + XML), storage round-trip, MSD-behind-MPA resolution, and XSD/JSON conformity coverage. `just check` clean; full suite **2440 passed**.
