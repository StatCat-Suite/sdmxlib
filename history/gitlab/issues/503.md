# Issue #503: Writers spell out schema defaults: omit an attribute at its format's default, except identity

## Decision (2026-10-19)

Output has **one canonical spelling per meaning, the minimal one**. An optional attribute at the default *its format and type* declare is omitted. The input's spelling is not preserved: the information model has no "stated vs defaulted" distinction to hold it in, and it would not survive a conversion anyway (2.1 requires `assignmentStatus`). There is **no option** to spell defaults out. Add one only if a real consumer breaks on an absent default.

Two exceptions, always written:
- **Identity:** an artefact's `id`/`agencyID`/`version`, and a reference's `@version`, `@maintainableParentVersion` and `@class`, even where 2.1 defaults them (e.g. `version="1.0"`). A consumer should not need the schema's defaults to know what is named.
- **What a format requires,** e.g. 2.1's `assignmentStatus`.

The default is per format and per type, not per attribute name:
- 3.1 flipped `TextFormat/@isMultiLingual` to default `false`;
- `textType` defaults to `String` on component formats and `ObservationalTimePeriod` on a time format;
- SDMX-JSON gives `usage` `"mandatory"` on some types and `"optional"` on others.

## Audit: defaults the writers spell out today

Measured by serialising the bare artefacts of `test_wire_conformance_gate`, `shapes.message()` and `maximal.message()`, then matching each attribute against the defaults its schema declares.

| attribute | 2.1 | 3.0 | 3.1 | JSON | default |
| --- | --- | --- | --- | --- | --- |
| `Attribute`/`Measure` `@usage` | — | ✓ | ✓ | ✓ | `optional` (JSON: per type) |
| `CubeRegion/@include` | ✓ | ✓ | ✓ | ✓ | `true` |
| `Start/End/Before/AfterPeriod/@isInclusive` | ✓ | ✓ | ✓ | | `true` |
| `Value/@cascadeValues` | ✓ | ✓ | ✓ | ✓ | `false` |
| `TextFormat/@textType` | ✓ | ✓ | ✓ | | per type |
| `TextFormat`/`ToTextFormat` `@isMultiLingual` | ✓ | ✓ | — | | `true` (3.1: `false`) |
| `minOccurs` | | | | ✓ | `1` |

Meanwhile `isPresentational="false"`, `isFinal="false"`, a key value's `include="true"` and others are already omitted. So the writers follow no single rule today; this issue gives them one.

Model check: `Attribute.usage` and `Measure.usage` are never `None`; an unstated usage *is* optional (`datastructure.py`). Omitting the default loses nothing.

## Why it matters

The registry sweep compares our rewrite with the source. Every default we spell out where a producer omitted it is reported as `read_gained`: on a 2% ESTAT sample, 9,684 `Attribute/@usage` and 7,786 `Measure/@usage`, all non-findings. #502 is the mirror case, where a producer spells out a default and we omit it, reported as `read_lost`.

## Done when

- The writers omit every non-identity optional attribute at its per-format, per-type default.
- A guard test does what the audit above did, failing on any non-identity attribute written at its declared default. It must be watched failing against today's writers first, so it is known to be able to fail.
- Together with #502: the sweep census treats `read_gained` and `read_lost` defaults alike, so neither side reports a schema default.
