# Issue #483: Structure map rules are unchecked: mixed source/target kinds, multi-source maps, frequency exclusivity, mapping arity (IM §9–10)

| | |
| --- | --- |
| State | closed |
| Opened | 2026-10-16 |
| Closed | 2026-10-21 |
| Milestone | %21 Conformance evidence: what the green checks do not prove |

Found by the IM rule census (#456). SDMX 3.1 Section 2 states these about structure maps, and nothing in `model.validation` checks them (only the SDMX-ML 2.1 projection, `_check_structure_map_in_21`, looks at source/target counts):

- §9.1.2.1 p. 111: "The StructureMap can either map a source and target DataStructureDefinition or a source and target Dataflow, it cannot mix source and target types."
- §9.1.2.1 p. 112: "If a ComponentMap has more than 1 source or target, a RepresentationMap must be used to describe how the values map".
- §9.1.4.2 p. 114: on an EpochMap and a DatePatternMap, `targetFrequencyId` is "Mutually exclusive with freqDimension".
- §10.1.2.1 p. 117: "the RepresentationMapping sourceValues and targetValues must match the order" — i.e. a mapping has as many source values as its map has sources, and as many targets as targets.

All four are checkable on the artefact alone (the first needs only the URN classes of `source` / `target`). When they land, the matching census rows move to `Validated`.

## Comments

### 2026-10-16

Evidence from the FMR oracle (#457): FMR 12.4.2 enforces two of these, and our own shape fixture broke both until it said so.

- **Mapping values are codes of their codelist endpoint.** `RM_N_TO_M` mapped to `B` in a codelist holding only `A`, and from `Z` in one without it. FMR: *Could not resolve reference from structure Representation Map ... to structure Code ...CL_OTHER(1.0).B*.
- **A component map's arity matches its representation map's.** `SM_N_TO_M` mapped two sources to one target through a map with two targets. FMR: *Target Component Size Mismatch. Representation Map AG:RM_N_TO_M(1.0) has 2 target mappings, Component Map ... expects 1*.

Both fixed in `tests/support/shapes.py`; nothing in `model.validation` would have caught either.
