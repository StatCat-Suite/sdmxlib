Found auditing %13/%14/%15. All three are one-liners; the value is that each names a *class* of defect the guards in #t-2/#t-3 then close.

## 1. A doc comment is parsed as a `noqa` directive

`code_query.py` and `hierarchy_query.py` both carry:

```python
#: This was a chain of ``isinstance`` arms carrying a ``# noqa: C901``, whose
```

Ruff scans the raw text, so the literal `# noqa: C901` reads as a directive with a malformed code. Backticks do not escape it. Every cold run emits:

```
warning: Invalid `# noqa` directive on src/sdmxlib/model/code_query.py:998
warning: Invalid `# noqa` directive on src/sdmxlib/model/hierarchy_query.py:831
```

It also inflates the `noqa` count (23 → 24) so a suppression audit reads wrong.

**Fix:** reword so the token is not present — e.g. "a per-function complexity suppression".

## 2. `text_by_ann: dict[Any, dict[str, str]]`

`_query_common.fetch_annotations_for`. The key is a DuckDB annotation id used only for `setdefault` / `get` — a pure-consumer position, which is exactly CLAUDE.md’s litmus for `object`.

## 3. `table = getattr(_thread_local, "table", None)`

`_query_common.cursor_for`. Unannotated, so the local is implicitly `Any`. The same file already has the correct shape three functions down:

```python
lang: str | None = getattr(field, "lang", None)   # the Any dies here
```

## Attribution

2 and 3 are **pre-existing**: both were present at the pre-%13 baseline in *both* `code_query.py` and `hierarchy_query.py`. #267 halved them and moved them into the shared module. Not new defects — newly visible ones.
