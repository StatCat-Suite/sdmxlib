This is `Query[T]` collection search, `item()` / `ItemExpr` filter expressions, and the `SchemaInspector` / `QueryPlan` custom-SQL seam. Together they are the documented entry point in `CLAUDE.md`'s "Common patterns":

```python
dsd.dimensions.filter(sl.item("is_enumerated"))
reg.query(sl.Dataflow, agency="ESTAT").browse()
```

`model/expr.py` is already inside the mutmut `only_mutate` scope, so it is one of the few modules where mutation evidence and property evidence can be compared directly once properties exist.

`tests/unit/test_sql.py` is 23 lines and tests alias-counter increments — that is the whole of the direct coverage for `sql.py`'s `CompileContext`.

## Scope

**`model/expr.py` / `ItemExpr`.** The natural properties are equivalence and algebra:
- `ItemList.filter(item("x"))` equals `ItemList.filter(lambda i: i.x)` for every generated list and every boolean attribute. This is a differential test against the lambda form, and it needs no separate oracle — the lambda *is* the oracle.
- Composition laws for whatever combinators `ItemExpr` supports (`&`, `|`, `~` if present): De Morgan, double negation, `a & a == a`, `a & ~a` empty, `a | ~a` total.
- `partition(p)` is a disjoint cover for every expression, not just for lambdas (`test_properties_core.py` asserts this for lambdas only).

**`api/query.py` / `Query[T]`.** Properties against an in-memory registry:
- Filters compose commutatively and idempotently, the same laws #217 established for `code_query`.
- A query's result is a subset of the unfiltered collection, and every member satisfies the conjunction of filters.
- Narrowing a filter never grows the result (monotonicity) — a strong property that needs no oracle.
- `browse()` yields exactly `collect()`'s members, in the same order, and does not re-fetch.
- Interaction between `agency=` / `id=` / `version=` selectors and version ordering — `test_version_ordering.py` and the `versions()` strategy already exist to feed this.

**`sql.py` / `local/sql.py`.** `CompileContext.next_alias` has a real invariant worth a property: aliases are unique within a context for any interleaving of prefixes. Assert that over a generated sequence of prefix draws rather than the two hand-written cases in `test_sql.py`.

## Risks

- **`Query[T]` needs a registry per example.** Use `InMemoryRegistry` rather than DuckDB where possible; if a property genuinely needs the storage path, scale `max_examples` the way `test_properties_code_query.py` does instead of dropping the property.
- **The uncovered lines may be error paths.** Worth checking before writing properties: if 400-407 is an unreachable branch, the finding is dead code, not missing tests, and should be filed as such.

## Test gates

- Differential property for `item()` against the lambda form covering every attribute kind it supports.
- Algebraic laws for `ItemExpr` composition asserted independently.
- Monotonicity, subset, and commutativity properties for `Query[T]`.
- Alias uniqueness for `CompileContext` as a property over generated prefix sequences.
- Coverage for the five modules reported before and after; each uncovered line either covered or explained.
