# Issue #425: Make pyrefly the only type checker — retire basedpyright

| | |
| --- | --- |
| State | closed |
| Opened | 2026-10-06 |
| Closed | 2026-10-07 |
| Labels | `design` |

## Goal

Make pyrefly the only type checker: it checks `src`, `tests` and `bench`, and basedpyright, its config, its pin and its suppression comments are removed.

## Why now

- **basedpyright just broke a fresh environment with no commit of ours.** basedpyright 1.39.10, built on pyright 1.1.412, stopped solving a generic class passed as a `Callable[[], R]` factory (`x: Box[int] = make(Box)`), which is the shape of every `field(factory=ItemList, ...)` in the model: 44 errors. It's still broken on pyright 1.1.414 / basedpyright 1.40.2. It's pinned to `==1.39.9` for now, and that pin goes away with this migration.
- **Speed.** basedpyright takes about 25 s over `src tests bench`, plus about 18 s for `check-dead-ignores`, a second basedpyright pass made redundant once #347 brought `tests/` under the main typecheck. pyrefly checks all three in about 1 s. `just check` would drop from about 54 s to under 10 s.
- **One tool.** pyrefly is already the editor LSP, and a single config replaces the "one owner per check" bookkeeping between two checkers.

## What we lose (measured, not guessed)

One deliberate violation per basedpyright rule enabled beyond `standard`, run through both checkers with this repo's configs:

| basedpyright rule | after migration |
| --- | --- |
| `reportMissingTypeArgument` | pyrefly `implicit-any-type-argument` |
| `reportMissingParameterType` | pyrefly `implicit-any-parameter` |
| `reportUnnecessaryCast` | pyrefly `redundant-cast` |
| `reportInvalidCast` | pyrefly `invalid-cast` |
| `reportDeprecated` | pyrefly `deprecated` |
| `reportOptionalMemberAccess` | pyrefly `missing-attribute` |
| `reportUnsafeMultipleInheritance` | pyrefly `bad-override` |
| `reportCallInDefaultInitializer` | ruff `B008` |
| `reportSelfClsParameterName` | ruff `N805` |
| `reportUnnecessaryTypeIgnoreComment` | moot: the `# pyright: ignore` comments go; pyrefly's `unused-ignore` covers its own |
| **`reportPropertyTypeMismatch`** | **nothing** |
| **`reportInconsistentConstructor`** | **nothing** |
| **`reportUnnecessaryContains`** | **nothing** |

The three losses are regression guards with 0 findings today. Plus the less tangible loss: **two checkers disagreeing is a signal.** CLAUDE.md records several cases where one caught what the other missed (the pyrefly 1.2 upgrade's five defects; basedpyright's dead-ignore rule exposing findings pyrefly had been hiding). That disappears.

## The work

### 1. Bring `tests/` under pyrefly

Today pyrefly sees `src` and `bench` only. With `tests` added (and `.` on the search path so `tests.support` resolves): **3,291 findings, about 1 s.**

| findings | kind | handling |
| --- | --- | --- |
| 1,842 | `unannotated-return` | test functions without `-> None`; off for `tests/` (basedpyright `standard` never asked) |
| 917 | `implicit-any-parameter` | pytest fixtures; the population of basedpyright's existing per-directory `reportMissingParameterType` subtraction (919) |
| 221 | `missing-attribute` on `NoneType` | Optional access; matches basedpyright's existing `reportOptionalMemberAccess` subtraction (227). `missing-attribute` is broader than the basedpyright rule, so this can't be a blanket "off": it needs a way to subtract only the Optional case, or the 221 fixed |
| about 300 | everything else | triage, see below |

The ~300: `bad-argument-type` (181, of which about 155 aren't about `None`: `attrs.fields()` on something not typed as attrs, `object` passed where `SupportsUrn` is expected, `**kwargs` of `list[object]`), 14 `missing-attribute` on `object` / protocols, 22 `no-any-return-implicit`, 16 `implicit-any-type-argument`, 12 `implicit-any-empty-container`, and a tail. Expect a mix of real gaps in test typing that basedpyright never flagged and pyrefly strictness; per CLAUDE.md, fix in code by default.

Per-directory subtractions need pyrefly's `[[sub-config]]` (`matches = "tests/**"`), each with its measured count and reason, the same shape as the `executionEnvironments` blocks it replaces.

### 2. Resolve the `tests/typing` probe disagreements

pyrefly fails three `assert_type` probes:

```
tests/typing/probe_registry_expect.py:50   assert_type(Any | None, LazyCodelist | None)
tests/typing/probe_urn_any.py:71           assert_type(Any | None, LazyCodelist | None)
tests/typing/probe_urn_any.py:72           assert_type(Any | None, LazyCodelist | None)
```

basedpyright resolves `get()` with an `SdmxUrn[Any]` to `LazyCodelist | None`; pyrefly to `Any | None`. That's #399's subject: decide which answer is right (and probably fix #399) rather than rewrite the probes to match whichever checker is left.

### 3. Remove basedpyright

- 122 `# pyright: ignore[...]` comments: 23 in `src`, 99 in `tests`. Delete each. Where pyrefly also needs a suppression it should already carry a `# pyrefly: ignore`; any that newly surface follow the usual approval rule. Also 3 `# pyrefly: ignore` in tests that pyrefly already reports unused (`tests/support/field_census.py:58-59`, `tests/support/mutation.py:231`).
- `pyproject.toml`: the `[tool.basedpyright]` block, its `executionEnvironments`, and the `basedpyright==1.39.9` pin.
- `justfile`: `typecheck` (becomes pyrefly, or folds into `pyrefly`) and `check-dead-ignores`; delete `tools/check_dead_ignores.py` and its tests.
- CLAUDE.md: the typing-conventions section (source of truth, "one owner per check", "expect to write both comments", the per-directory subtraction notes), the test-style note about `Ref[object]` for basedpyright inference (check whether pyrefly needs it), the protected-files note about `[tool.basedpyright]`, and `pyrefly.toml`'s own header ("basedpyright remains the source of truth").
- Comments in `src` that describe basedpyright workarounds. The notable one: `CodelistLike` (`model/codelist.py`) can't declare `name` / `description` / `codes` because basedpyright reads attrs converter fields as descriptors for protocol matching; `test_name_and_description_are_absent_for_a_reason` and `tests/typing/probe_codelist_like.py` pin that. Under pyrefly alone the protocol may finally widen. Re-test rather than assume.

### 4. Guard the result

Sabotage-test the new gate as CLAUDE.md asks: plant one violation per kind that matters (including a dead `# pyrefly: ignore` in `tests/`) and watch `just check` fail on each before trusting the green.

## Not in scope

- Re-adding the three lost rules some other way (no tool in the stack has them; revisit if pyrefly grows them).
- `--threads` for basedpyright (moot once it's gone).
