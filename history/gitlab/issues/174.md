# Issue #174: bug: hierarchy_query passes a bare Code to artefact_urn (AttributeError — Code isn't maintainable)

| | |

| State | closed |
| Opened | 2026-07-22 |
| Closed | 2026-07-22 |

## Bug

`hierarchy_query.py:219` calls `artefact_urn(value)` when `value` is a bare
`Code`:

```python
if isinstance(value, Code):
    from sdmxlib.model.in_memory_registry import artefact_urn
    return str(artefact_urn(value))
```

But `artefact_urn` reads `.agency_id`, `.version` (plus `.sdmx_package`,
`.sdmx_class`) off the argument, and **`Code` is a child item, not a
maintainable artefact** — it has no `agency_id`/`version` (those live on the
owning `Codelist`). So this raises `AttributeError` at runtime.

## How it surfaced

Found during the T1 typing-hardening work (milestone "Typing hardening"). It was
invisible because `artefact_urn(artefact: Any)` erased the argument type; an
experimental narrowing to `artefact_urn(artefact: HasUrn)` made basedpyright flag
`Code` as non-conforming, exposing the latent runtime failure. The narrowing was
reverted (kept `Any`) so the T1 MR stays scoped; this bug is tracked here.

## Repro (path)

Reached via the hierarchy-node filter DSL when a **`Code` object** (not a code
id string) is compared against a `_CodeUrnField`, e.g. `sl.node.<code-field> ==
<Code instance>`. Comparing against a code id string or a `Ref[Code]`/`SdmxUrn`
takes the other branches and is fine.

## Fix options

- A `Code` alone can't yield a URN — its identity needs the owning codelist's
  agency/id/version + the code's `item_id`. Options:
  1. Reject a bare `Code` with a clear error directing callers to pass a
     `Ref[Code]`, a `SdmxUrn`, or the code id string.
  2. If a `Code` carries enough context elsewhere, build the item URN via
     `SdmxUrn.make(Code, ..., item_id=code.id)` from the codelist context — but
     the codelist identity isn't available at this call site, so (1) is likely
     correct.
- Add a unit test for the `Code`-object comparison branch (currently uncovered —
  which is why the bug shipped).

## Related

Discovered alongside the deferral note in the T1 MR: `artefact_urn` stays `Any`
until this is resolved.
