# Issue #347: tests/ is not type-checked, so 59 suppressions in it were dead and nothing could say so

| | |
| --- | --- |
| State | closed |
| Opened | 2026-08-19 |
| Closed | 2026-09-08 |
| Labels | `design` |

`just typecheck` runs `basedpyright src tests/typing`, and `pyrefly.toml` has
`project-includes = ["src"]`. So **neither checker sees `tests/`** — 266 files,
larger than `src/`.

Two consequences, both measured during the %17 review.

## Suppressions there are inert

Before this review `tests/` carried 73 `# type: ignore` and 107
`# pyright: ignore`. **59 of them were dead** — basedpyright says so itself
when pointed at the directory (`reportUnnecessaryTypeIgnoreComment`). They were
removed in !392, but nothing prevents the next 59: the comments are written
against a checker that never runs, so they cannot be validated *or* invalidated
in the normal loop.

This is the same argument CLAUDE.md makes for the attributable forms
(`# pyright: ignore` over `# type: ignore`) — a suppression nobody can check
is a suppression nobody should trust. It just applies one level up: an
*unchecked directory* makes every form in it unattributable.

## What adopting it would cost

`uv run basedpyright tests` today:

```
  855  reportMissingParameterType     ← unannotated test params; a style choice
  795  reportArgumentType
  262  reportAttributeAccessIssue
  199  reportOptionalMemberAccess
   59  reportUnnecessaryTypeIgnoreComment   ← fixed in !392
   59  reportInvalidTypeArguments
   30  reportCallIssue
   ...
 2386  total
```

Most of the bulk is not defects. `reportMissingParameterType` (855) is
`def test_foo(tmp_path)` — pytest fixtures, which the suite deliberately does
not annotate. `reportOptionalMemberAccess` (199) is largely
`reg.get(urn).id` in a test that knows the artefact is there.

But `reportArgumentType` at 795 is worth a look before dismissing: the sample
below is a test passing a `str` where a `tuple[CodelistExtension, ...]` is
declared, which is the kind of thing that makes a test pass for the wrong
reason.

```
tests/unit/test_xsd_unique_constraints.py:205 - Argument of type "str" cannot be
  assigned to parameter "extensions" of type "tuple[CodelistExtension, ...]"
```

## Options

1. **Adopt with subtractions**, the same governance the rest of the stack uses:
   turn it on for `tests/`, switch off `reportMissingParameterType` and
   `reportOptionalMemberAccess` with a written reason, fix the rest. Unknown
   size until someone triages the 795.
2. **Adopt for a subset** — `tests/support/` and `tests/docs/pages/` are
   library-shaped fixture code, not tests, and would benefit most.
3. **Keep it out, but ratchet the dead suppressions.** A `check-any`-style
   count of `reportUnnecessaryTypeIgnoreComment` in `tests/`, pinned at 0.
   Cheap, and closes the specific hole this issue is about.

3 is the minimum that stops the regression. 2 is where the value is.

The `reportArgumentType` bulk was two causes, both fixed at source in `tests/support` rather than exempted: a helper returning `dict[str, object]` splatted into twenty constructors (250 in one file), and `Query[object]` where `Query[R: RowKind]` is *bound*. The issue asked whether `reportArgumentType` at 795 was worth a look before
dismissing. On this subset the answer was yes: six of the 112 were real, not
annotation noise.

- `serving(data=)` declared `bytes | None` while forwarding to `_data_stubs`,
  which takes a per-flow `Mapping[str, bytes]`.

- Four bench modules imported `artefact_urn` from `in_memory_registry`, which
  only re-imports it.
- `test_compete.py` imported `pysdmx.io.format` / `pysdmx.io.writer` plainly
  after an `importorskip` on the *parent* package — a partial install raised at
  collection instead of skipping.
- `Source.version` was `str` where it feeds `compile_structure_schema`.
- `test_bundle_reads` read `pstats.Stats.total_calls`, genuinely absent from
  typeshed (`Stats` assigns it in `init()`). Replaced by summing
  `profiler.getstats()`, verified equal and fully typed — no suppression.

### 2026-09-07

#370 is closed (!470), so the block on `tests/unit` is gone.

That issue was blocking because 20 call sites turned on how `LocalRegistry.get`
answers its signature. The answer is now `SdmxUrn[T] | Ref[T]`, positional-only,

```

after  #370:  1111 errors, of which  0 are get(str)
```

So `tests/unit` is now the same *kind* of work the three directories in !469
were — a fixed target rather than one waiting on an API decision. 1,111
findings across 236 files, dominated by:

| shape | count |
| --- | --- |
| `Argument of type X cannot be assigned to parameter Y` | 726 |
| `Cannot access attribute X for class Y` | 229 |
| everything else | ~156 |

Whether to take it in one pass or by directory slice is worth deciding before
starting; the 726 will not all be mechanical, and the issue's own sample
(`test_xsd_unique_constraints.py:205` passing a `str` where a
`tuple[CodelistExtension, ...]` is declared) is the kind that makes a test pass
for the wrong reason.

One caveat from !470 worth carrying into that work: subtracting
`reportMissingParameterType` is not free. In `tests/bench` it left the
`registry` fixture parameter unannotated, which made *every* `.get()` on it
unchecked — four `str` call sites survived a green `just check` and were caught
by the bundle tier instead. The subtraction is still right for test bodies, but
fixtures that carry a real type through to many call sites are worth annotating
anyway.
