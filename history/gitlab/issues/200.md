## The actionable parts

**1. Known-shape `dict[str, Any]` → typed.** The `_maint_fields` case (sibling [S1] issue) is the proof: one signature was generating 21 suppressions, and a TypedDict removes all of them. Worth sweeping the other known-shape payloads for the same pattern.

*Re-scoped, and #176 folded in here.* #176 proposed a `TypedDict` per SDMX-JSON message section, on the premise that `orjson.loads(...) -> Any` was the parse seam. Both halves are obsolete: orjson is no longer a dependency, and the reader now decodes through `msgspec.convert(..., type=list[CodelistJson])` — which *validates* the shape rather than merely annotating it, so a TypedDict there would be a downgrade. #176 is closed.

**What survives from it — the untyped envelope (2 sites).**

* `formats/sdmx_json/reader.py:317`
* `formats/sdmx_json/metadata.py:211`

```python
doc = msgspec.json.decode(data)          # -> Any, no type=
payload: dict[str, Any] = doc.get("data") or {}
```

Everything *inside* `data` is already typed via Structs; only the
`{"$schema": …, "meta": …, "data": …}` wrapper is still decoded untyped and
navigated by hand. The fix is one envelope Struct per message kind, decoded
with `type=`, which removes both `Any`s and lets the `$schema` discrimination
be typed too.

This is the exact pattern CLAUDE.md names — *"a bare `msgspec.json.decode(b)`
returns `Any` (pass `type=...`)"* — and pyrefly's `no-any-return-explicit`
guards the return side but not a bare decode assigned to a local. Note the
`payload: dict[str, Any]` annotation is doing its documented job of confining
the `Any` to that line, so this is a tidy-up rather than a live defect.

**2. The 6 `-> Any` returns:**

* `formats/sdmx_ml30/reader.py:724` + `sdmx_ml31/reader.py:710` `_resolve_ref_text` — near-duplicate helpers, both returning `Any`.
* `local/registry.py:164,211` `_FIFOCache.get` / `_CallScopedMemo.get` — both override `dict.get`; the `default: Any = None` / `-> Any` pair is inherited-signature pressure, may be fixable with a generic.
* `model/ref.py:147` `Ref.__getattr__` — **justified**, documented, carries the only `ANN401` noqa in the codebase.

## The `: Any` parameter row is no longer this issue'''s work

That row was a count without verdicts, and re-deriving the verdicts is what made #170 over-scope. It is now split three ways, all in this milestone:

* **#202** — 9 sites where a concrete type already exists in `model/` (e.g. `_write_representation` `isinstance`-checks `Facet` then `Ref` two lines below its `Any`). Mechanical.
* **#203** — 15 sites needing real Protocol / `TypeIs` design. Includes the `attrs.has(type(obj))` walkers in `local/registry.py`.
* **#204** — 7 sites where `Any` is correct; records the verdict so a fourth pass does not re-derive it.

**One item stays here.** `local/registry.py:152,164,211` (`_FIFOCache.__setitem__` / `.get`) are the same functions as the `-> Any` returns in part 2 above — the `default: Any` param and the `-> Any` return are one fix, so this issue keeps both halves.

**And one dependency runs the other way.** #203'''s `sdmx_ml30/reader.py:629,630` cannot be typed until `_resolve_ref_text` stops returning `Any` — part 2 of this issue. Do that first.

## Not actionable

`SdmxUrn[Any]` and `Ref[Any]` (31 lines) are deliberate and should stay — `CLAUDE.md` argues the case, and pyrefly's `explicit-any` is off for exactly this reason.

## Comments

### 2026-08-06

Closed by !208, !209, !210.

**`dict[str, Any]` 62 → 16; `Any` lines 221 → 170.** The 16 that remain are triaged with reasons in !210, not left as a residue: `model/convert.py` (10) is genuinely the dict↔model gradual boundary because `to_dict`/`from_dict` are generic over any attrs class; observation arrays stay `list[Any]` because they are heterogeneous by nature; 2 belong to #210; 3 are the documented single-annotated-local pattern.

**Part 2 was already done before this issue was worked.** Re-scoping found `_resolve_ref_text` no longer exists and `_FIFOCache.get` / `_CallScopedMemo.get` already returned `object`. Of the "6 leaky `-> Any` returns", only the two documented-and-justified ones were ever left. Worth recording because the issue's own table would have sent someone looking for four functions that are not there.

**Five defects fell out of typing, none of which was the point of the work:**

1. `{"id": null, "name": "Annual"}` in a data message decoded to the literal string `"None"` as a dimension value — the label picker tested key *presence* then `str()`'d the result. Silent corruption of the user's frame; no error path involved.
2. The SDMX-JSON 1.0 data reader raised `AttributeError` on a null or non-object `structure`, violating its own documented `Raises: ValueError`.
3. The structure reader raised `AttributeError: 'list' object has no attribute 'get'` on a non-object envelope — an internal leak rather than a statement about the input.
4. `structure_values._emit_istring` duplicated `_dto.emit_istr` exactly. The package also had two different functions named `emit_annotations`.
5. `local/registry.py`'s memo parameters said `dict[str, Any]` while the concrete class behind them, `_CallScopedMemo`, already subclassed `dict[str, object]`. Widening 14 sites produced zero checker findings.

**Two verification notes worth keeping**, since both would have produced a false pass:

- The SDMX-JSON writer stamps `meta.prepared` with `datetime.now()`, so raw output hashes are not stable across runs. Any equivalence check on this layer has to drop `meta` and prove stability by hashing twice before the result means anything.
- My first `structure_values` comparison used `json.dumps(sort_keys=True)`, which sorts *recursively* — so it would not have compared entry key order at all, the one thing most at risk when a dict construction is reordered. Sort only the outer keys.

Happy-path checks alone would have caught none of the five defects above. Every one surfaced from a separate diff of *malformed* inputs, which is where a change from hand-navigation to eager validation actually shows up.
