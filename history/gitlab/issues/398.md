# Issue #398: Dimension.codes declares ItemList but returns a Query when the DSD came from a LocalRegistry

| | |
| --- | --- |
| State | closed |
| Opened | 2026-09-08 |
| Closed | 2026-09-10 |

#397 one level deeper. Found while typing `tests/unit` for #347, where it
needed a guarded cast at the one site that hit it.

## The gap

```python
dsd = reg.get(DataStructure.urn_for(agency="AG", id="DSD"))
dim = dsd.dimensions["FREQ"]
len(dim.codes)      # type-checks — TypeError at runtime
```

Measured, against a `LocalRegistry` holding a codelist and a DSD that
references it:

| | declared | actual |
| --- | --- | --- |
| `dsd` | `DataStructure` | `DataStructure` ✓ |
| `dim.resolved_codelist` | `Codelist \| None` | **`LazyCodelist`** |
| `dim.codes` | `ItemList[Code] \| None` | **`Query`** |

`len(dim.codes)` raises `TypeError: a query has no len() — it is a plan, not a
collection`, which is the right error for the wrong reason: nothing said the
value would be a query.

## Why it is not #397

#397 fixed what `LocalRegistry.get` *returns*, with overloads keyed on the
URN's phantom. This is one level further in, through
`Dimension.resolved_codelist`:

```python
@property
def codes(self) -> ItemList[Code] | None:
    cl = self.resolved_codelist
    return cl.codes if cl is not None else None
```

`resolved_codelist` follows the component's `Ref`. When the DSD was read from
a `LocalRegistry`, that ref resolves to a `LazyCodelist` — so `.codes` is the
`Query` the lazy class deliberately returns. Both declarations are then wrong,
and there is **no `eager=` flag here to key overloads on**: the same
`Dimension` object gives one or the other depending on where the DSD came
from, which is not visible in its type at all.

## Scope

`resolved_codelist` has four callers in `src/` (all in `polars.py`) plus
`codes`. Every one is written against `Codelist`'s surface; they work because
`LazyCodelist` duck-types the scalar parts, and `.codes` is the one place the
two differ.

## Options

1. **Declare the union** — `Codelist | LazyCodelist` on `resolved_codelist`,
   and `ItemList[Code] | Query[CodeRow, Code] | None` on `codes`. Honest, and
   forces narrowing at every call site including the many that only touch the
   shared surface, where narrowing buys nothing.
2. **A `CodelistLike` protocol** both satisfy, with `codes` typed as the union
   and the scalar surface flat. The 29 shared members become one declared
   thing; callers that only read `id` / `name` / `version` are unaffected. The
   two that touch `codes` narrow.
3. **Make `Dimension.codes` always materialise** — `cl.codes` becomes
   `cl.materialize().codes` for the lazy case. The declaration becomes true and
   every caller keeps working, at the cost of loading a codelist that #378
   went to some trouble not to load.
4. **Leave it, document it.** It is one divergence, the runtime message is
   good, and `tests/docs/test_upgrading.py` already documents the codelist
   half as a trap readers must know about.

(2) is where the value is, and it generalises: the same protocol would give
`q.artefact`-style callers something better than `Maintainable` when they need
the item surface. (3) is the only one that does not change any call site, and
is worth pricing against #378's measurements before dismissing.

Not urgent — the runtime error is clear and names the fix. It is a declaration
that lies, in the same direction as #370 and #397, and the last one of that
family still standing.

## Comments

### 2026-09-10

!482 — option 2, with the gaps closed first so nothing narrows.

**It is worse than filed.** Not just a declaration: five public entry points
*raise* on any DSD read from a `LocalRegistry` —

```
polars.schema            polars.validation_report    polars.structure_frame
Dataset.pivot            Dataset.label
```

— because each iterates or takes `len()` of what has become a `Query`. The
scope note here says "four callers in `src/` (all in `polars.py`) plus
`codes`"; it is nine, across `polars.py`, `model/dataset.py` and
`formats/sdmx_json/_data_common.py`.

**Option 3 priced out, on the numbers.** `CL_GEOGRAPHY`, 579,951 codes:
`code_ids()` 92 ms, `len()` 22 ms, `materialize()` **2,854 ms** — 31x and 129x,
the cost #378 removed. It survives as `materialize()` for the two callers that
genuinely need each `Code`.

`Dimension.codes` keeps working and finally means what it declared: it
materialises, because asking for `Code` objects is asking for them to be built.
`code_ids()` sits beside it as the cheap path, and is a **method** for the
reason the bug existed — attribute access that can reach the database is what
made `dim.codes` read as free when it was not.

## Two things the issue could not have known

**A second defect.** `LazyCodelist.code_map` *dropped* codes with no label in
the requested language while `Codelist.code_map` falls back to the id, as
`polars._component_label_map`'s in-memory branch always had. The same call
meant two things, and the SQL one silently shrank the map — `Dataset.label`
builds a `replace_strict` from it, so a dropped code became a **null column
value**, not an error. Found by running the new tests against both classes off
one fixture, which is exactly what that shape of test is for. Both fall back
now; `test_code_map_missing_lang` asserted the old `{}` and now asserts the
agreement.

**Why `name`, `description` and `codes` are not in the protocol.** basedpyright
reads `Codelist.name` as `InternationalString` for attribute access and as
`__converterDescriptor_name` for protocol matching, so a protocol naming any
attrs converter field does not check even though every read of it does. That is
the whole reason `code_ids()` is a method rather than the field it wraps. No
suppression was needed — the method shape sidesteps it — and
`test_name_and_description_are_absent_for_a_reason` fails the day the checker
is fixed, so the workaround cannot outlive its cause. Worth its own issue
against basedpyright if you want it chased; the repro is two lines.

`sl.CodelistLike` is exported, per your call: it is the type of a public
property, so a user annotating a helper needs to name it.
