## Summary

The readers fetch the children they know by qualified name and never look at the rest, so an element they do not expect vanishes: no error, no warning, no record. A schema-invalid document reads as a valid one with less in it.

Found by the registry sweep (!516): Eurostat's 3.0 `AgencyScheme` uses `<str:Name>` / `<str:Description>` where the schema requires `<com:Name>`. The reader returns empty names, `validate()` then refuses the scheme for having none, and the writer emits a scheme with no `Name`, which is XSD-invalid. An injected `<str:Bogus>` disappears the same way.

(The source is wrong three ways: `str:Name`, plus `@version` and `@isFinal`, which 3.0 does not allow on an `AgencyScheme`.)

`read_istring` (`sdmx_ml/_common.py:213-222`) matches only `com:Name` / `com:Description`; every reader uses `find`/`findall` and never checks for leftovers.

## Fix direction

- Make the readers closed-world: an unexpected child is reported per artefact, either as a refusal under #435 or as a collected warning on the message.
- This is the read-side twin of #422's proposal (a `ReadGap` register and `parse(..., strict=True)`): #422 is about constructs the model cannot hold; this is about elements the reader does not look for.
- A narrow, named tolerance for Eurostat's `str:Name` is possible but is a workaround; standards first.
