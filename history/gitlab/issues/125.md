## Surfaced by

\`just coverage\` pass.

## State

\`src/sdmxlib/storage/readers.py\` — **72% line coverage** (152 of 545 lines untested).

## Why

Uncovered range lines **752–1058** is a contiguous cluster spanning these readers:

- \`_read_data_constraint\` (752–806)
- \`_read_category_scheme\` (822–862)
- \`_read_categorisation\` (875–886)
- \`_read_provision_agreement\` (900–913)
- \`_read_agency_scheme\` (927–979)
- \`_read_data_provider_scheme\` (993–1019)
- \`_read_representation_map\` (1033–1058)

These are the DuckDB read-back paths for non-codelist / non-DSD artefact types. Putting them into the storage is exercised (writers are at 96%), but \`local.Registry.get(urn)\` for these types is not, so we never actually read them back. This is a real correctness risk — a write-then-read round-trip could silently lose data on these artefact kinds and no test would catch it.

## Proposed work

Add to \`tests/unit/test_local_registry*.py\` (or a new \`test_storage_roundtrip.py\`): for each of the seven artefact types above, build a fixture, put it into a fresh \`Registry(":memory:")\`, get it back by URN, assert field-equal. The bench fixture \`make_message()\` already constructs several of these — could reuse.

## Acceptance

- \`just coverage\` reports \`storage/readers.py\` ≥ 90%.
- Round-trip equality tests for each of the seven artefact types under \`tests/unit/\`.
- If any round-trip fails, file a bug — that's a real lossy-storage finding, not a coverage gap.
