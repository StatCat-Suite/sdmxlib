# Issue #477: SDMX-ML: a component without @id takes its concept's id; the readers refuse it instead

| | |
| --- | --- |
| State | closed |
| Opened | 2026-10-16 |
| Closed | 2026-10-16 |
| Milestone | %21 Conformance evidence: what the green checks do not prove |

Found by the #474 census of defaulted attribute reads.

**What the schema says.** `ComponentBaseType`'s `@id` is optional in SDMX-ML 2.1, 3.0 and 3.1, and the XSD documents the default: *"If this identifier is not supplied, then it is assumed to be the same as the identifier of the concept referenced from the concept identity."* So `<str:Dimension><str:ConceptIdentity>…Concept=ECB:CS(1.0).FREQ</…></str:Dimension>` is a conformant dimension whose id is `FREQ`.

**What happens.** The readers read a component's id as `el.get("id", "")`. Read-time validation then refuses the whole DSD/MSD for the empty id, so **a conformant document is refused**. Measured on the maximal message through `sl.parse(strict=False)`, removing `@id` refuses the artefact for Dimension, Attribute and MetadataAttribute in every version, and for 3.x Measure (2.1 TimeDimension / PrimaryMeasure are schema-fixed, so unaffected).

The 3.x measure reader is the odd one: `measure_el.get("id", "OBS_VALUE")` — a 2.1-ism (2.1 fixes PrimaryMeasure's id; 3.x does not), so a 3.x measure without `@id` currently reads as `OBS_VALUE` whatever its concept is.

**Fix.** A component with no `@id` takes the item id of its `ConceptIdentity` URN; with neither, the artefact is refused (as #474 does for every other missing required id). This is the standard's own answer, not an assumption, so nothing goes on `msg.assumed`.

**Ecosystem check before implementing.** See what sdmx1 and pysdmx do with an id-less component.

## Comments

### 2026-10-16

Also found while landing #474 MR1: 2.1 `MeasureDimension` without @id is not refused but kept with id "" (read-time validation misses it), and 2.1 `MetadataAttribute` is a component too. The census `tests/unit/test_reader_defaults_census.py` pins the seven component id reads to this issue, and `test_read_assumptions.py` carries strict xfails for MeasureDimension and the 3.x Measure — fixing this flips them.

### 2026-10-16

SDMX-JSON too (found in #474 part 2): DimensionJson / AttributeJson / MetadataAttributeJson require `id`, but SDMX-JSON 2.0 makes a component's id optional. A conformant JSON component without an id is refused. `tests/unit/test_json_read_assumptions.py` pins the four shapes as strict xfails on this issue — deriving the id from `conceptIdentity` flips them.
