# Issue #289: t-8: Ref is invariant, which is why Ref[Any] is everywhere

| | |
| --- | --- |
| State | closed |
| Opened | 2026-08-10 |
| Closed | 2026-08-10 |
| Milestone | %16 Typing hygiene: enforce the Any rule the docs already claim |
| Labels | `needs-design`, `typing` |

Found while doing #287, and it reframes most of what is left in %16.

`Ref[Any]` appears 66 times in `src/` — the single largest `Any` shape after
`list[Any]`. It is **not** a gradual-typing boundary. It is a workaround for a
variance limitation.

## The measurement

Substituting `Ref[object]` produces **56 errors**, and every one has the same
form:

```
error: Argument of type "Ref[Concept]" cannot be assigned to parameter "ref"
       of type "Ref[object]" in function "write_concept_identity"
```

Not one is a genuine loss of type information. All 56 are variance: `Ref[T]` is
**invariant**, so `Ref[Concept]` is not a `Ref[object]`. `Ref[Any]` works only
because `Any` is bivariant — it accepts everything and everything accepts it.

Confirmed directly:

```
"Ref[Codelist]" is not assignable to "Ref[object]"
  Type parameter "T@Ref" is invariant, but "Codelist" is not the same as "object"
```

## What forces the invariance

```python
class Ref[T]:
    urn: SdmxUrn[T]
    _resolved: T | None = field(default=None, ...)
```

`_resolved` is a **mutable field of type `T`**, which makes `T` invariant under
PEP 695 inference. It is also load-bearing: it is the resolution cache the
whole `Ref` design rests on.

## Why this matters for %16

If `Ref` could be covariant, ~56 of the remaining `Any` occurrences would
become `Ref[object]` mechanically, and the largest category in the milestone
would mostly evaporate. If it cannot, then those 66 are *correct as written*
and should be documented as such rather than counted as debt — which changes
what the ratchet's number means.

Either answer is worth having. What is not acceptable is the current state,
where the codebase reads as though 66 sites are sloppy when they are working
around a language-level constraint.

## Options to weigh

1. **Make `_resolved` invisible to variance inference** — a read-only property
   over private storage, or `Final`. Needs checking against both checkers, and
   against attrs' field generation.
2. **Split the type** — an immutable `Ref[+T]` for the reference and a separate
   mutable resolution cache keyed by URN (the `Session` identity map already
   exists and may be the natural home).
3. **Accept invariance**, keep `Ref[Any]`, and document it at the class so the
   next reader does not re-derive this. Then exclude it from the ratchet with a
   written reason rather than pretending it is reducible.

## Do not start with a sweep

Whatever the answer, it touches the most central type in the library — 66
sites and every format writer. Prove the variance change on a branch and
measure before converting anything.

## Context

#287 removed the `AnyRef = Ref[Any]` alias for hiding these behind a name whose
own comment misdescribed them ("the specific artefact type is not yet known"),
which is not what they are.
