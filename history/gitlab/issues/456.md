## Problem

The element, attribute and JSON censuses (#422) prove that every construct the **schema** allows has an owner. But the XSD is syntax. The SDMX information model also states semantic rules that no schema expresses, for example:

- referential integrity;
- uniqueness of ids within a scope;
- what a constraint may attach to;
- how versions of a dependency must relate;
- which representations a component may take.

Our coverage of those rules is hand-written validation in `model/validation.py`. Hand audits are the method that missed the milestone 20 issues: a rule nobody listed fails nothing.

## Proposal

Apply the census shape to the IM:

1. Enumerate the constraints the SDMX standard states, from the IM (Section 2) and the technical notes, into a table. Give each a stable id and a citation.
2. Map every row to exactly one owner:
   - **validated:** a named check in `model.validation`, with a test that makes it fail;
   - **structural:** the model's types make the violation unrepresentable;
   - **declared non-check:** knowingly not enforced, with a reason, as `gaps.py` declares losses.
3. Add a guard that fails on a row with no owner, and on a validation check that no row cites. That makes it checked in both directions, as the censuses are.

## Done when

Every IM rule we can find has an owner, and the guard fails both ways.
