# Issue #89: Followup phase 2: SQL style sweep — triple-quoted everywhere

Part of the [Cleanup follow-ups](../-/milestones/4) milestone.

CLAUDE.md states:

> Always use triple-quoted strings for SQL (\`\"\"\"...\"\"\"\` or \`f\"\"\"...\"\"\"\`),
> including short fragments emitted by query compilers

The codebase violates this in many short SQL fragments. Audit findings (Rule 8):

- \`src/sdmxlib/storage/readers.py\` — ~20 double-quoted \`\"SELECT … ?\"\` short forms
- \`src/sdmxlib/storage/writers.py:107,137,152\` — \`\"INSERT/SELECT/DELETE …\"\` short forms; line 107 is an f-string interpolating an identifier
- \`src/sdmxlib/local/data_store.py\` — 13 double-quoted SQL fragments, several f-strings with identifier interpolation

## Plan
Sweep all SQL strings to triple-quotes:
- [ ] Short selects, inserts, deletes → \`\"\"\"…\"\"\"\` (single-line is fine inside triple-quotes)
- [ ] Existing f-string fragments that interpolate **identifiers** (table/view/secret names, never values) → \`f\"\"\"…\"\"\"\` triple-quoted
- [ ] Values stay parameterised — no change to safety

## Acceptance
- \`just ci\` passes.
- \`grep -nE '^\\s*[a-zA-Z_]*\\.execute\\(\"[A-Z]' src/sdmxlib/storage/ src/sdmxlib/local/ src/sdmxlib/model/code_query.py src/sdmxlib/model/hierarchy_query.py\` returns no matches.
- No SQL is constructed via concatenation or via f-string interpolation of values. Identifier-only interpolation in f\"\"\"…\"\"\" is allowed per CLAUDE.md.

## Out of scope
- Stylistic question of whether \`storage/lazy.py\` SQL should also move to triple-quoted (likely yes — bundle if cheap).
