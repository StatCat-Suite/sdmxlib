# Issue #339: a freshness window for the `latest` pointer: honour Cache-Control/ETag, with a caller override

| | |
| --- | --- |
| State | closed |
| Opened | 2026-08-18 |
| Closed | 2026-08-19 |
| Labels | `design`, `perf` |

Follow-up to #338, which settled the *rule* and left the *window* unbuilt.

#338 established: a pinned URN is immutable and caches forever; `latest` names a
mutable pointer and is never a cache key. That makes correctness unconditional
and costs a request per `latest` ask, because there is currently no window in
which the pointer may go un-re-asked. This issue builds the window.

## The decision already taken

The provider's `Cache-Control` governs the pointer's freshness by default, with
a caller override. Recorded in §1.3 of `docs/design/registry-and-catalog.md`.

The reasoning: this is the one place HTTP cache semantics legitimately apply.
A pinned artefact's lifetime is settled by SDMX versioning, not by a proxy
header — but *how long ago someone last checked where `latest` points* is
exactly what `max-age` and `ETag` are for.

## What providers actually send, measured from our cassettes

| provider | structures | revalidation available |
|---|---|---|
| ECB | `no-cache, no-store, max-age=0, must-revalidate` | none — no ETag, no Last-Modified |
| IMF | `no-cache, no-store, max-age=0, must-revalidate` | none |
| OECD | `public, max-age=86400` | Last-Modified |
| SDMX Global Registry | *(absent)* | ETag |

Two conclusions:

- **OECD and the Global Registry reward this.** 24 hours on structures is a
  deliberate statement, and an ETag makes revalidation a 304 instead of a body.
- **ECB and IMF give nothing to work with**, and their headers look like
  appliance defaults rather than assertions — they arrive on *codelists*, and
  the same responses stamp `isFinal="false"` on all 2420 artefacts recorded.
  This is why the override is part of the design and not an afterthought:
  obeying `no-store` literally optimises for a statement nobody meant to make.

## Scope

- conditional requests: send `If-None-Match` / `If-Modified-Since` when the
  stored response carried `ETag` / `Last-Modified`; treat 304 as "the pointer
  has not moved"
- honour `max-age` / `no-store` / `must-revalidate` for the **pointer only** —
  never for a pinned artefact, which #338 settled
- a caller override on `RestRegistry`, shaped so a floor is expressible
  (`latest_ttl=300` against a `no-store` provider) rather than only a ceiling
- the override must not be able to make a *pinned* artefact expire; that is not
  a knob, it is a category error
- store what is needed (validators, response time) somewhere bounded, per
  `docs/design/caching.md`

## Also here, since it is the same code

`Session._map` / `_resolved_map` are unbounded and never invalidated — the
defect #336 fixed for `_fetched` one layer up. #338 removed two of the four
indices; the remaining two still grow without limit. Bound them with the same
primitives (`_FIFOCache` / `SingleFlight`) while this work is in the file.

## Acceptance

- a test where the provider publishes a new version *and* sends `max-age`, and
  the second call is served locally inside the window and re-asked outside it
- a test that a 304 is treated as a hit and costs no body
- a test that a pinned URN is unaffected by every header combination above
- the override demonstrated against a `no-store` provider
- `Session`'s remaining indices bounded
