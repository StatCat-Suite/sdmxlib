# Issue #506: A TimeDimension without a concept is accepted, then written XSD-invalid

| | |
| --- | --- |
| State | closed |
| Opened | 2026-10-20 |
| Closed | 2026-10-20 |
| Milestone | %26 Found by the docs audit: correctness and refusals |
| Labels | `bug`, `conformance`, `model`, `priority::high` |

A `TimeDimension` with no `concept` passes construction (directly or via `from_dict`). It is then written to SDMX-ML 2.1 and 3.0 with no `<str:ConceptIdentity>`, which the XSD requires:

```python
dsd = sl.DataStructure(..., time_dimension=sl.TimeDimension(id="TIME_PERIOD"), ...)
sl.to_xml(sl.StructureMessage(data_structures=[dsd]), version="3.0")   # fails XSD validation
```

A `Measure` or `Dimension` without a concept is refused as it is built, so the "every component names its concept" rule (#492) misses the time dimension. Writing XML the schema rejects, with no error, is the worst outcome here.

**Fix:** apply the same construction rule to `TimeDimension`, and add it to whatever test enumerates the components the rule covers, so the next component kind can't be missed.

Found in !665.
