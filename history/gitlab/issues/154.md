### 2026-08-27

## Profiled — the top line was a bug, not attrs overhead

!445 takes the safe part. The profile's largest line was not `HierarchicalCode.__init__` at all:

```python
level = levels_by_id.get(str(level_id), Level(id=str(level_id)))
```

A default argument is evaluated **eagerly**, so this built a throwaway `Level` for every node whose level *was* declared — nearly all of them. 499,138 wasted constructions on FED, each dragging two `InternationalString` converters and an `Annotations` converter with it. Five objects per node, discarded.

The eager reader (`storage/readers.py:886`) already spelled it correctly. Only the lazy path had it wrong, which is why nothing caught it — both produce identical objects.

With that, the re-subscripted `Ref[Code]` generic, and a tuple-form `re.Match.group` in `SdmxUrn.parse`:

| | before | after |
| --- | --- | --- |
| total function calls | 31,447,494 | **20,466,463** |

**34.9% of the work removed.** Wall clock ~3.71 s → ~3.16 s (~15%) — less than the call reduction, because the calls removed were the cheap ones.

## What is left, and why I stopped

This issue's suggestion 1 — `__new__` + `object.__setattr__` to bypass attrs validation — is the largest remaining lever and is **not** in !445. The risk this issue already names is real: a field added to `HierarchicalCode` later would be silently skipped by the bypass, in a core model class. That wants a decision rather than a drive-by.

Same for a shared empty `InternationalString` singleton (~12% on the codelist path). Nothing in `src/` mutates `_data` today, but it is a global object-identity change to a core value type on the strength of that.

## Follow-up

The same eager-default bug at four sites in `storage/readers.py` (:399, :828, :885, :1063), all in per-row loops — the eager read path, so out of !445's scope. Worth ~5%.

## A note on measurement

Wall-clock A/B on this laptop was unusable while another build was running — it disagreed in *direction* between hierarchies, and one run showed `isinstance` costing 8x more for fewer calls. Everything above is call counts, which are load-independent. That is also what the regression guard asserts, per CLAUDE.md's rule about counting expensive calls rather than timing them.

### 2026-08-27

Correction to my note above, after measuring rather than estimating.

The `storage/readers.py` eager-default sites are **~1% of the read**, not the ~5% I guessed — `Annotations.__init__` is 0.125 s of a 9.00 s eager `CL_GEOGRAPHY` read. `Annotations()` does not drag converters with it the way `Level()` did, so the analogy that produced my estimate did not hold. Eight sites, not four.

The eager path's real cost is `_collect_refs` at **42%** of that read — filed as #376. Provably fruitless for `Code`, which has no `Ref` field. Separate from this issue's `materialize()` path.
