`storage/writers.py:525` `_serialize_component(comp)`. Reads `concept`, `representation`, `usage`, `attachment` — all via `getattr(..., None)` because the members differ. A `Dimension | Attribute | Measure` union changes those `getattr` calls into attribute access on some members but not others, so it needs a decision, not a find-and-replace.

### 5. Blocked on a leaky return (2 sites)

`formats/sdmx_ml30/reader.py:629,630` — `source: Any` / `target: Any` are **local annotations, not params**. The true type is `AnyRef | MapDataType | None`, but they take their value from `_resolve_ref_text`, which itself returns `Any`. **Fix that return first** — it is one of the six leaky `-> Any` returns catalogued in #200. This site is a dependent, not independent work.

### 6. Overtaken by other work (1 site)

`storage/writers.py:1623` `ingest_registry(registry)`. Since #170 was filed, `347b292` landed the narrowed read-seam Protocols (`RegistryReader` / `SupportsGet` / `SupportsGetAll` in `model/registry.py`) — one of those is probably the answer. But the body does `getattr(registry, "_store", {})`, reaching into a private attribute, which is also in **#198**'s SLF001 scope. Coordinate: typing the param without addressing `_store` leaves the real coupling in place.

### 7. attrs-graph walkers — the documented `TypeIs` case (2 sites)

* `local/registry.py:841` `_resolve_refs(obj)`
* `local/registry.py:907` `_collect_refs(obj)`

Both walk an arbitrary attrs graph and gate on `attrs.has(type(obj))`. CLAUDE.md names this exact pattern under "Narrow, don't cast":

> a `TypeIs` helper when the runtime probe doesn't narrow on its own (`attrs.has(type(val))` is the classic — the TypeGuard lands on the discarded `type(val)`, not on `val`)

So the fix is prescribed already: a `TypeIs`-returning helper wrapping `attrs.has`, then `obj: object`. This is also the pattern the pyrefly 1.2 upgrade found two real defects with (per CLAUDE.md), so it is worth doing properly rather than leaving as `Any`.

### 2026-08-05

Done in !193 — all 13 sites.

**The issue's premise did not survive contact.** This was scoped as "design the small Protocols", inheriting `05006f6`'s framing that the remainder needed dedicated new Protocols. **No new Protocol was needed.** In every group an existing type already described the surface:

| group | sites | resolved with |
| --- | --- | --- |
| 1 — maintainable writers | 5 | `MaintainableArtefact` (XML) / `SupportsUrn` (storage) |
| 2 — scheme maps | 3 | new `SchemeMap` / `ItemSchemeMap` unions |
| 3 — `emit_annotations` | 1 | `Code \| Concept` |
| 4 — components | 1 | new `Component` union |
| 5 — repmap locals | 2 | done earlier in !189 |
| 6 — `ingest_registry` | 1 | **deleted** — never called in any revision |
| 7 — attrs walkers | 2 | `object` + bound `cls`, matching `InMemoryRegistry._walk_refs` |

**Three things found along the way:**

1. **Storage's seam is `SupportsUrn`, not `MaintainableArtefact`.** Typing group 1 uniformly with the concrete base was a type error: `DataflowBinding` reaches `_put_spine` without being a maintainable, and `put_artefact` already declared `SupportsUrn`. The `Any` had hidden that the XML and storage seams are genuinely different types.

2. **A `getattr` guard that never narrowed.** `write_maintainable_attrs` tested `getattr(obj, "valid_from", None) is not None` and then read `obj.valid_from` *directly* — the guard lands on the discarded call, so the read was unchecked.

3. **`ingest_registry` was born orphaned.** `git log -S` across all history shows it was never called in any revision. `SHARED_STORAGE_SPEC.md` designed `LocalRegistry.ingest()` to delegate to it; what shipped went straight to `add_all`, which already batched and already threaded `source_registry`. Deleted, with the stale Phase 7 spec line corrected.

**Where the milestone stands:** every remaining `: Any` parameter in `src/` is now #204's documented leave-as-Any set. Nothing in the untyped shell is unexamined.

**Not fixed here:** `Registry.ingest()` still reaches into `registry._store` behind a live `# noqa: SLF001` on the public API path — #198's scope. Deleting `ingest_registry` removed an unused *copy* of that access, not the real one.
