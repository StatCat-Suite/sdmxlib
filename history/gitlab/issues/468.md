## What

`MetadataConstraint` is SDMX 3.x's constraint on reference metadata: allowed metadata attribute values, attached to an MSD, a Metadataflow or a MetadataProvisionAgreement. In 2.1 it is a `ContentConstraint` attached to a metadata structure.

## Now

sdmxlib refuses it on read (`formats/sdmx_ml/_common.py`: "it does not model 3.x's MetadataConstraint"). A 2.1 `ContentConstraint` on a metadata structure is refused too, since the census found it was being read as a data constraint (#422).

sdmx1 models it (`sdmx.model.v30.MetadataConstraint`); pysdmx does not.

## Done when

The milestone's checklist holds:
- the model, beside `DataConstraint`, sharing what it can (cube regions, member selections);
- reading and writing in 2.1 (as a `ContentConstraint` on a metadata target), 3.0, 3.1 and SDMX-JSON;
- storage, the query language, the maximal fixture and the censuses.
