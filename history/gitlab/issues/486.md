Found by the IM rule census (#456). The two sources disagree on which extended codelist wins a code conflict:

- SDMX 3.1 Section 2, §4.3.3.2 p. 50, `CodelistExtension.sequence`: "The latest Codelist used overrides any previous Codelist."
- `Codelist.apply_extensions` (`model/codelist.py`): "the codelist's own codes win over inherited ones, and an earlier extension over a later one", citing the schema's documentation and FMR. The XSD (3.0 and 3.1) and SDMX-JSON say only that the order "indicates the order of precedence of the extended codelists for conflict resolution of codes" — no direction.

So the IM text reads the opposite way from what we implement. Needs a decision, ideally with FMR's behaviour confirmed by a test against it (#457), before anything changes. The census row records this as a declared non-check pointing here.
