## Summary

#436 checks each *artefact's* subtree. It does not check:

- **The containers** between `mes:Structures` and the artefacts (`str:Codelists`, `str:Concepts`, …). An unexpected element there is skipped: a misplaced artefact, or a container the reader has no section for.
- **The message header.** An unexpected header element vanishes the same way.

## Notes

- A stray element in a container is not inside any artefact, so #435's per-artefact refusal has nothing to refuse. The natural outcome is a document-level `SdmxConformanceError`, or a `Refusal` with no artefact. Decide which.
- Related: a section the reader has no model for (`DataConsumerScheme`, `OrganisationUnitScheme`) is read as zero artefacts with no error (#422's "not modelled" note). A container check is the natural place to report those too.

Follow-up to #436.
