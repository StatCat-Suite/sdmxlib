**Phase 4.** The two attribute-level constraint kinds, extracted together because they are the same walk over the schema and the same comparison against the model.

## `use="required"`

On complex types sdmxlib models: **63** in 2.1, **20** in 3.0, **20** in 3.1. An attribute the schema requires and the writer omits produces an invalid document — the failure mode is identical to a missing child element, but the extraction is different, so #228 does not cover it.

One is already known real, from milestone 10: 2.1's `LocalComponentListComponentRefType` requires `containerID`, `class` **and** `package` on every component reference, and `ComponentMap` carries only a pair of ids. That was found by generating a structure map and reading the error; the extraction would have stated it up front.

## `use="prohibited"`

On modelled types: **24** in 2.1, **24** in 3.0, **25** in 3.1. This is the *silent field loss* kind — the schema forbids the attribute, so a correct writer must drop it, and whatever the model held is gone with no round-trip warning.

Also already known real: SDMX-ML 3.1 marks `CategorisationBaseType/@version` as `use="prohibited"`, so a categorisation's version cannot survive a 3.1 round-trip. That is recorded in `KNOWN_GAPS` — found, again, by a generated artefact coming back with `1.0` instead of what went in.

The other ~24 per version have not been checked. Each is either already handled, or a field quietly lost on that target.

## The test

For each (type, attribute) pair, resolve to the model field and assert:

- **required** → the writer emits it for every artefact the model can build, or the write boundary refuses.
- **prohibited** → the round-trip either preserves the field by other means, or the loss is recorded in `KNOWN_GAPS` with the schema citation. An unrecorded prohibited attribute backed by a populated model field is a silent-loss bug.

Expect most of the ~44 per version to resolve to attributes the writer already handles or to types we do not model. The value is in the residue, and in the *list* being complete rather than sampled.
