# Issue #461: SDMX-JSON read is 2.3x slower since M20: the unknown-key walk costs more than the decode

| | |
| --- | --- |
| State | closed |
| Opened | 2026-10-15 |
| Closed | 2026-10-15 |
| Milestone | %22 Read/write and serving performance: win back M20's cost, fix JSON interop |
| Labels | `perf`, `sdmx-json` |

## Measured

Reading BIS codelists as SDMX-JSON 2.0 (5 MB, 105 codelists, 9,716 codes) went from **23 ms to 54 ms (+133%)** across milestone 20. Reading the DSDs went from 5.7 ms to 9.9 ms (+75%). pysdmx reads the same codelist file in 20 ms.

## Lead (profiler; confirm by A/B)

The leading candidate is `formats/sdmx_json/_losses.py:_walk`, the pass from #422/#445 that reports keys the structs skipped.
- It walks the whole decoded tree: 543,630 calls over 5 reads, 0.315 s cumulative, which is most of the regression.
- `from_code` and `Code.__init__` follow it.

## Direction

Keep the reporting, which is the point of #445. Do less work to get it, for example:
- decode once rather than decoding again for the walk;
- or walk only the subtrees whose struct can skip a key.

Add a guard that counts walk visits per document size.

## Done when

The JSON read is back near its pre-M20 time, with loss reporting unchanged (`test_json_census`, `test_read_losses` green), and a count guard is in place.
