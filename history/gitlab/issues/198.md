`# noqa: SLF001` (private-member access) is the most-repeated suppression in `src/` — **40 sites**, and 34 of them are in four files doing the same legitimate thing: a package reaching into its own internals.

```
local/registry.py         13
local/data_store.py       11
catalog.py                 6
model/in_memory_registry.py 4
```

Typical: `catalog` reading `Registry._conn`, the registry interning `ref._resolved`, the memo touching `_store`. SLF001 exists to catch *cross-boundary* private access; ruff has no same-package exemption, so intra-package cohesion reads as a violation at every line.

The remaining **6 are scattered and stay as-is** — each is a distinct, locally-argued case, and several are arguably ruff limitations rather than real access (e.g. `istring.py:41` sets `obj._data` inside its own class's alternate constructor; `code_query.py` / `hierarchy_query.py` read `key._field` off a sibling AST node):

```
model/istring.py:41   model/hierarchy_query.py:459   model/code_query.py:575
model/dataset.py:314  api/registry.py:306            formats/sdmx_json/_data_common.py:523
```

## Fix

Per-file ignores for the four files, each with a one-line reason naming *which* internals and why the coupling is intended. Leave the scattered six as line comments so they keep their individual justification.

## Acceptance

* 34 line-level noqas removed; 4 config entries with rationale; the 6 scattered ones untouched.
* `just check` clean (RUF100 will catch any that were doing something else).

### 2026-08-05

Main body done in !198 — **40 → 12**, with no suppressions added and no `ruff.toml` change.

## The re-scope

This issue proposed four per-file ignores for "intra-package hot files". That describes **7** of the 34 sites. The other **27** were a single different pattern — an alternate constructor setting *its own class's* private state:

```python
instance = cls.__new__(cls)
instance._conn = registry.connection   # noqa: SLF001
```

Writing "this file intentionally reaches into other objects' internals" over `data_store.py` and `catalog.py` would have been **false** — 100% of their suppressions are self-construction — and would have blanket-silenced future genuine violations there.

## The fix was a type annotation, not a suppression

`_x` is private to the *class*, not the instance. Ruff already agrees — probed directly:

| access | flagged? |
| --- | --- |
| `other._x` inside `__eq__` | **no** |
| `inst._x` inside a classmethod, on a local | **yes** |
| `c._x` from a different class | yes — correct |

Not a rule disagreement: a **type-inference gap**. Ruff cannot tell a bare `cls.__new__(cls)` local is an instance of the enclosing class. Annotating it — `instance: Self = cls.__new__(cls)` — removes all 27, plus `istring.py:41`, which this issue had already flagged as "arguably a ruff limitation" without connecting it to the others.

That is 28 removed by making the code *more* explicit. The alternative considered — rewriting the constructors to take `self` — would have been contorting correct code around a false positive.

## The 12 that remain, and what they revealed

Genuine cross-class access: `Ref._resolved` interning (6), `Registry.ingest` reading `registry._store`, `_SortKey`/`_FieldExpr` sibling reads (2), and three others.

Left as line comments — at 12 across 8 files a per-file ignore would now hide more than it explains. But examining them raised a prior question that this issue implicitly assumed an answer to: **what is our underscore convention for?** Measured against ten major projects, sdmxlib underscores 77% of instance attributes where the highest peer is 45% and fastapi is 11%. That is written up as **#207** with a proposed rule; the fate of these 12 (and of SLF001 itself) should follow from that decision rather than precede it.
