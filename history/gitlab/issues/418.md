# Issue #418: CodelistExtension.codelist accepts a URN string, then the SDMX-ML 3.0 writer crashes with AttributeError

| | |
| --- | --- |
| State | closed |

| Labels | `bug`, `model` |

## Summary

`CodelistExtension.codelist` is annotated `Ref[Codelist]` but has no
converter. A URN string or an `SdmxUrn` is accepted at construction, and
SDMX-ML 3.0 serialisation then crashes:

```python
urn = "urn:sdmx:org.sdmx.infomodel.codelist.Codelist=AG:CL_A(1.0)"
ext = sl.CodelistExtension(codelist=urn)                     # accepted
ext = sl.CodelistExtension(codelist=sl.SdmxUrn.parse(urn))   # accepted
serialize(StructureMessage(codelists=[base, cl_with_ext]), version="3.0", validate=True)
# AttributeError: 'str' object has no attribute 'urn'
#   _v3_writer.py:291 _write_urn_text  ->  el.text = str(ref.urn)
```

`validate=True` does not catch it. The first failure is an `AttributeError`
from deep inside the writer, which names neither the artefact nor the field.
SDMX-ML 2.1 does not crash, but only because it drops extensions without
reading them (declared in `gaps.py`).

Measured on `main` @ `6cf7bc5`.

## Why it matters beyond this field

Most reference fields coerce a URN string; `Dimension(concept=<urn str>)`
works, for example. This one does not, and nothing checks that the
annotation and the runtime value agree. Other `Ref[...]` fields lacking a
converter may have the same problem.

## Proposed fix

- Give `CodelistExtension.codelist` the same `Ref` converter as the other
  reference fields.
- Add a sweep test over every attrs class in `sdmxlib.model`: each field
  annotated `Ref[...]` or `SdmxUrn[...]` accepts a URN string and stores the
  annotated type. The point is to find the rest of this class of bug, not
  only this instance.

Belongs to the milestone's ingest theme: the type annotation is the rule,
and construction should enforce it.
