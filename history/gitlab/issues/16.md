Implement `from_dict(cls, data)` and `to_dict(artefact)` for round-tripping domain objects through plain Python dicts.

## Motivation

Users building artefacts from database metadata or config files need a dict ↔ domain object bridge that doesn't go through XML/JSON wire formats:

```python
config = json.loads(Path("dsd_config.json").read_text())
dsd = sl.from_dict(sl.DataStructure, config)

d = sl.to_dict(dsd)
json.dumps(d, indent=2)  # human-readable
```

## Dict format

Mirrors domain model field names (not XML structure). Example:

```python
{
    "id": "CL_FREQ", "agency_id": "SDMX", "version": "1.0",
    "name": {"en": "Frequency"},
    "codes": [{"id": "A", "name": {"en": "Annual"}}]
}
```

Refs serialize as URN strings. Representation uses a `"type"` discriminator: `{"type": "Enumeration", "urn": "..."`} or `{"type": "TextFormat", "text_type": "String"}`.

## Implementation

New file `model/convert.py` (stdlib only — no lxml, no json module dependency at module level).

**`to_dict`:** Walk the object graph recursively. `InternationalString` → `dict`. `ItemList`/`ArtefactList` → `list[dict]`. `Ref` → `str(ref.urn)`. Enums → `.value`. `None` fields omitted.

**`from_dict`:** Use a `_CHILD_TYPES` dispatch table (`"codes" → Code`, `"dimensions" → Dimension`, etc.). Leverages coercion from #14 — pass `name=data["name"]` directly and `__post_init__` handles `InternationalString` wrapping. `Ref` fields: `Ref.unresolved(SdmxUrn.parse(urn_str))`.

## Tests

New `tests/unit/test_convert.py` covering round-trip for: `Code`, `Codelist`, `Concept`, `ConceptScheme`, `Dimension`, `DataStructure`, `Dataflow`, `StructureMessage`.
