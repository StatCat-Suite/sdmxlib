## Update: three corrections, found while fixing the comments

**1. We had seen this before.** `tests/unit/test_query_resolve_binds.py` already records "50,006 `importlib` lookups — five per row — all of them DuckDB's client probing for pandas on every bound value". So the issue body's "nothing reports this" is true upstream, but not here.

**2. The "DuckDB got 25x faster" re-measure (fe03e51) was pandas, not DuckDB.** #271 measured ~48 us per bound value, and fe03e51 re-measured ~1.9 us on 1.5.3 and moved the advice ("crossover ~500-1000"). The same benchmark on duckdb 1.5.5, run both ways:

| N | bound, no pandas | bound, pandas | registered |
| --- | --- | --- | --- |
| 100 | 13.7 ms | 4.3 ms | 5.4 ms |
| 1,000 | 85.6 ms | 5.4 ms | 5.5 ms |
| 5,000 | 445 ms | 10.0 ms | 6.5 ms |
| 50,000 | 4,121 ms | 59.1 ms | 13.6 ms |

With pandas installed it's ~1-2 us per value, which matches fe03e51; without it, 80-110 us, which matches #271. The crossover is ~100 values without pandas (sdmxlib's default) and ~1,000 with it. The user-facing cookbook (`docs/cookbook/discovery.md`) told readers ~1,000.

**3. `duckdb/duckdb-python#238` doesn't say what we cited it for.** `session.py` and `test_value_set.py` cited it as upstream calling the binding cost `wontfix`. It is about parameterised statements taking a materialising code path, which is a different problem.

## Open question this raises: should `InSet` compile to `= ANY(?)`?

#301 kept one placeholder per value because collapsing to `ANY(?)` measured 1.0x. That holds **only without pandas**, where the probe dominates both shapes:

| | `IN (?, …)` | `= ANY(?)` | ratio |
| --- | --- | --- | --- |
| no pandas, 1,000 | 99.6 ms | 85.9 ms | 1.2x |
| no pandas, 50,000 | 4,420 ms | 4,019 ms | 1.1x |
| pandas, 1,000 | 14.1 ms | 5.3 ms | 2.6x |
| pandas, 50,000 | 459 ms | 58 ms | 7.9x |

So `ANY(?)` is a real win for anyone with pandas installed (or the stub), and neutral otherwise. It changes `to_sql()` output and how `canonical_key` sees the values, so it's left here as a decision, not folded into the comment fix.
