# Issue #487: Cross-artefact IM rules are unchecked: partial schemes, constraint values, metadata set targets and values

| | |
| --- | --- |
| State | closed |
| Opened | 2026-10-16 |
| Closed | 2026-10-21 |
| Milestone | %21 Conformance evidence: what the green checks do not prove |

Found by the IM rule census (#456). Several IM rules relate one artefact to another it references, and none is checked — `validate_references` checks only that a reference resolves:

- §3.5.3.1 p. 37: a partial ItemScheme "cannot contain Items that are not present in the full ItemScheme", and an Item's content "cannot deviate from the content in the full ItemScheme".
- §12.3.3.1 p. 127: ComponentValue / MemberValue values "must be consistent with the Representation declared for the Component" in the DSD or MSD.
- §7.4.2.1 p. 102: a MetadataSet's targets "must be part of those specified in the relevant Metadataflow or MetadataProvisionAgreement", and an OtherUncoded value "must conform to the Representation specified for the MetadataAttribute".
- §7.4.2.1 p. 101: "the MetadataSet must conform to the MetadataStructureDefinition".

The first needs the full scheme, which a message rarely carries; the others need the structure resolved. The census rows declare each as not checked and point here. Data sets' conformance to their DSD is #459's.

## Comments

### 2026-10-16

One more, found by the FMR oracle (#457): the 3.0 and 3.1 XSDs document on `DataStructure/Metadata` that *the referenced metadata set cannot contain nested metadata attributes, as these are not supported in the data*. Our maximal fixture references an MSD whose `MA` has a nested `MA_CHILD`, and a `MetadataAttributeUsage` names the nested one. Nothing checks it -- it relates a DSD to the MSD it references. (FMR 12.4.2 never got as far as saying so: it refuses `MetadataAttributeUsage` outright.)
