# Issue #24: Support CoreRepresentation on Concept with automatic inheritance in Dimension/Attribute/Measure

| | |
| --- | --- |
| State | closed |
| Opened | 2026-04-01 |
| Closed | 2026-04-01 |
| Labels | `type::feature` |

SDMX concepts can declare a CoreRepresentation that components inherit when no LocalRepresentation is set. Currently the `core_representation` field on `Concept` exists but is never populated by readers, and `__post_init__` on `Dimension`/`Attribute`/`Measure` never checks it.

**Changes needed:**
- ML21 and ML30 readers: parse `<str:CoreRepresentation>` on `<str:Concept>` elements using the existing `_read_representation` helper
- `Dimension.__post_init__`, `Attribute.__post_init__`, `Measure.__post_init__`: when `representation` is None and the concept is resolved, inherit `concept().core_representation`
- Result: `dim.representation` is always the effective representation — no caller-side resolution needed
