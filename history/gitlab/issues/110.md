3.1 model audit follow-up (post-MR !63).

## Semantic gap

\`HierarchicalCodeType\` in 3.1 carries optional \`@validFrom\` / \`@validTo\` (xs:dateTime) on each hierarchy node, separate from the underlying \`Code\`'s own validity. Domain content: \"in this hierarchy, this code became reachable on date X and was removed on date Y.\"

We already track \`valid_from\` / \`valid_to\` on maintainables (Codelist, etc.) but not on individual \`HierarchicalCode\` nodes. Round-trip of a 3.1 hierarchy with temporal node validity silently drops it.

## Action

Add to \`src/sdmxlib/model/hierarchy.py\`:

\`\`\`python
valid_from: datetime | None = None
valid_to: datetime | None = None
\`\`\`

## Done when

- [ ] Fields on \`HierarchicalCode\`.
- [ ] 3.0 / 3.1 writer + reader round-trip them.
- [ ] Existing 2.1 hierarchy parsing is unchanged (2.1 doesn't define these).
