## What

The SDMX information model's VTL package has six maintainable item schemes, all in SDMX-ML 2.1, 3.0 and 3.1 and SDMX-JSON:

| artefact | items |
| --- | --- |
| `TransformationScheme` | `Transformation`: a VTL expression assigned to a result |
| `RulesetScheme` | `Ruleset`: datapoint and hierarchical rulesets |
| `UserDefinedOperatorScheme` | `UserDefinedOperator` |
| `VtlMappingScheme` | `VtlMapping`: VTL aliases for SDMX artefacts |
| `CustomTypeScheme` | `CustomType` |
| `NamePersonalisationScheme` | `NamePersonalisation` |

A `TransformationScheme` references the other five, so they belong together.

## Now

sdmxlib refuses each on read: "sdmxlib does not model TransformationScheme".

sdmx1 (`sdmx.model.common`) and pysdmx (`pysdmx.model`) both model all six. Use their shapes as the reference, per CLAUDE.md.

## Done when

The milestone's checklist holds for all six: model, readers and writers in every format, store, query paths, the maximal fixture, the censuses and `docs/upgrading.md`. VTL expressions are held as text; parsing VTL is out of scope.
