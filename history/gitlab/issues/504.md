## What happened

`tools/mutate_area.py src/sdmxlib/query/_compile.py <116 query test files> --max-children 6` on `main` (55f13ff), 2026-10-19:

    1718 mutants   killed 1510   survived 155   segfault 52   timeout 1

The 2026-09-11 run of #324 had 28 segfaults. A segfault is booked as neither killed nor survived, so it drops out of the triage.

## Sampled in a fresh process

Each mutant was run outside mutmut's fork server: `MUTANT_UNDER_TEST=<name> PYTHONPATH=mutants/src pytest -x -n 6 <the same 116 files>`.

| mutant | fresh-process result |
| --- | --- |
| `_conjoin__mutmut_5` (`TRUE` → `true`) | **killed** (`test_no_facet_emits_the_empty_string_not_none`) |
| `_Scope.from_sql__mutmut_2` | **killed** |
| `compile_select__mutmut_37` | **killed** |
| `_reference__mutmut_5` (`" AND "` → `" and "`) | **passes all 3,018**: equivalent |
| `_Scope.compile__mutmut_53` | **passes all 3,018** |
| `_order_sql__mutmut_16` | **passes all 3,018** |

Discrimination check: `_conjoin__mutmut_5` under the same `-n 6` setup fails, so the mutant is active in xdist workers and the passes are real.

So the segfault verdict carries no information. Half the sample were survivors or equivalents. The child crash looks like the fork-safety class (#314, #498), a property of forking off the stats parent rather than of the mutant.

## Also

The same command against the **whole** `tests/unit` (#324's documented resume command) no longer runs. The stats child is SIGKILLed (`ChildProcessError: Child exited with code -9`) with no message, almost certainly for memory: about 11,300 traced tests in one process. The result reads `1718 mutants killed 0 survived 0`. The narrow selection is what `mutate_area.py`'s docstring recommends; #324's resume command should say so.

## Done when

- Every segfault verdict in a run is re-checked in a fresh process, by `mutate_area.py` itself or a documented follow-up step, and the report says how many were re-classified.
- Or the crash is found and fixed so the verdicts are real.
- `docs/design/mutation-evidence.md` says the segfault column of earlier runs is not a kill count.

## Comments

### 2026-10-20

All 52 re-checked in fresh processes, against the tests mutmut's stats map says cover each mutant's function (the first 10 against all 116 files): **18 killed, 34 survived.** So the segfault verdicts hid 34 survivors, and `_compile.py`'s true survivor count on 55f13ff is 155 + 34 = **189**, not 155.
