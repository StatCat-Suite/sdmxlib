# Issue #194: [S1] RegistryReader must describe the registries we actually have — removes 2 attr-defined ignores

| | |
| --- | --- |
| State | closed |
| Opened | 2026-08-04 |
| Closed | 2026-08-04 |
| Milestone | %9 Suppression audit: fix the defect, not the symptom |
| Labels | `type::refactor`, `typing` |

Two call sites take `registry: object` and then call methods on it:

```python
# model/binding.py:298
flow = registry.get(binding.dataflow.urn)          # type: ignore[attr-defined]
# model/hierarchy.py:459
for ha in registry.get_all(HierarchyAssociation):  # type: ignore[attr-defined]
```

This is not carelessness — `binding.py` **documents** the workaround in its own docstring:

> *"rather than the `RegistryReader` Protocol so the overloaded `RestRegistry.get` and similar registries satisfy it."*

So the decision was considered. The problem is what it costs: with the parameter typed `object`, **every** mistake at those call sites is invisible, not just the one being worked around. Stripping the two comments shows the checker knows nothing about `registry` at all.

## Root cause

`model/registry.py:RegistryReader` does not describe the registries in this codebase:

* it declares `get[T]` + `__contains__` only — `get_all` is missing entirely, which is what `hierarchy.py` needs;
* its `get[T](urn: SdmxUrn[T]) -> T | None` does not structurally match `RestRegistry.get`, which is overloaded (URN form *and* `(type, agency=, id=, version=)` query form).

## Fix

Make the Protocol match reality, then type both parameters with it. Options to weigh:

* add `get_all` to `RegistryReader`, and give its `get` the same overload set as `RestRegistry` so the real implementations conform; or
* split a narrower Protocol per consumer (`SupportsGet`, `SupportsGetAll`) — these two functions each need one method.

The second is likely cleaner and avoids forcing every federation source to grow a `get_all`.

## Acceptance

* Both parameters typed to a Protocol; both `type: ignore[attr-defined]` deleted.
* No new suppression introduced at the implementation sites (i.e. the real registries genuinely conform).
* `just check` clean; binding-drift and hierarchy-association tests green.
