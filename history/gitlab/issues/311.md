# Issue #311: version ordering is lexicographic — 1.9 sorts after 1.10, so "the latest version" is wrong

| | |
| --- | --- |
| State | closed |
| Opened | 2026-08-14 |
| Closed | 2026-08-16 |
| Milestone | %17 Query DSL: a second backend, and the evidence the first one lacks |
| Labels | `dsl`, `storage`, `type::bug` |

`artefact.version` is `TEXT`, so every ordering over it is lexicographic:

```python
latest = q.dataflow.version.rank(descending=True).over(q.dataflow.agency, q.dataflow.id) == 1
reg.query(q.dataflow).qualify(latest)     # picks 1.9 over 1.10
```

`1.9` sorts after `1.10` as a string, so "the latest version" is wrong for any
catalogue whose minor version reaches double digits. Same for
`order_by(q.dataflow.version.desc())` and any `<` / `>` comparison.

## Why this is not theoretical

SDMX 3.0 versions are SemVer, and `1.10` is a perfectly ordinary version for a
maintained codelist. "Give me the current one" is one of the most common
catalogue questions — it is the headline example on the new windows section of
`docs/cookbook/discovery.md`.

Related but distinct from #188, which is about the *default* `"1.0"` failing
metadata JSON schema's strict `VersionType`. This is about ordering.

## Current state

`docs/cookbook/discovery.md` carries a warning admonition, and
`test_version_ranking_is_lexicographic_as_the_warning_says` pins the behaviour
so the page cannot quietly become wrong in either direction. So this is
documented, not silent — but documented-and-wrong is still wrong.

## Options

1. **Bake a sortable column at write time**, the approach `depth` /
   `ancestor_ids` already use: a zero-padded or tuple-valued
   `version_sort` alongside `version`. Fits
   `docs/design/caching.md`'s hierarchy — the input is immutable within an
   artefact version, so it is a bake rather than a runtime cost — and needs no
   compiler change beyond pointing the accessor's ordering at it.
2. **Order in SQL by parsing**, e.g. `string_split` + cast. No migration, but
   it runs per row per query and cannot use an index.
3. **A `version` type in the expression layer** that compiles comparisons to
   the parsed form. Most work, most general.

(1) looks right and is cheap. Worth checking what SDMX actually permits in a
version string first — wildcards (`1.0.0-draft`, `1.0+`) exist in 3.0 and a
naive zero-pad would mis-sort them.
