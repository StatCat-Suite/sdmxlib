# Issue #351: version.min()/max() compare as text, so agg(version.max()) says 1.9 is later than 1.10

| | |
| --- | --- |
| State | closed |
| Opened | 2026-08-20 |
| Closed | 2026-08-21 |
| Labels | `bug`, `dsl` |

Found by an independent audit; reproduced and verified before filing.

`version.min()` / `version.max()` compare versions as **text**, so two parts of
the same library disagree about which version is later:

```python
# one codelist at 1.9 and 1.10 — 1.10 is the later version
reg.query(q.codelist).order_by(q.codelist.version.desc()).select(v=q.codelist.version).collect()
# [{'v': '1.10'}, {'v': '1.9'}]        correct — #311's ordering

reg.query(q.codelist).group_by(q.codelist.id).agg(v=q.codelist.version.max()).collect()
# [{'resource_id': 'CL_X', 'v': '1.9'}]   WRONG
```

The emitted SQL is `max(s0.version)` over the raw `VARCHAR`, not over the baked
`version_sort` that `order_by` and `rank` route through.

## Why this is #311 leaking

`Version` exists as its own column class *precisely* so `1.9` is not treated as
later than `1.10`. It overrides `sort_column`; `order_by`, `desc()` and
`rank()` honour that. Aggregates do not — they take the plain column.

The `min`/`max` docstring reasons that they are "usable where `sum`/`mean` are
not, because SQL and polars both order text". That is the exact argument #311
rejected for ordering, applied to aggregation.

## Why it is the worst place for it

"The latest version of each artefact" is the single most common query in a
versioned-artefact catalogue, and `group_by(id).agg(max(version))` is the first
thing anyone writes for it. It returns a plausible-looking wrong answer with no
warning. The `qualify(version.rank(descending=True).over(agency, id) == 1)`
idiom is correct — and is not in the cookbook, so the wrong spelling is also
the discoverable one.

## Scope

- `min`/`max` on a `Version` column should aggregate on the sort key and return
  the original text — `arg_max(version, version_sort)` / `arg_min`.
- No test mentions `version.max()`. `tests/unit/test_version_ordering.py` covers
  the ordering path only.
- Worth a guard asserting `order_by(version.desc()).first()` and
  `agg(version.max())` agree, since the defect is precisely that they do not —
  the two implementations are each other's oracle.
- Add the `qualify` latest-per-artefact idiom to `docs/cookbook/discovery.md`;
  it is the correct spelling and is currently undocumented.

- **#351** — `_compile.py:796` special-cases `min`/`max` when `sort_column != column`, emitting `arg_max(value, key)` so the answer comes back in the column's own terms rather than as its sort key. Guarded by `tests/unit/test_version_ordering.py`.
