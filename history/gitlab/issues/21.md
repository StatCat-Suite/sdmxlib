# Issue #21: Round-trip fidelity: parse and re-emit ContentConstraint / Constraints

| | |
| --- | --- |
| State | closed |
| Opened | 2026-03-31 |
| Closed | 2026-03-31 |

## Problem

Every ECB dataflow response contains a `<Constraints>` block with a
`ContentConstraint` that declares which dimension value combinations have data
(e.g. only currencies ZAR, USD, EUR exist for the EXR dataflow). The current
reader silently drops the entire block.

See `docs/design/round_trip_fidelity.md` (Change 2) for full design.

## What changes

### Domain model (`model/constraint.py`, new file)
- `KeyValue` — allowed values for one dimension in a CubeRegion
- `CubeRegion` — selects a region of observation space; `allows(key)` method
- `ConstraintAttachment` — what the constraint is attached to (dataflow, DSD, or provision)
- `ContentConstraint` — maintainable artefact with id/agency_id/version/name/regions/attachment; `allows(key)` convenience method

### `StructureMessage` (`model/message.py`)
- Add `constraints: ArtefactList[ContentConstraint]` field

### Readers
- SDMX-ML 2.1: `_read_constraints()` — reads ContentConstraint + CubeRegion + KeyValue
- SDMX-ML 3.0: same (DataConstraint element name in 3.0)
- SDMX-JSON: `_read_constraints()` from `dataConstraints` key

### Writers
- SDMX-ML 2.1: `_write_constraints()` — emits `<str:Constraints>`
- SDMX-ML 3.0: same
- SDMX-JSON: `_write_constraints()` — emits `dataConstraints`

### Test fixtures
- Add a `ContentConstraint` to `tests/fixtures/sdmx_ml21/minimal.xml`
- Add same to `tests/fixtures/sdmx_ml30/minimal.xml`
- Add round-trip assertions for constraint ids, attachment, CubeRegion keys, and `allows()`

## Acceptance criterion

```python
orig = parse(Path("tests/fixtures/sdmx_ml21/ecb_dataflow.xml").read_bytes())
rt   = parse(serialize(orig))
assert len(rt.constraints) == len(orig.constraints)
```

Currently fails. Must pass after this change.
