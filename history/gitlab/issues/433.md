# Issue #433: CubeRegion loses KeyValue TimeRange and attribute/component value sets on read, then writes an empty KeyValue

## Summary

`CubeRegion` cannot hold two things both SDMX-ML versions put in it, so they are lost on read. The empty `KeyValue` left behind is then written schema-invalid, and `CubeRegion.allows()` misreads it.

Found by the registry sweep (!516) on OECD's constraints, from both its 2.1 and 3.0 APIs:

- `CubeRegion/KeyValue/TimeRange`: **1,453** (all in `StartPeriod`/`EndPeriod` form).
- `CubeRegion/Attribute` (2.1) / `CubeRegion/Component` (3.0): **758** each.

## What happens

`KeyValue` is `dimension_id` + `values: frozenset[str]` (`model/constraint.py:64-69`); `CubeRegion` is `include` + `keys` (`:84-88`). The shared reader (`sdmx_ml/_common.py:919-936`) reads only `Value` children, so:

```xml
<com:KeyValue id="TIME_PERIOD"><com:TimeRange>
  <com:StartPeriod isInclusive="true">1990-01-01T00:00:00</com:StartPeriod>
  <com:EndPeriod isInclusive="true">2023-12-31T00:00:00</com:EndPeriod>
</com:TimeRange></com:KeyValue>
<com:Attribute id="UNIT_MULT"><com:Value>0</com:Value><com:Value>6</com:Value></com:Attribute>
```

becomes `KeyValue("TIME_PERIOD", frozenset())`, and the attribute set disappears. Then:

1. Both writers emit `<KeyValue id="TIME_PERIOD"/>`, which fails 2.1, 3.0 and 3.1 ("Expected is one of (Value, TimeRange)"): 2.1 `writer.py:360-368`, 3.0 `_v3_writer.py:795-805`.
2. `CubeRegion.allows()` (`constraint.py:90-94`) treats the empty set as "nothing allowed", so every key in an include region with a lost time range looks forbidden.
3. The store then drops the empty `KeyValue` altogether (#437).

## Schema

- 2.1 `CubeRegionType`: `KeyValue*` then `Attribute*` (`SDMXCommon.xsd:772-784`); `CubeRegionKeyType` is `Value+` **or** `TimeRange` (`:810-823`); `TimeRangeValueType` is `BeforePeriod` | `AfterPeriod` | `StartPeriod`+`EndPeriod`, each with `@isInclusive`.
- 3.0 `CubeRegionType`: `Annotations?`, `KeyValue*`, `Component*` (`SDMXStructureConstraint.xsd:470-484`), same `KeyValue` choice.

## Fix direction

- Model: a time-range variant on `KeyValue` (sdmx1 calls it `RangePeriod`), and `CubeRegion.components` for the attribute/component value sets. Readers, writers, JSON and storage to match; `allows()` to evaluate a time range.
- Immediately, independent of the model work: refuse an empty `KeyValue` at write rather than emit it.

Distinct from #422's "CubeRegion / KeyValue validity" row, which is `validFrom`/`validTo` on the region.

## Gate

`constraint_key_value_without_values` (2.1, 3.0, 3.1) is in `KNOWN_INVALID` against this issue.
