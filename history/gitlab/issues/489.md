# Issue #489: SDMX-JSON 1.0: attributeRelationship {"none": {}} refuses the DSD instead of reading a dataflow attachment

| | |
| --- | --- |
| State | closed |
| Opened | 2026-10-16 |
| Closed | 2026-10-21 |
| Milestone | %21 Conformance evidence: what the green checks do not prove |

Found by the FMR oracle (#457). FMR 12.4.2 serves an attribute with no relationship in SDMX-JSON 1.0 as

```json
"attributeRelationship": {"none": {}}
```

which the vendored 1.0 schema allows: `AttributeRelationshipType` has `none` ("the value of the attribute will not vary with any of the other components" -- 2.1's dataflow-level attachment). Our reader refuses the whole DSD:

> an attributeRelationship needs exactly one of dataflow, dimensions, group, observation; it has none

That is SDMX-JSON 2.0's vocabulary applied to a 1.0 document. The 1.0 `none` should read as the dataflow attachment, as 2.1's `<str:None/>` does.

Related, and not silent (each is refused by name): the 1.0 reader does not read `contentConstraints` ("sdmxlib does not model ContentConstraint") or `hierarchicalCodelists`. Whether SDMX-JSON 1.0 *structure* reading should cover them is a scope question; today the library writes 1.0 only for `/availability` constraints.

Recordings: `tests/integration/fmr/12.4.2/*/back/AG-json10.json`.
