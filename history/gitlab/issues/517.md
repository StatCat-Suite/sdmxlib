# Issue #517: Label column naming differs between Dataset and the query/polars APIs

| | |
| --- | --- |
| State | closed |
| Opened | 2026-10-20 |
| Closed | 2026-10-21 |
| Milestone | %26 Found by the docs audit: correctness and refusals |
| Labels | `api`, `needs-design`, `priority::low` |

Label columns are named differently depending on the API:

| API | Labelled column |
| --- | --- |
| `Dataset.collect(with_labels=True, lang="en")` / `.lazy(...)` | replaces `FREQ` with **`FREQ_label`** |
| `sdmxlib.polars.label(lf, dsd, lang="en")` | adds **`FREQ_label_en`** |
| `Query.frame(labels="en")`, `Frame.collect(labels="en")` | adds **`FREQ_label_en`** |

The docs now describe each accurately (!665), but a reader moving between the data tutorial and the query tutorial gets two conventions. The `_en` form keeps two languages in one frame and matches `name["en"]` → `name_en`; the `Dataset` form also *replaces* the code column instead of adding beside it.

Decide whether `Dataset` should follow the `<id>_label_<lang>` convention and keep the code column. That would be a `breaking-change`.

Labelled `needs-design`.

## Comments

### 2026-10-21

**Decision (maintainer):** `Dataset` follows the query API, in both signature and output.

- `Dataset.collect(labels=...)` and `Dataset.lazy(labels=...)` take `str | Sequence[str]`, as `Query.frame` / `Frame.collect` do. A bare string is one language, not two characters; that rule is already pinned by `test_a_bare_language_is_one_language_not_two_characters`.
- Output **adds** `<id>_label_<lang>` beside each coded column, one per language asked for: `FREQ`, `FREQ_label_en`, `FREQ_label_fr`. The code column is kept.
- `with_labels=` and `lang=` are removed, with no shim.
- `Dataset` goes through the same label path as `Query.frame`, so the two can't drift.

Breaking.
