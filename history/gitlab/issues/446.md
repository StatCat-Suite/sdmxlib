## Summary

#436's closed-world check covers child *elements* only. An attribute the schema does not allow is still read past in silence. Real case: Eurostat's 3.0 `AgencyScheme` carries `@version` and `@isFinal`, which SDMX-ML 3.0 does not allow on it (3.0 fixes the organisation-scheme version and removed `isFinal`). They are ignored rather than reported.

## Fix direction

Extend #436's generated table with allowed attributes per element (`xs:attribute` and `xs:attributeGroup`, through extension and restriction, honouring `use="prohibited"`, which restrictions use heavily in these schemas), and check them in the same `iterwalk` pass. Then:

- **Cost.** Re-measure; #436's walk is 9–14% of parse time.
- **Real data.** Re-run the cached-registry survey. Attributes are where registries are least strict, so the refusal count needs looking at before it ships.
- **Policy.** Decide whether an extra attribute that carries no meaning in the target version should refuse the artefact or only be reported. That is a design choice.

Follow-up to #436.

## Comments

### 2026-10-15

Measured 2026-10-15 by validating every cached sweep document against the vendored XSDs: 104 documents, 6.8 GB, from BIS, ECB, ESTAT, IMF, OECD and SDMX, over the 2.1 and 3.0 APIs. The four largest were validated as their sweep chunks. Disallowed attributes found: **2**, both on one element: ESTAT 3.0 `AgencyScheme` with `@version` and `@isFinal`. That element also uses `str:Name` where 3.0 requires `com:Name`. Since #436's element walk already costs 9–14% of parse time, adding an attribute check is not justified by this data. Moved out of milestone 20 to the backlog (user decision).
