# Issue #279: Component.concept accepts a bare item and the writer silently drops it

| | |
| --- | --- |
| State | closed |
| Opened | 2026-08-09 |
| Closed | 2026-08-17 |
| Labels | `storage`, `type::bug` |

Found while building #276.

`Dimension.concept` (and the other `Component` subclasses) is declared
`Ref[Concept] | None`. attrs accepts a bare `Concept` at runtime, and the DSD
component writer then does:

```python
# src/sdmxlib/storage/writers.py
concept_urn_str = str(concept_ref.urn) if isinstance(concept_ref, Ref) else None
```

So a bare item **silently writes `concept_urn = NULL`** and the concept
association is lost on a store/load round-trip. Nothing warns, and the
artefact validates.

## How it surfaced

`sl.artefact.uses_concept("REF_AREA")` (#276) returned `[]` against a catalogue
that plainly used the concept. The query SQL was correct; `dsd_component.concept_urn`
was NULL:

```
dsd_component: [('...DataStructure=AG:DSD1(1.0)', 'REF_AREA', None, '...Codelist=AG:CL_GEO(1.0)')]
```

Building the ref properly (`Ref[Concept].unresolved(urn)`) fixes it. So this is
a caller type error — but one the library converts into silent data loss rather
than an error.

## Why it matters beyond a type error

- Both checkers catch it in typed code, but a notebook, a JSON-driven builder,
  or any untyped construction path will not be checked.
- The failure is invisible: the artefact round-trips, validates, and is simply
  missing an edge. Concept-driven discovery then returns wrong answers with no
  signal.
- `isinstance(x, Ref)` returning False is being used as "no concept", which
  conflates *absent* with *malformed*.

## Suggested fix

Raise on the malformed case rather than writing NULL — the writer knows the
difference between `None` (legitimately absent) and a non-`Ref` value
(a mistake). Worth auditing the sibling `getattr(comp, ...)` reads in
`_component_row` for the same shape; `representation` may have it too.

Alternatively, an attrs converter on the field that wraps a resolved item into
a `Ref` — but item URNs need the parent scheme, which the component does not
have, so raising is probably the honest option.
