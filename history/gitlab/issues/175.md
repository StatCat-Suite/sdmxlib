## Decide a convention for internal structural Protocol names

We keep introducing small structural `Protocol`s for typing (`HasUrn`, `HasId`,
`Maintainable`, `_HasCodeMap`, and more coming from the #170 writer-typing work,
e.g. a `.urn`-bearing "UrnRef"). They're currently named inconsistently:

- `model/ref.py`: **`HasUrn`** (identity surface: sdmx_package/sdmx_class/agency_id/id/version)
- `model/collections.py`: **`HasId`**, **`Maintainable`**
- `polars.py`: **`_HasCodeMap`** (leading underscore — the lone outlier)

### Options

1. **`Has<Attr>`** — matches most of the existing code (`HasId`, `HasUrn`). Terse.
2. **`Supports<Capability>`** — the typeshed / stdlib idiom (`SupportsRead`,
   `SupportsIndex`, `SupportsRichComparison`). Reads clearly as *a protocol, not a
   concrete class* — the property @gabrielgellner leaned toward. Slightly verbose.
3. **Domain nouns** (e.g. `UrnRef`) — natural for a specific concept, but doesn't
   signal "protocol".

### Naming vs privacy (settled)

Leading-underscore is only for genuinely single-function, single-module helpers.
typeshed conveys privacy by *module placement* (`_typeshed`), not by mangling the
name. So a reused/meaningful protocol should get a clean name; `_HasCodeMap`
should lose its underscore under whichever scheme we pick.

### Watch-outs

- `HasUrn` already means the *identity* surface, NOT "has a `.urn` attribute" — a
  new `.urn`-attribute protocol must not reuse that name (→ `UrnRef` /
  `SupportsUrn`).
- Whatever we pick, retrofit the existing ones (`HasUrn`, `HasId`, `Maintainable`,
  `_HasCodeMap`) for consistency — pre-1.0, so renames are cheap.

### Context

Came up during #170 (typing duck-typed writer params). That work deliberately
avoided minting a named protocol for the URN writers (used `AnyRef` + a caller
narrow instead), so nothing is blocked on this — it's a standardization pass to
schedule.

## Comments

### 2026-07-22

Decided: adopt the **Supports*** convention (signals 'protocol, not a concrete class'). Applying now — HasUrn -> SupportsUrn, HasId -> SupportsId, _HasCodeMap -> SupportsCodeMap; Maintainable kept (a domain role, not a capability protocol).
