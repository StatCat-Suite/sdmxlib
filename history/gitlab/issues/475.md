# Issue #475: SDMX-ML 2.1 ContentConstraint without @type is read as Allowed; the schema default is Actual

| | |
| --- | --- |
| State | closed |
| Opened | 2026-10-16 |
| Closed | 2026-10-16 |
| Milestone | %21 Conformance evidence: what the green checks do not prove |
| Labels | `bug`, `conformance` |

## Problem

The SDMX-ML 2.1 schema declares `ContentConstraint/@type` with `default="Actual"` (`SDMXStructureConstraint.xsd:146`). The reader in `formats/sdmx_ml/_common.py` does:

```python
role = cc_el.get("role") or cc_el.get("type", "Allowed")
```

So a 2.1 `ContentConstraint` that omits `@type` is read as **`Allowed`** where the standard says **`Actual`**. Those are opposite meanings: what data may be reported, against what data exists.

## Impact

Latent so far. In the 2026-10-15 sweep, every 2.1 constraint states its type:

| registry | constraints | without `@type` |
| --- | --- | --- |
| BIS | 83 | 0 |
| ECB | 212 | 0 |
| OECD | 2,890 | 0 |
| SDMX | 94 | 0 |

Any producer that relies on the schema default would be misread silently.

## Fix

Default 2.1's `@type` to `Actual`, the schema's value. In 3.x, `@role` is required and has no default, so a missing one is an assumption for the issue on reader-assumed values, not this one.

Add a test that reads a 2.1 `ContentConstraint` without `@type` and gets `Actual`. Check that it fails today.
