# Issue #368: AnnotationValue is silently dropped: SDMX 3.0 and SDMX-JSON carry it, the model has no field

| | |
| --- | --- |
| State | closed |
| Opened | 2026-08-21 |
| Closed | 2026-08-21 |

Found while implementing #366.

## The loss

SDMX-ML 3.0's `AnnotationType` has five children; we model four:

| Wire | Model |
| --- | --- |
| `AnnotationTitle` | `Annotation.title` |
| `AnnotationType` | `Annotation.type` |
| `AnnotationURL` | `Annotation.url` |
| `AnnotationText` | `Annotation.text` |
| **`AnnotationValue`** | **— nothing —** |

SDMX-JSON 2.0/2.1 carry it as `annotation.value`, described as *"AnnotationValue holds a string containing the non-localised value text of the annotation."* It is the un-localised sibling of `text`, which is exactly the shape you want for a machine-read annotation — an ORDER, a flag, a numeric weight — where a language map is meaningless.

`grep -rn AnnotationValue src/sdmxlib/` returns nothing: not modelled, not read, not written, and not declared in `gaps.py`.

## Confirmed empirically, not just by grep

```python
doc = b'''... <str:Code id="A"><com:Annotations><com:Annotation>
  <com:AnnotationType>ORDER</com:AnnotationType>
  <com:AnnotationValue>239</com:AnnotationValue>
  <com:AnnotationText xml:lang="en">t</com:AnnotationText>
</com:Annotation></com:Annotations> ...'''

cl.codes["A"].annotations[0]
# Annotation(id=None, title=None, type='ORDER', url=None, text=InternationalString(en='t'))
# -> "239" survived nowhere
```

Read, dropped, no warning. This is the #355 class of silent loss and it is undeclared, so `test_field_coverage` cannot see it either — the field does not exist to be diffed.

## Why it matters beyond faithfulness

#366 makes the data writers emit annotations so consumers can read `ORDER` and friends. A publisher who puts that value in `AnnotationValue` rather than `AnnotationText` — which is the *more correct* choice for a non-localised number — has it dropped before the writer ever sees it. So this caps what #366 can deliver.

## Scope

1. Add `value: str | None = None` to `Annotation`.
2. Read/write it in the 3.0 and 3.1 SDMX-ML readers and writers, and in SDMX-JSON (`annotation_dict` + the structure ingest).
3. **2.1 has no `AnnotationValue`** — it is a 3.0 addition, confirmed against the vendored XSDs (2.1's `AnnotationType` has four children, 3.0's has five). So this needs a `gaps.py` entry for the 2.1 target, and is a genuine limit rather than an omission there.
4. Storage column + the `test_field_coverage` register entry that follows from the field existing.
