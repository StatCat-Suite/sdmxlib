## Summary

`TimeDimension.representation` is an untyped `Facet`, so a `textType` outside `TimeDataType` is accepted and written in every format, schema-invalid, with no refusal.

Found by the registry sweep (!516): **54** IMF DSDs carry `TimeDimension/LocalRepresentation/TextFormat@textType="String"` (e.g. `SURVEY:SURVEYS_SUBJECT_SURVEY_STATUSES(1.2.0)`). Written invalid in 3.0, 3.1 and JSON (54), and 2.1 (12 — the other 42 are refused for their measures). IMF's source document fails the 3.0 XSD on it.

## Schema

All three versions type the time dimension's format as `TimeTextFormatType`, whose `textType` is `common:TimeDataType` (the observational time-period types plus `DateTime`): 2.1 `SDMXStructureBase.xsd:556`, 3.0 `:468`, 3.1 `:474`. `String` is in none.

Writers: `_v3_writer.py:689-691`, `sdmx_ml21/writer.py:226-228`, both via `write_text_format` (`_common.py:1264`) unchecked.

## Fix direction

Format-independent (every target forbids it), so it belongs with #419: a `validate()` rule, beside the existing `_check_enumeration_format`, that a `TimeDimension` facet type is a `TimeDataType`. Coercing to `ObservationalTimePeriod` would invent data.

Tracking: #423
