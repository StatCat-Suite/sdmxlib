# Issue #117: perf: cache SdmxUrn.__str__ to cut registry-build + JSON-parse allocations

## Context

Surfaced by the new Phase 1 bench suite (MR !79). \`pytest-memray\` flags \`SdmxUrn.__str__\` (\`src/sdmxlib/model/urn.py:113-115\`) as the **#1 allocator** in two separate hot paths:

| Test | Watermark | \`SdmxUrn.__str__\` share |
|---|---|---|
| \`test_registry_add_all[10k]\` | 1.5 MiB | 1.0 MiB |
| \`test_parse[large-json]\` | 1.2 MiB | 1.0 MiB |

The function materialises \`urn:sdmx:org.sdmx.infomodel.{package}.{class}={agency}:{id}({version})[.item]\` via f-string concatenation on every call.

## Why this matters

- \`InMemoryRegistry.add\` calls \`str(urn)\` for the canonical-ref key once per artefact → 10k artefacts = 10k string materialisations of a value that never changes.
- JSON cross-refs are stored as URN-text; round-tripping a message re-stringifies every ref.
- \`SdmxUrn\` is a frozen attrs class — the string is invariant for the lifetime of the object.

## Proposed fix

\`@cached_property\` on \`__str__\` won't work directly (it's a dunder). Two clean options:

1. **Cache on instance** via a private \`_str_cache\` slot set lazily on first \`__str__\` call.
2. **Module-level LRU** keyed by the attrs tuple — but \`SdmxUrn\` is hashable already so we can just \`functools.lru_cache\` a free function.

Option 1 fits the frozen-attrs idiom better; no global cache lifetime to reason about. Slot the cache via \`@define(slots=True, ...)\` or use \`__getattr__\` fallback.

## Estimated impact

- Registry-build allocation footprint: expect 30–50% reduction at 10k artefacts (\`add_all[10k]\` watermark drops from 1.5 MiB toward ~500 KiB).
- JSON-parse: \`__str__\` contribution mostly survives because the URNs are different objects each parse — but if we also intern parsed URNs (separate concern), the cache helps the registry-side leg.

## Acceptance

- \`just bench-mem\` shows \`SdmxUrn.__str__\` drop out of the top-3 allocators for \`test_registry_add_all\`.
- \`just bench\` shows \`test_registry_add_all\` wall unchanged or faster (the f-string cost was also non-trivial — ~150 µs/artefact today).
- Equality / hashing semantics on \`SdmxUrn\` unchanged.
