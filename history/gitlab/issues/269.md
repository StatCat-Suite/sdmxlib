# Issue #269: 19 benchmarks fail on main — bench fixtures build artefacts validate() rejects

| | |
| --- | --- |
| State | closed |
| Opened | 2026-08-09 |
| Closed | 2026-08-20 |
| Labels | `bug`, `perf`, `tests` |

Nineteen benchmarks fail or error on `main`, unmodified. Found while adding query-DSL benchmarks (!257); the query benchmarks themselves pass, so this is pre-existing and separate.

```
7 failed, 94 passed, 2 skipped, 12 errors
```

## Cause

The bench fixtures build artefacts that `validate` rejects:

```
sdmxlib.model.validation.ValidationError: 100001 validation issues:
  error: Codelist.name — name is required (SDMX NameableArtefact)
  error: Codelist.codes[C000000].name — name is required (SDMX NameableArtefact)
```

`tests/bench/fixtures.make_codelist` creates codes without names. That was fine when the fixture was written and stopped being fine when validation started requiring `name` on every `NameableArtefact` — most likely #221, which tightened validation to match the XSD.

Affected: `test_validation_overhead.py` (5), `test_serialize.py` (2), `test_parse.py` (12 errors, fixture-time).

## Why it matters beyond the noise

`just bench` is the only performance instrument the project has, and a fifth of it has been red for long enough that nobody noticed. A harness that always fails is a harness nobody reads — which is how the query DSLs ended up with no coverage at all until !257.

## Scope

- Give `make_codelist` and the other bench fixtures names on every nameable artefact, so they build artefacts the library considers valid.
- Check the remaining fixture builders in `tests/bench/fixtures.py` for the same gap rather than fixing only the ones that happen to fail today.
- Confirm the fix does not change what the benchmarks measure: adding a name changes object size slightly, so re-baseline afterwards rather than comparing across the fix.

## Note on interpreting timings after this lands

!257 calibrated the harness for microsecond-scale work: `--benchmark-min-time=0.0005 --benchmark-disable-gc --benchmark-warmup=on`, now the default in the `bench` recipe. Run-to-run drift on identical code is <= 1.84%, so treat a delta under ~3% as noise, 5% as probably real, 10% as certainly real. Compare medians and IQR, never mean and stddev — at 2 us the mean is noise-dominated.
