# Issue #484: A dataflow of an evolving DSD needs a dimension constraint, and nothing checks it (IM §5.3.2.1)

| | |
| --- | --- |
| State | closed |
| Opened | 2026-10-16 |
| Closed | 2026-10-21 |
| Milestone | %21 Conformance evidence: what the green checks do not prove |

Found by the IM rule census (#456). SDMX 3.1 Section 2, §5.3.2.1 p. 75: a Dataflow defines a DimensionConstraint, and "this is a mandatory requirement if the DataStructureDefinition sets its' evolvingStructure property to 'true' and is sematically referenced by the Dataflow"; §5.3.2.2 p. 79 narrows it to a reference "on the latest minor version".

`Dataflow.dimension_constraint` and `DataStructure.evolving_structure` both exist; nothing relates them. It is a cross-artefact rule — the flow's DSD must be resolved — so it fits `validate_references` / `validate_message` rather than `validate`.
