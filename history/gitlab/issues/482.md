# Issue #482: Facet sequence rules are unchecked: isSequence, interval, start/end values and times (IM §3.6.3.3)

| | |
| --- | --- |
| State | closed |
| Opened | 2026-10-16 |
| Closed | 2026-10-20 |
| Milestone | %21 Conformance evidence: what the green checks do not prove |

Found by the IM rule census (#456). SDMX 3.1 Section 2, §3.6.3.3 (p. 45) states the sequence facets as rules, and nothing checks them — `Facet` accepts every combination and every writer emits it:

- "If this attribute holds a value of true, a start value or time and a numeric or time interval must be supplied." (`isSequence`)
- `interval` / `timeInterval`: "In order for this to be used, the isSequence attribute must have a value of true."
- `startValue` / `endValue`: used "in conjunction with the isSequence and interval facets (which must be set in order to use this facet)"; `startTime` / `endTime` likewise with `timeInterval`.
- "This value is mandatory for a numeric sequence to be expressed." (`startValue`), and the same for `startTime` in a time sequence.

Each is a single-`Facet` rule, so it belongs in `model.validation` beside `_check_facet_bounds`. When it lands, the census rows `IM-3.6.3.3-*` move from `NotChecked` to `Validated`.

Open question: refuse, or warn (#481)? A facet with `interval` but no `isSequence` is schema-valid XML — the XSD types each facet independently — so this is an IM rule the wire formats do not enforce.

## Comments

### 2026-10-20

Per #481's decision (2026-10-20): this rule is stated by the IM and enforced by no wire schema, so it **warns** (`sl.SdmxWarning`) rather than refuses.
