## Summary

Found by putting the store into the field census: `LocalRegistry.add` then `get(eager=True)` over `tests/support/maximal.py`, which sets every field. The census had only ever run the four wire formats, which is how #437 (`data_keys`) and #438 (`enumeration_format`) went unseen.

Beyond those two and the naive/aware datetimes of #440, the store loses:

| lost | example |
|---|---|
| `RepresentationMap.maps[].valid_from` / `valid_to` | `date(2020, 1, 1)` → `None` |
| hierarchy `Level.annotations` (on `levels[]` and on each node's `level`) | 1 → 0 |
| `MetadataStructure.targets` / `.report_structures` (the 2.1 layer) | 1 → 0 |
| `Agency.parent` | `Agency(id='A0')` → `None` |
| `uri` on items that `gaps.py` does not declare for storage | data and metadata providers, nested categories, DSD components (dimensions, attributes, measures, time and measure dimension, groups), hierarchy nodes and levels, MSD attributes |

## The uri row

`gaps.py` declares item `uri` a storage limit for codes, concepts, top-level categories and agencies ("storage carries uri on the artefact spine, not on items"). The same loss on every other item kind is undeclared. Either declare it for all of them, or store it. The census will hold whichever is decided.

## Guard

`tests/unit/test_store_round_trip.py` (from #437's MR) records each of these against this issue, and asserts each one still happens, so a fix fails it until the entry is removed.
