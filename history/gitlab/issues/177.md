# Issue #177: Reader ref-resolution witness is decorative: Ref[T] return is an unbacked downcast

| | |
| --- | --- |
| State | closed |
| Opened | 2026-07-22 |
| Closed | 2026-07-22 |

## Summary

The `type[T]` witness threaded through the format readers' ref-resolution
helpers (`resolve_ref` in `formats/sdmx_ml/_common.py`, `_resolve_urn` in
`formats/sdmx_json/reader.py`, merged in !145 / #173) **documents** an assertion
but does not **enforce** it. The `Ref[T]` return of the *resolved* branch is an
unbacked downcast that is type-safe only under basedpyright's `Any`-unification;
pyrefly (correctly) infers it as `Ref[object]`.

## Detail

The resolved branch:

```python
obj = index.get(str(urn))        # obj: object   (index is dict[str, object])
return Ref.of(urn, obj)          # Ref.of(cls, urn: SdmxUrn[T], obj: T) -> Ref[T]
```

`Ref.of` solves the class typevar `T` from two conflicting constraints:
`urn: SdmxUrn[Any]` (→ `T=Any`) and `obj: object` (→ `T=object`).

- **basedpyright** lets `Any` win → `Ref[Any]` → flows into the declared `Ref[T]`. ✓ (0 errors)
- **pyrefly** takes the concrete `object` → `Ref[object]` → rejects the `Ref[T]` return (`bad-return`).

pyrefly is substantively right: `obj` is only known to be `object`, so the honest
type is `Ref[object]`. Nothing casts or checks `obj` against the `cls` witness —
the witness is **decorative**. Relabeling the payload `Ref[T]` is an assertion
the type system cannot back.

Discovered while comparing pyrefly against basedpyright on `src` (pyrefly reports
this as `[bad-return]` at `json/reader.py:148`, `_common.py:289/295`). The sibling
`SdmxUrn[T] -> SdmxUrn[object]` errors pyrefly also raises are, by contrast, a
pyrefly **false positive** (widening a genuinely phantom `SdmxUrn` param is sound)
— that half needs no action.

## Severity

Low in practice: the readers are internal, the resolution `index` is built from
the same message, and each call site's `cls` is chosen to match the field's
expected class, so the payload *is* a `T` in well-formed input. But it's a latent
soundness gap and a checker-portability wart.

## Proposed fix — make the witness load-bearing

```python
obj = index.get(str(urn))
if isinstance(obj, cls):          # narrows obj: object -> T; connects witness to payload
    return Ref.of(urn, obj)
return Ref.unresolved(urn)
```

This satisfies both checkers *and* actually enforces the type.

### Behavior-change decision required

With the guard, if the index holds an object of the **wrong class** for that URN,
we fall through to `unresolved` instead of returning a mistyped resolved Ref.
That is arguably *more* correct (don't resolve to a wrong-typed object), but it is
a behavior change — decide the wrong-type-in-index case before landing:

- (a) fall through to `unresolved` (proposed — safest), or
- (b) resolve anyway but log/raise on class mismatch, or
- (c) keep current behavior and use an explicit `cast("T", obj)` (enforces nothing;
  silences pyrefly without the runtime check — least preferred).

Only the resolved (`.of`) branch is affected; the `unresolved` branch is already
sound. `cls=object` sites (heterogeneous refs) are unaffected: `isinstance(obj,
object)` is always true.

## Acceptance

- [ ] Decide the wrong-type-in-index policy (a/b/c above).
- [ ] Enforce the witness in `resolve_ref` and `_resolve_urn`.
- [ ] No new `cast`/`# type: ignore`; both basedpyright and (the `bad-return`
      subset of) pyrefly clean on the touched lines.
- [ ] Test: a resolved ref whose indexed object mismatches `cls` behaves per the
      chosen policy.
