# Issue #429: Reference versions are written without checking the target grammar: silently invalid in every format

| | |
| --- | --- |
| State | closed |
| Opened | 2026-10-09 |
| Closed | 2026-10-14 |
| Milestone | %20 3.x-native model: hold all of 3.x, project to 2.1, validate at ingest |
| Labels | `bug`, `conformance`, `status::started` |

## Summary

Every writer checks a maintainable's **own** version against the target grammar (`VersionFormatError`). None checks the version inside a **reference**. A reference version that the target cannot express is written as-is, and the document fails the schema with no refusal.

Found by the registry sweep (!516): IMF's 3.0 documents reference by wildcard (`…CS_DQAF_GFS_SURVEY(3.0+.0)…`), and the 2.1 projection of them writes **20,983** schema-invalid `Ref@version` / `@maintainableParentVersion` attributes (hierarchies 12,007, concept schemes 6,536, DSDs 2,327, dataflows 102, categorisations 11).

## Measured (a dataflow whose `structure` ref carries the version)

| ref version | 2.1 | 3.0 / 3.1 | JSON |
|---|---|---|---|
| `1.0.0-draft` | **invalid** | valid | valid |
| `1.2.3.4` | valid | **invalid** | **invalid** |
| `1.0+.0` (3.0 wildcard) | **invalid** | valid | valid |
| `1.0+`, `*`, `~` | **invalid** | **invalid** | **invalid** |
| `latest` | valid* | refused (#233) | refused (#233) |

\* `sdmx_ml/_common.py:1227` (`urn_to_ref_el`) silently writes a `"latest"` **item** reference as version `"1.0"`. `_check_latest_refs` (`model/validation.py:1986`) calls exactly that kind of silent change worse than refusing.

- `SdmxUrn.parse` keeps any version text opaque, so `*`, `~` and `1.0+` are constructible although no grammar accepts them as a reference version.
- 2.1 `VersionType` is `[0-9]+(\.[0-9]+)*` (`SDMXCommonReferences.xsd:72`); 3.0's `UrnReferenceVersionPart` explicitly allows the `+` wildcard forms.
- Emit sites: `sdmx_ml/_common.py:1227,1231` (2.1 `Ref`), `_v3_writer.py:388` (`_write_urn_text`), `sdmx_json/_structure_dto.py`.

## Fix direction

- A per-target reference-version pass in `check_serialisable`, mirroring `_check_latest_refs`: refuse a reference whose version the target cannot express, naming the reference and suggesting 3.0 or a pinned version. Resolving a wildcard on write changes which artefact the reference names, so it is not an option.
- Item refs with `"latest"`: refuse rather than write `1.0`.
- A reference version valid in **no** grammar (`*`, `1.0+`) is format-independent → refuse at construction or at `add` (#419).
- Wildcard references as a model concept are #422's last row; this issue is only about not writing them invalid.
