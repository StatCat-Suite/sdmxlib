# Issue #471: Read and write SDMX-ML 2.1 reference metadata: project the Report layer onto 3.0-shaped MetadataSets

| | |
| --- | --- |
| State | closed |
| Opened | 2026-10-16 |
| Closed | 2026-10-21 |
| Milestone | %23 Full information-model coverage: every maintainable artefact type |
| Labels | `conformance`, `model` |

## Problem

sdmxlib reads and writes reference metadata in SDMX-ML 3.0 (`<mes:GenericMetadata>`) and SDMX-JSON. **SDMX-ML 2.1 reference metadata is not supported at all.** `serialize` documents it as out of scope, and `parse` has no 2.1 metadata path. Most registries serving reference metadata today are 2.1 (.Stat NSI), so a 2.1 metadata document cannot be read. And a `MetadataSet` built from 3.x cannot be projected to 2.1, unlike every structure artefact since milestone 20.

## The two shapes

| | SDMX-ML 2.1 (`SDMXMetadataGeneric.xsd`) | sdmxlib's model (3.0-shaped) |
| --- | --- | --- |
| identity | **not maintainable**: optional `@setID` only | maintainable: id, agency, version |
| structure | `@structureRef` to a header `<Structure>`, which names an MSD or a Metadataflow | `structure: Ref[Metadataflow] \| Ref[MetadataProvisionAgreement]` |
| provider | optional `<DataProvider>` | implied by a `MetadataProvisionAgreement` |
| layering | `MetadataSet` → 1..n **`Report`**, each with `@id` (its report structure), one `<Target>` and one `<AttributeSet>` | **no report layer** (3.0 dropped it): one `targets` list and one `attributes` tree per set |
| targets | `Target` → 1..n `ReferenceValue`, each one of `ObjectReference`, `DataKey`, `DataSetReference`, `ConstraintContentReference`, `ReportPeriod` | `targets: list[Ref[object]]`, identifiable artefacts by URN only |
| set attributes | `action`, `reportingBeginDate`/`EndDate`, `validFromDate`/`ToDate`, `publicationYear`/`Period` | `valid_from` / `valid_to` |
| reported values | `ReportedAttribute` with `@value`, `common:Text`, `common:StructuredText` (XHTML), nested `AttributeSet` | `ReportedAttribute` tree, which the 3.0 reader already builds |

## Proposed projection (decisions to confirm before implementing)

**Read, 2.1 → model:**
1. **One `MetadataSet` per `Report`.** The report layer is what 3.0 removed, and a report is exactly one target plus one attribute tree. A set with a single report keeps its `setID` as the id. With several, each becomes `<report id>@<setID>`, the `<map>@<set>` rule milestone 20 used for maps and hierarchies (#421).
2. **Identity.**
   - **agency:** from the `DataProvider`'s agency, else from the MSD or Metadataflow maintainer.
   - **version:** `1.0`.
   
   The synthesis is a declared conversion in `formats/gaps.py`.
3. **Structure.**
   - **A Metadataflow:** taken as it is.
   - **An MSD only:** our model has nowhere to point. Refuse, or point at a synthetic marked flow? To decide.
   - **A `DataProvider`:** resolve to the `MetadataProvisionAgreement` binding it to the flow, if the message or a registry holds one.
4. **Targets.**
   - **`ObjectReference`:** becomes a URN target.
   - **`DataKey`, `DataSetReference`, `ConstraintContentReference` and `ReportPeriod`:** no URN form. Each is a declared loss, recorded on `StructureMessage.lost`'s metadata counterpart, or the set is refused if that leaves no target. To decide.
5. **Set attributes:**
   - **`validFromDate`/`ToDate`:** to `valid_from`/`valid_to`.
   - **`action`, the reporting dates and the publication year or period:** declared losses unless the model gains them, which 3.0's `MetadataSet` also carries, so check the 3.0 reader first.

**Write, model → 2.1:**
- **Layout:** one 2.1 `MetadataSet` with one `Report`. `setID` is the id, and agency and version are a declared loss unless marked for the reader to restore (the milestone 20 pattern).
- **Targets:** URN targets become `ObjectReference`s.
- **The flow or provision agreement:** goes in the header `<Structure>`.

**Out of scope here, its own follow-up if wanted:** 2.1 **structure-specific** metadata (`SDMXMetadataStructureSpecific.xsd`).

## Done when

- `parse` reads 2.1 GenericMetadata, and `serialize(MetadataMessage, version="2.1")` writes it.
- Every row above is implemented as decided, or recorded in `formats/gaps.py`.
- A 3.0 → 2.1 → 3.0 round trip is exact, or exact up to the declared gaps.
- The vendored 2.1 metadata samples read, and the output validates against the 2.1 XSD.
- #459's census measurement covers the new reader and writer.
