# Issue #502: Sweep census lists explicit schema defaults and 2.1's alias form as read losses

| | |
| --- | --- |
| State | closed |
| Opened | 2026-10-19 |
| Closed | 2026-10-21 |
| Labels | `tests` |

## Problem

The registry sweep's `read_lost` is meant to show only what we fail to hold (`bench/sweep/census.py`; `DERIVABLE` sets aside what is derivable). Re-run on 2026-10-19, it still lists four constructs that sdmxlib holds:

| path | where | count | why it is not a loss |
| --- | --- | --- | --- |
| `MetadataAttribute/@isPresentational=false` | IMF 3.0 | 11,205 | the XSD default (`false`); the model holds `is_presentational`, and the writer omits a default |
| `CubeRegion/KeyValue/@include=true` | IMF 3.0 | 3 | the XSD default (`true`) |
| `CubeRegion/KeyValue/@removePrefix=false` | IMF 3.0 | 3 | no XSD default, but `false` is what absence means to the model (`remove_prefix`) |
| `HierarchicalCode/CodelistAliasRef` + `CodeID/Ref/@id`, `IncludedCodelist/@alias` | OECD 2.1 | 13,381 / 212 | 2.1's alias spelling of a code reference; the writer uses the other legal form (a full `Code` reference), and the alias is a label local to the document (#434 reads it whole) |

They were nearly filed as unmodelled content on 2026-10-19. Only DataConsumerScheme (#469) was real.

## Fix

- Add each to `census.DERIVABLE`, with its reason as the existing entries carry one.
- For the alias form, the count stays visible under `read_lost_derivable`, as `@urn` does.

## Done when

- `just sweep-run IMF OECD` lists none of these under `read_lost`.
- A census unit test pins that a non-default `isPresentational="true"` that the model failed to hold would still count as lost. The census has to stay able to fail.

## Comments

### 2026-10-20

Its mirror is #503: the writers spell out defaults a producer omitted, and the sweep reports those as `read_gained` (9,684 + 7,786 `@usage=optional` on a 2% ESTAT sample). The census fix here should treat `read_gained` and `read_lost` defaults alike.
