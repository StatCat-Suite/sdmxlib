# Issue #403: Guards that stop being able to fail — four in one session, and the rule that catches them

| | |
| --- | --- |
| State | closed |
| Opened | 2026-09-11 |
| Closed | 2026-09-11 |
| Labels | `tests` |

CLAUDE.md already states the principle twice:

> A finding that cannot fail is a finding nobody acts on. (§ ruff warnings)

> …a guard that has only ever passed is not known to be a guard.
> (`tests/bench/test_bundle_reads.py`)

Both are about writing a guard *correctly in the first place* — watch it fail
before trusting it. Neither says anything about the case that actually keeps
happening: **a guard that was correct, was watched to fail, and later stopped
being able to.** Nothing it asserts changed. Its *subject* moved.

Four instances in one working session, each a different mechanism, and three
of the four surfaced only because something unrelated forced a re-run.

## The four

**1. A proxy that outlived its meaning** — `test_storage_cascade`, fixed in
!476. It asserted `len(again) > 20` as a stand-in for "the cascade ran". #144
made the cascade type-dispatched, so the honest count dropped to 9 and the
proxy failed — correctly, by luck. Had the number landed above 20 the test
would have kept passing while measuring something that no longer existed.

**2. The subject became trivial** — `test_ml3_fork_drift`, !487/!488. It
compared the two packages' function bodies. After the reader merge each module
held one forwarding `read`, so the two were *trivially* identical: thirteen
assertions passed, and the reader could have been re-forked in a two-line
change with nothing to say so.

**3. The guard read the wrong file** — `test_ml3_writer_parity
::test_every_annotation_site_is_reached`, fixed in !488. It counted
`write_annotations` call sites in `sdmx_ml30/writer.py`, which !487 had reduced
to 49 lines. **This is the one that caught itself**, and the reason is the
whole point of this issue: it asserts `sites == len(_MARKERS)` and failed at
`0 == 30`. A `>=` bound, or `sites > 20`, would have passed in silence.

**4. The guard read the wrong stream** — `tools/check_docstrings.py`, caught
pre-merge in !483. The pydoclint arm parsed `proc.stdout`; pydoclint 0.9 writes
findings to stderr and leaves stdout empty. It reported a clean tree on a file
pydoclint had just flagged, and — being a gate that starts at zero — its output
was identical whether it worked or not.

Adjacent, and the reason this is worth writing down rather than filing as four
fixes: #402's runner had been dead for four occurrences across three issues for
exactly this reason, and #284 before it.

## What to add to CLAUDE.md

A short section under the testing rules, saying the thing the two existing
sentences do not:

1. **Assert the exact quantity when it is knowable.** `sites == len(_MARKERS)`
   fails when its subject moves; `sites >= 20` does not. Use a bound only when
   the true value legitimately varies, and say why in the message — the loose
   bound in `test_cascade_dispatch` (`<= 10`) has that justification written
   next to it.
2. **A comparison needs a discrimination check.** If a test compares two
   things, assert they are *capable* of differing. `test_ml3_fork_drift` now
   asserts each shared class really carries the implementation, precisely
   because "the two modules agree" became free.
3. **A guard that starts at zero needs a sabotage test.** Green and broken look
   identical. Both `check_docstrings` arms and the `NOT_EDGES`-style inventories
   now carry one.
4. **Name the subject, not a proxy for it.** A count standing in for "did X
   happen" decays the moment X's cost changes.

None of that is new practice here — every one of the four fixes above applied
it. It is not written down, so it gets rediscovered per incident.

## Not proposed

An automated check. "Is this assertion still capable of failing" is not
decidable, and mutation testing is the closest tool — which #324 is already
about, and which is out of `just ci` for cost reasons. This is a written rule
and a review question, which is what the two existing sentences are too.
