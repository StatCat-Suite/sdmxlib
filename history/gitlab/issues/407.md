# Issue #407: Codelist and DataStructure have no ref_to — #404's constructive half, so every 3.0 Hierarchy author builds item URNs by hand

| | |
| --- | --- |
| State | closed |
| Opened | 2026-09-28 |
| Closed | 2026-09-28 |
| Labels | `api`, `enhancement`, `model`, `usability` |

#404 and #405 fixed the *consuming* side of item references: `validate_references`
now resolves them, and the readers index every item kind, so `node.code()` on a
parsed `Hierarchy` hands back the `Code`. Thank you — deleting that workaround
took 79 lines out of a downstream project.

The *producing* side has no equivalent. `ConceptScheme.ref_to(concept_id)` builds
an item `Ref`; `Codelist` and `DataStructure` have no counterpart, and `Ref.to`
refuses items by design. So anyone **authoring** a 3.0 `Hierarchy` assembles the
URN by hand.

## Repro

```python
import sdmxlib as sl

A, V = "AGENCY", "1.0.0"
cs = sl.ConceptScheme(id="CS", maintainer=A, version=V, name={"en": "Concepts"},
                      concepts=[sl.Concept(id="AREA", name={"en": "Area"})])
cl = sl.Codelist(id="CL_AREA", maintainer=A, version=V, name={"en": "Area"},
                 codes=[sl.Code(id="CA", name={"en": "Canada"})])
dsd = sl.DataStructure(id="DSD", maintainer=A, version=V, name={"en": "DSD"},
                       dimensions=[sl.Dimension(id="AREA", concept=cs.ref_to("AREA"))])

cs.ref_to("AREA")                 # Ref(CS → resolved)
hasattr(cl, "ref_to")             # False
hasattr(dsd, "ref_to")            # False
sl.Ref.to(cl.codes["CA"])         # TypeError
```

```
TypeError: Ref.to expects a MaintainableArtefact, got Code. Child items
(Dimension, Code, Concept, ...) are not maintainable — build the URN with
SdmxUrn.make(...) and pass it to Ref.unresolved(urn) or Ref.of(urn, obj).
```

The error message is clear and correct, and it is the right refusal — a `Code`
is not maintainable. The gap is that it has nowhere to send you except the raw
constructor:

```python
sl.SdmxUrn.make(sl.Code, package=sl.Code.sdmx_package, artefact_class=sl.Code.sdmx_class,
                agency=cl.agency_id, id=cl.id, version=cl.version, item_id="CA")
sl.SdmxUrn.make(sl.Dimension, package=sl.Dimension.sdmx_package, artefact_class=sl.Dimension.sdmx_class,
                agency=dsd.agency_id, id=dsd.id, version=dsd.version, item_id="AREA")
```

Six keyword arguments, of which three restate the parent artefact and two
restate the item class. Every one is an opportunity to pass the *wrong*
parent's agency or version and produce a URN that names an artefact which does
not exist — and since #404 landed, `validate_references` will now correctly
report that as broken, which is a better failure than before but still a
failure that a builder would have made unreachable.

## Why this is not a corner

A 3.0 `Hierarchy` cannot be constructed without it. Both of these are the
documented shape of the artefact, not an exotic usage:

| Field | Target | Required by |
| --- | --- | --- |
| `HierarchicalCode.code` | `Code` | every node of every `Hierarchy` |
| `HierarchyAssociation.linked_object` | `Dimension` | every binding of a hierarchy to what it organises |

`Categorisation.target` → `Category` is the same shape and predates 3.0.

## Suggested fix

Mirror `ConceptScheme.ref_to` on the other item-bearing schemes:

```python
cl.ref_to("CA")            # Ref[Code]
dsd.ref_to("AREA")         # Ref[Dimension] — dispatch on where the id is found
cat_scheme.ref_to("X")     # Ref[Category]
```

`DataStructure` is the interesting one: `dimensions`, `measures` and
`attributes` are three item lists under one maintainable, so either it
dispatches on which list holds the id (and raises on an id in none, or in more
than one), or it takes an explicit role — `dsd.ref_to("AREA", role=sl.Dimension)`.
Dispatch reads better at the call site; an explicit role is unambiguous. I have
no strong preference, but the ambiguity is worth settling before the signature
ships.

The same table #404's fix already needed — class, package, item class, accessor
— should be able to drive this, so the two can share one source of truth rather
than drifting.

## Workaround

Two functions, ~60 lines with docstrings, wrapping `SdmxUrn.make` and deriving
agency and version from the parent artefact so a URN cannot disagree with the
thing it names. Carried downstream as `urns.py`.

## Related

- #404 — item URNs in `validate_references`. Fixed; this is its constructive half.
- #405 — readers indexing item kinds. Fixed.
