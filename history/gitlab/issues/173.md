**Tier 3 — structural / experimental.** From the `Any` audit (★1, the one real
variance issue).

`Ref[T]` is **invariant** because `_resolved: T | None` is a public mutable
`T`-slot (the registry writes it in place). Invariance means `Ref[Codelist]` is
not a `Ref[object]`, so `Ref[object]` can't be the common supertype of all refs
— which forces `AnyRef = Ref[Any]` (`model/ref.py:216`) to recover bivariance.
It ripples into the heterogeneous stores (see T1 store issue, `_refs`).

**Proposed fix — make `Ref` covariant:**
- Back `_resolved` (and `_urn`) with **`object`-typed private fields** (registry
  already reaches through `# noqa: SLF001`).
- Surface `T` only in output positions: `urn` as a read-only `@property ->
  SdmxUrn[T]`, `__call__ -> T`, and factories `unresolved[U]/of[U]/to[U]` using
  **method-scoped** typevars (a covariant class typevar can't sit in factory
  inputs).
- Declare `class Ref[T_co]` (covariant). Isolate the one unsafe `object -> T`
  narrowing to `__call__`.

Then `Ref[Codelist]` **is** a `Ref[object]` and most `AnyRef`/`Ref[Any]`/casts
collapse to the checked `Ref[object]`.

**Deliverable (this issue is a spike):** prototype on a branch; **count** how
many `Ref[Any]`/`AnyRef`/`# type: ignore` actually collapse and whether any new
ignores appear. Decide from that data whether to land it. Honest caveat: at
parse-boundary reader sites the values are genuinely type-unknown, so they only
improve `Any -> object` (checked but still erased); the real win is at sites that
hold a `Ref[Subtype]` and currently widen.

**Risk:** high — core type with heavy test coverage. Measure before committing.
**Related:** enables narrowing `_refs: dict[str, AnyRef]` -> `dict[str, Ref[object]]`.
