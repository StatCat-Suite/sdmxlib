# Issue #119: perf: Component.codelist property chain ~35 ns per resolve

## Context

Surfaced by Phase 3 bench (MR !81). \`test_nav_codelist_resolve\` measures 66 ns per \`dim.codelist\` access vs 31 ns for the equivalent \`cl_by_dim_id[dim_id]\` direct dict — a **2.1× overhead** even after the Ref is resolved and interned.

The chain (\`src/sdmxlib/model/datastructure.py:128-139\` + \`src/sdmxlib/model/ref.py:89\`):

\`\`\`python
# Component.codelist
@property
def codelist(self) -> Codelist:
    representation = self.representation
    if not isinstance(representation, Ref):
        msg = f\"Representation is not a codelist reference: ...\"
        raise TypeError(msg)
    return representation()

# Ref.__call__
def __call__(self) -> T:
    if self._resolved is None:
        raise UnresolvedRef(self.urn)
    return self._resolved
\`\`\`

Per access: property descriptor + attribute read + isinstance check + method call + attribute read + None check + return. ~35 ns of pure Python interpreter overhead atop the dict lookup.

## Why this matters

The \`Component.codelist\` accessor is the canonical \"give me the codelist for this dim\" call site. It's invoked once per dimension in every walk, every \`code_map\` build, every \`column_labels\` build. \`dsd.all_codelists\` calls it once per dimension/attribute/measure.

At thousands of resolves per request (large DSDs, batch processing) this adds up to single-digit-millisecond overhead vs a flat dict.

## Proposed fix

**Slot-cache the resolved codelist on the Component instance** on first access.

\`\`\`python
# in Component / RepresentationMixin
__slots__ = (..., \"_codelist_cache\")

@property
def codelist(self) -> Codelist:
    cached = getattr(self, \"_codelist_cache\", None)
    if cached is not None:
        return cached
    representation = self.representation
    if not isinstance(representation, Ref):
        raise TypeError(...)
    cl = representation()
    self._codelist_cache = cl
    return cl
\`\`\`

Safe because:
- Components are \`@define\` attrs classes; \`representation\` doesn't change after construction.
- The cached codelist is whatever the Ref resolved to; if Ref state ever flips back to unresolved we'd need invalidation — but that doesn't happen in current code.

Invalidation hook needed if the Ref-replacement path in InMemoryRegistry (\`_walk_refs\`) ever swaps in a different resolved object. Worth adding a test.

## Estimated impact

- Per-access: 66 ns → ~35 ns once cached (matches direct dict).
- \`dsd.code_map\` on the 10×200 DSD: shave 100-200 ns × 10 dims = 1-2 µs off.
- Compounded with #118 (ItemList dispatch): full nav walk-all-codes should approach 1.5× tax instead of 5.8×.

## Acceptance

- \`just bench\` shows \`test_nav_codelist_resolve\` measurably faster.
- \`test_nav_walk_all_codes\` tax drops.
- No semantic change to \`dim.codelist\` raising \`UnresolvedRef\` / \`TypeError\` for the unresolved or non-Ref cases.
- New test asserting cache invalidation if/when \`representation\` is reassigned (or guard: assert attrs-frozen post-init).
