# Issue #422: SDMX 3.x content the model cannot hold is dropped silently on read

| | |

## Summary

A 3.x-native model has to be able to **hold** everything a 3.x document
carries. These 3.x constructs have no field or type in the model, so a
3.x → model → 3.x round trip loses them. Readers are tolerant, so the loss
is **silent**.

Checked against `main` @ `6cf7bc5` (model classes and attrs fields) and
the SDMX-ML 3.0 XSDs.

| 3.x construct | model today | loss on read |
|---|---|---|
| `AnnotationURL`: repeatable and localised (`xml:lang`) | `Annotation.url: str \| None` | all but one URL, and every language |
| `ValueList` (maintainable; values need not be IDs) | no type | whole artefact |
| `GeographicCodelist`, `GeoGridCodelist` (`GeoFeatureSetCode`, `GeoGridCode`) | no type | whole artefact |
| `MetadataConstraint` | no type | whole artefact |
| `Link` on identifiables | no field | all links |
| `ComponentMap` N:M (repeatable `Source` / `Target`) | `source_id`, `target_id` (1:1) | every component past the first |
| `CubeRegion` / `KeyValue` validity (`validFrom` / `validTo`) | `CubeRegion(include, keys)`, `KeyValue(dimension_id, values)` | time-bounded constraint values |
| `SentinelValue` on text formats | no `Facet` field | sentinel definitions |
| `minOccurs` / `maxOccurs` on DSD `Attribute` / `Measure` (multi-valued) | only on `MetadataAttribute` | multiplicity |
| `MeasureRelationship` on attributes | no field | the attachment to measures |
| `MetadataAttributeUsage` in a DSD (DSD → MSD link) | no field | DSD-level metadata attributes |
| `TimeDimension` / `Dimension` `@position` | no field | explicit position |
| wildcarded or ranged version references (`1.0+`, `*`) | `SdmxUrn` has the `"latest"` sentinel only | the range; a reader either fails or pins it |

Each row needs one decision: **model it**, or **refuse it on read with a
clear error**. A tolerant reader that drops silently is the one outcome
to rule out. The `gaps.py` register is write-side only. Proposal: give it
a read-side twin (`ReadGap`, declared per construct) so a
`parse(..., strict=True)` can refuse, and the default read can report.

## Not modelled in either version (context, not in scope)

`Process` (#361), `ReportingTaxonomy`, `DataConsumerScheme`,
`OrganisationUnitScheme`, and the VTL family (`TransformationScheme`,
`VtlMappingScheme`, `NamePersonalisationScheme`, `RulesetScheme`,
`UserDefinedOperatorScheme`, `CustomTypeScheme`). Whether a reader fails or
skips on these should be pinned by a test either way.

Tracking: #423

## Comments

### 2026-10-09

## Registry sweep: confirmations and two corrections (!516)

Confirmed on live data, with counts:

- `MetadataAttributeUsage`: 4,176 (IMF)
- `HierarchicalCode/Level`: 12,279 (IMF)
- `Link`: 37 (BIS)
- `MeasureRelationship`: BIS 91, FMR 124
- wildcard references: IMF throughout (`(1.0+.0)`). Writing them invalid in 2.1 is #429.
- `DataConsumerScheme`: read as no artefacts at all, with no error (FMR). The "pin it by a test" note above applies.

**Corrections to !516's baseline.** None of these were losses:

- Every MSD `@maxOccurs` and DSD `Measure/@usage` reported lost was the XSD default (`1`, `optional`).
- IMF's 26,823 code `AnnotationText`s and Eurostat's ~830,000 `AnnotationURL`s were empty elements.

The census now counts these attributes by value and empty elements apart (`m20/sweep-defaults`). So **`minOccurs`/`maxOccurs` on MSD attributes is not a confirmed row**. The row for DSD `Attribute`/`Measure` multiplicity still stands.

Related, and new: #436. Readers drop elements they do not expect, which is the same silent-loss mechanism for content the model *could* hold.

### 2026-10-14

Fixed on the milestone branch `feature/m20-3x-native`; the code reaches `main` with the milestone MR. Closed now so the milestone page shows it as completed — `status::started` marks it as fixed on the branch rather than on `main`.
