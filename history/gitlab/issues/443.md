# Issue #443: LazyHierarchy.materialize() drops every node's annotations

## Summary

`LocalRegistry.get(h.urn)` returns a `LazyHierarchy`. Its `materialize()` builds each `HierarchicalCode` without `annotations`, so every node comes back with none. `get(h.urn, eager=True)` and the `q.hcode` collect both carry them, so the three ways out of the store disagree.

Measured on `tests/support/maximal.py`'s hierarchy: eager, 1 annotation on the node; `materialize()`, 0.

## Where

`storage/lazy.py`, `LazyHierarchy.materialize()` (around line 1120). The node rows it reads carry no annotation lookup, and `HierarchicalCode(...)` is built without `annotations=`. The hierarchy's own annotations are kept (`annotations=self.annotations`); only the nodes' are lost.

## Why the census did not see it

`tests/unit/test_store_round_trip.py` (#437) reads back with `get(eager=True)`. Found while fixing #442, whose tests cover lazy reads of `uri` but not of node annotations.

## Fix direction

Read node annotations the way `resolve.resolve_hcode_keys` does: one `annotations_for_urns` over the node URNs. Guard it by running the store census over the lazy `materialize()` path as well as eager, so lazy and eager are held to the same register. Mind the bundle tier's `q.hcode` call budget; `materialize()` is the FED-hierarchy hot path its comments describe.
