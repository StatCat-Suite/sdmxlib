**Phase 3** — depends on #test-1 (shared factories: strategies replace ad-hoc builders).

Hypothesis is not in the dev group yet. This issue adds it and builds the strategy layer everything else in phase 3 stands on. It should land with a *small* number of properties — enough to prove the setup — not a sweep.

## Why this codebase suits property testing unusually well

- **38 of 94** unit-test files already hand-roll a round-trip. Round-trip is the canonical property; we are writing them one example at a time.
- Only **5 of 94** files use mocks. Properties need real objects, and that is already how the suite is built.
- The domain has genuine algebraic structure: URNs parse/format, versions order, `InternationalString` splits and rejoins, collections index and filter.
- Only **20 of 94** files use `parametrize`, so example-diversity today comes from hand-picked fixtures.

## Scope

**1. Dependency + profiles.** `hypothesis` in the dev group with an upper bound (CLAUDE.md's checker-pinning rationale applies: unbounded floors let a release land in CI with no commit of ours in between).

Three profiles. Example count is deliberately **not** rationed — measured, 25 -> 100 examples costs 0.28 s on the heaviest property, against a pipeline that spends a minute on `uv sync`. Rationing exploration for that is false economy, and local runs have no constraint at all.

- `dev` — local default, Hypothesis's own example count; tuned for inner-loop feedback.
- `ci` — same exploration as `dev`, plus `derandomize=True`. That is the one real difference and it is about reproducibility, not thrift: `.hypothesis/` is gitignored and absent in CI, so a failure must reproduce from the report alone.
- `deep` — 20x the examples for deliberate hunting. `HYPOTHESIS_PROFILE=deep just test`, or `just test-properties`.

`.hypothesis/` goes in `.gitignore`. Any failing example Hypothesis finds gets pinned as an explicit `@example(...)` so the regression is reproducible without the database.

**2. `tests/support/strategies.py`** — composite strategies built on #test-1's factories:

- `sdmx_ids()` / `agency_ids()` / `versions()` — drawn from the *actual* patterns in `model/validation.py`, not invented. This is the highest-value piece: it makes the validation regexes and the strategies agree by construction, and any disagreement is a finding.
- `international_strings()` — including the empty case and multi-language maps. Language tags should include the awkward real ones already in our fixtures (`pt-BR`, `zh-Hans`, `es-419`).
- `codes()` / `codelists()` — with and without hierarchy (`parent_id`), since parent/child cycles are a real invariant.
- `facets()` — all 11 bounds, which is exactly the surface the `write_text_format` table refactor touched.
- `annotations()`, `concepts()`, `concept_schemes()`, `data_structures()`.

**3. A first, deliberately small set of properties** on pure value types:

- `SdmxUrn.parse(str(u)) == u` for every generated URN (`model/urn.py` is 100% line-covered — this asks whether that means anything).
- `InternationalString`: `ingest_istr(*emit_istr(s))` preserves the map; `emit_pair()` on empty returns `(None, None)`.
- Version ordering is a total order: irreflexive, antisymmetric, transitive.
- `ItemList` / `ArtefactList`: indexing agrees with iteration; `filter` never yields an element the predicate rejects; `partition` produces two disjoint halves whose union is the input.

## Explicitly not in scope

Serializer round-trips (#test-6) and query-DSL differential testing (#test-7). Those are where the value is, and both need this layer to exist first.

## Risks to watch

- **Strategies that mirror the implementation.** If `sdmx_ids()` is derived from the same regex `validation.py` enforces, a property asserting "generated ids validate" is circular. Derive the strategy from the *spec*, and treat any generated-but-rejected id as a question about which one is wrong.
- **Slow strategies.** Building a full `DataStructure` per example will dominate runtime. Keep the heavy strategies for #test-6 and measure.

## Test gates

- `just test` runtime increase recorded and under a stated budget.
- Both profiles exercised; the `ci` profile's runtime reported explicitly.
- Any bug found gets a pinned `@example` and its own issue.
