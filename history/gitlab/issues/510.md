# Issue #510: A predicate over another relation is accepted when both read the same table, and answers silently

| | |
| --- | --- |
| State | closed |
| Opened | 2026-10-20 |
| Closed | 2026-10-20 |
| Milestone | %26 Found by the docs audit: correctness and refusals |
| Labels | `bug`, `dsl`, `priority::high` |

The runtime root check compares *tables*, not relations. A predicate over another relation is accepted whenever the two relations read the same table, and it **silently answers a different question**:

```python
reg.query(sl.q.dataflow).filter(sl.q.codelist.agency == "ZZ").ids()
# ['F']  — the dataflow F whose agency is ZZ; the codelist predicate was read as a dataflow one
```

Every maintainable root reads `sdmx.artefact`, so `q.dataflow`, `q.codelist`, `q.dsd` and the others are interchangeable to this check. The type checker catches it (`Pred[R]`), but untyped code, notebooks and agents don't run one.

**Fix:** compare the predicate's root accessor (its row kind) with the query's, not the underlying table. Refuse with a message naming both relations. Add a property over every pair of roots sharing a table.
