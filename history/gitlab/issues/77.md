## Goal

Capture pre-fix performance numbers as committed baselines, so the per-call-cursor + FIFO-cache refactor can be measured against something durable. Required before any code change in the next issue.

## Tasks

- [ ] Create `bench/` layout (or extend existing — confirm before starting) with a `pytest-benchmark`-style or standalone script.
- [ ] Workloads to baseline (against v0.27.2):
  - Single-threaded `reg.get(dataflow_urn)` — 10k iterations, cold + warm cache.
  - Single-threaded `reg.get(codelist_urn, eager=True)` — 10k iterations.
  - Single-threaded `reg.code_map(...)` — 1k iterations.
  - Concurrent (ThreadPoolExecutor, 1/4/8/16 workers) — mixed `get` workload, ops/sec.
  - **Cache-hit hot loop** — 32 threads × 1000 reads of the *same* URN. This is the workload the FIFO change is meant to keep lock-free; we want a precise pre-change number to compare against.
- [ ] Commit baseline numbers to `bench/baselines.json` (median + p99 per workload).
- [ ] Bench harness should print delta-vs-baseline in output but **not fail CI** on regression — surface it, don't gate on it. Updating baselines is an explicit `just bench-update` step (so any regression is a conscious decision, not silent drift).

## Acceptance

- Baselines committed and reproducible (`just bench` runs locally without flake — document any required test data setup).
- Numbers for all workloads above present in `bench/baselines.json`.

## Out of scope

- Any code change to the library. Pure measurement.
