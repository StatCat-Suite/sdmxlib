# Issue #491: A data constraint holds cube regions or key sets, not both (IM §12.3.3.1); nothing checks it

| | |
| --- | --- |
| State | closed |

Found by the FMR oracle (#457), and missed by the IM rule census (#456) because the sentence carries no strong marker.

SDMX 3.1 Section 2, §12.3.3.1 p. 127: *"A DataConstraint has a choice of two ways of specifying value subsets"* -- data key sets, or cube regions. The XSDs do not enforce the choice (both elements are in a sequence), our model allows both on one constraint, and nothing refuses it.

FMR 12.4.2 does: *"For maintenance purposes the Fusion Registry will not allow a Constraint to contain both Cube Regions and Series Restrictions"*. The maximal fixture carries both; the oracle's ledger records it as a `registry-rule`.

Decide: a validation check (and a census row owning the sentence), or a declared non-check -- the IM states it, the schemas do not.
