3.1 model audit follow-up (post-MR !63).

## Semantic gap

3.1 \`LevelType\` carries an optional \`CodingFormat\` element (type \`CodingTextFormatType\`, a restriction of \`SimpleComponentTextFormatType\`). It encodes character / length constraints that codes at this level must follow — e.g. \"ISO-3166-2 subdivision codes are 1–3 alphanumeric chars\".

We already have a \`Facet\` type in \`model/representation.py\` covering the same kind of constraint (text type, max length, pattern, etc.) for component representations. Reusing it on \`Level\` keeps the API surface small.

## Action

Add \`coding_format: Facet | None = None\` to \`Level\` in \`src/sdmxlib/model/hierarchy.py\`. The 3.1 writer (when added) emits it as \`<str:CodingFormat>\`; reader populates it.

## Notes

The \"recursive Level\" XSD shape (\`<Level><Level>\`) is a syntax-only encoding of the level chain. Our existing \`ItemList[Level]\` already captures the chain semantically. **Don't** introduce \`Level.child: Level\` — that would conflate XSD syntax with the domain model.
