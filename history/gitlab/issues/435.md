## Summary

The readers' unit of failure is the **document**. One artefact the reader refuses takes every other artefact in the message with it.

Found by the registry sweep (!516): registry.sdmx.org's 3.0 `datastructure` document (the reference FMR) fails to parse as a whole: `SdmxConformanceError: <Enumeration>: schema requires a Codelist reference here, but the URN names a ConceptScheme`. All **23** DSDs are lost for 3 bad ones.

## What is in the document

`UNSD:IMTS(1.2)`, `UNSD:IMTS_AGGREGATES(1.2)` and `UNSD:IMTS_COMPACT(1.2)` each have a `<str:Dimension id="MEASURE">` enumerated by `ConceptScheme=UNSD:CS_MEASURE(1.0)`, whose own `@urn` says `datastructure.Measure=…`: a 2.1 `MeasureDimension` down-converted into a 3.0 document that has none. The document is XSD-invalid (6 errors, all on these three components), so refusing them is right.

Raised at `_v3_reader.py:294` → `read_representation` → `_common.py:535 resolve_ref` → `_checked :370` → `_require_urn_class :161-176`. Nothing between there and the document catches it.

## Fix direction

- Catch per maintainable in each top-level artefact loop, and return the good artefacts plus a structured list of the refused ones (URN + error), or make the whole-document failure an opt-in strict mode.
- Do not reify the bad dimension: `Dimension.representation` cannot hold a `Ref[ConceptScheme]`. An explicit, named compat reading of this FMR pattern as a 3.0 measure is a separate maintainer decision.

The refusal list is the natural home for the closed-world reporting of #436, and for #422's proposed `ReadGap` reporting.
