3.1 model audit follow-up (post-MR !63).

## Semantic gap

SDMX 3.1 \`HierarchyType\` carries a required \`@hasFormalLevels\` boolean that distinguishes two semantically different structures:

- **Leveled hierarchy** (\`true\`): every code lives in exactly one named level. Levels form a depth-ordered chain. E.g. ISO geography \"continent → country → region → locality\".
- **Value-based hierarchy** (\`false\`): codes form a tree without a level concept. E.g. a topical subject taxonomy.

Our \`Hierarchy\` model currently exposes \`is_leveled: bool\` as a derived property: \`len(self.levels) > 0\`. That's not quite the same — a hierarchy can declare levels but not bind codes to them, in which case the declaration is metadata only and the structure is still value-based.

## Action

Add \`has_formal_levels: bool = False\` as an explicit field on \`Hierarchy\`. Mark \`is_leveled\` as either deprecated or as a convenience alias.
