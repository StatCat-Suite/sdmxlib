# Issue #437: LocalRegistry drops DataConstraint data_keys, empty KeyValues and key order

## Summary

`LocalRegistry` loses parts of a `DataConstraint` on `add` → `get`:

| lost | where seen (sweep, !516) |
|---|---|
| `data_keys`: all of them | ECB **84** constraints (e.g. `ECB.DISS:BKN_PUB_CONSTRAINTS(1.0)`: 406 → 0), FMR 2 (`IAEG-SDGs:CN_SERIES_SDG_GLC(1.26)`: 4,039 → 0) |
| a `KeyValue` with no values | OECD **1,453** (`ESTAT:CR_A_SEEA_AEA_A(1.4)`: 13 keys → 12) |
| key order within a region | not guaranteed |

## Root cause

- `data_keys`: no table. `put_data_constraint` (`storage/writers.py:1234-1300`) writes the spine, `data_constraint`, `cube_region` and `region_key_value`; `storage/schema.py:653-695` has nothing for data keys; `_read_data_constraint` (`storage/readers.py:918-928`) never passes `data_keys=`.
- Empty `KeyValue`: `writers.py:1293` writes one `region_key_value` row per **value**, so a key with none writes nothing, and the reader rebuilds keys from those rows (`readers.py:905-915`). The empty key exists because the reader dropped its `TimeRange` (#433), but the store should not compound it.
- Order: `region_key_value` has no position column and the reader no `ORDER BY`.

## Fix direction

- `data_key(constraint_urn, key_idx, include)` + `data_key_value(constraint_urn, key_idx, position, component_id, value)`, in the cascade delete (`writers.py:599`) and the reader.
- Store keys separately from their values (`region_key(constraint_urn, region_idx, position, component_id)`), so an empty key and the order both survive.
