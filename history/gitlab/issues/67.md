# Issue #67: _delete_artefact_cascade missing DELETE on hierarchy_level → PK violation re-adding a Hierarchy

| | |
| --- | --- |
| State | closed |
| Opened | 2026-05-05 |
| Closed | 2026-05-05 |

## Summary

`LocalRegistry.add(hierarchy)` is documented as "Add or replace" but the second call for the same Hierarchy URN raises a `ConstraintException` on the `hierarchy_level` primary key. `_delete_artefact_cascade()` clears `hierarchy_meta` and `hierarchy_node` rows but **not** `hierarchy_level`, so re-running ingest (or any code that re-adds an existing Hierarchy) fails after a single retry.

## Repro

```python
import sdmxlib as sl, tempfile
from pathlib import Path

ag = sl.Agency(id="STC_CP")
lvl = sl.Level(id="Universe", name={"en": "Universe"})
h = sl.Hierarchy(
    id="H_TEST",
    maintainer=ag,
    version="1.0",
    name={"en": "Test"},
    levels=[lvl],
    tree=[sl.HierarchicalCode(id="ROOT", code=None, level=lvl)],
)

with tempfile.TemporaryDirectory() as tmp:
    db = Path(tmp) / "t.duckdb"
    with sl.LocalRegistry(db) as reg:
        reg.add(h)        # ok
        reg.add(h)        # ConstraintException
```

Result (sdmxlib 0.19.1, DuckDB-backed registry):

```
ConstraintException: Constraint Error: Duplicate key
"hierarchy_urn: urn:sdmx:org.sdmx.infomodel.codelist.Hierarchy=STC_CP:H_TEST(1.0),
 level_id: Universe" violates primary key constraint.
```

In our case the symptom appears during `census-load` re-runs: H_CP_TOPIC persists fine the first time, a downstream step crashes, and the second attempt at `census-load` (or even the second hierarchy persisted in the same run, when two hierarchies share a Level id collision after a partial earlier write) fails on PK.

## Root cause

`storage/writers.py:_delete_artefact_cascade()` (~line 377) deletes from `hierarchy_node` and `hierarchy_meta` but skips `hierarchy_level`:

```python
conn.execute("DELETE FROM hierarchy_node WHERE hierarchy_urn = ?", p)
...
conn.execute("DELETE FROM hierarchy_meta WHERE urn = ?", p)
```

`put_hierarchy()` calls `_delete_artefact_cascade()` first and then INSERTs new Level rows, so leftover Level rows from the previous version of the same hierarchy collide on the (`hierarchy_urn`, `level_id`) PK.

## Suggested fix

One additional line in `_delete_artefact_cascade()`:

```python
conn.execute("DELETE FROM hierarchy_level WHERE hierarchy_urn = ?", p)
```

Either next to the `hierarchy_node` delete (item tables) or next to the `hierarchy_meta` delete — both make sense semantically.

## Manual workaround

Until the fix lands, callers can clear the rows themselves before re-adding:

```python
import duckdb
conn = duckdb.connect("path/to.duckdb")
for t in ("hierarchy_node", "hierarchy_level", "hierarchy_meta"):
    conn.execute(f"DELETE FROM sdmx.{t}")
```

## Environment

- sdmxlib 0.19.1
- DuckDB (whatever sdmxlib pins)
- Python 3.13
- macOS
