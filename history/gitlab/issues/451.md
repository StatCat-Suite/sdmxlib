# Issue #451: SDMX-JSON writes a wildcarded codelist-extension member value its schema rejects

SDMX-ML 3.x types a codelist extension's member value as `WildcardedMemberValueType`: an id that may hold `%` (pattern `[A-Za-z0-9_@$-%]+`). SDMX-JSON 2.0 and 2.1 type `memberValues` as `MemberValueType`, which is a plain `idType` (or `{value: idType, cascadeValues}`), so a `%` value has no JSON form.

The JSON writer emits it anyway. The output fails the SDMX-JSON schema (found in #421: `/data/geographicCodelists/0/codelistExtensions/0/exclusiveCodeSelection/memberValues/0: '%' is not valid under any of the given schemas`), and `gaps.py` declares nothing.

Fix: refuse a wildcarded member value for the `json` target in `check_serialisable`, or declare it if there is a lossless alternative (there is none in the schema), with a `test_sdmx_json_*` case.
