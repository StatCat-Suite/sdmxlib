## Comments

### 2026-10-20

**Decisions (2026-10-20):**

1. **Warnings use `warnings.warn` with a library category, `sl.SdmxWarning`, subclassed per rule family.** Since #492, rules run when an artefact is built, and a constructor cannot return a list of issues. So `warnings` is the only channel that works where the rules live. Callers can filter it, and `warnings.simplefilter("error", sl.SdmxWarning)` (or pytest's `-W error::…`) makes it strict. `ValidationIssue.severity` is removed: a warning never becomes an issue.
2. **The tier.** A rule the IM states but no wire schema enforces **warns**: #482's facet sequence rules, #491's constraint holding both cube regions and key sets, and #455's side-by-side levels. A rule the schemas enforce **refuses**, as today. So nothing that builds today starts failing because of these rules.
3. **`parse(lossless=True)` does not promote warnings.** `lossless` asks whether anything in the document was dropped or invented. Whether its content breaks an IM rule is a separate question, and the caller's warning filter governs that.

Open for the implementation: whether `storage/writers.py`'s one existing `RuntimeWarning` (two sources writing the same URN) moves under `SdmxWarning`.
