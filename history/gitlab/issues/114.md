# Issue #114: model: add is_final to Dataflow, CategoryScheme, Categorisation, ConceptScheme, StructureMap

| | |
| --- | --- |
| State | closed |
| Opened | 2026-05-31 |
| Closed | 2026-05-31 |
| Milestone | %5 xsd-coverage-followups |

Surfaced while implementing #113. The \`is_final\` field is missing from five \`MaintainableArtefact\` subclasses despite being valid for them in the 2.1 XSD's \`MaintainableType\`. This is the same gap #112 caught for \`ProvisionAgreement\`, just wider.

## Missing

- \`Dataflow\`
- \`CategoryScheme\`
- \`Categorisation\`
- \`ConceptScheme\`
- \`StructureMap\`

## Have it correctly

- \`Codelist\`, \`DataStructure\`, \`AgencyScheme\`, \`DataProviderScheme\`, \`DataConstraint\`, \`Hierarchy\`, \`MetadataStructure\`, \`Metadataflow\`, \`MetadataSet\`, \`ProvisionAgreement\`, \`RepresentationMap\`, \`ConceptSchemeMap\`, \`CategorySchemeMap\`.

## Action

Add \`is_final: bool = False\` to each. Same 2.1-only semantics as #112 — 3.0 / 3.1 \`MaintainableType\` drops the attribute, so 3.0 / 3.1 serializers ignore the field.

## Done when

- [ ] All five classes carry the field.
- [ ] 2.1 round-trip preserves it (writer already emits via \`_write_maintainable_attrs\`; verify no regressions).
- [ ] No new public-API exports needed.
