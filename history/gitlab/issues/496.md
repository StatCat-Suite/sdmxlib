# Issue #496: SDMX-JSON schema guards never check formats; our output has date and date-time violations

## Problem

**Our SDMX-JSON schema guards check structure but never formats.** `jsonschema` checks `"format": "date-time"` only when a format library such as `rfc3339-validator` is installed. Nothing in the dev environment installs one, so every `date-time`, `date` and `uri` in our JSON output has gone unchecked.

Formats were checked once by accident. Installing pysdmx's `json` extra (in the `bench-compete` group) pulled in `rfc3339-validator`, and `just ci` then failed 1,679 tests. 1,670 of them were in `test_json_read_assumptions.py`, which decides whether a key is "required" by validating the document with that key removed. With formats checked, `maximal`'s JSON is invalid before anything is removed, so every key read as required. All 1,679 trace back to these violations:

| where | written | the schema wants |
| --- | --- | --- |
| item maps' `validFrom`/`validTo` (concept and organisation scheme maps) | `'2020-01-01'`, a date | `date-time` |
| representation mappings' `validFrom`/`validTo` | a date | `date-time` |
| cube-region time ranges (`startPeriod`, `beforePeriod`, …) | `'2020-01-01T00:00:00'`, no zone | not valid under any branch |
| data messages' observation time `start`/`end` | `'2021-01-01T00:00:00'`, no zone | `date-time` |
| data messages' `meta.prepared` | the caller's value, with no zone in our tests | `date-time` |
| structure and metadata `meta.prepared` | no zone | `date-time` (fixed in !636) |

There is also a structural one under the 2.1 schema: `representationMaps` reports `representationMappings`, `source` and `target` as unevaluated properties. It needs checking whether 2.1 renamed them.

## Why it matters

These documents are not valid SDMX-JSON. pysdmx, validating, warns on the zoneless timestamps, and a strict consumer would refuse them. It went unseen because the guard that should have caught it could not.

## Proposal

1. **Make format checking unconditional:**
   - add `rfc3339-validator` (and whatever else `jsonschema`'s format checker needs for the formats the schemas use) to the dev group;
   - make `tests/support/json_schema.py` pass a `FormatChecker` explicitly;
   - **add a sabotage test** proving that a zoneless `date-time` fails validation, so the check cannot silently turn off again (CLAUDE.md: a guard that starts at zero needs a sabotage test).
2. **Fix each violation in the writers.** A date written where `date-time` is required gets midnight UTC; the model may hold a date or a date-time, so this needs reading per field. Zoneless timestamps get their zone. A data message's `prepared` should be validated or given a zone where the caller supplies it.
3. **Then** land the `bench-compete` group's `pysdmx[xml,json]` (branch `chore/bench-compete-json`). Until the violations are fixed, that change turns `just ci` red for anyone who has run `just bench-compete`, since the extra installs `rfc3339-validator` into the project environment.

Found by #458's SDMX-JSON writer installment (!636).
