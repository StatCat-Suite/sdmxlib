# Issue #355: Round-trip field losses found by the #354 census (~50 per format)

| | |
| --- | --- |
| State | closed |
| Opened | 2026-08-20 |
| Closed | 2026-08-20 |

`tests/unit/test_field_coverage.py` (landed with the #354 work) round-trips a
maximally-populated message and diffs every field. It found roughly fifty
losses per format. They are registered in `KNOWN_LOSSES` there, so nothing new
can slip in, but the register is **debt, not a baseline to live with** — each
entry is a field a caller can set and not get back.

This issue tracks working it down. Groups are in rough value order.

## 1. `HierarchicalCode.name` / `.description` — all four formats

A hierarchy node's own label, which is the main reason to give a node a name
instead of just referencing a code. Dropped by 2.1, 3.0, 3.1 and SDMX-JSON.
Highest-value fix in the list: it is user-facing text, and it is silent.

## 2. `ConstraintAttachment` — all four formats

The type carries four possible anchors and only `dataflow` survives. A
constraint attached to a DataStructure, ProvisionAgreement or DataProvider
comes back attached to nothing — which changes what the constraint *applies
to*, not merely how it is described.

## 3. Component relationships — all four formats

`Attribute.related_measure`, `Attribute.related_group`, `Group.uri`,
`Dataflow.dimension_constraint`, `Agency.parent`. The attribute relationships
are how a DSD says what an attribute attaches to, so losing them changes the
meaning of the structure.

## 4. `validFrom` / `validTo` on most maintainables — 3.0 / 3.1

Survives on a Codelist and is dropped on agency schemes, provider schemes,
all three map types, hierarchy associations, MSDs and metadataflows. The
attribute is on `MaintainableType`, so every one of these can carry it.

## 5. `is_final` — 2.1 and SDMX-JSON

A declared `gaps.py` limit for 3.0/3.1 (SDMX 3.0 removed it). But 2.1 and
SDMX-JSON *do* carry it and drop it for everything except `Codelist`, so those
are bugs rather than limits.

## 6. 2.1 annotation drift

The 2.1 writer has 23 `write_annotations` call sites to 3.0's 27 — the same
fork drift #346 fixed in the other direction. Missing on both scheme-map types,
`RepresentationMap`, `StructureMap`, `Hierarchy` and `HierarchicalCode`.

## 7. `MetadataStructure.targets` / `.report_structures` — 3.0 / 3.1 / JSON

Plus `MetadataAttribute.enumeration_format` and `.is_presentational` in 2.1.

## 8. Smaller / needs an XSD check first

* `Level.coding_format.min_value` / `max_value` — the 2.1 writer now emits
  them (that fix landed); no reader reads them back.
* `Level.coding_format.is_multilingual` — likely a genuine limit like
  `decimals` already is; confirm against `CodingTextFormatType` and move it to
  `gaps.py` if so.
* `DataConstraint.reference_period` — 3.0, 3.1, JSON.
* `Codelist.extensions`, `Measure.concept_role`, `HierarchyAssociation` as a
  whole, `Metadataflow.targets` — all 2.1, all probably genuine limits that
  belong in `gaps.py` rather than in a bug list. Each needs the XSD checked.
* `Category.uri` and `Level.uri` — SDMX-JSON only.
* `HierarchicalCode.level` back-reference — 2.1.

## Note on `gaps.py`

`TARGETS` has no `json` entry, so SDMX-JSON limits currently have nowhere to be
declared and sit in the test's register instead. Worth adding.

## How to work it

Fix a group, delete its lines from `KNOWN_LOSSES`, and the test tells you if you
deleted one you had not actually fixed — or fixed one you forgot to delete.
