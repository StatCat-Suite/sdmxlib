# Issue #366: SDMX-JSON data writer emits no value-level annotations, so Explorer cannot order values

| | |
| --- | --- |
| State | closed |
| Opened | 2026-08-21 |
| Closed | 2026-08-21 |

Split out of #365, where `order` was proposed as the companion fix to `parent` and turned out to be the wrong field.

## What Explorer actually reads

`value.order` is a legal property in the 1.0/2.0/2.1 data schemas, and **nothing consumes it**. `@sis-cc/dotstatsuite-components` takes its sort position from an annotation instead:

```js
// rules/src/get-values-enhanced.js
export const getOrder = (annotations = []) => {
  const orderAnnotation = R.find(R.propEq('ORDER', 'type'), annotations) || {};
  return Number(orderAnnotation.text || '-1');
};
```

which then feeds `__indexPosition`, the key both hierarchisation paths sort on:

```js
// rules2/src/hierarchiseDimensionWithNativeHierarchy2.js
const values = R.sortBy(R.prop('__indexPosition'), dimension.values || []);
```

The reference .Stat NSI emits **both** — a sample crs1 value is `{"id":"NGA","order":239,...,"annotations":[9]}` where annotation 9 is type `ORDER` — but only the annotation is read. Values with no `ORDER` annotation fall back to `-1`, i.e. all tie.

## What we emit

Neither. `_data_common.py` reads code annotations (for `duration`, see `_annotation_duration`) but never *writes* a value-level `annotations` array, and there is no message-level `annotations` block for those indices to point into.

So the whole annotation channel is missing, not just `ORDER`. That is the scope here: value entries need an `annotations: [i, ...]` array of indices into a message-level `annotations[]`, which is how the wire format models it.

## Scope note

Worth deciding whether this is `ORDER` specifically or the general channel. The general channel is the honest fix — annotations are how SDMX-JSON carries `NOT_DISPLAYED`, `DEFAULT`, `LAYOUT_ROW` and the rest, all of which Explorer reads (types seen in a real crs1 message: `COMP_RULE`, `DEFAULT`, `HIER_CONTEXT`, `LAYOUT_COLUMN`, `LAYOUT_ROW`, `LAYOUT_ROW_SECTION`, `NOT_DISPLAYED`, `NonProductionDataflow`, `ORDER`). Emitting only `ORDER` would leave the same shaped gap for the next one.

Not urgent: without it, values sort in first-seen order, which is deterministic but arbitrary.
