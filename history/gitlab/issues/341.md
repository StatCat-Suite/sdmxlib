# Issue #341: list()/unique() answer NULL for an empty fan-out where polars answers []

| | |
| --- | --- |
| State | closed |
| Opened | 2026-08-19 |
| Closed | 2026-08-20 |
| Labels | `design`, `dsl` |

Found while fixing #326, and **separate from it**. #326 was about whether a
null *inside* a group counts; this is about what a group with **no rows at
all** collects to.

```
codelist        unique()            n_unique()
CL_AREA         [None, 'W']         2          # #326, fixed
CL_EMPTY        None                0          # this issue
```

polars answers `[]` and `0`. We answer `NULL` and `0`, so
`len(unique()) == n_unique()` — the invariant #326 restored — needs `or []`
at the call site to hold for an empty group.

## It is already known, and already hedged

`tests/unit/test_query_select.py::test_a_parent_with_no_children_collects_to_empty_not_missing`
asserts:

```python
assert empty["codes"].to_list()[0] in ([], None)
```

Accepting either is what an undecided question looks like written down. The
test's *name* claims "empty not missing" while its assertion permits missing.

## Why it is not obviously a bug

`list()` over zero rows is `NULL` in SQL, and this language has generally
taken SQL's answer where SQL has one. But it has also taken polars' *names* —
`list`, `unique`, `n_unique`, `mean` — and #326 established that taking a name
without its semantics is the thing to avoid. `COALESCE(list(...), [])` is
cheap.

## Options

1. **`[]`, matching polars.** `COALESCE` at the three collect sites. The
   invariant then holds without a caller normalising, and "collects to empty
   not missing" becomes true rather than aspirational.
2. **Keep `NULL`, and say so.** Rename the test to what it checks, and
   document that an empty fan-out is `None` — distinguishable from a group
   that collected only nulls, which is `[None]`. That distinction is real and
   might be worth keeping.

Option 2 has a genuine argument option 1 does not answer: `None` and `[None]`
mean different things, and polars cannot express the difference.

## Acceptance

- one answer, asserted rather than hedged with `in ([], None)`
- `len(unique()) == n_unique()` holds for an empty group without a caller
  normalising, or the docs say why it does not
