**Phase 1 of the wire-conformance milestone.** Nothing is fixed here — the point is to make the whole gap visible and counted, so the later phases are measured rather than estimated.

## The invariant

For every artefact kind sdmxlib models, and every wire target (2.1, 3.0, 3.1, SDMX-JSON), `serialize` must either:

- produce a document that validates against the official schema, **or**
- raise `ValidationError` naming what cannot be represented.

Silently emitting an invalid document is the failure mode this milestone exists to remove. It is the worst of the three outcomes: the call succeeds, the bytes look plausible, and the first sign of trouble is a consumer rejecting the file — by which point sdmxlib is not in the stack trace.

## The test

A parametrised gate over `artefact kind × format`, built from a bare (minimally-populated) artefact of each kind:

```python
@pytest.mark.parametrize("fmt", _FORMAT_IDS)
@pytest.mark.parametrize("field", sorted(_BARE_ARTEFACTS))
def test_bare_artefact_is_valid_or_refused(field: str, fmt: str):
    msg = StructureMessage(**{field: [_BARE_ARTEFACTS[field]()]})
    try:
        serialize(msg, version=_WIRE_VERSION[fmt])
    except ValidationError:
        return                      # refused, with a reason — acceptable
    assert_schema_valid(fmt, msg)   # otherwise it must validate
```

Every currently-failing pair goes into a `KNOWN_INVALID` table with its schema error, exactly as `KNOWN_GAPS` works today. The table is the milestone's burn-down: each later issue removes entries, and the milestone closes when it is empty.

## Notes

- **Bare artefacts are the floor, not the ceiling.** This catches missing *required* children. Constraints on populated artefacts (uniqueness, attribute requirements) are phases 3–5.
- Do **not** fold this into the existing generative property. That one asserts round-trip fidelity of a *well-formed* artefact; this asserts the library never lies about a malformed one. Different question, different failure message.
