# Issue #103: 3.1 emission: Categorisation drops version attribute

Surfaced by the v3.1.0 XSD vendoring (MR !63) — \`tests/unit/test_xsd_schemas.py::test_minimal_30_diverges_from_31_on_known_attrs\`.

## What changed

SDMX 3.1 dropped the \`version\` attribute on \`Categorisation\`. The 3.1 schema rejects:

\`\`\`xml
<str:Categorisation agencyID=\"TEST\" id=\"CAT_DF_TEST\" version=\"1.0\">
\`\`\`

Categorisation now follows the AgencyScheme / DataProviderScheme sui-generis pattern — fixed identity per agency, never versioned.

## Action when adding 3.1 emission

- \`sdmx_ml31/writer.py\` (when added): when wrapped in 3.1 namespaces, do not emit \`version\` on Categorisation.
- Reader: tolerate both forms.
- Round-trip implication: a 3.0-read Categorisation carries a version; the 3.1 writer must drop it. If callers depend on the version, surface a warning when downgrading.

## Out of scope

- Implementation. Pinned for the future 3.1 writer.

- [ ] 3.1 writer emits Categorisation without \`version=\`.
- [ ] Round-trip test passes through the 3.1 XSD.
