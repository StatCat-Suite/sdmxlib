# Issue #516: reg.data()/DataQuery are still public despite the no-eager-query decision

| | |
| --- | --- |
| State | closed |
| Opened | 2026-10-20 |
| Closed | 2026-10-21 |
| Milestone | %26 Found by the docs audit: correctness and refusals |
| Labels | `api`, `needs-design`, `priority::low` |

`registry-and-catalog.md` records a decision against an eager query surface ("no eager query"), and says `RestRegistry.data()` / `DataQuery` (`fetch`, `slice`, `measures`, `pivot`, `fetch_to`, `pivot_to`) would go once `observations()` covered the data plane.

`observations()` / `ObsQuery` now exist on both registries (#297, #312), and `reg.data()` / `sl.DataQuery` / `sl.dim` are still public, documented in `llms.txt` and the data tutorial as a parallel way in.

Decide one of:

1. Retire `data()` / `DataQuery` / `DimFilter` in favour of `observations()` + `download()`. Check first what `DataQuery` does that `ObsQuery` can't (pivot, a measure axis, `fetch_to`).
2. Keep both, and record why in the design doc, replacing the stale decision.

Labelled `needs-design`. Option 1 would be a `breaking-change`.

Found in !665.

## Comments

### 2026-10-21

**Decisions so far (maintainer, in discussion):**

- **Typing:** an observation query's result is typed from the DSD, as `Dataset`'s is today. Component columns get `pl.Enum` from the codelist and the facet types. `ObsQuery.frame()` currently returns whatever DuckDB holds (`VARCHAR`); that changes.
- **Terminals stay as they are.** `collect()` builds domain objects everywhere, and on observations it refuses, pointing to `frame()`. `frame()` returns the rows as a `pl.DataFrame`. `collect()` is not overloaded to return a table on `ObsQuery`.
- **`Frame` becomes `Select`.** The projection plan returned by `select(...)` / `group_by().agg(...)` / `agg(...)` clashed with the `.frame()` method. It is renamed `Select`, matching SQL and SQLAlchemy, with no alias.

**Still open:** whether `reg.data()` / `DataQuery` / `sl.dim` are retired in favour of `observations()`, and whether `Dataset` stays as a DSD-aware result (`obs....dataset()`) or its tools become functions over a typed frame.

### 2026-10-21

**Decided (maintainer):** what `Dataset` offers moves onto `ObsQuery` as **methods**, and the sinks are **typed** (cast from the DSD, as `frame()` is since !677). `stream()` stays raw: it is the unfiltered view and the escape hatch for bad data.

Order, one MR each:
1. `obs.structure`, the query's `DataStructure` (replaces `ds.dimensions` / `measures` / `wide_dimension`).
2. `obs.sink_parquet(path)`, `obs.sink_csv(path)` and `obs.sink_json(path, lang=)`, over `stream()` with bounded memory, each batch typed.
3. `obs.validate()`, which reads the rows untyped and runs `validation_report`, so every bad value is named instead of failing on the first.
4. `obs.pivot(on=None)`: the measure axis comes from the DSD's `MeasureDimension`, or `on=` replaces `DataQuery`'s `measure_dim=`.
5. Retire `reg.data()` / `DataQuery` / `sl.dim` / `Dataset`, and move the data tutorial and cookbook onto `observations()`. This is the breaking step.

Already covered by the query language: `slice` and `measures` become key-pushed `filter(obs.col(...))`; `start_period` / `end_period` become `TIME_PERIOD >=` / `<=`; `code()` becomes `obs.col()`, which already rejects a typo. Filtering by a label stays in polars, after `frame(labels=)`.

### 2026-10-21

Steps 1–4 merged: !678 (`obs.structure`), !679 (typed sinks), !680 (`obs.validate()`), !682 (`obs.pivot(on=)`). !681 fixed a bug that pivot exposed: `DataflowBinding.from_dsd` dropped a 2.1 `MeasureDimension` from the binding.

Decision before step 5: **file reads load into a store.** `scan_csv` (in both `slpl` and `RestRegistry`) and the SDMX-JSON data readers become a DuckDB view or registered Arrow table, bound with `from_dsd`, and return an `ObsQuery`. A file then gets pivot, validate, sinks and labels through the same surface as a store. `Dataset` is retired, with no slim version kept for files.

### 2026-10-21

Decision on file reads: **`reg.scan_csv(source)` and `reg.scan_json(source)` on `LocalRegistry` and `RestRegistry`**, returning an `ObsQuery`. The registry resolves the file's STRUCTURE_ID, and the rows land in its store. A CSV **path** becomes a typed DuckDB view over `read_csv` (lazy, zero-copy, re-read on each query). Bytes are ingested. `slpl.scan_csv` is removed. Without a catalog: `LocalRegistry(':memory:')` + `add_all([dsd, flow])`.
