# Issue #259: dsl-9: make the query compilers total — 18 NotImplementedErrors on the to_sql() path

| | |
| --- | --- |
| State | closed |
| Opened | 2026-08-09 |
| Closed | 2026-08-10 |
| Milestone | %14 Query DSLs: say what the docs already claim |
| Labels | `dsl`, `type::refactor` |

The two query compilers raise `NotImplementedError` from eighteen places on the `to_sql()` path. Every one of them is a combination the type system permits but the compiler cannot emit.

```
src/sdmxlib/model/code_query.py:      10
src/sdmxlib/model/hierarchy_query.py:  8
```

They fall into three groups:

- **Unsupported field for an operation.** `_emit_is_null` accepts a `_FieldExpr` and rejects `_AnnotationField` / `_NameField` / `_DepthField`. So `node.annotations["x"].is_null()` type-checks, builds a `Predicate`, and blows up at `.ids()`.
- **Unsupported sort key.** `_emit_sort_field` rejects annotation- and code-typed fields, so `q.sort_by(code.annotations["x"])` fails at materialisation.
- **Unsupported nesting.** `_emit_subquery_predicate` rejects annotation predicates inside `.any(...)`, because they would need a join inside the `EXISTS`.

## Why this is worth fixing rather than documenting

The failure lands at the wrong time and on the wrong person. The DSL's whole value proposition is that a filter is a value you can build, pass around and compose; a predicate that is well-typed and unbuildable defeats that. And the error surfaces at `.ids()` / `.collect()`, arbitrarily far from the line that constructed it.

There is a testing consequence too, which is how this surfaced: #248's `test_every_predicate_kind_is_covered` can assert that every *predicate kind* has a property, but there is no equivalent guard over the field × operation matrix, and the raises are exactly the cells that have no behaviour to test. The matrix is currently documented only by which `isinstance` checks a given emitter happens to list.

## The shape of the fix

`_StringRef` is the culprit: every string-typed ref inherits `contains` / `starts_with` / `ends_with` / `is_null` / `is_not_null`, whether or not its field supports them. Split the capability out of the inheritance chain so a ref only exposes the operations its field can compile:

- A ref whose column is `NOT NULL` should not have `is_null()`.
- A ref that cannot be a sort key should not be accepted by `sort_by` — that one is a signature change on `sort_by(key: _Ref)`, which is why it currently defers to a runtime raise.
- Annotation refs inside `.any(...)` is the one case that may be a genuine "not yet", in which case it wants a real implementation (correlated `EXISTS`, which #254 is introducing anyway) rather than a type change.

Note the ordering: **#254 lands first**. Its `EXISTS` rewrite of the annotation predicates makes the `_emit_subquery_predicate` guard unreachable — its stated message ("would require annotation joins inside the EXISTS subquery") stops being true — and #254 already obliges removing or rewriting that raise. Doing this issue first would mean touching the same guard twice.

## Scope

- Enumerate the field × operation matrix for both compilers, from the emitters, and write it down. That table is the deliverable even if some cells stay unsupported.
- For each raise: make the state unrepresentable, or implement the case. A raise that survives must have a comment saying which of the two it is and why.
- Do not "fix" this by broadening the emitters to accept everything. `sort_by(annotations[...])` has no sensible SQL without a join, and inventing one is worse than the current error.

## What success looks like

`to_sql()` on both compilers is total: given a `Predicate` the type system allowed you to build, it emits SQL. Any remaining `raise` is on the *parse*/construction side, where it is cheap to test and lands at the call site.

## Test gates

- The field × operation matrix documented and, where a cell is unsupported, unrepresentable rather than raising.
- A test that constructs every reachable ref × operation pair and compiles it — the guard that a new field cannot silently acquire an operation it cannot emit.
- No net change to the generative properties' pass rate; this is a refactor, and #248/#249's differential suites are the regression net.
