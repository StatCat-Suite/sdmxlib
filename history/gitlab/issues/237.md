# Issue #237: Reading must not silently drop or reshape data — audit and enforce

| | |
| --- | --- |
| State | closed |
| Opened | 2026-08-07 |
| Closed | 2026-08-07 |

The write side of this question is settled: `serialize` must either produce a schema-valid document or raise, and #227's gate holds that line for every artefact in every format. The read side has no equivalent rule, and the default has been the opposite — parse what is understood, drop the rest, report success.

## The criterion

**For every format `F` and every document `D` valid in `F`, `serialize(parse(D), F)` must carry the same information as `D` — or the loss must be declared.**

The property under test is a **document** round-trip, not a model one. Transforming a 2.1 document into sdmxlib's internal model is not the problem and never was — that is the library's job, and the internal shape is free to differ from any wire format. The problem is when that transformation cannot be *undone*: when `D → model → D` does not give `D` back.

So "reshaping" here means specifically **irreversible** reshaping. Reading a 2.1 `<CodelistMap>` into a `RepresentationMap` is fine. Reading it into something that re-emits as a *different* 2.1 document is not.

This is the exact mirror of the existing write-side property. The round-trip properties today start from a generated **model artefact** and check `model → D → model`. That direction cannot see any of this: a field the reader never populates and the writer never emits is invisible to it, because it was never in the generated artefact to begin with. Starting from `D` is what makes the loss observable.

## A demonstrated instance

The SDMX-TWG's own `constructed-sample.json` omits `version` on all three of its metadata sets. Parsing and re-emitting it:

```
  D -> model -> D, SDMX-JSON metadata:
    METADATASET1   input version=None     output version='1.0.0'
    META_UPDATE    input version=None     output version='1.0.0'
    STAT_PRES      input version=None     output version='1.0.0'
```

Nothing raised, and the output is schema-valid. But it is not the document that went in: an absent optional field came back present. The reader defaults it because the model has no way to say "no version was given" (#234 chose that default deliberately, since `"1.0"` was invalid there). That is a reshape which does not round-trip, and it is exactly the class this issue is about.

## What the rule cannot be

A blanket "raise on anything we cannot reproduce" would break parse-then-fix flows the library deliberately supports:

- **Artefacts sdmxlib does not model at all.** Eight of 2.1's `<Structures>` children are types with no model counterpart (Process, Ruleset, Transformation, …). Refusing to parse a registry file because it also contains a `<str:Processes>` section would make the library unusable. These fail the criterion, and should not raise.
- **Unresolvable references.** Already correct: a `Ref` that cannot be resolved stays `unresolved`, which is a normal state for a partial message.
- **Declared format asymmetries.** A 3.1 categorisation genuinely has no version to read; 3.0 metadata values genuinely carry no type marker. These are in `KNOWN_GAPS` and are not defects — they are the "or the loss must be declared" half of the criterion.

A first proposal for the boundary, to be argued with:

| `D → model → D` loses something that is… | what should happen |
|---|---|
| an artefact kind the model has | **raise** — this is #236 |
| a field the model has | **raise**, naming the field |
| a field the model lacks but the format requires on write | **raise** — the re-emission would be invalid or invented |
| a field the model lacks, optional in the format | declare in `KNOWN_GAPS`; do not raise |
| an artefact kind the model lacks entirely | do not raise, but make it discoverable — a `message.unread_sections` the caller can inspect is the least intrusive option |
| an unresolvable reference | unchanged — keep as `unresolved` |

## The audit

Build it as the read-side analogue of #227's gate: a document-in, document-out comparison per format, with every current failure recorded in a burn-down table and asserted *still failing*, so fixing one forces the entry out.

The input corpus is the hard part, and there are three sources worth using together:

1. **Checked-in fixtures**, including the SDMX-TWG samples — real documents, already in the tree, and the only ones representing what registries actually emit.
2. **Documents produced by our own writers** from generated artefacts. Cheap and broad, but blind by construction to anything the writer never emits — which is where the bugs are.
3. **Hand-built documents targeting known gaps**, like the one in #236. The only way to reach sections no writer produces.

## Measure behaviourally, not by grep

Worth stating as part of the issue, because it has produced a wrong answer three times in this milestone:

- a grep-built table of what the 2.1 writer drops named all four map types; the writer emits every one of them (!231);
- a grep of the 3.0/3.1 readers reported `ConceptSchemeMaps` and `CategorySchemeMaps` as unread; both round-trip fine;
- only the 2.1 `MetadataStructures` gap survived being checked with an actual document.

Build the document, parse it, re-emit it, compare. What a reader does is a question for the reader, not for a regex over it.

## Relationship to other issues

- **#236** is the one confirmed instance and can be fixed independently of this policy.
- **#235** is the writing counterpart for the same artefact. Under this criterion it is squarely in scope: 2.1 → model → 2.1 for a MetadataStructure cannot be an identity while the model has nowhere to put `MetadataTarget` / `ReportStructure`. Whether that justifies modelling the layer is the question #235 asks.
- **#227**'s gate is the write-side analogue of what this issue proposes building.
