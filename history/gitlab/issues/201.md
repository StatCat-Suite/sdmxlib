One-line investigation. `model/urn.py:35`:

```python
class SdmxUrn(Generic[T_co]):  # noqa: UP046 — PEP 695 has no variance syntax; T_co must be an explicit covariant TypeVar
```

The stated reason is that PEP 695 has no *explicit* variance syntax — true. But PEP 695 **infers** variance from usage, so `class SdmxUrn[T]` may come out covariant on its own, making both the legacy `Generic[T_co]` form and the noqa unnecessary.

Worth care rather than a blind edit: commit `9234d27` deliberately made this covariant to fix a real defect (an `SdmxUrn[Any]` was masking a covariance violation), so the property is load-bearing.

## How to check

1. Rewrite as `class SdmxUrn[T]`, drop the noqa and the explicit TypeVar.
2. `just check` — pyrefly's `variance-mismatch` is enabled under `preset = "all"` and will say if the inferred variance is wrong.
3. Confirm the covariance actually holds, e.g. `assert_type` on a `SdmxUrn[Codelist]` where a `SdmxUrn[object]` is expected — the case that motivated `9234d27`.

If inference gives covariance: delete the noqa and the TypeVar. If not: keep both, and replace the comment's reasoning with what was actually observed.

## Comments

### 2026-08-05

Answered in !195 — **the noqa stays**, and the reason is now the measured one.

| form | basedpyright | pyrefly |
| --- | --- | --- |
| explicit covariant TypeVar + `Generic[T_co]` | ✅ | ✅ |
| PEP 695 `class SdmxUrn[T_co]` | ✅ | ❌ |

The issue's premise was half right: PEP 695 *does* infer variance, and one checker does come out covariant. It just isn't unanimous, and this repo gates on both.

**Why they disagree:** `T_co` appears exactly twice in `model/urn.py` — the TypeVar declaration and the class header. It is a **pure phantom**, never used in the class body. Inference has nothing to infer *from*, so the tools fall back differently: basedpyright treats an unused parameter as covariant, pyrefly as invariant. Pyrefly then rejects `SdmxUrn[Codelist]` where `SdmxUrn[object]` is wanted — the exact assignment `9234d27` made covariant to fix a real defect. Both are defensible readings of an unused parameter.

**Method:** the probe was validated against a known-invariant control *first*, so a pass could not be mistaken for a checker that simply was not looking. Recommended for the sibling issues — an earlier MR in this milestone shipped a "verified non-vacuous" claim whose verification was itself methodologically wrong.

**No regression test, and that was checked rather than assumed:** making `SdmxUrn` invariant produces 4 basedpyright errors in `src/` (`ref.py:163` among them), so `just check` already guards the property. A dedicated test could not guard variance regardless, since tests are outside the default checker scope.

Outcome: UP046 cannot be satisfied here without losing a property one of the two gates requires. The suppression was justified; only its explanation was wrong.
