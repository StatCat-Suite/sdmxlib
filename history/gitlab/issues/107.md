3.1 model audit follow-up (post-MR !63).

## Semantic gap

3.1 \`ValueMappingType\` carries richer mapping semantics than the literal-pair we model in \`ValueMap\`:

\`\`\`xml
<xs:complexType name=\"MappedValueType\">
  <xs:simpleContent>
    <xs:extension base=\"xs:string\">
      <xs:attribute name=\"isRegEx\" type=\"xs:boolean\" use=\"optional\"/>
      <xs:attribute name=\"startIndex\" type=\"xs:integer\" use=\"optional\"/>
      <xs:attribute name=\"endIndex\" type=\"xs:integer\" use=\"optional\"/>
    </xs:extension>
  </xs:simpleContent>
</xs:complexType>
\`\`\`

Plus per-mapping \`@validFrom\`/\`@validTo\` (date) on \`ValueMappingType\`.

Semantically these aren't variants of the literal pair — they're **different mappings**:
- Literal: \"the value \`EU-DE\` maps to \`DE\`\".
- Regex: \"any value matching \`^EU-([A-Z]{2})$\` maps to capture-group 1\".
- Index: \"characters [3:5] of the source map to the target\".
- Validity-bounded: \"this mapping is correct from 2020-01-01 to 2023-12-31\".

Our current \`ValueMap(source_value, target_value)\` covers only the literal case. Codelist-to-codelist round-trip works because that's the common shape, but richer maps (regex transforms in real ESCB pipelines) get downgraded silently.

## Action

Most Pythonic option: discriminated union — e.g.
\`\`\`python
@define
class LiteralValueMap:
    source_value: str
    target_value: str
    valid_from: date | None = None
    valid_to: date | None = None

@define
class RegexValueMap:
    source_pattern: str   # regex
    target_template: str  # \"DE-\\\\1\" style backreferences
    valid_from: date | None = None
    valid_to: date | None = None

@define
class IndexValueMap:
    source_value: str
    target_value: str
    source_start_index: int
    source_end_index: int
    valid_from: date | None = None
    valid_to: date | None = None

ValueMap = LiteralValueMap | RegexValueMap | IndexValueMap
\`\`\`

Less invasive option: keep one \`ValueMap\` class with optional flags. Choose at implementation time.

## Done when

- [ ] \`ValueMap\` (or the discriminated union) covers the three variants + validity dates.
- [ ] 2.1 serializer drops the extras silently (the old \`<CodeMap>\` shape can't represent them).
- [ ] 3.0 serializer round-trips literal + validity (\`ValueMappingType\` in 3.0 already supports validity).
- [ ] 3.1 serializer (eventual) round-trips all three variants.
