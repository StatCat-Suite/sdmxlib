# Issue #511: Query misuse reaches DuckDB as a raw error instead of a refusal naming the fix

| | |
| --- | --- |
| State | closed |
| Opened | 2026-10-20 |
| Closed | 2026-10-21 |
| Milestone | %26 Found by the docs audit: correctness and refusals |
| Labels | `bug`, `dsl`, `priority::medium` |

Several misuses of the query language reach DuckDB and fail with a raw `BinderException` / `NotImplementedException` / `PathError: cannot compile Compare`, instead of a refusal that names the fix. CLAUDE.md's rule is that wrong calls must fail with a message naming the fix, and `tests/unit/test_query_misuse.py` is where these belong.

Each was reproduced on main after !665:

- [ ] **`ObsQuery.ids()` / `.urns()`**: `BinderException: Table "s0" does not have a column named "resource_id"`. Worse, the `TypeError` from `obs.collect()` / `.page()` tells the user to "use `.ids()`". These should be absent or refused (data-plane-query.md §6.2).
- [ ] **`qualify(<Pred>)`** is accepted, and then fails at compile with `PathError: cannot compile Compare`. It should be refused at the clause.
- [ ] **`filter(<WinPred>)`**: the message is the generic "A column is not a question about a row…". It should name `qualify()`.
- [ ] **A parent-rooted predicate inside `.any()`** (`q.codelist.codes.any(q.codelist.id == …)`) gives `BinderException: Referenced table "s1" not found`.
- [ ] **An aggregate `where=` rooted at another relation** (`q.codelist.codes.count(where=q.dsd.id == …)`): same binder error.
- [ ] **A window aggregate inside `group_by().agg()`** (`agg(t=q.code.position.sum().over())`): `BinderException: column "position" must appear in the GROUP BY`.
- [ ] **An aggregate compared to an aggregate** (`codes.count() > codes.id.n_unique()`): `NotImplementedException: Unable to transform python value of type Agg`.
- [ ] **A column compared to a column** (`q.code.id == q.code.parent.id`): refused by the literal check, but with "Did you mean <Str parent_id>?", which reads as if it were supported. The message should say column comparison is not supported yet (query-language.md §13, open question 1).
- [ ] **An untyped observation column compared with a number** (`obs.col("OBS_VALUE") > 1.5` when the DSD declares no type): `BinderException: Cannot compare VARCHAR and DOUBLE`.
- [ ] **`"FR" in cl.codes`**: Python's generic "not a container or iterable". `len()` and iteration already have tailored refusals; `in` should too, naming `.filter(...).exists()`.
- [ ] **The `PathError` for `q.component.dsd.dataflows`** names an internal hop (`'dsd.dataflows.spine'`).

Found in !665.

## Comments

### 2026-10-20

!674 covers every item except **item 9**: an untyped observation column compared with a number. Whether such a column is numeric depends on the physical table, not the DSD (a measure with no declared type), so a clean refusal needs the store's schema (`SchemaInspector.columns`) at plan time. Left open for that.

### 2026-10-21

Decision on item 9: **typed `obs.col`** (design §6.3). An enumerated component becomes `Str`, a numeric Facet `Num`, from the DSD. A component the DSD leaves untyped stays `Untyped`, but takes its physical type from the store schema, and comparing a number with a text column is refused at filter time.

### 2026-10-21

Correction to the item 9 decision: `obs.col` keeps its static `Untyped` type (design §6.3's static half). The decision is **option 2**:
- `obs.col(id)` checks at runtime. A component's kind (text or number) comes from the DSD, or from the store's physical column type when the DSD gives none. Comparing a number with a text column, or a string with a number column, is refused as the predicate is built, naming the fix. This includes the silent `== 1`.
- `obs.text(id)` / `obs.num(id)` return exact `Str[ObsRow]` / `Num[ObsRow]`, checked against that kind when called.
