# Issue #344: partial=False is ignored for a pinned URN — the resolved cache does not record how completely it resolved

| | |
| --- | --- |
| State | closed |
| Opened | 2026-08-19 |
| Closed | 2026-08-19 |
| Labels | `design` |

Measured while adding `resolve=` / `partial=` to `FederatedRegistry` (#343).
Independent of that change — it reproduces on a bare `RestRegistry`:

```python
for version in ("1.0", "latest"):
    urn = sl.DataStructure.urn_for(agency="ESTAT", id="DSD_X", version=version)
    with sl.RestRegistry(..., transport=stub) as reg:
        reg.get(urn, resolve=True)                    # detail=referencepartial
        reg.get(urn, resolve=True, partial=False)     # asks for detail=full
    print(version, "->", details_requested)

# 1.0      -> ['referencepartial']      ← the second request never went out
# latest   -> ['referencepartial', 'full']
```

A caller who writes `partial=False` against a **pinned** URN is handed the
trimmed codelists, silently. That is #338's defect verbatim — *"a wrong answer
to an explicit question"* — and the regression test written for it,
`tests/unit/test_rest_partial.py`, uses `version="latest"` throughout, so the
pinned half was never covered.

## Why it happens

`Session._resolved_map` is keyed by URN alone:

```python
cached = self._session.get_resolved(urn) if wants_refs else self._session.get(urn)
if cached is not None:
    return cached
```

`ingest(..., resolved=True)` marks a URN resolved without recording *how
completely*. A `detail=referencepartial` fetch and a `detail=full` fetch both
set the same flag, so the second call is a cache hit on the first.

`latest` escapes only incidentally: it is a pointer, so #338 re-asks it every
time and the `detail=full` request happens on the way past. Nothing about the
partial/full distinction is being handled there either.

## Why the fix is not just "key on partial"

An identity map holds **one** object per URN, and
`test_a_fuller_fetch_upgrades_the_interned_codelist` documents that a later,
fuller fetch *fills in* the object an earlier one handed out. So the resolved
map is not really a cache of answers — it is a record of what has been
learned. The right shape is probably a completeness *level* per URN
(`unresolved < partial < full`) with the hit condition being "at least as
complete as asked", rather than a second keyed entry that would duplicate an
object the session deliberately interns once.

That also settles the reverse direction for free: `partial=True` after a
`partial=False` should hit, because full is more than enough. It currently
does, by accident.

## Scope

- `Session.ingest` / `get_resolved` in `api/session.py`, and the one call site
  in `RestRegistry._read`.
- `tests/unit/test_rest_partial.py` should be parametrised over pinned and
  `latest` rather than testing only the second. Its four tests all pass today
  against `latest` and three of them would fail pinned.
- `tests/unit/test_federated_registry.py::test_partial_reaching_the_wire_is_a_
  latest_only_guarantee` is the placeholder recording this, and should be
  deleted by the fix.
