# Issue #158: SDMX-ML writers drop annotations on items/components — silent round-trip loss (sibling of #157)

| | |
| --- | --- |
| State | closed |
| Opened | 2026-07-13 |
| Closed | 2026-07-13 |

## Summary

The SDMX-ML writers (`sdmx_ml21/writer.py`, `sdmx_ml30/writer.py`, and the
shared item writers in `sdmx_ml/_common.py`) emit `<com:Annotations>` on
**maintainable** artefacts (Codelist, DSD, Dataflow, …) but **not** on
**items / components**: Code, Concept, Category, Dimension, TimeDimension,
Attribute, Measure, HierarchicalCode, Level, and MetadataAttribute.

The readers, by contrast, **do** parse item-level annotations everywhere
(codes/concepts/categories via `_common.read_*`; dimensions / time
dimensions / attributes / measures / hierarchical codes / levels /
metadata attributes via the per-format readers). So for every component
type this is **silent round-trip data loss**: an annotation read in from a
provider is dropped the moment the graph is re-serialised to SDMX-ML.

This is the SDMX-ML sibling of #157 (which was the SDMX-JSON writer
dropping annotations). #157 fixed the JSON side for both maintainables and
items; the XML writers still lag one level down.

## Reproduction

```python
from sdmxlib.formats import sdmx_ml30 as ml
from sdmxlib.model.annotations import Annotation, Annotations
from sdmxlib.model.collections import ItemList
from sdmxlib.model.datastructure import DataStructure, Dimension
from sdmxlib.model.message import StructureMessage

dsd = DataStructure(
    id="DSD", maintainer="T", version="1.0", name={"en": "D"},
    dimensions=ItemList([
        Dimension(id="FREQ", annotations=Annotations([Annotation(type="DIM", title="x")]))
    ]),
)
back = ml.reader.read(ml.writer.write(StructureMessage(data_structures=[dsd])))
print(list(back.data_structures["DSD"].dimensions["FREQ"].annotations))  # [] — dropped
```

## Expected

Each item/component writer emits `<com:Annotations>` as its **first**
child (XSD requires it before `Name`/`Description`/`ConceptIdentity`), so
component annotations round-trip through SDMX-ML 2.1 and 3.0 just like
maintainable-level annotations already do.

## Fix

Add `write_annotations(el, x.annotations)` (first child) to each item
writer in all three files:

- `sdmx_ml/_common.py`: `write_code`, `write_concept`, `write_category`
- `sdmx_ml30/writer.py`: `_write_code`, `_write_concept`,
  `_write_dimension`, `_write_time_dimension`, `_write_attribute`,
  `_write_measure`, `_write_hierarchical_code`, `_write_metadata_attribute`,
  and the inline Level node in `_write_hierarchy`
- `sdmx_ml21/writer.py`: `_write_dimension`, `_write_time_dimension`,
  `_write_attribute`, `_write_measure`, `_write_hierarchical_code`,
  `_write_level_chain`

Guarded by a round-trip + XSD-validation test asserting item annotations
survive on both versions (XSD validation catches the ordering rule).
