# Issue #390: the bundle bench tier is not in `just ci`, so an API rename breaks it silently

| | |
| --- | --- |
| State | closed |
| Opened | 2026-09-05 |
| Closed | 2026-09-06 |
| Labels | `tests` |

`just ci` is `check test test-docs test-integration docs-build`. The bundle
tier is not in it, and `tests/bench/test_bundle_reads.py` constructs its
registry from `LocalRegistry` public API — so a rename in that API compiles,
type-checks, passes 6,284 unit tests, and breaks the tier silently.

## How it was found

!456 renamed `resolve_cache_size` to `resolve_cache_items` (#386). `just ci`
was green. `just bench-bundle` was 19 errors:

```
TypeError: LocalRegistry.from_connection() got an unexpected keyword argument
'resolve_cache_size'. Did you mean 'resolve_cache_items'?
tests/bench/test_bundle_reads.py:71
```

I only ran it because that MR was *about* the cache. Nothing would have caught
it otherwise, and the next person to rename something in `LocalRegistry` gets
no such hint.

This is the failure mode `_bundle.py`'s own module docstring is written
against, arriving from the other side. That docstring argues at length that a
stale path must *raise* rather than skip, because "a finding that cannot fail
is a finding nobody acts on". A tier that is never run by the gate cannot fail
either.

## Why it is not simply "add it to `ci`"

Three things make this a decision rather than a one-liner, and they pull
different ways.

**1. It is not hermetic.** The tier needs `$SDMXLIB_BENCH_BUNDLE` or the
sibling workspace. Absent both, `bundle_path()` returns `None` and the tier
skips — so adding it to `ci` is *safe* everywhere, and a no-op on any machine
without the bundle. On the machine that has it, `just ci` grows ~60 s.

**2. Skipping is exactly what the module argues against.** If it lands in `ci`
and silently skips on the one machine that matters, we have moved the problem
rather than fixed it. Whatever ships should make "the gate did not check this"
visible — `conftest.pytest_terminal_summary` already prints the skip reason on
its own line, which may be enough, or may want to be louder.

**3. The tier is benchmarks *and* assertions, mixed.** The justfile comment on
`bench-bundle` says so: "this tier carries count assertions alongside its
benchmarks, and those are the part that must fail when the code regresses."
The assertions are cheap and are what a gate wants. The benchmarks are the
~60 s. There is no marker separating them today — both are `bundle`.

## Directions

1. **`ci` runs the whole tier.** Simplest, and honest about the cost. ~60 s on
   the machine that has the bundle, nothing anywhere else.
2. **Split the marker** — `bundle` for the assertions, `bundle-bench` (or
   `--benchmark-skip`) for the timing — and put only the assertions in `ci`.
   Cheaper, and it matches what the justfile comment already says the two
   halves are for.
3. **A smoke check instead**, one test that constructs every public entry
   point the tier uses. Catches this class of break with no bundle at all, and
   catches nothing else.

(2) is probably right and (3) is a cheap complement, since (3) works on a
machine that has never seen the bundle — which is most of them.

## Acceptance

- A rename of a `LocalRegistry` constructor keyword fails `just ci` on a
  machine holding the bundle, and is at minimum *reported* on one that is not.
- If the tier is split, the split is by what the two halves are for — an
  assertion that must fail on a regression, versus a timing that is
  informational — and not by wall time alone.
- Whatever lands is verified the way this was found: rename a keyword, watch
  the gate go red, put it back.

## The split, by purpose

`just bench-bundle-assertions` runs `-m "bench and bundle" --benchmark-skip`,
and `ci` gains it:

| | tests | in `ci` |
| --- | --- | --- |
| asserts a property | 15 | yes |
| reports a number (takes the `benchmark` fixture) | 8 | no |

That is direction **2**, and `--benchmark-skip` draws exactly the line this
issue asked for — the measuring tests are precisely the ones taking that
fixture — so there is no new marker to maintain and no way for a test to end up
in the wrong half later.

Measured: **15 passed, 8 skipped in 123 s**; `just ci` end to end 5:52 on the
machine holding the bundle, ~0 s of added cost on one without it. (The 96 s I
quoted while deciding was the tier alone on an idle machine. The same pass took
the unit suite from 143 s to 188 s, so that gap is load, not the tier — but the
honest number for the gate is 123 s.)

Now gated, and previously not: the per-item calls/bytes budget (%18), the
collect-vs-frame ratios (#382), and the pruned-join and declined-order ratios
(#391).

## Point 2 — "skipping is exactly what the module argues against"

Taken seriously, and it turned up two bugs in the hook that was supposed to
handle it:

- **It printed a canned reason.** Always `skip_reason()`, the "no bundle at
  all" message — so a structural-only bundle reported
  `$SDMXLIB_BENCH_BUNDLE is unset` when the variable *was* set. It now reports
  the reasons it actually found, counted.
- **#391's data-plane skip was invisible to it.** That reason did not name
  `$SDMXLIB_BENCH_BUNDLE`, and the hook matches on that name, so a bundle
  without `lake.ducklake` skipped eight tests in silence. `data_plane_skip_reason`
  now names the variable — better advice, and what makes the hook fire.

The banner reads **"bundle tier not run — the gate did not check it"** and
names what is unguarded, because a green gate that skipped these checked less
than it looks like it did.

Verified on a structural-only bundle: 7 structural assertions pass, 8
observation tests skip, banner names `lake.ducklake` as the missing file.

## Acceptance

- **A renamed constructor keyword fails `just ci`** on a machine with the
  bundle. Verified the way this issue asked — renamed it, ran the gate:

      E  TypeError: LocalRegistry.from_connection() got an unexpected keyword
         argument 'resolve_cache_items'. Did you mean 'resolve_cache_entries'?

  then put it back.
- **Reported, not silent, on a machine without one** — see above.
- **Split by purpose, not wall time**, as required. Note the two do not
  coincide: 96 s of the assertion half is two tests (the per-item budget
  profiles each read twice, and the ratios time both arms), and direction 3's
  "cheap subset" would have been ~3 s but split on cost, which this issue ruled
  out.

## Not done

Direction **3**, the hermetic smoke test. Still worth having — it would work on
the machines that do *not* have the bundle, which is most of them — but it is a
different piece of work: catching a keyword rename without a bundle means
calling the constructors for real, which means a synthetic bundle fixture.
Filed nothing; noting it here as the obvious follow-up if the gate ever needs
to be machine-independent.
