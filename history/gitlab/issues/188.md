# Issue #188: Version default "1.0" fails metadata JSON schema's strict SemVer VersionType

| | |
| --- | --- |
| State | closed |
| Opened | 2026-07-22 |
| Closed | 2026-08-21 |

## Context

Surfaced during #182 (MR !172, metadata msgspec migration).

The two SDMX-JSON 2.1 schemas define `VersionType` **differently**:

- **structure** schema: lenient — "unlimited sequence" format, accepts `1.0`.
- **metadata** schema: strict — reduced SemVer, `pattern` requires 3 parts (`1.0.0`), rejects `1.0`.

Our model defaults `version` to `"1.0"` everywhere (`MaintainableArtefact`). That is:

- conformant for **structure** messages (lenient VersionType), but
- **non-conformant** for **metadata** messages — a `MetadataSet` with the default `"1.0"` version fails metadata-schema validation on the `version` field.

The #182 conformity test sidesteps this by using an explicit `1.0.0` fixture, so the emitted-output-conforms guarantee only holds when the caller supplies a 3-part version.

## Questions to resolve

1. Is the structure-vs-metadata `VersionType` divergence intentional in the TWG schemas, or a schema bug? (If a bug, note it upstream; if intentional, we must handle both.)
2. Should the model default move to `"1.0.0"` (3-part) globally? That's conformant for both schemas (the lenient structure one accepts 3-part too) but is a broad, visible change touching many fixtures/tests.
3. Or should only the metadata layer normalise `1.0` → `1.0.0` on emit? (Localised, but a writer-side mutation of the caller's version string.)

## Acceptance (once decided)

- A `MetadataSet` built with model defaults emits metadata-schema-conformant `version`, OR the divergence is explicitly documented and the default-version behaviour is a deliberate, tested choice.

Relevant: `src/sdmxlib/model/base.py` (version default), `tests/schemas/sdmx_json/2.1/*VersionType`, `src/sdmxlib/formats/sdmx_json/metadata.py`.

Follow-up to !172 (#182).

## Comments

### 2026-08-21

Closing as stale — fixed by the #234 work.

`MetadataSet.version` now defaults to `"1.0.0"`, which satisfies the metadata schema's strict `VersionType` semver pattern. Verified on `main`:

    MetadataSet    version default = '1.0.0'
    Codelist       version default = '1.0'

`Codelist` deliberately still defaults to `"1.0"` — this bites only in the metadata schema, because the *structure* schema states no pattern at all. #234 records the same reasoning, and notes the JSON reader now reads the fallback off the model rather than restating the literal, so the two cannot drift.

417 metadata tests pass, including schema-validated round-trips over both formats.

### 2026-10-08

Correction, from #417: the closing note above says the SDMX-JSON structure schema "states no pattern at all" for versions. It does — `VersionType` is an `anyOf` over SDMX-ML 3.0's two patterns (legacy and semver); only its `description` still carries the 2.1 prose. The structure writer now checks the 3.0 grammar (!515).
