**Phase 3** — depends on #test-5. This is where the Hypothesis investment pays off.

## The measurement

**38 of 94** unit-test files contain a hand-rolled `_roundtrip` / `roundtrip` helper. Eight define a function literally named `_roundtrip`. We are already property-testing; we are just supplying the examples by hand, from ~22 XML and 4 JSON fixtures.

Six serializer pairs, each with the same underlying property — `read(write(x))` preserves everything wire-representable:

| Pair | Notes |
| --- | --- |
| SDMX-ML 2.1 | + XSD validation of the emitted document |
| SDMX-ML 3.0 | + XSD |
| SDMX-ML 3.1 | + XSD; reader is the least covered at 78% |
| SDMX-JSON 2.0 structure | + JSON-schema validation |
| SDMX-JSON 2.0 metadata | recursive `ReportedAttribute` tree |
| DuckDB storage | `storage/writers.py` -> `storage/readers.py` |

Plus `to_dict` / `from_dict` in `model/convert.py` (81% covered, and generic over any attrs class — a natural property).

## Why this is likely to find real bugs

The suppression-audit milestone found **five defects** in exactly this territory, none of them the point of the work, and every one invisible to the valid-fixture round-trips we already run:

- a data-message value entry of `{"id": null, "name": "..."}` decoding to the literal string `"None"`;
- two readers raising `AttributeError` in violation of a documented `Raises: ValueError`;
- a duplicated `emit_istr` with a second, subtly separate implementation.

All five surfaced only from *malformed or unusual* inputs. Hypothesis generates exactly that class of input, continuously, instead of when someone thinks to try it.

The `write_text_format` table refactor is a concrete instance: eleven `Facet` bounds, each written once. A property over `facets()` covering all eleven simultaneously is a much stronger statement than the 14 fixtures that happen to contain a `TextFormat`.

## Scope

**1. One parametrised property per serializer pair**, over the strategies from #test-5. Keep the existing XSD and JSON-schema validation in the loop — a round-trip that validates is a much stronger property than one that merely re-reads.

**2. Reconcile with `test_roundtrip_property_guard.py`.** That file is already a hand-built version of this: a fully-populated artefact per serializer, with a `KNOWN_GAPS` table under `xfail(strict=True)`. Do not duplicate it — the generated properties must consult the *same* known-gap list, or every known gap becomes a Hypothesis failure on day one. Strict-xfail is a good design and should survive.

**3. Field-level coverage assertion.** The existing guard checks named fields survive. The generative version should be able to state which fields it actually exercised, so "the property passed" cannot quietly mean "the strategy never generated that field."

## The hard part, stated up front

**Round-trip is not equality for every field.** Known asymmetries — `version="latest"` normalisation, `InternationalString` primary-language selection, empty-vs-absent collections, `Ref` resolution state — mean the property is "equal after canonicalisation", and the canonicaliser is itself code that can be wrong. Write it explicitly and review it as production code, not as test scaffolding; a too-generous canonicaliser silently weakens every property in this issue.

## Test gates

- Every serializer pair has a generative round-trip property.
- `KNOWN_GAPS` shared, not duplicated; strict-xfail preserved.
- Any newly-found gap gets an issue and a pinned `@example`, and is added to the table only once it is understood.
- CI-profile runtime reported.
