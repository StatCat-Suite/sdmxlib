# Issue #238: Artefact 'uri' is never read or written, so it is lost on every round-trip

| | |
| --- | --- |
| State | closed |
| Opened | 2026-08-07 |
| Closed | 2026-08-07 |
| Labels | `bug` |

An artefact's `uri` attribute is read by nothing and written by nothing, so it is lost on every round-trip that carries one. The ECB's data structure carries `uri="https://www.ecb.europa.eu/vocabulary/stats/exr/1"` on its DSD, and both ECB fixtures lose it.

Found by the document-fidelity harness (#237). It is the last remaining non-structural difference in the corpus: with it fixed, `ecb_data_structure.xml` and `ecb_dataflow.xml` would round-trip cleanly, leaving only the 2.1 wrapper-artefact family (#235-adjacent).

## Why this is not a small fix

It looked like a one-attribute gap. It is not: `uri` is declared on **`IdentifiableType`**, so it applies to every identifiable artefact — every maintainable *and* every item (Code, Concept, Category, Agency, component). SDMX-JSON has the same field under `links`/`uri` conventions.

Concretely, adding it means:

1. **A field on ~20 model classes.** `MaintainableArtefact` is a mixin, not an attrs class, and its docstring is explicit that "subclasses must redeclare the standard fields … because slotted dataclasses cannot inherit slots from a non-dataclass parent". So there is no single place to add it.
2. **Read and write in four formats.** The write side is cheap for maintainables — `WriterHelpers.write_maintainable_attrs` is one function — but the read side constructs each artefact individually, and items are separate again.
3. **A storage column**, or an accepted storage-layer loss recorded in `KNOWN_GAPS`.

## Options

1. **Maintainables only.** Covers the observed cases and most real use, at roughly a fifth of the work. Leaves item-level `uri` silently lost, which under the #237 criterion is still a defect — so this is a partial fix that needs its own recorded gap.
2. **Everything identifiable.** Complete, and the only version that satisfies the criterion. The bulk is mechanical but it touches every artefact class and every reader.
3. **Refuse on read.** Consistent with #237's fallback, but disproportionate: `uri` is an optional external pointer, and refusing the ECB's own DSD because it links to a vocabulary would be worse than the loss.

Option 2 is the right end state. Option 1 is a defensible step toward it if the item-level gap is recorded rather than ignored.

## Related

`GroupDimensionBaseType` also declares `uri`, and 2.1 marks it `prohibited` there — already classified in the prohibited-attribute inventory as unreachable, since sdmxlib sets ids on `<Group>` rather than on the `<GroupDimension>` inside it.
