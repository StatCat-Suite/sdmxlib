# Issue #505: LocalRegistry(conn) silently ignores a DuckDB connection and opens a stray file

| | |
| --- | --- |
| State | closed |
| Opened | 2026-10-20 |
| Closed | 2026-10-20 |
| Milestone | %26 Found by the docs audit: correctness and refusals |
| Labels | `api`, `bug`, `priority::high` |

`sl.LocalRegistry(conn)` accepts a DuckDB connection, ignores it, and opens a **new database file** named after the connection's repr.

```python
conn = duckdb.connect(":memory:")
reg = sl.LocalRegistry(conn); reg.open(); reg.close()
os.listdir(".")   # ['<_duckdb.DuckDBPyConnection object at 0x10ce5e970>']
```

Nothing reaches the caller's connection, and nothing says so: everything added lands in a stray file in the working directory. `LocalRegistry.from_connection(conn)` is the right spelling. Until !665 the local registry tutorial used the broken form, and its doc test passed.

**Fix:** refuse a non-path `uri` in `__init__` with a `TypeError` that names `from_connection`. Guard it with a test that passes a connection.

Found writing the docs patch pass (!665).
