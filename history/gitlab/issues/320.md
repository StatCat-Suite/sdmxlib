# Issue #320: is_final and uri are persisted for some maintainables and silently dropped for six others

| | |
| --- | --- |
| State | closed |
| Opened | 2026-08-17 |
| Closed | 2026-08-17 |
| Labels | `storage`, `type::bug` |

Found by the derived round-trip guard (#316) on its first run — a fourth
instance of the family that issue was filed about.

`is_final` and `uri` are declared on **every** maintainable. Storage keeps them
for some types and drops them for others:

```
is_final lost: Categorisation, CategoryScheme, ConceptScheme, Dataflow,
               ProvisionAgreement, RepresentationMap
uri lost     : Categorisation, CategoryScheme, ConceptScheme, Dataflow,
               ProvisionAgreement, RepresentationMap
```

Same six for both, which suggests one cause rather than twelve.

```python
cl = Codelist(id="X", maintainer=AG, name={"en": "x"}, is_final=True, uri="http://e/u")
# round-trips: is_final True -> True,  uri kept

cs = ConceptScheme(id="X", maintainer=AG, name={"en": "x"}, is_final=True, uri="http://e/u")
# round-trips: is_final True -> False, uri -> None
```

The artefact validates, round-trips, and is simply not the one that was
persisted — the exact shape of !303, #307 and #309.

## Why nothing caught it

`_put_spine` writes both columns, so the *spine* is fine; the divergence is in
what each type's writer or reader does with them. Existing round-trip tests
build fixtures that do not set `is_final` — its default is `False`, so a reader
that never populates it looks correct — and `uri` is rarely set in a fixture at
all.

That is exactly why #316 asks for **distinguishable** values rather than merely
valid ones: `is_final=False` cannot tell a working reader from one that does
nothing.

## Scope

Find the one cause behind the six. `_put_spine` is shared, so the likely
suspects are the per-type readers in `storage/readers.py` not selecting the
columns, or the reconstruction path dropping them.

## Gates

The derived guard from #316 covers this once fixed — the entries should be
deleted from its known-gap table rather than a new test written.
