# Issue #465: Structure JSON omits meta.schema, so pysdmx cannot read sdmxlib's output

## Problem

pysdmx 1.20.0 refuses sdmxlib's structure JSON ("Cannot parse input as SDMX-JSON"), although the output is valid against the SDMX-JSON 2.0 schema. pysdmx recognises a JSON message by `meta.schema`, and sdmxlib's structure writer doesn't write it. Today's output:

```json
"meta": {"id": "SDMXLIB", "prepared": "…", "sender": {"id": "SDMXLIB"}}
```

`meta.schema` is optional in the 2.0 schema. But BIS/FMR and pysdmx always write it, and so does sdmxlib's own data writer (`sdmx_json/data_v2.py`, `_SCHEMA_URL`). The metadata writer writes a top-level `$schema` instead.

## Fix

Write `meta.schema` (the structure schema URL for the version written) in the structure writer. Consider `contentLanguages` too, which both peers write.

Add a test that pysdmx reads sdmxlib's structure JSON when the `bench-compete` group is installed. The benchmark already checks this: see `just bench-compete`, "Written output".

## Done when

pysdmx reads sdmxlib's structure JSON for codelists and DSDs, and the benchmark shows "identical".
