**Phase 2** — depends on #test-3, whose surviving-mutant list is the evidence for half of this.

Two opposite failure modes, both real here:

- **Under-detecting** — a test that passes whether or not the code is right. Mutation testing (#test-3) finds these mechanically.
- **Over-detecting** — a test coupled so tightly to *how* the code works that a correct refactor breaks it. Mutation testing cannot see these; they need reading.

## The evidence for over-detection

**85 `pytest.raises(..., match=...)` assertions** across the unit suite, against 54 bare `pytest.raises`.

This bit during the suppression-audit milestone. Typing the SDMX-JSON envelopes changed error *messages* while preserving error *types*:

```
Expected `str`, got `int` - at `$[0].id`
Expected `str`, got `int` - at `$.data.codelists[0].id`     <- after
```

Seven such changes landed, all improvements. None broke a test — but only because the existing `match=` patterns happened not to cover those paths. That is luck, not design.

The question per site: is the message text **part of the contract** (a user-facing error we promise) or an **implementation detail** (a msgspec path string)? Assert on type + a stable substring for the former; assert on type alone for the latter.

Note this cuts both ways — #test-3's output may show that some bare `pytest.raises` are too *loose*, passing on the wrong exception entirely.

## Also in scope

- **The 5 mock-using files.** Few enough to inspect individually. A mock that asserts on internal call shape is the classic over-detector; verify each is standing in for something genuinely untestable (network, clock) rather than for real objects.
- **Tests that pin SQL text.** The query DSLs build SQL as strings; any test asserting on generated SQL rather than on query *results* is coupled to the emitter. Check whether any exist.
- **The `test_roundtrip_property_guard.py` known-gaps table.** It uses `xfail(strict=True)` so a closed gap fails loudly — a good design. Re-verify each entry is still a real gap; several serializer fixes have landed since it was written.

## Test gates

- Every `match=` site classified contract / implementation-detail, with the implementation-detail ones loosened.
- Each of the 5 mock sites given a verdict.
- Every `KNOWN_GAPS` entry re-verified against current behaviour.
- Suite still green, and the loosened tests still fail when the *type* is wrong — check by mutation, not by inspection.
