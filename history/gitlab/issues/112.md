3.1 model audit follow-up (post-MR !63). Two findings from the agent audit that I didn't spot-verify against the XSD before filing. Resolve before acting on them.

## #1: Does 3.1 \`DataflowType\` add \`<DimensionConstraint>\` ?

The agent reported 3.1 introduces \`<DimensionConstraint>\` on \`DataflowType\` to support \"evolving DSD\" (list of dimensions the dataflow restricts itself to, even as the DSD grows). If real, this is semantic: the dataflow declares its committed surface separate from whatever future dimensions the DSD adds.

**Verify:** read \`tests/schemas/sdmx_ml31/SDMXStructureDataflow.xsd\` and confirm whether \`DataflowType\` has a sequence element for dimension constraints, what the type is, and the cardinality. Compare against the 3.0 version of the same file.

If confirmed: add \`dimension_constraint: tuple[str, ...] = ()\` to \`Dataflow\`; document the use case.

## #2: Does \`ProvisionAgreement\` need \`is_final\` ?

The agent reported \`ProvisionAgreement\` is missing \`is_final\` — but every other \`MaintainableArtefact\` we model carries it.

**Verify:**
- \`grep -n is_final src/sdmxlib/model/provision.py\` — is it actually missing or did the agent miss it?
- If missing: check the 2.1 + 3.0 + 3.1 XSDs for whether \`MaintainableType\` (which \`ProvisionAgreement\` ultimately restricts) carries \`@isFinal\`. If yes, add to our model.
- If present in the model already: this finding is a false positive and the issue can be closed.

## Done when

- [ ] Both findings either confirmed and addressed, or refuted and closed.

## Comments

### 2026-05-31

Both claims verified against the vendored XSDs:

1. **PA.is_final**: confirmed missing in `model/provision.py`. `MaintainableType` in 2.1 `SDMXStructureBase.xsd` has `@isFinal` (optional, default false). 3.0 and 3.1 `MaintainableType` (in `SDMXCommon.xsd`) dropped the attribute entirely. So PA needs `is_final` for 2.1 round-trip fidelity; 3.0/3.1 writers ignore it.

2. **Dataflow.dimension_constraint**: confirmed new in 3.1 (`SDMXStructureDataflow.xsd` `DataflowType`). Optional single `<DimensionConstraint>` carrying 1+ `<Dimension>id</Dimension>` children. Real semantic content for evolving-DSD support — declares the Dataflow's committed dimension surface independent of future DSD growth. Absent from 3.0.

Closing this issue. The `is_final` fix is small enough to fold into the #111 enum-cleanup MR (both being model consistency fixes). The `dimension_constraint` work gets its own issue.
