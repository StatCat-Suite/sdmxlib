Correction to the section that got mangled by shell quoting:

**2. The column.** A component living on the sidecar has to render against the *sidecar's* alias, not the root's. Today `Observations.__getitem__` builds `Untyped((), self.__table__, column)` and every column resolves to the root alias. A `USING` join merges only the join *keys*, so a non-key sidecar column referenced as `s0.GEO_NAME` is a binder error.

So the root has to know which table each component lives on — which means `Observations` needs the inspector's plan. It is built from a binding alone today, and `DuckDBDataStore.observations` is where an inspector is in scope, so that is the natural place to pass it in.
