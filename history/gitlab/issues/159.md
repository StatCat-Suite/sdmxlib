# Issue #159: Serializer round-trip audit: systematic silent field drops across ML/JSON/storage (post #157/#158)

| | |
| --- | --- |
| State | closed |

## Summary

Follow-up to #157 / #158 (SDMX-JSON + SDMX-ML annotation drops). A
systematic audit of **all** serializer pairs (SDMX-ML 2.1, SDMX-ML 3.0
structure + GenericMetadata, SDMX-JSON structure + metadata, DuckDB
storage) found the annotation bug was one instance of a broad class:
**model fields with a wire representation that one side of a reader/writer
pair handles but the other silently drops**, so data is lost on
round-trip.

Findings are split into **A. asymmetric drops** (data present is silently
lost — the dangerous category) and **B. symmetric gaps** (the wire can
carry it but neither side does — real fidelity holes, no regression).

Each item below was verified with a constructed-object round-trip repro
(build → serialise/persist → parse/read → compare).

## A. Asymmetric silent drops (data present → lost)

1. **SDMX-JSON structure: `isFinal` dropped on ALL maintainables.**
   `sdmx_json/reader.py` parses `isFinal` in 8+ places; `sdmx_json/writer.py`
   emits it **nowhere**. `Codelist(is_final=True)` → JSON has no `isFinal`
   key → round-trips to `is_final=False`. Affects all 14 maintainable
   sections. **HIGH.**

2. **DuckDB storage: `valid_from`/`valid_to` dropped on all maintainables**
   (except HierarchyAssociation). `storage/writers.py` persists them to the
   `artefact` spine and `_read_spine` selects them, but only
   `_read_hierarchy_association` passes them to its constructor. Codelist
   stored `(2020-01-01, 2021-01-01)` → read back `None, None`. **HIGH.**

3. **SDMX-ML 2.1: `MeasureDimension` dropped entirely by the writer.**
   `sdmx_ml21/reader.py:_read_measure_dimension` parses it onto
   `DataStructure.measure_dimension`; `_write_data_structure` never emits
   it. Cross-sectional 2.1 DSDs lose the component silently. **HIGH.**

4. **SDMX-JSON structure: RepresentationMap regex/index maps collapse to
   literal.** `_write_representation_map` emits every `ValueMap` as a plain
   `{sourceValues,targetValues}` with no `isRegEx`/`startIndex`/`endIndex`;
   the reader only rebuilds `LiteralValueMap`. `RegexValueMap` /
   `IndexValueMap` round-trip to `LiteralValueMap` — semantic corruption,
   not just loss. **HIGH.**

5. **SDMX-ML 3.0 metadata: `MetadataSet.valid_from/valid_to` dropped by
   reader.** `metadata.py:_write_metadata_set` emits `validFrom`/`validTo`;
   `_read_metadata_set` never reads them. MED-HIGH.

6. **SDMX-JSON metadata: `MetadataSet.valid_from/valid_to` dropped by
   reader.** Same shape as #5 in `sdmx_json/metadata.py`. MED-HIGH.

7. **SDMX-ML 2.1: Agency / DataProvider item annotations dropped by
   writer.** Readers parse them; `_write_agency` / `_write_data_provider`
   emit only id/name/description. (The two org item types #158's fix did
   not cover — they have hand-written writers, not the shared `_common`
   item writers.) MED. *(Check the ML-3.0 org item writers for the same
   gap while fixing.)*

## B. Symmetric gaps (wire supports it, neither side does)

Storage (no schema columns → never written, never read):
- **`Attribute.related_dimensions` / `related_measure` / `related_group`**
  — the AttributeRelationship is lost when a DSD is persisted. (High-value
  structural semantics — consider promoting.)
- `Codelist.extensions`, `Concept.core_representation` facet detail
  (min/max value, decimals, pattern, is_sequence, start/end value),
  `Facet.is_multi_lingual` (all representations), `Level.coding_format` +
  `Level.annotations`, `Contact.faxes` / `x400s`,
  `DataConstraint.reference_period` / `release_calendar`,
  RepresentationMap non-literal maps + primitive-dataType endpoints +
  per-mapping validity + `maps` ordering.

SDMX-JSON:
- **`concept_role`** on DSD components — survives SDMX-ML round-trip but is
  dropped by both JSON sides.
- `Hierarchy.has_formal_levels`, `HierarchicalCode.valid_from/valid_to`,
  per-mapping `ValueMap.valid_from/valid_to`, `Level.coding_format`,
  `ReportedAttribute.annotations`.

SDMX-ML metadata:
- `MetadataSet.annotations`, `ReportedAttribute.annotations`
  (both also produce non-conformant output where the XSD allows the block).

## Cross-cutting themes

- **Validity bounds** (`valid_from`/`valid_to`) are mishandled in three
  independent layers (storage reader, ML-3.0 metadata reader, JSON metadata
  reader).
- **Annotations** keep leaking at the edges (org items, metadata layer).
- **`isFinal`** never reached the JSON writer.

## Why tests missed this

Every round-trip test asserts only on the fields it happens to populate,
and none populated these. A **generic "every model field survives
round-trip" property test per format** (parametrised over a
fully-populated instance of each artefact type, with `xfail` markers for
the known B gaps) would catch this whole class and prevent regressions.

## Plan

- Fix all of **A** now (per-format round-trip + XSD-validation tests).
- **B** tracked here as follow-ups.
- Add the generic per-format round-trip property test as the durable guard.

## Closing summary

Audit complete. Of 20 identified serializer round-trip gaps, **18 are fixed** across 6 merged MRs (!125–!130) plus a serialize micro-opt (!131), all shipped in **v0.44.1**:

- **Table A (asymmetric silent drops):** annotations (JSON + ML items), isFinal (JSON), MeasureDimension (ML 2.1), RepresentationMap regex/index discriminators (JSON), MetadataSet validity (JSON + ML 3.0 metadata), org-item annotations (ML), storage maintainable validity.
- **Table B (symmetric gaps):** storage facet detail / is_multi_lingual / attribute relationships / contact fax+x400; ML 2.1 concept_role + `<Contact>`; JSON concept roles / hasFormalLevels / level codingFormat / hierarchical-code + per-mapping validity; ML 3.0 level codingFormat.

A generic per-format round-trip **property guard** (!126, `test_roundtrip_property_guard.py`) now guards against regressions and self-tracks remaining gaps via strict xfails.

**2 remaining guard xfails are permanent by-design** (wire format cannot carry them): SDMX-ML 2.1 CodeMapType has no per-mapping validity; SDMX 3.0 dropped isFinal.

**Remaining storage work** (lower blast-radius, not guard-exercised) split out to #160: Codelist extensions, DataConstraint reference_period/release_calendar, storage Level codingFormat.

Closing — follow-on tracked in #160.
