## The question

> Why can we represent invalid state in our internal model? Shouldn't
> validation occur on ingest/creation?

Today's answer is deliberate, and recorded in two places:

- `_check_required_content`: *"a field is optional so a partially-assembled
  artefact stays storable, and this re-asks the question when the artefact
  is about to become a document."*
- `_check_version`: *"a store is format-agnostic … only writing picks a
  format."*

That reasoning holds for rules that **depend on the format**: whether a
`DataStructure` with three measures is valid depends on whether you
write 2.1 or 3.0. It does **not** hold for rules where every format gives the
same answer. For those, deferring the check to the writer has three costs:

1. **The store holds artefacts that no format can express.** A consumer
   serving from a `LocalRegistry` (sdmxlib-rest, for one) learns this
   per request, as a 500, for an artefact it was allowed to register.
2. **Every writer has to repeat the rule, and they drift apart.**
   The org-scheme version check covers SDMX-ML but not JSON, and covers two
   scheme types but not the third (#416). The version grammar is
   checked by the ML writers but not the JSON writer (#417).
3. **A silent drop that every format declares is still a silent drop.** The
   register in `gaps.py` lists nine rules whose target set is *all four
   formats*. The model accepts the field, and nothing anywhere can ever write
   it.

## Proposal

Split the rules by **whether the answer depends on the format**:

- **Format-independent → enforced at `Registry.add` / `add_all`**, or better,
  made unconstructible. A builder or `attrs.evolve` chain may still pass
  through partial states; `add` is the boundary where an artefact becomes
  *registered*, and a registered artefact should be writable to at least
  one format.
- **Format-dependent → stays at the writer**, as the explicit projection
  step (refuse, declared drop, or convert), reported through
  `unrepresentable(artefact, target)`.

`_FIXED_SCHEME_IDS` is the precedent. It pins a value that every schema pins
and is enforced in `validate()` today. Everything in the first table below has
the same shape.

## What this is not

- **Not "readers become strict."** A reader still accepts what a real
  registry publishes, and reports. The change is that a tolerant read
  hands the caller a `ValidationReport` with the artefact, rather than a
  registered artefact that fails later.
- **Not a single global switch.** sdmxlib-rest considered and rejected one
  ("serve anyway / refuse"). The useful output is a precise error at `add`
  that names the artefact and the rule.

## Breaking

Yes. Registering an artefact that `add` used to accept now raises. Pre-1.0
this is a minor bump, but it needs a deprecation window (warn for one release,
then raise), because real bundles will contain some of these artefacts.
