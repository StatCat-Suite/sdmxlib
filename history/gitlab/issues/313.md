# Issue #313: cookbook tail: six Query/Frame methods have no entry, including unique() and explain()

| | |
| --- | --- |
| State | closed |
| Opened | 2026-08-14 |
| Closed | 2026-08-17 |
| Milestone | %17 Query DSL: a second backend, and the evidence the first one lacks |
| Labels | `dsl`, `type::docs` |

#278 asked that every %15 capability ship an executable cookbook entry. Swept
the shipped `Query` / `Frame` / `Grouped` / `Page` surface against
`docs/cookbook/` and its drivers; six methods have no entry:

| method | what it is |
| --- | --- |
| `Query.explain` | the plan, without running it |
| `Frame.explain` | the same for a projection |
| `Query.one` | exactly one row, or raise |
| `Query.one_or_none` | at most one row |
| `Query.preview` | a bounded head, for a REPL |
| `Frame.unique` | `SELECT DISTINCT` |

Two of these are real capabilities rather than conveniences.

**`Frame.unique`** is `SELECT DISTINCT`, and it carries a decision worth
documenting: it is **full-row only and takes no arguments**, because a subset
form fails twice over — `filter(keep).unique(agency)` and
`unique(agency).filter(keep)` return different rows, so it would not commute
with `filter`, and it leaves *which* row of each group survives unspecified.
Excluding the subset form keeps `unique` in the commuting set rather than
adding a carve-out to the third composition law. A caller wanting one row per
group has `group_by(...).agg(...)`, which says which one.

**`explain()`** is the inspectability half of the design — the same instinct
as the `sql_corpus` and the mutation benchmarks. It becomes *total* precisely
because nothing executes implicitly, which is the argument strict laziness was
adopted for. Undocumented, it is invisible.

`one` / `one_or_none` are the terminals a caller reaches for when a query
should identify a single artefact, and their difference (raise vs `None`) is
the sort of thing people guess wrong.

## Scope

Add them to an existing page rather than a new one — `discovery.md` for the
terminals and `explain`, `structures_as_frames.md` for `unique` — with driver
tests in the existing style. Cheap; it is the tail of #278 rather than new
work.

## Why file it rather than leave #278 open

#278 is a %15 deliverable and %15's capabilities all have entries now. This is
the residue found by sweeping the surface afterwards, and it belongs with the
follow-up work rather than holding the milestone open.
