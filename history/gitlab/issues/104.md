Surfaced by the v3.1.0 XSD vendoring (MR !63) — \`tests/unit/test_xsd_schemas.py::test_minimal_30_diverges_from_31_on_known_attrs\`.

## What changed

SDMX 3.1 removed the \`role\` attribute on \`DataConstraint\`. In 3.0:

\`\`\`xml
<str:DataConstraint id=\"CC_TEST\" agencyID=\"TEST\" version=\"1.0\" role=\"Allowed\">
\`\`\`

In 3.1, \`role\` is no longer an attribute on the element. The semantic (Allowed vs Forbidden) is likely now expressed elsewhere — either via a separate element or via the CubeRegion's existing \`include=\"true|false\"\` flag at scope.

## Action when adding 3.1 emission

- Audit the 3.1 \`DataConstraintType\` complexType (see \`tests/schemas/sdmx_ml31/SDMXStructureConstraint.xsd\`) to figure out the replacement representation.
- \`sdmx_ml31/writer.py\` (when added): emit DataConstraint without \`role=\`; map the model's \`constraint_type\` value to whatever 3.1 uses.
- Reader: parse the new shape; keep the 3.0 \`role=\` path for backward compat.
- Update \`test_minimal_30_diverges_from_31_on_known_attrs\` to drop \`role\` from the expected divergence list once 3.1 emission lands.
