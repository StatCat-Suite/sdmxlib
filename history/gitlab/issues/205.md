Found while implementing strict read-boundary conformance (!190). Filed rather than fixed there — it is a separate, larger surface.

## The gap

`tests/unit/test_roundtrip_property_guard.py` round-trips every structural field through json / ml21 / ml30, but **never validates the emitted XML**. CLAUDE.md is explicit about why that matters:

> XSD validation catches a class of writer bugs that pure round-trip can't: the writer emits non-conformant XML that our own reader tolerates.

That is exactly what happened. The guard stayed green while its hierarchy case emitted a `<Code>` reference carrying a *codelist* URN — the XSD requires `.codelist.Code=`. Reader and writer agreed with each other, so the round-trip passed. !190 found it only because the strict reader check refused the URN.

## Wiring XSD validation in

Adding four lines to `_roundtrip_structure` — validate `writer.write(msg)` against `compile_structure_schema(version)` before re-reading, for `ml21` and `ml30` — takes the file from 2 failures to **25**. Distinct violations:

```
Element 'Attribute': The attribute 'assignmentStatus' is required but missing.
Element 'CodingFormat', attribute 'textType': value 'String' is not in the enumeration
Element 'ConceptRole': [facet 'pattern'] The value '' is not accepted by '.+\.conceptscheme\.Concept=...'
Element 'ConceptRole': Element content is not allowed, because the type definition is simple.
Element 'DataStructureComponents': Missing child element(s).
Element 'Parent': This element is not expected.
```

These are a mix of genuine writer bugs (`assignmentStatus` omitted; `ConceptRole` emitted as an element with content where the XSD wants a simple URN-typed body) and fixtures that construct states the schema does not allow (`CodingFormat/@textType="String"` is not in the 3.0 enumeration).

The patch that produces this is saved in !190's discussion; it is four lines plus imports.

## Why it matters more now

!190 made the *reader* strict about reference classes. A writer that emits non-conformant XML now produces messages **sdmxlib itself will refuse to parse** — the round-trip is no longer self-consistent by construction. Each of the 25 needs triage into "writer bug" vs "fixture builds an impossible artefact", and the second category is a `validate()` gap.

## Suggested approach

1. Land the four-line harness change with `xfail` markers carrying one-line diagnoses, so the count can only go down.
2. Fix the writer bugs (`assignmentStatus`, `ConceptRole`) — those are real emitted-output defects affecting anyone consuming our XML.
3. Fix or delete fixtures that build schema-impossible states; consider whether `validate()` should reject them at construction.

## Acceptance

`test_roundtrip_property_guard` validates every emitted XML payload against the vendored XSDs, with zero unexplained failures.
