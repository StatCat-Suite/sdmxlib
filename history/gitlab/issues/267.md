Byte-identical today: `_FieldExpr`, `_AnnotationField`, `_AnnotationTextField`, `_AnnotationRef`, `_AnnotationTextRef`, `_AnnotationsAccessor`, `_NameField`, `_NameAccessor`, `_NameLangRef`, `_StringRef`, `_LabelRef`, `_FoldedOps`, `_Eq`, `_StringMatch`, `_IsNull`, `_Cmp`, `_InSet`, `_SortKey`, `_HasAncestor`, `_IsAncestorOf`, `_AnyAncestorMatches`, `_AnyDescendantMatches`, `Predicate`.

## Why this is not merely untidy

**The duplication has produced real bugs, repeatedly.**

- **#255** exists *because* the two drifted: accent/punctuation folding was added to `code_query` in two commits and never to `hierarchy_query`, so the same query against a hierarchy holding the same labels silently returned nothing. Nobody decided that; one file was edited.
- **#248**'s hop-bound defect was, in its own commit message, "four emitters across the two query DSLs" — the identical bug, written twice, fixed twice.
- **#254**'s annotation-JOIN duplication: same, both modules.

Every fix this milestone has been applied twice by hand. That is the failure mode, not the inconvenience.

**It compounds with the remaining work.** #262 adds `_And` / `_Or` / `_Not` — three more predicate classes, three more emitters, two more dispatch-table entries, all of which would be written twice. So the sequencing question is real: factor first, or accept a third round of copying and a third opportunity to drift.

## What genuinely differs, and must stay parameterised

A naive merge is wrong. The 16 materially-different names are the real content:

| axis | `code_query` | `hierarchy_query` |
| --- | --- | --- |
| table | `sdmx.code` | `sdmx.hierarchy_node` |
| row alias | `c` | `hn` |
| key column | `code_id` | `node_id` |
| parent column | `parent_id` | `parent_node_id` |
| annotation owner | `code_urn` | `node_urn` |
| scope column | `codelist_urn` | `hierarchy_urn` |
| default order | `position NULLS LAST, code_id` | `node_id` |
| extra fields | — | `level`, `code` (a URN into another artefact) |
| extra predicates | `_InHierarchy`, `_IsDescendantOf` | — |
| coercion | none | `_coerce_value` for `Level` / `Ref[Code]` / `SdmxUrn` |
| row → object | `Code` | `HierarchicalCode` |

Eleven axes, of which most are a column name. That is a table-shaped parameterisation, not an inheritance hierarchy.

## Scope

- A shared private module — `model/_query_common.py`, following the precedent `model/_label_match.py` set in #255 (plain names, private module, CLAUDE.md rule 4). Not `sdmxlib.sql`: that is the public cross-library seam and this is compiler internals, the same reasoning applied in #255.
- Move the field expressions, the predicate dataclasses, the ref hierarchy (`_Ref` / `_StringRef` / `_LabelRef` / `_FoldedOps` and the accessors), and the emitters that differ only by column name.
- Parameterise on a small frozen descriptor carrying the table above, threaded to the emitters rather than baked in.
- Each DSL keeps: its accessor namespace (`code` / `node`), its genuinely distinct predicates, its row→object construction, and its query class.
- The two `test_every_predicate_kind_is_covered` tests must keep working — they enumerate `Predicate` subclasses off each module, so the shared base needs re-exporting or the tests need pointing at the shared module.

## Explicitly not in scope

**The oracles stay duplicated.** `tests/support/oracle.py` and `hierarchy_oracle.py` restate rather than share, deliberately: two oracles that share a helper can be wrong the same way, which is the one failure mode differential testing cannot catch. That argument is about *test* independence and does not transfer to production code — do not "tidy" the oracles while doing this.

## Risks

- **This is a large, low-value-looking diff over code with excellent test coverage.** That is the good case for a refactor, but it should land alone, not folded into a feature.
- **A descriptor threaded through every emitter can become its own complexity.** If the parameterisation needs more than the table above, that is a signal the two are less alike than they look and the refactor should stop early rather than force it.
- Both modules are on the `just test-properties` list; the 20× run is the acceptance gate, not `just ci`.

## Test gates

- No behaviour change: both differential property suites pass unchanged, at 20×.
- `just ci` green; no new suppressions. `src/` currently has zero complexity suppressions (#263 retired the last one) and this must not reintroduce any.
- Duplicated-line count re-measured and reported in the MR, using the same method as above.

## Comments

### 2026-08-09

## Correction: the class hierarchy *can* be shared

!256 shares the type-free half (~184 lines) and its first revision argued the remaining ~411 could not be shared, because each DSL's own `Predicate` base is what makes both checkers reject a cross-DSL predicate.

**That argument was wrong.** It framed the choice as share-the-base or don't, and skipped the option that resolves it: a **generic** shared base.

```python
# shared
class Predicate[D]: ...

@attrs.frozen
class Eq[D](Predicate[D]):
    field: FieldExpr[D]
    value: object
    negate: bool = False

# code_query
class CodeDialect: ...
def filter(self, predicate: Predicate[CodeDialect]) -> CodeQuery: ...
```

Prototyped and verified — both checkers still reject the cross-DSL call, and accept the correct ones:

```
basedpyright: Type parameter "D@Predicate" is covariant, but
              "NodeDialect" is not a subtype of "CodeDialect"
pyrefly:      Argument `Predicate[NodeDialect]` is not assignable to
              parameter `predicate` with type `Predicate[CodeDialect]`
```

attrs frozen classes work under PEP 695 generics at runtime: `eq`, `hash`, frozen enforcement and subscripted construction all behave, and every parameterisation is **one runtime class** — which matters, because the `_EMITTERS` tables key on `type(pred)`.

## Remaining scope

- A phantom dialect marker per DSL (`CodeDialect` / `NodeDialect`), carried on `FieldExpr[D]`, `Predicate[D]` and `Ref[D]`.
- Move generically: the predicate dataclasses (`Eq`, `StringMatch`, `IsNull`, `Cmp`, `InSet`, `HasAncestor`, `IsAncestorOf`, `HasNoNarrower`, `AnyAncestorMatches`, `AnyDescendantMatches`), `SortKey`, the common field expressions (`NameField`, `AnnotationField`, `AnnotationTextField`, `DepthField`), and the ref hierarchy (`Ref`, `StringRef`, `LabelRef`, `FoldedOps`, the name and annotation accessors).
- Each DSL keeps: its dialect marker, its own field types (`IdField` vs `NodeIdField`, plus hierarchy's `LevelField` / `CodeUrnField`), its accessor namespace, its column mapping, its `_EMITTERS` table, its query class, and its row→object construction. `code_query` additionally keeps `InHierarchy` / `IsDescendantOf`.
- Re-export the shared `Predicate[D]` alias as each module's public `Predicate`, so `sl.Predicate` and the `sdmxlib.sql.Predicate` protocol conformance are unchanged.

## Watch for

- **`test_every_predicate_kind_is_covered`** in both property files enumerates `Predicate` subclasses out of each module. It will need to enumerate the shared module plus module-local kinds. Do not weaken it — it has caught three missing properties this milestone.
- **Runtime separation genuinely does go away** (the phantom is erased), unlike the static one. A predicate smuggled across DSLs past the type checker would hit the column mapping instead — `IdField` is not in hierarchy's map — so it still errors, just from the field rather than the predicate. Worth a test pinning that.
- **`sl.CompileContext` / `Predicate.to_sql(ctx)`** are the public cross-library seam. The alias must keep pinaxlib's usage compiling.

## Gate

Behaviour-preserving: no test should change except the predicate-kind enumeration. Both differential suites at 20× are the acceptance gate, plus a basedpyright *and* pyrefly probe asserting the cross-DSL rejection survives.

Done in two steps — !256 (the type-free half) and !258 (the generic fold).

| | start | after !256 | after !258 |

| duplicated lines | ~600 | ~411 | **~119** |

| `code_query.py` | 1391 | 1240 | **882** |

The predicate AST and ref hierarchy are generic in a `RowKind` — the relation a predicate filters — carried on `CompileContext[R]` rather than on the predicate, so predicates stay pure data and refs stay pure factories.

**Beyond deduplication**, the change added a guarantee that did not previously exist: a mismatched *context* is now a type error, not only a mismatched predicate.

```python
q.filter(sl.node.id == "A")                     # was an error
(sl.code.id == "A").to_sql(sl.node.context())   # now an error too
```

## What the issue got wrong, recorded for the next reader

The first attempt argued the class hierarchy **could not** be shared without losing the static separation each DSL's own `Predicate` base provides. That was wrong — it framed the choice as share-the-base or don't, and skipped the generic base that resolves it. The false reasoning briefly reached a module docstring and an MR description before being corrected.

## Verified

- **SQL byte-identical to the pre-refactor `main`** across all 61 cases in `tests/support/sql_corpus.py` — so execution cannot have regressed, exactly rather than statistically.
- `just ci` green; `just test-properties` at 20× — 73 passed.
- Performance against the !257 baseline: `is_in` × 5000 within 0.5%, small compiles +3–6%.

Two regressions were caught by the !257 baseline and fixed, neither of which would have failed a test: runtime generic subscripting on `_field` (**+24%** of a single-predicate compile) and the shared `_coerce` hook running per element in `is_in` (**+88%** at width 5000).

The residual +3–6% on small compiles is real, stable, and left in deliberately — two extra calls per predicate against a compile that is ~1% of a 216 µs query, so +0.05% end to end.
