# Issue #423: Tracking: 2.1 ↔ 3.x incompatibility catalogue for a 3.x-native model

| | |
| --- | --- |
| State | closed |
| Opened | 2026-10-05 |
| Closed | 2026-10-15 |
| Milestone | %20 3.x-native model: hold all of 3.x, project to 2.1, validate at ingest |
| Labels | `conformance`, `design`, `status::started` |

## Goal

The internal model is **SDMX 3.x-native**: it can hold everything a 3.x
document carries, and SDMX 2.1 is a **projection** ("downmux"), with every
loss declared.

The model is currently documented as the opposite (`formats/gaps.py`): *"a
**union** of the SDMX 2.1 and 3.0 information models"*. A union holds both
shapes of each concept. That is how a 2.1 MeasureDimension and a 3.0
multi-measure list coexist on one `DataStructure`, and how `is_final` sits
beside a 3.0 version string. The union reads and writes most documents
correctly. It cannot answer "what is this artefact in 3.x terms", and it lets
the store hold states that no format can write.

This issue is the catalogue. The individual pieces are in this milestone:

| # | issue | kind |
|---|---|---|
| #416 | organisation-scheme version is `1.0` in every format; JSON writes invalid; MetadataProviderScheme silently loses it in 3.x | bug |
| #417 | SDMX-JSON writer applies no version grammar; two comments say the JSON structure schema has none | bug |
| #418 | `CodelistExtension.codelist` accepts a string, and the 3.0 writer crashes | bug |
| #419 | validate format-independent rules at `Registry.add` | design, breaking |
| #420 | version and finality: one 3.x-native model, projected to 2.1 | design, breaking |
| #421 | union shapes → one canonical 3.x shape plus declared conversions | design |
| #422 | 3.x content the model cannot hold, lost silently on read | model |

Everything below was measured on `main` @ `6cf7bc5`, against the vendored
schemas, using `declared_gaps()`, `model.validation`, and probes through
`serialize(..., validate=True)` with `_is_schema_valid` from
`tests/unit/test_wire_conformance_gate.py`. Each XSD occurrence claim
was checked by hand. A tool diff of the 2.1 vs 3.0 XSDs gets
`use="prohibited"` and choice-level `minOccurs` wrong, so it was used only to
find candidates.

## A. Foundational incompatibilities: the model's core has to pick a side

| area | 2.1 | 3.x | model today | decision needed | issue |
|---|---|---|---|---|---|
| version grammar | `N(.N)*` | legacy `N(.N)?` or semver `N.N.N(-pre)?`; JSON metadata semver only | union (also accepts `1.2.3.4-draft`, valid in neither) | structured `Version`; how to handle `1.03` and `1.2.3.4` at ingest | #420 |
| finality | `isFinal` on every maintainable | none: the version carries it | stored `is_final`; 3.x drops it | derive `is_final` from the version | #420 |
| organisation-scheme version | fixed `1.0` | prohibited (3.x ML), `const 1.0` (JSON) | any string | fix it at `1.0` | #416 |
| measures | one `PrimaryMeasure` `OBS_VALUE` + `MeasureDimension` | `MeasureList` 0..n | both | canonical `measures[]`, convert `MeasureDimension` | #421 |
| hierarchies | HCL (maintainable) ⊃ Hierarchy (nameable) | Hierarchy (maintainable) + `HierarchyAssociation` | both | canonical 3.x, HCL as provenance | #421 |
| maps | `StructureSet` ⊃ nameable maps | top-level maintainable maps | both | canonical 3.x | #421 |
| constraints | `ContentConstraint` + `AttachmentConstraint` | 3.0 `DataConstraint`/`MetadataConstraint`; 3.1 split into Data/Availability | `DataConstraint` + `AttachmentConstraint` | pick the 3.1 model (#69) | #421 |
| MSD | targets + report structures | flat attribute list; targets on `Metadataflow` | both | canonical 3.x | #421 |
| provision | one PA → any `StructureUsage` | PA (data) + `MetadataProvisionAgreement` | both | canonical 3.x; project MPA to a 2.1 PA | #421 |
| codelist extension | none | `extensions[]` | 3.x | materialise on 2.1 projection | #421 |
| references | `<Ref>`; version optional ("latest") | URN, version required; wildcards and ranges | `SdmxUrn` + `"latest"` sentinel | model wildcard and range refs | #422 |
| annotations | single URL, no value | localised multi-URL, `AnnotationValue` | single URL; value present | multi-URL | #422 |

## B. Valid in the model, invalid or lossy only when written to a format

This is the table asked for: states that pass `validate()` and only fail
when an artefact is reified into a particular document.

**B1. Format-independent: no format can write it.** These belong at
ingest. The full table, with today's handling, is in #419. Headline rows:

| state | every format | today |
|---|---|---|
| organisation-scheme `version != "1.0"` | not writable | ML refused for 2 of 3 types; **3.x silent loss** for MetadataProviderScheme; **JSON invalid** for all |
| `Agency.parent`, `DataProvider.parent` | dropped | declared drop |
| `enumeration_format.decimals` / `.is_multilingual` | dropped | declared drop |
| `Level.coding_format.decimals` / `.is_multilingual` | dropped | declared drop |
| `HierarchicalCode.name` / `.description` | dropped | declared drop |
| version valid in neither grammar | not writable | stored by design; ML refuses; JSON unchecked |
| empty tree / dimensions; map without source or target | not writable | refused at write; storable on purpose |
| component with no concept | not writable | refused at message level only |
| `Ref` field holding a `str` | — | 3.0 writer **crashes** |
| item `uri` | writable | the **store** drops it (`gaps.py` target `storage`) |

**B2. Format-dependent: legitimately a projection question.** Status is one of:
*refused* (raises, with a message naming the artefact), *declared drop* (in
`gaps.py`; `unrepresentable()` reports it), *converted* (written in another
shape), or **silent** (a bug).

## C. 3.x content the model cannot hold

Lost on read, silently. This blocks the 3.x-native goal more directly than
anything in B. The full list is in #422: multi/localised `AnnotationURL`,
`ValueList`, geo codelists, `MetadataConstraint`, `Link`, N:M `ComponentMap`,
`CubeRegion` validity, `SentinelValue`, min/maxOccurs on DSD components,
`MeasureRelationship`, `MetadataAttributeUsage`, `@position`, and wildcard/range
references.

## D. Not modelled in either version

`Process` (#361), `ReportingTaxonomy`, `DataConsumerScheme`,
`OrganisationUnitScheme`, and the VTL schemes. Out of scope; listed so
"exhaustive" means something.

## Relation to earlier milestones

- **m11 Wire conformance** ("no artefact serialises to an invalid document")
  closed with `KNOWN_INVALID = 0`, but over *bare* artefacts. The
  silent-invalid cases in B are all populated fields (a non-default version,
  an extension). Extending the conformance gate's fixtures to **populated**
  artefacts, one per row of B, would have caught #416 and #417.
- **m12 Cross-version conversion** measured 2.1 → 3.0 → 2.1. The
  3.x-native goal needs the opposite direction as the primary one:
  3.x → model → 3.x lossless, and 3.x → model → 2.1 with declared losses.

## Suggested order

1. Bugs #416, #417 and #418: small, and independent of the design.
2. #420 (version and finality). Everything else keys on artefact identity.
3. #419 (ingest validation), with a deprecation window.
4. #421 measures and extensions, then hierarchies, maps and constraints.
5. #422, row by row: model it or refuse it on read.
