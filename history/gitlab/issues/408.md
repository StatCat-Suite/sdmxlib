# Issue #408: Dataset.validate can never report an invalid code after scan_csv — the DSD-derived pl.Enum schema raises first

| | |
| --- | --- |
| State | closed |
| Opened | 2026-09-28 |
| Closed | 2026-09-28 |
| Labels | `api`, `bug`, `data`, `usability` |

`Dataset.validate` is documented as returning a report of coded values that are
not members of their component's codelist, and both its docstring and the
`Dataset` class example reach it through `scan_csv`:

```python
ds = slpl.scan_csv("data.csv", dsd)
report = ds.validate()
```

That path cannot produce a non-empty report. `scan_csv` builds the Polars schema
from the DSD, so an enumerated component is typed `pl.Enum` over its codelist,
and a value outside it is a **parse error on read** — raised before `validate`
has anything to look at. The report comes back empty or the call raises; it
never reports.

## Repro

```python
from pathlib import Path
import polars as pl, sdmxlib as sl, sdmxlib.polars as slpl

A, V = "AGENCY", "1.0.0"
cs = sl.ConceptScheme(id="CS", maintainer=A, version=V, name={"en": "Concepts"},
                      concepts=[sl.Concept(id=i, name={"en": i}) for i in ("AREA", "TIME_PERIOD", "OBS_VALUE")])
cl = sl.Codelist(id="CL_AREA", maintainer=A, version=V, name={"en": "Area"},
                 codes=[sl.Code(id="CA", name={"en": "Canada"})])
dsd = sl.DataStructure(
    id="DSD", maintainer=A, version=V, name={"en": "DSD"},
    dimensions=[sl.Dimension(id="AREA", concept=cs.ref_to("AREA"), representation=sl.Ref.to(cl))],
    time_dimension=sl.TimeDimension(id="TIME_PERIOD", concept=cs.ref_to("TIME_PERIOD")),
    measures=[sl.Measure(id="OBS_VALUE", concept=cs.ref_to("OBS_VALUE"))],
)

csv = ("STRUCTURE,STRUCTURE_ID,ACTION,AREA,TIME_PERIOD,OBS_VALUE\n"
       "dataflow,AGENCY:DF(1.0.0),I,XX,2020-01,1.0\n")      # XX is in no codelist
Path("bad.csv").write_text(csv)

slpl.scan_csv(Path("bad.csv"), dsd).validate()   # raises
slpl.scan_csv(csv.encode(), dsd).validate()      # raises
```

```
polars.exceptions.ComputeError: could not parse `XX` as dtype `enum`
at column 'AREA' (column number 4)
```

Both source kinds, path and bytes.

The machinery underneath is fine — give it a frame that was not typed from the
DSD and it does exactly what the docstring says:

```python
frame = pl.DataFrame({"AREA": ["XX"], "TIME_PERIOD": ["2020-01"], "OBS_VALUE": [1.0]})
sl.Dataset(structure=dsd, data=frame.lazy()).validate()
# [{'column': 'AREA', 'invalid_value': 'XX', 'count': 1}]
slpl.validation_report(dsd, frame)
# [{'column': 'AREA', 'invalid_value': 'XX', 'count': 1}]
```

So `validate` is reachable only by building the `Dataset` by hand, which is the
one construction path the docs do not show.

## Why it matters

The two behaviours answer different questions and both are wanted:

- *Is this file usable at all?* — the `pl.Enum` schema, which fails fast and
  cheaply. Correct default for a pipeline.
- *What exactly is wrong with this file, and how much of it?* — the report,
  with column, value and count. This is what you want when a supplier sends a
  bad extract and you have to tell them what to fix. A `ComputeError` naming
  one value and a byte offset is not that.

Right now the second is unavailable for the format the library reads.

A related wrinkle: the failure is also *partial*. `ComputeError` stops at the
first bad value, so a file with 400 bad codes across 3 columns reports one.

## Suggested fix

Either of these, or both:

1. `scan_csv(..., coerce=False)` (or `strict=False`) reading enumerated columns
   as `pl.String`, so `validate` can do its job. The DSD still drives the
   non-enumerated dtypes.
2. `Dataset.validate` growing a documented note that after `scan_csv` it is
   vacuous, and the class example moving to the hand-built path — the cheap
   fix, if the fail-fast behaviour is considered correct and sufficient.

(1) is the more useful of the two: "tell me everything wrong with this file"
is a real question with no current answer.

## Side note on the docs

`sdmxlib.polars.scan_csv` is a narrowed convenience wrapper over
`sdmxlib.formats.sdmx_csv.reader.scan_csv`, dropping `infer_schema_length` and
`dataflow`. Its docstring says *"Convenience entry point. For full options see
`scan_csv`."* — which resolves to itself. It should name the underlying
function, or the wrapper should forward the two options.
