## Why write it down

Three passes have now re-derived this same list — #170's original audit, #200's census ("32 `: Any` parameters, all inside the exempted shell"), and the #170 re-scope. That is three times the cost of one comment.

ANN401 is already off for `formats/**` (`ruff.toml:115`), so there is no suppression to add and nothing to silence — the lint config *is* the machine-readable half of this decision. What's missing is the per-site half: which of the exempted `Any`s are deliberate and which are merely unexamined. Right now a reader can't tell the two apart, which is exactly what made #170 over-scope in the first place.

## Proposed form

One short comment per cluster (not per line) naming the boundary — decoded-JSON value, heterogeneous index, open payload — plus a pointer to CLAUDE.md's "typed core, untyped shell". Prose only; no code change, no config change.

## Comments

### 2026-08-05

**Add an eighth site: `storage/readers.py` `get_artefact -> Any | None`.**

Surfaced by !189. #200's table counts **6** `-> Any` returns but its body enumerates only 5 — this is the missing one, and the verdict is document-and-keep, which makes it this issue's rather than #200's.

Why it stays `Any`:

* It dispatches on the stored `artefact_type` string through `_READERS`, so the return genuinely varies per row — there is no single static type to give it.
* **66 call sites** (14 in `src/`, 52 in tests). Narrowing to `object | None` would require a narrowing step at every one; that is a redesign of the storage read seam, not a leak fix.
* It sits in the ANN401-exempt shell (`ruff.toml:120`), and the *typed* seam already exists above it — `Registry.get[T]`, which recovers the type from a witness. `get_artefact` is the untyped layer that one is built on, which is exactly the "typed core, untyped shell" split.

Suggested comment: name the dispatch, and point at `Registry.get[T]` as the typed entry point callers should prefer.

Note this makes the issue title's "7" stale — 8 sites now: the 7 parameters plus this return.

### 2026-08-05

Done in !194 — by inverting the issue.

This was scoped as **documentation**: record that 8 `Any` annotations are correct so a fourth pass doesn't re-derive the verdict. I tested the verdict before writing it down. **7 of the 8 were not justified** — they were untyped, and the Protocols describing them already existed:

```
obj / parent   -> agency_id, id, version    ==  SupportsUrn
item           -> id                        ==  SupportsId
artefact_type  -> sdmx_package, sdmx_class  ==  type[SupportsUrn]
```

`resolve_urn` was the clearest: its body opens with `isinstance(urn_val, str)`, which narrows `object` fine — the `Any` was doing nothing at all.

Had I implemented this issue as written, the wrong verdict would have been committed as a comment saying "deliberate, leave it" — which is precisely what stops the next person from looking. Worth remembering for the sibling issues: a "leave it" conclusion deserves testing as much as a "fix it" one.

**What was actually correct:** one site. `readers.get_artefact` dispatches on the runtime `artefact_type` column, so no static type describes its result, and narrowing to `object | None` would add an isinstance step at all 66 call sites without making anything safer. Documented in place, pointing at `Registry.get` as the typed entry point.

**And then the documentation became enforcement.** With every shell `Any` typed, `ruff.toml`'s ANN401 exemption for `formats/` / `storage/` / `local/` was covering exactly one justified site. Maintainer approved replacing it with a single scoped `# noqa: ANN401`, so ANN401 is now on across all of `src/`. Verified both directions: reintroducing an `Any` parameter in `formats/` trips the rule, and RUF100 confirms the new noqa is load-bearing rather than dead.

`src/` now carries **zero** `Any`-annotated parameters or locals. That is a linter guarantee now, not a convention — which is a better outcome than the comment this issue asked for.
