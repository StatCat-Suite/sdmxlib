## Summary

A reference to a class SDMX does not define is read faithfully and written back unchanged, which is schema-invalid in every format, with no refusal.

Found by the registry sweep (!516): BIS categorises Fusion Metadata Registry proprietary artefacts. 135 categorisation sources are `urn:sdmx:org.sdmx.infomodel.publicationtable.PublicationTable=BIS:CPMI_CT13B(1.0)` and 74 are `…pdq.PreDefinedQuery=…`; all **209** are written invalid in 2.1, 3.0, 3.1 and JSON. BIS's own documents already fail their XSD on these refs.

## Schema

- 2.1: `Ref@class='PublicationTable'` and `@package='publicationtable'` are not in the enumerations.
- 3.0/3.1: `Source` is `common:UrnReferenceType`, whose `UrnClassesPart` is an alternation of ~70 `.+\.<package>\.<Class>=.+` patterns. libxml2 reports only the last alternative, which is why the message names `transformation\.VtlMappingScheme`.
- JSON: the `source` pattern fails, and `Unevaluated properties ('source', 'target')` follows from it.

Emit sites: `_v3_writer.py:388-389`, `sdmx_ml/_common.py:1232-1233,1418-1420`, `sdmx_json/_structure_dto.py:796`.

## Fix direction

Keep the reader lenient (round-tripping what the registry said is right), and refuse on write: a `check_serialisable` rule that every outgoing reference's `(package, class)` is one the target defines, taken from the model's own class registry. A declared gap does not fit: nothing is dropped, there is simply no valid form. The message should name the non-standard class.
