## Known survivors that were measured and never killed

`tests/unit/test_properties_code_query.py` records the pilot's outcome in its module docstring:

> The #213 mutation pilot left 123 surviving mutants in `validation.py` and 27 in `collections.py`; `code_query.py` was outside its scope.

Those 150 mutants are the pilot's actual finding, and they are still standing. #218's ruling was that per-mutant triage — *real gap* / *equivalent* / *won't fix* — is the useful artifact; that triage was never carried out for these two modules, so the numbers currently function as trivia rather than as a work list.

Both modules are well covered by the line-coverage instrument, which is precisely why the survivors matter:

| Module | Statements | Line cov | Surviving mutants |
| --- | --- | --- | --- |
| `model/validation.py` | — | high | 123 |
| `model/collections.py` | 200 | 92% | 27 |

`collections.py` has four properties in `test_properties_core.py` (indexing-vs-iteration, filter subset, partition cover, `ArtefactList.ids`) and 27 mutants survived anyway — a useful calibration on how much a handful of properties actually pins.

## Scope

- Re-run mutmut over `validation.py` and `collections.py` first: the counts predate later test work and some survivors may already be dead. Report the current numbers before doing anything else.
- Triage every remaining survivor into the three buckets. Expect a substantial equivalent-mutant rate in `validation.py` — much of it is message formatting and ordering of checks, where a mutant changes prose rather than behaviour.
- Write tests for the *real gaps*. Prefer extending the existing properties over adding examples, since this issue is also evidence for the properties-vs-examples question in #dsl-5.
- Record equivalents in a form that survives — a file under `docs/design/` or a structured comment mutmut can be pointed at — so the next run does not re-triage the same set. #218 asked for exactly this under "if A or B" and it was never produced.
- If a survivor points at a *validation rule that is genuinely missing* rather than a test that is missing, file it separately. #221 (`validate()` accepts maintainable and agency ids the XSD rejects) came out of this territory and was a real defect, not a test gap.

## Risks

- **Equivalent-mutant fatigue.** 150 mutants is a lot of triage and most of the value is in the minority that are real. Timebox the pass, work `collections.py` first (27 is tractable and calibrates the rate), and if `validation.py`'s equivalent rate proves very high, that is itself a reportable result about whether the module belongs in scope.
- **Chasing the score.** The output of this issue is killed real gaps plus a recorded equivalent set, not a percentage. #218 explicitly rejected score-driven test writing.

## Test gates

- Current survivor counts reported for both modules, replacing the stale 123 / 27.
- Every survivor in one of the three buckets, with the bucket assignment reviewable.
- Real gaps closed by tests, preferring properties.
- Equivalents recorded durably, with a note in `CLAUDE.md` or `docs/design/` on how to add to that record.
- The stale counts in `test_properties_code_query.py`'s docstring updated or removed, so the file stops asserting a number that is no longer true.
