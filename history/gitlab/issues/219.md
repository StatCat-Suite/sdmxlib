# Issue #219: typing: Ref has two constructor forms and declares one — keep only Ref.to(obj)

| | |
| --- | --- |
| State | closed |
| Opened | 2026-08-06 |
| Closed | 2026-08-06 |
| Labels | `design`, `typing` |

`Ref` accepts two constructor forms but declares only one, so the supported artefact form is a type error for every caller. **Decision: keep one form — `Ref.to(obj)` — and make `Ref(obj)` fail.**

## The gap

```python
urn: SdmxUrn[T]                       # what the field declares

def __attrs_post_init__(self) -> None:  # what the constructor accepts
    if isinstance(self.urn, MaintainableArtefact):
        self.urn = SdmxUrn.make(...)      # derive URN from the object
        self._resolved = obj              # and intern it
```

Passing an artefact is deliberate and documented. But no checker can model "this field is replaced with a different type in post-init", so declaration and reality disagree. At runtime `Ref(cl)` and `Ref.to(cl)` are **identical** — verified, `==` is True, same URN, same resolved object.

## What it costs today

**Three suppressions in `ref.py`, all serving this one gap:**

| Line | Suppression |
| --- | --- |
| 109 | `reportAttributeAccessIssue` / `bad-assignment` — reassigning `self.urn` |
| 118 | `reportAttributeAccessIssue` / `bad-assignment` — setting `self._resolved` |
| 216 | `reportArgumentType` / `bad-argument-type` — `Ref.to` calling `cls(urn=obj)` |

**38 call sites across 9 test files** use the untyped form. `src/` uses it zero times — not from discipline, but because `just typecheck` runs `basedpyright src` and `pyrefly.toml` sets `project-includes = ["src"]`. Neither checker has ever read `tests/`.

**The library actively recommends the untypeable form.** `polars.py:505` raises a `ValueError` whose message tells the user to write exactly the thing that will not typecheck:

```
"...Construct the Dataset with dataflow=Ref[Dataflow](flow) and retry."
```

`ref.py`'s module docstring (`allows Ref(cl_freq) instead of Ref.unresolved(cl_freq.urn)`) and the class docstring's Construction block (`Ref(cl_freq)  # from domain object`) do the same.

## The fix — one form

- `Ref(urn)` — URN only. Typed.
- `Ref.to(obj)` — artefact. Typed. Does the URN derivation itself instead of delegating to post-init.
- `Ref.of(urn, obj)` / `Ref.unresolved(urn)` — unchanged.

`__attrs_post_init__` keeps only its rejection branch, so `Ref(obj)` is **loudly refused** rather than silently accepted:

```python
@classmethod
def to(cls, obj: T) -> "Ref[T]":
    if not isinstance(obj, MaintainableArtefact):
        raise TypeError(...)
    urn: SdmxUrn[T] = SdmxUrn.make(
        type(obj), package=obj.sdmx_package, artefact_class=obj.sdmx_class,
        agency=obj.agency_id, id=obj.id, version=obj.version,
    )
    return cls(urn=urn, _resolved=obj)
```

**Prototyped and verified** — basedpyright reports **0 errors with 0 suppressions**, and at runtime:

```
Ref2.to(cl)          -> urn:sdmx:...Codelist=T:CL(1.0), resolved: True
Ref2(cl)  artefact   -> TypeError: Ref expects a SdmxUrn, got Codelist.
                        To build a Ref from a maintainable artefact use Ref.to(obj).
Ref2(dim) child item -> TypeError: Ref expects a SdmxUrn, got Dimension. ...
Ref2.to(dim)         -> TypeError: Ref.to expects a MaintainableArtefact, got Dimension
```

All three suppressions go away.

## Rejected: the attrs converter

The obvious fix — `urn: SdmxUrn[T] = field(converter=_to_urn)`, which is how `maintainer: Agency = field(converter=_to_agency)` absorbs a `str` in this codebase — **does not work here**, and it is worth recording why so nobody re-derives it:

```
error: Type "SdmxUrn[MaintainableArtefact]" is not assignable to return type "SdmxUrn[T@_to_urn]"
```

Narrowing `SdmxUrn[T] | MaintainableArtefact` with `isinstance` lands on the *union member*, so `T` is lost and `SdmxUrn.make(type(v))` yields `SdmxUrn[MaintainableArtefact]`. In `Ref.to` the parameter is declared `T`, so narrowing gives `T & MaintainableArtefact` and `T` survives — which is exactly why the classmethod form works and the converter form cannot.

A converter also cannot set `_resolved`, so it would not preserve the interning half of the current behaviour anyway.

## Migration

Breaking, deliberately — pre-1.0, no compat shim.

- `ref.py`: move the derivation into `.to`, trim post-init to validation, drop 3 suppressions.
- `polars.py:505`: fix the error message to recommend `Ref.to(flow)`.
- `ref.py` module + class docstrings: `Ref(cl_freq)` -> `Ref.to(cl_freq)`.
- 38 test call sites across 9 files.
- Check `docs/` for the same pattern.

## Test gates

- `just check` clean with **zero** suppressions in `ref.py` for this reason.
- A test asserting `Ref(some_artefact)` raises `TypeError` and that the message names `Ref.to`.
- Round-trip and registry-interning tests unchanged — `.to` must intern exactly as the old path did.
- Grep gate: no `Ref(<artefact>)` construction anywhere in `src/`, `tests/` or `docs/`.

## Note

Found while sharing test factories (#211). The 38-vs-0 split between `tests/` and `src/` is the same signal as the `Ref[X](artefact)` finding there: `tests/` gets no type checking at all, so gaps like this accumulate silently. That question — whether to widen the checkers to `tests/` — is #212's to answer, and this issue is worth fixing either way.
