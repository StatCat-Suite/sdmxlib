## Context

After milestone #8 (#178–#181), the SDMX-JSON **structure** reader and writer are fully typed msgspec Structs — with one deliberate exception: **`CodelistExtension`** and its `CodeSelection` / `MemberValue` subtree stay hand-built dicts.

Current state:
- Writer: `_write_codelist_extension` / `_write_code_selection` / `_write_member_value` emit `dict` / `str | dict`.
- Reader: `_read_codelist_extensions` / `_read_code_selection` / `_read_member_value` parse dicts.
- DTO seam: `CodelistJson.codelist_extensions: list[dict[str, object]] | None` — msgspec encodes/decodes the container, but the contents are untyped `dict[str, object]`.

This was a cost/benefit call during the read migration (MR !171), not a hard blocker. This issue tracks revisiting it so the SDMX-JSON layer has **no dict islands left**.

## Why it wasn't typed with the rest

Three wire quirks make a clean `omit_defaults` Struct awkward:

1. **`MemberValue` is an `anyOf`: bare string OR object.** The `memberValues` array is heterogeneous — `"A"` (bare code id) or `{"value": "A", "cascadeValues": ...}`. A typed decode of `list[str | MemberValueJson]` needs a msgspec **dec_hook** to disambiguate string-vs-object per element.
2. **`cascadeValues` is `bool | "excluderoot"`.** `CascadeSelectionType` is `xs:boolean` *plus* the literal `excluderoot` → genuinely `bool | str`, mapping to the 3-value `CascadeSelection` enum (`INCLUDE_DESCENDANTS` / `SELF_ONLY` / `EXCLUDE_ROOT`), not 1:1 with either JSON type.
3. **The include/exclude selection is an `xs:choice`.** Two mutually-exclusive keys `inclusiveCodeSelection` / `exclusiveCodeSelection` collapse to one model field (`CodeSelection.mode`). A Struct would carry both as optional and need a post-decode check that exactly one is set — re-introducing the invariant the model folded into a mode flag.

It's also low-traffic: SDMX 3.0/3.1-only, silently dropped on 2.1 output, rare in real payloads.

## Proposed shape (to be validated)

- `MemberValueJson = str | MemberValueObjJson` union + a `dec_hook` for the anyOf.
- `cascade_values: bool | str | None` on the object variant, ingested to the enum.
- `CodeSelectionJson` with both `inclusive_code_selection` / `exclusive_code_selection` optional + a `__post_init__` / ingest-side check that exactly one is present, mapping to `InclusionMode`.
- `CodelistExtensionJson(codelist, prefix, <one selection>)`, replacing the `dict[str, object]` field on `CodelistJson`.
- Lock with a round-trip + TWG JSON-schema conformity test covering: bare-string members, cascade `true` / `false` / `excluderoot`, and both inclusive and exclusive selections.

## Acceptance

- No `dict[str, object]` islands remain in `formats/sdmx_json/` structure read/write.
- Existing codelist-extension round-trip tests still pass; new tests cover the three quirks above.
- `just check` clean.

Relevant code: `formats/sdmx_json/writer.py` (`_write_*` helpers), `formats/sdmx_json/reader.py` (`_read_codelist_extensions` / `_read_code_selection` / `_read_member_value`), `formats/sdmx_json/_structure_dto.py` (`CodelistJson.codelist_extensions`), model `model/codelist.py` (`CodelistExtension` / `CodeSelection` / `MemberValue` / `CascadeSelection` / `InclusionMode`).
