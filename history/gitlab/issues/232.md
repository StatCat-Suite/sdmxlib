# Issue #232: Phase 6: extend conformance coverage to MetadataMessage

| | |
| --- | --- |
| State | closed |
| Opened | 2026-08-06 |
| Closed | 2026-08-11 |
| Milestone | %11 Wire conformance: no artefact serialises to an invalid document |

**Phase 6.** The spec-coverage matrix (#223) covered `StructureMessage` and stopped there. `MetadataMessage` is the other envelope sdmxlib writes, and its coverage is uneven in a way worth stating exactly:

| | validated against official schema? | generative coverage? |
|---|---|---|
| SDMX-JSON metadata | **yes** — `compile_json_schema("metadata")`, used by two test modules over fixtures | no |
| SDMX-ML 3.0 `<mes:GenericMetadata>` | **no** — `SDMXMetadataGeneric.xsd` is vendored but `tests/support/xsd.py` only exposes `compile_structure_schema` | no |

So emitted metadata XML has never been checked against the schema it claims to conform to, and neither format is exercised with generated payloads.

## Work

1. Add `compile_metadata_schema(version)` alongside `compile_structure_schema`, pointing at the vendored `SDMXMetadataGeneric.xsd`. Expect this alone to surface findings — it did for structures.
2. Strategies for `MetadataSet` and `ReportedAttribute`, including the two shapes that are easy to get wrong:
   - **repetition via sibling attributes with the same id**, never a values list (the model is explicit about this, so a generated payload should exercise it);
   - **recursive children**, so nesting depth is not always 1.
3. The same round-trip property as the structure side — write, validate against the official schema, read back, compare — for both formats.
4. Extend the #227 gate to `MetadataMessage`, so a metadata payload also cannot silently serialise to an invalid document.

## Note on the envelope

`MetadataSet` is deliberately *not* a `StructureMessage` field, and the coverage guard's stale-entry check exists partly to keep it from being listed as one — it was, briefly, and the check caught it. This issue covers it in the right place rather than relaxing that guard.
