# Issue #384: resolving a Ref re-runs the field's converter on a value that is already a Ref — 10x on setattr

| Labels | `design`, `perf` |

Second piece of the 3.67 s "ref walk + assignment" in
`get(H_CP_GEO_FED, eager=True)` — see #383 for the decomposition.

## The measurement

`_assign_resolved` writes each resolved target onto its owner:

```python
setattr(owner, name, Ref.of(ref.urn, target))
```

Because the model's `@define` classes carry converters, attrs installs an
`on_setattr` hook, so every one of those assignments re-runs the field's
converter through `attr/setters.py:convert`. On 200,000 assignments:

| | ms | µs/set |
| --- | --- | --- |
| `setattr` (through attrs' `on_setattr`) | 73.0 | 0.37 |
| `object.__setattr__` (bypasses it) | 7.2 | 0.04 |

**10.2x.** cProfile confirms the path is real rather than an artifact:
`attr/setters.py:56(convert)` accounts for 499,490 calls into
`importlib._bootstrap:645(parent)` — 0.73 s of a profiled run — during the
`H_CP_GEO_FED` eager read.

## Why the converter has nothing to do

The value being assigned is `Ref.of(ref.urn, target)` — already a `Ref`, built
one line above by this same function. The converter it re-runs is the one that
turns a permissive input (a bare URN, a raw artefact) into a `Ref`; handed a
`Ref` it returns it unchanged. So this is ~0.33 µs per edge to confirm
something the call site constructed.

## What makes this not simply a one-line fix

`object.__setattr__` bypasses the converter, which is the point, and also
bypasses anything else `on_setattr` is doing on that class. Today that is
converters and nothing else — but "today" is the whole risk, and a bypass is
invisible at the point where someone later adds a validator to a model field
and quietly finds it not running on this path.

So the shape matters more than the saving:

1. **Bypass at the one call site**, with a comment and a test that the assigned
   value is already of the field's type. Smallest, and carries the risk above.
2. **A narrow helper** — `model._refshape` or a sibling — that asserts the
   value's type and then bypasses, so the check happens once at the seam rather
   than being assumed. Slightly slower than (1) and much easier to defend.
3. **`Ref` fields declare `on_setattr=None`.** Says at the *field* what is true
   of it — a `Ref` field never needs conversion on assignment because
   everything that assigns one already has a `Ref`. Most honest, widest diff,
   and it changes public behaviour: `dsd.dimensions["FREQ"].codelist = some_urn`
   would stop converting. That may well be undesirable.

(2) is probably right. (3) is worth thinking about before dismissing, because it
is the only one that puts the fact where the field is.

## Scale

~0.19 s on this read — the smallest of the three items in the 3.67 s, behind
#154's `SdmxUrn.parse` (~1.13 s) and ahead of nothing much. **Not worth doing
alone.** It is filed so that whoever takes #154's item 2 or #378 has it in view,
since all three live in the same twenty lines and a single pass over
`_resolve_refs` / `_assign_resolved` could take all of them.

## Acceptance

- The assignment path does not re-run a converter on a value that already has
  the field's type.
- Guarded by a **count** of converter invocations, per CLAUDE.md — a wall-clock
  assertion at 0.19 s on a shared laptop measures nothing.
- Whatever is chosen, a test that assignment through the *public* API still
  converts, so the bypass cannot silently widen.
