## Why this is the highest-value gap

The machinery already exists. #216 built a `_round_trip` helper that writes an artefact in each of four formats, **validates the document against the official XSD or JSON schema**, and reads it back. Extending it to another artefact type costs one strategy and one property.

That schema step is what makes this worth doing rather than more round-trips: it turns the vendored XSDs into a conformance suite nobody has to maintain, checking thousands of constraints nobody thought to state — sequence ordering, required attributes on rarely-exercised branches, pattern facets on ids.

The evidence that it finds things: applied to just **two** classes, it has already produced

- the SDMX-JSON writer emitting `[]` where the schema requires `minItems >= 1` (#216),
- Concept ids needing `NCNameIDType` where Code ids need `IDType` (#216),
- `validate()` accepting maintainable ids the XSD rejects (#221).

Eighteen classes have never had a generated artefact put through that check.

## Scope

Per class: a strategy in `tests/support/strategies.py` and a case in
`tests/unit/test_properties_roundtrip.py`. The round-trip helper, the schema
validators, the `KNOWN_GAPS` sharing and the profile-scaled example counts are
all already in place.

Expect findings, and expect some of them to be **strategy** bugs rather than
library bugs — that has been the pattern throughout: `Code` names being
required, concept ids being NCName, U+FFFE being category `Cn`. Each one is a
question about which side is wrong, and answering it is the point.

## Suggested order

1. **DataStructure** — the most complex artefact and the centre of the model; dimensions, attributes, measures, groups, attachment levels.
2. **Dataflow, Categorisation, ProvisionAgreement** — small, reference-carrying, cheap.
3. **AgencyScheme / DataProviderScheme** — contacts have a rich sub-structure (emails, telephones, faxes, x400s, uris) with `minItems` constraints.
4. **Hierarchy / HierarchyAssociation** — recursive; `code_forests` already exists to build on.
5. **DataConstraint** — cube regions and key sets, plus the 3.1 availability split.
6. **The map family** — StructureMap, RepresentationMap, ConceptSchemeMap, CategorySchemeMap.
7. **MetadataStructure / Metadataflow / MetadataSet** — the reference-metadata side.

## Not in scope

Extending `validate()` coverage per class is #221's business. This issue is
about the *serialisation* oracle.
