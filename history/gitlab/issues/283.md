# Issue #283: t-2: ruff warnings do not fail the gate, so nobody reads them

| | |
| --- | --- |
| State | closed |

Two `warning:` lines survived %13, %14 and %15 — roughly 4,300 added lines of `src/` — because ruff exits 0 on them.

They survived for a specific and repeatable reason: they are noisy, they appear on every run, and the working habit that develops is to filter them out of check output. That is exactly the failure mode the `select = ["ALL"]` policy exists to prevent, applied one level up — a finding that cannot fail is a finding nobody acts on.

## Fix

Make `just lint` fail on ruff `warning:` output, not just on findings. Roughly:

```
uv run ruff check src tests 2>&1 | tee /dev/stderr | grep -q "^warning:" && exit 1
```

(needs care with pipefail and with `ruff format --check`.)

## Check first

Confirm ruff has no native "treat warnings as errors" flag before adding a shell wrapper — if one exists, use it. The wrapper is the fallback, not the preference.
