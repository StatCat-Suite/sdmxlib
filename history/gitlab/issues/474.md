# Issue #474: Readers fill in required values a document omits, and nothing on the message says so

| | |
| --- | --- |
| State | closed |
| Opened | 2026-10-16 |
| Closed | 2026-10-16 |
| Milestone | %21 Conformance evidence: what the green checks do not prove |
| Labels | `conformance`, `validation` |

## Problem

`StructureMessage.lost` records what a reader **dropped**, and `refused` records what it **would not build**. But nothing records what a reader **assumed**: a value it filled in because the document omitted something the schema **requires**. The artefact then looks exactly as if the document had stated that value, and a user can't tell the two apart. Only the registry sweep sees it, by diffing what is written back (`read_gained`).

This is about assumptions, not schema defaults. A value the schema itself defaults (SDMX-ML 3.x `usage="optional"`, 2.1 `ContentConstraint/@type="Actual"`) is the standard's own answer and needs no note.

## Known sites (from the readers, measured against the 2026-10-15 sweep)

| assumption | where in the code | real-world count |
| --- | --- | --- |
| a missing `AttributeRelationship` (required) read as **dataset-level** | `formats/sdmx_ml21/reader.py` (attribute relationship, falls through to `AttachmentLevel.DATASET`), `formats/sdmx_ml/_v3_reader.py` (same, 3.x), `formats/sdmx_json/_structure_ingest.py` (`from_attachment(None)`) | IMF: 3,047 `MetadataAttributeUsage`s and 16 `Attribute`s (milestone 20 chose this tolerance deliberately, #421) |
| a missing 3.x `DataConstraint/@role` (required) read as **`Allowed`** | `formats/sdmx_ml/_common.py` (`cc_el.get("role") or cc_el.get("type", "Allowed")`) | IMF: 3 constraints |

There are probably more; the readers have never been surveyed for this.

## Proposal

1. **Record each assumption on the message,** as `lost` records a loss. For example `StructureMessage.assumed`, one entry per artefact and construct, naming the value assumed and why: `DataStructure=IMF:X(1.0): Attribute.attachment x16 assumed DATASET — the document omitted the required AttributeRelationship`.
2. **Decide what `lossless=True` does with them.** Probably raise, since an assumed value is not what the document said. Or add a separate `parse(..., assume=False)` that refuses instead.
3. **Survey every reader** for the remaining sites: fall-through defaults, `.get(attr, default)` on attributes the schema marks `use="required"`, and `or "<value>"`. Make each one either a recorded assumption or a refusal. A census-style guard (cf. `test_element_census.py`) could keep that list closed: every required attribute or element a reader can fill in has an owner.

## Done when

- No reader fills in a required value silently; each is on the message, or refused.
- The survey's list is pinned by a test.
- `docs/upgrading.md` describes the new account.
