# Issue #485: An enumerated metadata attribute must use a Codelist; a ValueList is accepted (IM §7.3.4.1)

| | |
| --- | --- |
| State | closed |
| Opened | 2026-10-16 |
| Closed | 2026-10-21 |
| Milestone | %21 Conformance evidence: what the green checks do not prove |

Found by the IM rule census (#456). SDMX 3.1 Section 2, §7.3.4.1 p. 98, of a MetadataAttribute: "If the Representation is enumerated, then is must use a Codelist."

`MetadataAttribute.representation` accepts a `ValueList` (`to_representation` takes `Ref[Codelist | ValueList]` for every component), and nothing refuses it. Check what the 3.0/3.1 XSDs allow for `MetadataAttributeRepresentationType` before choosing between a validation check and narrowing the type — narrowing would make the census row `Structural` rather than `Validated`.

## Comments

### 2026-10-16

Also in scope, from the same census row (IM-7.3.4.1-1): an MSD attribute's occurrence bounds are not range-checked. `_check_3x_components` refuses a DSD component whose minOccurs is negative or whose maxOccurs is below 1 or below minOccurs; nothing does the same for `MetadataAttribute.min_occurs` / `max_occurs`. IM §7.3.4.1 p. 98: "specified as being mandatory (minOccurs=1 or more) or optional (minOccurs=0)".
