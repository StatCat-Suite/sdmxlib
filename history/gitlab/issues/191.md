# Issue #191: Emit native SDMX 3.0 reference-metadata links (replace the .Stat METADATA-annotation compat shim)

Follow-up to #162.

## Context

#162 shipped a **legacy `.Stat` compatibility shim**: a
`type="METADATA"` annotation (title = MSD URN) spliced onto each DSD, the
only DSD↔MSD discovery mechanism every `.Stat` component (DLM / NSI /
Explorer) can read. It is deprecated-on-arrival.

The **canonical** SDMX 3.0 discovery mechanism is a dynamically-generated
`link` (from any Identifiable structure to its reference-metadata
report/metadataflow), emitted at export time — exactly what FMR does. It
is *not* a persisted DSD annotation. See SDMX-JSON feature 001
(sdmx-twg/sdmx-json#89) and SDMX-ML feature 002 (sdmx-twg/sdmx-ml#17).

## Work

1. **Confirm the exact `rel` token** for a structure→metadata-report link
   in SDMX-JSON 2.0 / SDMX-ML 3.0. This could not be pinned from the
   published field guide in #162 (its "Linking mechanism" section was not
   retrievable; only `rel="self"` is enumerated there). Read that section
   or capture a live FMR / Eurostat SDMX 3.0 response.
2. Add `link_structure_message(message, dsd_metadata_map, *, rel=...)`
   alongside `annotate_structure_message`, reusing the **same**
   `build_dsd_metadata_map` derivation (its `DsdMetadataLink` already
   carries `metadataflow_urn` / `set_urns` for hrefs).
3. Emit the link in the three structure writers (SDMX-JSON `links[*]`;
   SDMX-ML 3.0). The SDMX-JSON DTO already has a `Link(rel, href)` struct.
4. Once consumers move off `.Stat` onto FMR / native 3.0 links, the
   annotation shim (`annotate_structure_message`) can be removed.

## Note

`.Stat` of all kinds cannot currently consume the 3.0 link, so the
annotation shim from #162 remains the primary output until downstream
consumers migrate. This issue is the forward-looking replacement, not an
immediate swap.

### 2026-07-31

## Implemented (SDMX-JSON arm)

- `builders.metadata_annotation.build_metadata_target_links(catalog)` →
  `target_urn -> [metadataset_urn]` (one SQL round-trip over
  `metadata_target`; keyed on the actual target artefact, matching FMR).
- `formats.sdmx_json.writer.write(msg, *, metadata_links=..., base_url=...)`
  emits the native `{rel:"metadata", href:<…/metadata/metadataset/…>, urn:<set>}`
  link on each targeted maintainable. Opt-in; omitted entirely when the
  param is absent (no change to existing output). `base_url` required when
  `metadata_links` is given.
- Added `urn` to the SDMX-JSON `Link` DTO and `links` to `MaintainableJson`.
- Output shape verified byte-for-byte against the live FMR capture.

## Remaining

- **SDMX-ML 3.0** native metadata link not yet emitted. SDMX-ML has no
  generic JSON-style `links[]` array, so this needs an XSD investigation
  into how the 3.0 structure schema represents the back-link before
  implementing. Tracked here as the remaining sub-task.

### 2026-07-31

The SDMX-JSON arm shipped in v0.47.0 (MR !179). This issue stays open for the remaining **SDMX-ML 3.0** native metadata-link sub-task (needs the XSD investigation into the 3.0 back-link representation).

### 2026-07-31

SDMX-ML 3.0 native `<com:Link rel="metadata">` arm shipped in v0.48.0 (MR !181), verified byte-for-byte against live FMR. Both SDMX-JSON and SDMX-ML 3.0 now emit the native discovery link. Closing.
