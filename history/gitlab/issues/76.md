## Goal

Lock down the corruption described in #75 with failing unit tests **before** any code change. Two distinct failure modes to capture:

1. The obvious one — `IndexError` / `ValueError` from clobbered row buffers (`readers.py:264`, `readers.py:1328`).
2. The data-integrity one — a `get(urn_A)` call returning an artefact populated from row data belonging to a *different* URN. This is the real reason to ship the fix; if we only catch (1) we miss the case where the server returns a 200 with wrong content.

## Tasks

- [ ] `tests/test_concurrent_reads.py` (`@pytest.mark.unit`):
  - Populate a small `Registry` (Dataflow + DSD + Codelists), enough variety that mis-paired rows are detectable.
  - `ThreadPoolExecutor(max_workers=8)` issuing ~500 mixed `reg.get(urn)` calls.
  - Assert: every result's `urn`/`id`/`agency` matches the URN that was requested. Not just "no exception" — identity.
  - Use `pytest-repeat` (or an inner `for _ in range(50)` loop) to amplify the race window so the test fails deterministically on `main`.
- [ ] **Cache-hit invariant test**: warm cache with one `get`, then 32 threads × 1000 reads of the same URN, assert identity on every result. This is the canary for the FIFO-cache change in the follow-up issue.
- [ ] Run on `main` (v0.27.2) and confirm both tests fail reliably. Record the failure modes in a comment on the issue.

## Comments

### 2026-05-28

Reproducer tests landed in branch `test/concurrent-read-repro` / MR !37.

**Failure determinism on `main` (v0.27.2):** 9/10 invocations of the suite fail (at least one of the two tests failing).

**Dominant failure mode** — `reg.get(urn)` returns `None` for an URN that's definitively in the registry:

```
AssertionError: missing artefact for 'urn:sdmx:org.sdmx.infomodel.datastructure.DataStructure=SDMX:DSD_2(1.0)'
AssertionError: missing artefact for 'urn:sdmx:org.sdmx.infomodel.codelist.Codelist=SDMX:CL_1(1.0)'
AssertionError: missing artefact for 'urn:sdmx:org.sdmx.infomodel.conceptscheme.ConceptScheme=SDMX:CS_2(1.0)'
```

Same root cause as the `IndexError`/`ValueError` in #75 — the shared cursor's row buffer is clobbered between `execute()` and `fetchone()` — but DuckDB's behaviour when the buffer is gone is to return an empty result, which surfaces here as a missing artefact rather than a malformed row. The identity-mismatch path (a `Codelist` row populating a `Dataflow` artefact) is also guarded by the assertion and would fire if the racing thread happened to leave a non-empty wrong-shaped buffer behind.

This issue is complete pending MR review. Next: #77 (bench baseline).
