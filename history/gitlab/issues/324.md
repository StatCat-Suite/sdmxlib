## What the triage is for

#218's ruling stands: *the triage is the artifact and the percentage is not.*
Each survivor is one of

* **real gap** — write the test; it pins behaviour nothing pins today,
* **real defect** — the mutant is *correct* and the code is wrong (this has
  already happened once, and was the most valuable outcome so far),
* **equivalent** — no observable difference. SQL's case-insensitivity produces
  a lot of these (`' DESC'` → `' desc'`, `COUNT` → `count`); record them, do
  not chase them,
* **dead code** — the mutated line cannot be reached. Two kinds seen already:
  a branch that duplicates its own fall-through (delete it), and a fallback
  whose guard can never fire (needs a signature change; note and move on).

Record every classification in `docs/design/mutation-evidence.md` as it is
made. A survivor with no recorded verdict is one the next person re-reads.

## The verdict: a fourth kind

Nine mutants in each function sat in code **no query can reach**: every
declared facet and every declared root constraint carries exactly one value.
All three `_edges.FACETS` are single; all twenty `__constraint__` attributes in
`accessors.py` are `("artefact_type", ("Something",))`. The multi-value
`IN (...)` branch is unreachable through `q.*`.

That is not the "dead code" this issue lists — it is neither a duplicated
branch nor a guard that cannot fire. The branch works, is documented, and has
no *caller* yet: **dead by declaration, not by design**. Both docstrings state
the capability, and a facet spanning `Dimension` and `TimeDimension` is an
obvious future one, so the branch stays and is pinned directly rather than
leaving whoever declares that facet to discover whether it works.

The other three per function are reachable and emit SQL that *runs* —
`len(values) == 1` → `!= 1` emits `IN (?)` for a single value, different text
and identical rows — so the tests assert emitted SQL rather than result sets.
One bonus kill outside both clusters: `_conjoin__mutmut_5`, from asserting an
empty clause is *dropped* rather than merely falsy.

`test_no_declared_facet_or_constraint_carries_more_than_one_value` records the
premise as an assertion, so the day a multi-value facet is declared it fails
and says the branch is now live.
