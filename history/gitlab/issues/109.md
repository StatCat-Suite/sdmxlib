3.1 model audit follow-up (post-MR !63).

## Semantic gap

3.1 \`CodelistType\` allows a Codelist to declare one or more \`CodelistExtension\` elements naming other codelists it composes from, with include/exclude rules and an optional prefix.

Real semantic content: \"\`CL_AREA_ALL\` extends \`CL_AREA\` plus \`CL_AREA_ARCHIVED\`, including all codes from the first and only specific codes from the second, prefixed with \`ARCH_\`.\"

Without modelling this, a derived codelist appears as a flat list of its own codes — we lose the composition semantics (which codes came from where, what got renamed) and break the \"changes propagate from the base\" invariant.

## Action

Add a small \`CodelistExtension\` value type and a tuple field on \`Codelist\`:

\`\`\`python
@define
class CodelistExtension:
    source: Ref[Codelist]
    include_codes: tuple[str, ...] = ()    # empty = include all
    exclude_codes: tuple[str, ...] = ()
    prefix: str | None = None
\`\`\`

Plus \`extensions: tuple[CodelistExtension, ...] = ()\` on \`Codelist\`.
