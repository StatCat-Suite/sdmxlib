# Issue #357: is_final: emitted where the schema forbids it, and not read back where it exists

| | |
| --- | --- |
| State | closed |
| Opened | 2026-08-20 |
| Closed | 2026-08-20 |

First group worked down from #355. `is_final` looked like one bug and was four,
in both directions.

## 1. Emitted into SDMX-ML 3.0/3.1, which has no `isFinal`

`gaps.py` has declared this a 3.0/3.1 limit since #159, and
`write_maintainable_attrs` set the attribute anyway. Confirmed: `isFinal` does
not appear anywhere in the 3.0 XSD.

It reached the wire for any artefact whose writer used the shared helper *and*
carried `is_final=True`. A `CategoryScheme` did, and the emitted document is
rejected outright:

    Element 'CategoryScheme', attribute 'isFinal': The attribute is not allowed

Nothing caught it because no test combined `is_final=True` with XSD validation —
fixtures that set the flag were not validated, and validated fixtures did not
set the flag.

## 2. Emitted into 2.1 organisation schemes, where it is `fixed="false"`

`SDMXStructureOrganisation.xsd` gives `AgencyScheme`, `DataProviderScheme` and
`DataConsumerScheme` `use="optional" fixed="false"`. The attribute exists and
only one value is legal — so writing `true` fails validation just as surely as
writing it into 3.0, and is easier to miss because the attribute *is* there.

A genuine limit; now declared in `gaps.py`.

## 3. Not read back in 2.1, for eleven of seventeen maintainables

The 2.1 writer emitted `isFinal` for everything. The reader read it for six
types. So an `isFinal="true"` codelist round-tripped and an otherwise identical
concept scheme silently came back `false`. Fixed with a shared
`ReaderHelpers.read_is_final`.

## 4. Not read back in SDMX-JSON, for seven ingest functions

Same shape: the writer emits it for every maintainable, the reader read it for
some. Fixed.

## Bonus: a dozen register entries that were one fact

2.1 derives `Hierarchy`, `RepresentationMap`, `StructureMap`, `ConceptSchemeMap`
and `CategorySchemeMap` from **`NameableType`, not `MaintainableType`** — they
are not maintainable artefacts in 2.1 at all. The containing
`HierarchicalCodelist` or `StructureSet` is, and carries the version and
validity. SDMX 3.0 promoted all five, which is why the model gives them these
fields.

That single fact accounts for `is_final`, `valid_from` and `valid_to` on all
five — fifteen register entries that looked like fifteen bugs. Declared in
`gaps.py`.

## Result

2.1 register 51 → 46, SDMX-JSON 29 → 23. Every remaining `is_final` entry is now
a declared format limit rather than an unexplained loss.
