## Goal

Require the latest release of every runtime dependency, and move the lower bounds in `pyproject.toml` to them, so every install and every `just ci` runs what we test against.

## Where we are

| dependency | floor in `pyproject.toml` | latest |
| --- | --- | --- |
| polars | `>=1.39.3` | **2.0.0** (major) |
| pyarrow | `>=18.0.0` | **26.0.0** |
| msgspec | `>=0.19` | 0.22.0 |
| lxml | `>=6.0.2` | 6.1.3 |
| typing-extensions | `>=4.13` | 4.16.0 |
| attrs | `>=26.1.0` | 26.1.0 (current) |
| duckdb | `>=1.5.6` | 1.5.6 (current) |
| httpx | `>=0.28.1` | 0.28.1 (current) |

The floors allow the latest, and fresh environments resolve them: the worktrees behind !631 and !632 got polars 2.0.0 and pyarrow 26.0.0, and `just ci` passed there. But `uv.lock` is gitignored, so an existing checkout keeps whatever it once resolved until `uv lock --upgrade`. The main checkout was on polars 1.41.1 and pyarrow 24.0.0. A floor this far below what we test means a user can install a combination nobody has run.

## Work

- **polars 2.0.** It is a major release. Read its changelog against what `sdmxlib/polars.py`, the data plane and `query/` use (`select()` returns polars frames), and check for deprecation warnings: they fail the gate under `filterwarnings = ["error"]`.
- **pyarrow 18 → 26.** Check the Arrow bulk-insert path into DuckDB (see the pandas-probe note in the project memory), and the data writers.
- **msgspec 0.22** covers every SDMX-JSON reader and writer. Measure the JSON read: #466 tracks a gap to pysdmx, and #493 the garbage-collector cost.
- **Raise each floor to the version tested**, with a comment where a floor is load-bearing, as duckdb's already is.
- **Performance:** run `just bench-compete-scale` before and after, interleaved. The perf-MR rule applies, so report memory too.
