# Issue #210: typing: bind the writer dispatch tables so attribute and converter must agree

| | |
| --- | --- |
| State | closed |
| Opened | 2026-08-05 |
| Closed | 2026-08-06 |
| Milestone | %9 Suppression audit: fix the defect, not the symptom |
| Labels | `design`, `typing` |

Follow-up to !203, which narrowed the two writer dispatch tables from bare `Any` to a callable type. That was a partial fix; this is the rest.

## What !203 achieved, and what it left

```python
sdmx_ml21/writer.py   list[tuple[str, list[tuple[str, Callable[[etree._Element, Any], None]]]]]
sdmx_json/writer.py   list[tuple[str, str, Callable[[Any], WireStruct]]]
```

Measured exactly what that `Any` does and does not do:

```
out = conv(item)     -> type is WireStruct     Any does NOT leak into the output
conv(1, 2)           -> error: expected 1 arg  arity IS checked
conv("wrong type")   -> no error               the ARGUMENT is unchecked
```

So it is not infectious in the usual sense — the `Any` stays inside the call. What remains unchecked is the **pairing**: nothing stops

```python
("codelists", "codelists", to_dataflow)
```

which typechecks today and fails at runtime inside `write()`.

## Why the annotation cannot be narrowed further

`Callable` is contravariant in its parameters. The entries are `Callable[[AgencyScheme], …]`, `Callable[[Codelist], …]`, `Callable[[Dataflow], …]`; a common supertype needs a parameter type that is a *subtype* of all of them — that is `Never`, and `Callable[[Never], WireStruct]` is uncallable.

The list is genuinely erasing a per-entry type. No annotation recovers it, because the invariant is dependent: *this attribute holds items of type T **and** this converter takes T*.

## Proposal — bind the two sides with a type variable

Replace the string attribute with a getter, and construct entries through a generic factory:

```python
@frozen
class _Section:
    key: str
    get: Callable[[StructureMessage], Sequence[Any]]
    convert: Callable[[Any], WireStruct]

def section[T](
    key: str,
    get: Callable[[StructureMessage], Sequence[T]],
    conv: Callable[[T], WireStruct],
) -> _Section:
    """`T` is inferred from *both* the getter and the converter, so they must agree."""
    return _Section(key, get, conv)
```

Prototyped, and it catches the mismatch:

```python
section("codelists", lambda m: m.codelists, to_dataflow)
# error: Parameter 1: type "Codelist" is incompatible with type "Dataflow"
```

## What this buys beyond the type

* **Mismatched attribute/converter pairs become type errors** — currently silent until runtime.
* **`getattr(msg, attr)` disappears.** Both writers currently reach the message through a dynamic string attribute; the getter replaces it with a checked access. That is an untyped hole the earlier `Any` audit never counted, because `getattr` is not an annotation.
* Storage still erases to `Callable[[Any], WireStruct]`, but the erasure now happens **after** checking, at the one place the mistake is actually made.

## Cost

Entries become `section("codelists", lambda m: m.codelists, to_codelist)` rather than a bare tuple — a little more syntax, though the getter states plainly what is read.

Both writers' `write()` bodies change, since they iterate `getattr(msg, attr)` today. Contained: two files, ~14 entries each, and the round-trip tests exercise every section.

## Note

This pattern generalises. The same "table of (key, heterogeneous callable)" shape appears elsewhere in the codebase; if it works well here it is worth applying to the others rather than annotating each with `Any`.

## Comments

### 2026-08-06

Closed by !211.

Two corrections to the issue as filed, both found by re-measuring instead of implementing from its text:

**It listed two tables; there are four.** `sdmx_ml30` and `sdmx_ml31` still carried a bare `Any` in the writer slot — `list[tuple[str, list[tuple[str, Any]]]]` — having been missed when !203 narrowed the other two. 62 entries bound across the four writers.

**The premise was verified, not assumed.** Probed both halves before building on them: `("codelists", "codelists", to_dataflow)` really does typecheck under the old shape, and the `section[T]` factory really does reject it. Worth doing because the whole change rests on the second claim.

The shared factory for the three SDMX-ML writers lives in `formats/sdmx_ml/_common.py` as `section_entry`, so the pattern is defined once rather than three times.

**On the guard test.** The invariant is type-level and erased at runtime, so nothing can be asserted by calling it. I first wrote the guard as a subprocess call to basedpyright — strictly stronger, since it asserts the checker actually rejects a mismatched pair — but that needs `# noqa: S603`, and suppressions are the maintainer's call. Shipped the `__type_params__` version instead, which asserts the mechanism. Both were mutation-tested against de-genericising the factories, the one edit that silently restores the old behaviour; both fail on it. If S603 is ever waived, the stronger version is the better guard.

The issue's closing note — that this pattern generalises — checked out as having nothing to act on today: no other table in `src/` currently has the "(key, heterogeneous callable)" shape. `section_entry` is exported from `_common` if one appears.
