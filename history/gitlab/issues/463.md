# Issue #463: SDMX-ML reads are 32-50% slower since M20: closed-world, links and per-item checks

| | |
| --- | --- |
| State | closed |

| Closed | 2026-10-16 |

## Measured

SDMX-ML reads slowed across milestone 20:

| file | before | now | change |
| --- | --- | --- | --- |
| BIS codelists, 2.1 (3 MB) | 66 ms | 97 ms | +47% |
| BIS codelists, 3.0 | 65 ms | 94 ms | +45% |
| BIS DSDs, 2.1 | 15 ms | 20 ms | +32% |
| BIS DSDs, 3.0 | 13 ms | 20 ms | +50% |

sdmxlib still reads XML faster than pysdmx (129 ms) and sdmx1 (173 ms), but the gap has narrowed.

## Leads (profiler; confirm by A/B)

On the codelist read, over 5 reads:
- `_closed_world.check_children` (#436): once per codelist (105 per read), 0.103 s cumulative over 5 reads;
- `read_links` (#422): 49,105 calls, 0.053 s;
- `read_parent_id`: 0.048 s;
- `_check_name` validation for each item.

`read_istring` and `read_annotations` are the largest by self time, but they may predate M20; the A/B will tell.

## Direction

Measure each lead's share with A/B first. Then make each check cheaper, for example:
- one pass over children shared by the closed-world check and the reader;
- skip a links lookup when the element has no `Link` child.

Don't remove any check.

## Done when

XML reads are back within about 10% of pre-M20, the censuses and closed-world tests are unchanged, and count guards are in place.

## Comments

### 2026-10-15

!591 merged: the 2.1 reader no longer searches for links, the 3.x reader finds them with `iterchildren`, and no `QName` is built per code. Codelist reads are −11% (2.1) and −6% (3.0).

**Still open here:**
- the closed-world child check: 8.8 ms of the BIS codelist read;
- read-time validation: 5.7 ms.

Both are conformance guarantees with no readability-neutral fix found yet. They're to be re-measured on the scale tier before deciding.

### 2026-10-16

**Closing with the diagnosis** (measured 2026-10-15 on `main` after !591 and !598).

!591 delivered the readable gains: 2.1 skips links, links are found with `iterchildren`, and no `QName` is built per code (codelist reads −11% on 2.1, −6% on 3.0). !598 (#466) also made the XML-character scan in validation ~6× faster on ASCII names.

What remained, measured by switching each off:

| cost | UNSD `CL_COMMODITY` 2.1 (68k codes) | synthetic 100k (2 languages) | BIS codelists |
| --- | --- | --- | --- |
| closed-world check | 30 ms (7%) | 113 ms (13%) | 8 ms |
| read-time validation | 22–40 ms (5–9%) | 34 ms (4%) | 4 ms |

**Options tried and rejected:**
- **Closed-world.** Today's `iterwalk` is already ~230 ns per element. Dropping the `str()` per tag saved ~1 ms. Collecting the distinct (parent, child) pairs in one pass, with the exact walk as fallback, saved −28% of the check (−9 ms UNSD, −18 ms synthetic, about 2% of the read). It isn't worth a second implementation of a conformance check.
- **Validation.** What's left is one call per code, and every name has to be looked at. Building the issue path only on failure gained nothing (the f-strings are cheap). A bulk ASCII check over all names was slower on UNSD, because joining 68k long names costs more than it saves.

Both checks stay as they are: they are conformance guarantees, and their remaining cost is the work they have to do.
