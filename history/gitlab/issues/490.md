# Issue #490: parse() reads an SDMX error message as an empty StructureMessage

| | |
| --- | --- |
| State | closed |
| Opened | 2026-10-16 |
| Closed | 2026-10-21 |
| Milestone | %21 Conformance evidence: what the green checks do not prove |

Found while reading the FMR oracle's recordings (#457). `sl.parse()` on an SDMX error message returns an empty `StructureMessage`, with nothing in `refused` or `lost`:

```xml
<message:Error xmlns:message="http://www.sdmx.org/resources/sdmxml/schemas/v2_1/message" ...>
  <message:ErrorMessage code="100"><com:Text>No Results Found</com:Text></message:ErrorMessage>
</message:Error>
```

`parse` routes an XML document by its root element (`<mes:Structure>` / `<mes:GenericMetadata>`), and `<message:Error>` falls through to the structure reader, which finds nothing to read. So a caller parsing a saved response cannot tell "the registry said 100 No Results Found" (or 500) from "an empty result".

The REST client never reaches this -- it raises on the HTTP status first -- so it bites only callers of `parse` on stored bytes. An SDMX error message should raise, carrying its code and text (SDMX-JSON has the same envelope, `{"errors": [...]}`).
