All **20** `# noqa: D102` (undocumented public method) in `src/` are in one file, `storage/lazy.py`, and all are facade properties mirroring the domain-artefact API:

`id`, `maintainer`, `agency_id`, `version`, `name`, `description`, `is_final`, `valid_from`, `valid_to` — twice (LazyCodelist and LazyHierarchy) — plus `has_formal_levels` and `levels`.

These implement a documented protocol; each individually is self-evident. Twenty identical suppressions is the wrong shape for one decision either way.

## Two defensible fixes — pick one

1. **Per-file ignore** in `ruff.toml` with a rationale: these are protocol-conformance properties whose meaning lives on the protocol, not the implementation.
2. **Write the docstrings** — one line each, and `LazyCodelist` / `LazyHierarchy` are public API that users read via `help()`.

Option 2 is more work but arguably right for a published library; option 1 is honest if we accept that the docs live on `Codelist` / `Hierarchy`. Worth a maintainer call rather than an agent picking.

## Acceptance

* Zero `# noqa: D102` in `src/`, by either route.
* If (1): the per-file ignore carries the reason.
* `just check` clean.
