# Issue #128: JSON writer non-conformance: items vs named arrays, isFinal, name vs names

| | |
| --- | --- |
| State | closed |
| Opened | 2026-06-01 |
| Closed | 2026-06-01 |
| Labels | `conformance`, `json` |

## Surfaced by

The SDMX-JSON 2.1 schema vendoring MR (MR-1 of this work). Validating our existing JSON fixtures against the upstream schema (\`tests/schemas/sdmx_json/2.1/sdmx-json-structure-schema.json\`, v2.1.0) returns 14–25 errors per fixture. The upstream constructed sample validates cleanly, so the validator + schema are correct; the gap is in our writer + fixtures.

## Concrete bugs found

### 1. Item arrays are named per scheme type, not generic \`items\`

Spec requires each maintainable scheme to expose its items via a kind-specific array name:

| Scheme type | Expected array | Our writer emits |
|---|---|---|
| \`CodelistType\` | \`codes\` | \`items\` |
| \`ConceptSchemeType\` | \`concepts\` | \`items\` |
| \`AgencySchemeType\` | \`agencies\` | \`items\` |
| \`DataProviderSchemeType\` | \`dataProviders\` | \`items\` |
| \`CategorySchemeType\` | \`categories\` | \`items\` (and nested \`items\` within Category) |

Affected writer sites (\`src/sdmxlib/formats/sdmx_json/writer.py\`):
- L140: \`_write_agency_scheme\` → \`agencies\`
- L171: \`_write_data_provider_scheme\` → \`dataProviders\`
- L201: \`_write_codelist\` → \`codes\`
- L221: \`_write_concept_scheme\` → \`concepts\`
- L243, L261: \`_write_categories\` / \`_write_category_scheme\` → \`categories\`

Reader needs to accept both (named array + legacy \`items\`) for backwards-compat with previously-written sdmxlib JSON. \`_read_codelist\` already does this (\`cl.get("codes") or cl.get("items")\`); the others (\`_read_agency_scheme\`, \`_read_concept_scheme\`, \`_read_category_scheme\`, \`_read_data_provider_scheme\`) need the same fallback.

### 2. \`isFinal\` field is not in the spec at all

The string \`isFinal\` appears 0 times in the SDMX-JSON 2.1 structure schema. SDMX 3.0+ dropped the attribute and the JSON spec is 3.0+ era. Our writer emits it conditionally at 6+ sites (every \`if x.is_final: obj["isFinal"] = True\`). Drop them.

### 3. \`name\` should be string, \`names\` should be the i18n dict

The spec splits the istring shape across two fields:
- \`name\`: single \`string\` (a default-language representation, picked by sender)
- \`names\`: \`{"<lang>": "<text>", ...}\` — the multilingual payload

Our writer emits \`name\` as the multilingual dict directly. Schema rejects with \`{'en': 'Frequency'} is not of type 'string'\`. Same applies to \`description\` / \`descriptions\`.

Affected: every \`_istring_dict(x.name)\` and \`_istring_dict(x.description)\` site in the writer.

### 4. DSD has unexpected \`dataStructureComponents\`

Surfaced for \`/data/dataStructures/0\`. The spec uses different component grouping at the JSON layer; our writer emits the XML-shaped \`dataStructureComponents\` wrapper but the JSON schema expects components flattened differently. Needs a dedicated investigation in \`_write_data_structure\`.

### 5. \`name_fr\` in \`with_groups.json\` fixture

Fixture bug rather than writer bug — predates this work. While in there, fix it to use the correct \`names\` dict shape.

## Proposed shape of a fix

Single MR covering writer + reader + fixtures together. Order:

1. Drop \`isFinal\` everywhere from the JSON writer (smallest change, no ambiguity).
2. Rename \`items\` → \`codes\` / \`concepts\` / \`agencies\` / \`dataProviders\` / \`categories\` per scheme; extend the corresponding readers to also accept \`items\` as a fallback for backwards compat.
3. Split \`name\` into \`name\` (str picked by writer policy — likely fall back to the first available language) + \`names\` (i18n dict). Symmetric for \`description\`.
4. Update the 3 \`tests/fixtures/sdmx_json/*.json\` fixtures to match the new writer output.
5. Wire \`assert_valid_sdmx_json\` into \`tests/unit/test_sdmx_json_writer.py\` round-trip helper — same pattern as the SDMX-ML XSD-validated tests.

## Acceptance

- Every JSON fixture XSD-validates against the vendored v2.1.0 schema.
- Round-trip (parse XML → write JSON → schema-validate → parse JSON → write XML → semantic equality) passes across the existing fixture matrix.
- Reader accepts both new and legacy field shapes so previously-written sdmxlib JSON still parses.
