## State

\`src/sdmxlib/model/hierarchy_query.py\` — **65% line coverage** (162 of 463 lines untested).

## Why

The HierarchyQuery DSL exposes a broad surface of filter operations (depth bounds, ancestor/descendant cascades, level selection, leaf filtering, etc.). Existing tests cover the common paths but many combinator branches and edge cases are not hit:

- Lines 408–498: bulk of query-construction branches
- Lines 565–720: execution / SQL emit paths for specific filter shapes
- Lines 766–932: result-shaping / format coercions

The uncovered code is dense across the file rather than one big cluster — suggests we need a wider matrix of query construction × hierarchy shape rather than one missing fixture.

## Proposed work

1. Build a fixture matrix: small (3 levels, balanced), wide (10 children per node), deep (5+ levels), and sparse (many leaves at different depths). One fixture per shape.
2. Test every documented DSL combinator on at least one shape:
   - depth bounds (\`.at_depth\`, \`.up_to_depth\`)
   - relationship cascades (ancestors, descendants, siblings)
   - level filtering
   - leaf-only / branch-only
   - chained combinators
3. Add boundary tests: empty hierarchy, single node, malformed parent refs.

## Acceptance

- \`just coverage\` reports \`hierarchy_query.py\` ≥ 85%.
- A test matrix table in \`tests/unit/test_hierarchy_query.py\` listing which combinator × shape pairs are exercised.
