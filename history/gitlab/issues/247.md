# Issue #247: Fuzz the readers: one declared exception, and pin the hardening we inherited

| --- | --- |
| State | closed |

The generative strategies only ever produce artefacts that are **correct**. That is the right shape for round-trip properties — you cannot assert "this survives" about something that was never valid — but it means every byte the readers have been tested on came from a well-formed document. The readers sit directly on the untyped shell (lxml, msgspec), and a provider returning a truncated response is not hypothetical.

## Measured starting point

Feeding 6600 mutated fixtures through `parse`:

| count | exception | source |
| --- | --- | --- |
| 4935 | `lxml.etree.XMLSyntaxError` | lxml |
| 788 | `msgspec.DecodeError` | msgspec |
| 720 | `ValueError` | ours — and the only one `parse` documented |
| 45 | `msgspec.ValidationError` | msgspec |
| 15 | `SdmxConformanceError` | ours |
| 13 | `UnicodeDecodeError` | stdlib |

No crashes and no hangs — but handling a malformed provider response meant importing **lxml and msgspec** to name their exceptions. That is the opposite of the boundary this library draws everywhere else: parse, validate, hand typed objects inward.

Separately, the classic parser attacks are all already refused — entity amplification, XXE, deep nesting — but refused *by inheritance*, from lxml's defaults and msgspec's typed decode, with nothing in the suite saying so. One `etree.XMLParser(resolve_entities=True)` or `huge_tree=True`, for a reason that looked good at the time, would undo all three silently.

## The contract

`parse` gets one declared failure: `SdmxParseError`, a sibling of the existing `SdmxConformanceError` (which becomes a subclass, since "the document says something impossible" is still "this payload is not usable SDMX"). It subclasses `ValueError` — which is what `parse` already promised, and what every wrapped exception except lxml's already was — so existing handlers keep working. The underlying failure is preserved as `__cause__`.

## Why Hypothesis and not Atheris

Atheris 3.1.0 ships three wheels, `cp312`/`cp313`/`cp314`, all `manylinux2014_x86_64`, and no sdist. There is no macOS build and no arm64 build, so it cannot be installed on the machine where `just ci` runs. Beyond availability, Hypothesis shrinks a failure to a minimal payload — the single biggest practical advantage for a parser — composes with the existing strategies, adds no dependency, and `derandomize` makes failures reproducible without a seed corpus on disk. `hypothesis.target()` supplies guided search without coverage instrumentation.

HypoFuzz is the coverage-guided option that hooks into the same `@given` tests, if the plain fuzzer stops finding things. Two caveats for later: a non-OSI licence, and it pulls `starlette`, `hypercorn`, `trio`, `libcst` and `black` into the dev group.

## Targets

- byte mutation of the fixture corpus — truncate, flip, delete, duplicate, inject;
- structure-aware mutation — the document stays well-formed and stops being valid SDMX (dropped attribute, renamed element, corrupted URN, wrong JSON value type). This is the half byte mutation cannot reach: ~3 in 4 byte mutations die inside the XML parser before our code runs;
- mutation of our own **writer output**, so the shapes we actually emit are fuzzed, not only the two dozen files checked in;
- fixed pins for billion laughs, XXE, deep nesting and a 100 000-attribute element.
