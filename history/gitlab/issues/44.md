# Issue #44: feat: standards-compliant MetadataSet serialisation (GenericMetadata messages)

Follow-up from #43 phase 2.

## Background

SDMX-ML 3.0 and SDMX-JSON 2.0 both split message types:

- **Structure messages** carry definitions (DSDs, Codelists, MSDs, **Metadataflows**)
- **GenericMetadata messages** carry populated **MetadataSets** with reports and values

In v0.11.0 we (incorrectly) added MetadataSet round-trip inside our SDMX-JSON
\`Structure\` message. That works for sdmxlib-internal round-trips but is not
standards-compliant — a real SDMX-3 client wouldn't parse it that way.

In v0.13.0 we'll be adding standards-compliant SDMX-ML 3.0 for MSD +
Metadataflow inside the Structure message envelope. MetadataSet was
deliberately excluded from that MR because it belongs in a different
message type entirely.

## Scope

1. **Audit SDMX-JSON 2.0 schema** — confirm whether \`metadataSets\` is or
   isn't a legal field inside a Structure JSON message. If it isn't:
   - Deprecate the v0.11.0 placement (still parse it for back-compat, but
     emit a warning)
   - Route MetadataSets through a new GenericMetadata JSON handler

2. **New format module(s)** for GenericMetadata messages:
   - \`formats/sdmx_metadata_ml30/\` — reader + writer for SDMX-ML 3.0
     \`<mes:GenericMetadata>\` messages
   - JSON equivalent — likely an extension to \`formats/sdmx_json/\` with
     a separate entry-point distinguishing the message envelope

3. **API surface** — likely two new top-level helpers:
   - \`sl.parse_metadata(bytes)\` → returns just metadata sets
   - \`sl.to_metadata_xml(metadata_sets)\` / \`sl.to_metadata_json(...)\`

   \`StructureMessage\` keeps \`metadata_sets\` as an internal in-memory
   convenience but the serialisation layer routes by artefact kind.

4. **Bridge**: \`reg.metadata(metadataflow).attached_to(urn).fetch()\`
   helper from #43's original spec — fetches a GenericMetadata response
   from a real SDMX 3.0 reference-metadata API (IMF, ESMS) and parses it.

## Why separate from #43

- Cleanly scoped MR — one message envelope per MR
- Lets v0.13.0 ship the structures-side standards compliance without being
  blocked on resolving the JSON audit
- The JSON audit may surface choices that affect the model layer (e.g.
  removing \`metadata_sets\` from \`StructureMessage\`); doing it in
  isolation reduces blast radius
