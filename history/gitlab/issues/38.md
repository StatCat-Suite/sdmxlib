# Issue #38: Add SQL-backed CodelistScope.roots() and CodelistScope.children(parent_id) for tree navigation

| | |
| --- | --- |
| State | closed |
| Opened | 2026-04-20 |
| Closed | 2026-04-20 |
| Labels | `api`, `feature-request`, `performance` |

## Problem

Walking a codelist hierarchy currently requires loading the entire codelist eagerly:

    cl = local.get(codelist_urn, eager=True)  # loads ALL N codes into Python objects
    cl.roots()                                 # Python filter: parent_id IS NULL
    cl.children_of("1")                        # Python filter: parent_id == "1"

For large codelists (e.g. Statistics Canada CL_GEO with 5345 codes), this materializes
thousands of Code objects just to answer a question about ~6–13 direct children. When
used in a lazy tree UI (each + click fires one request), this full load happens on every
single expand — even though only one level is needed each time.

## The schema already supports it

The sdmx.code table has a parent_id column and a covering index:

    CREATE INDEX IF NOT EXISTS idx_code_parent ON code(codelist_urn, parent_id);

Someone clearly anticipated this access pattern. The scope API just never exposed it.

## Proposed fix

Add two SQL-backed navigation methods to CodelistScope:

    store.codelist(urn).roots()           # SELECT WHERE parent_id IS NULL
    store.codelist(urn).children("1")     # SELECT WHERE parent_id = '1'

Both return ItemList[Code] (or an enrichable scope), use the existing index, and touch
only the rows actually needed regardless of total codelist size.

## Impact

With these methods, a lazy tree UI can walk Geography one level at a time:

    # click + Canada  → reads ~13 rows
    store.codelist(geo_urn).children("1").collect()

    # click + Nova Scotia  → reads ~6 rows
    store.codelist(geo_urn).children("10").collect()

Instead of loading 5345 codes on every click to discard 5339 of them.

The HTMX hx-trigger="intersect once" pattern already handles client-side caching
correctly (each node loads once, then open/close is pure CSS). The server side just
needs to stop over-fetching.
