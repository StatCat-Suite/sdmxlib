# Issue #20: Round-trip fidelity: parse and re-emit AgencyScheme / OrganisationSchemes

| | |
| --- | --- |
| State | closed |
| Opened | 2026-03-31 |
| Closed | 2026-03-31 |

## Problem

Every real SDMX 2.1 response from the ECB (and most other agencies) contains an
`<OrganisationSchemes>` block that the current reader silently drops. This means
agency names are lost on read and never written back.

See `docs/design/round_trip_fidelity.md` (Change 1) and `docs/design/ergonomics.md`
(Problem 7) for full design.

## What changes

### Domain model (`model/organisation.py`)
- Add `Contact` value class (name, department, role, phones, uris, emails)
- Extend `Agency` with `name`, `description`, `contacts`, `parent` fields
- Add `AgencyScheme` as a `MaintainableArtefact` (id, agency_id, version, name, agencies)
- Add `DataProviderScheme` with `DataProvider` items (needed for `ProvisionAgreement` resolution)

### `StructureMessage` (`model/message.py`)
- Add `agency_schemes: ArtefactList[AgencyScheme]` field
- Add `data_provider_schemes: ArtefactList[DataProviderScheme]` field

### Readers
- SDMX-ML 2.1: add `_read_organisation_schemes()` — reads `AgencyScheme` and `DataProviderScheme`
- SDMX-ML 3.0: same, plus parse `Contact` children on each `Agency`

### Writers
- SDMX-ML 2.1: add `_write_organisation_schemes()` — emits `<str:OrganisationSchemes>`
- SDMX-ML 3.0: same, plus emit `<str:Contact>` children

### Test fixtures
- Add `<str:OrganisationSchemes>` block to `tests/fixtures/sdmx_ml21/minimal.xml`
- Add corresponding block to `tests/fixtures/sdmx_ml30/minimal.xml`
- Add round-trip assertions: `msg.agency_schemes.ids()` and `msg.agency_schemes[...].agencies["ECB"].name["en"]`

## Acceptance criterion

```python
orig = parse(Path("tests/fixtures/sdmx_ml21/ecb_dataflow.xml").read_bytes())
rt   = parse(serialize(orig))
assert len(rt.agency_schemes) == len(orig.agency_schemes)
```

Currently fails (agency_schemes are dropped). Must pass after this change.
