# Issue #193: [S1] Allow `id` as a builtin shadow in config — removes 21 A002/A001 noqas

| | |
| --- | --- |
| State | closed |

| Closed | 2026-08-04 |
| Milestone | %9 Suppression audit: fix the defect, not the symptom |
| Labels | `type::chore`, `typing` |

SDMX artefacts have an `id` field, so every constructor and lookup that takes one shadows the `id` builtin. That is a single project-wide decision currently written out **21 times**:

```
20 × A002  # noqa: A002    (parameter named `id`)
 1 × A001  # noqa: A001    (assignment to `id`)
```

Sites: `model/base.py`, `model/concept.py`, `model/binding.py`, `model/urn.py`, `model/collections.py`, `storage/lazy.py` ×2, `api/registry.py` ×5, and others.

The reason is legitimate — the alternative is renaming a field the SDMX information model names `id`. But a reason that applies everywhere belongs in config, where it is stated once and reviewed once.

## Fix

```toml
[lint.flake8-builtins]
# SDMX names this field `id`; shadowing the builtin is the model, not an accident.
builtins-ignorelist = ["id"]
```

## Verified before filing

Running the real config with that option added: RUF100 flags **exactly 21** now-dead noqa directives — the same 21 — and they are auto-fixable with `ruff check --fix`. No other rule changes count.

## Acceptance

* `builtins-ignorelist` set with a rationale comment in `ruff.toml`.
* All 21 `A001`/`A002` noqas removed; `just check` clean (RUF100 proves none were load-bearing for anything else).
