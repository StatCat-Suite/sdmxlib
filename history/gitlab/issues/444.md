## Summary

Since #442 the store keeps `uri` on every item table, and `collect()` returns it. But the query language exposes no path for it, so `reg.query(sl.q.code).filter(sl.q.code.uri == ...)` and `select(uri=sl.q.code.uri)` are not available. You have to collect and filter in Python.

## Scope

Every item relation that gained a `uri` column in schema 2.23: code, concept, category, agency, data and metadata providers, component, group, hierarchy node and level, and metadata attribute. Maintainables already carry `uri` on the artefact spine. Check whether that is exposed too and make the two consistent.

## Notes

- `query/accessors.py` declares the paths per relation, and `sl.schema` reflects the DDL, so raw SQL (`reg.sql`) already sees the columns. This issue is only about the path language.
- Per CLAUDE.md, add a differential property for the new paths, or extend the existing ones (`tests/support/oracle.py`, `hierarchy_oracle.py`). The strategies must set `uri`, or every property over it is vacuous (rule 4).
