The #422 position check (`formats/_positions.py`, 901421a) refuses a DSD whose stated `Dimension/@position` values are not consecutive in document order. ESTAT's SDMX 3.0 registry publishes **802 of ~349k** DSDs with gaps — `ESTAT:DSB_ICTEG01(7.0)` numbers its dimensions 1, 2, 3, 5, 6 (a removed dimension, by the look of it), order intact. The sweep in !571 is the first baseline to run the rule, and shows all 802 as `read_refused`.

**Decided (2026-10-13):** accept a gap, refuse disorder. The model keeps no position — order is all it holds — so a skipped number loses nothing, while a position that contradicts document order still says something impossible.

- Positions must strictly increase with document order (any base, any gaps); duplicates and decreases are refused.
- Same rule for SDMX-JSON's `position`.
- Sweep delta: ESTAT 3.0 `datastructure` `read_refused` 802 → 0.
