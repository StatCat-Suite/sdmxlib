# Issue #209: refactor: SDMX-ML closure factories -> classes (measured: no perf cost); drop the legacy rebindings

| | |
| --- | --- |
| State | closed |
| Opened | 2026-08-05 |
| Closed | 2026-08-05 |
| Labels | `design`, `type::refactor` |

**Proposal.** Came out of #199's triage: the two largest functions in the codebase carry complexity suppressions, and the reason they are large is a design choice that measurement does not support.

## What the factories are

`formats/sdmx_ml/_common.py` exposes two closure factories that bind the SDMX-ML namespace triple and return a bundle of helpers:

```python
def make_reader_helpers(*, com: str, str_: str, mes: str) -> ReaderHelpers:  # noqa: C901, PLR0915
    def c(tag: str) -> str: return f"{{{com}}}{tag}"
    def s(tag: str) -> str: return f"{{{str_}}}{tag}"
    ...  # 24 nested defs
```

They exist so the 2.1 / 3.0 / 3.1 readers and writers share one implementation, differing only in namespace URIs.

| factory | nested defs | lines | C901 | statements |
| --- | --- | --- | --- | --- |
| `make_reader_helpers` | 24 | 670 | 88 (limit 10) | 210 (limit 50) |
| `make_writer_helpers` | 22 | 335 | 76 | 221 |

These are the two largest functions in `src/` by an order of magnitude, and account for 4 of the 12 complexity suppressions.

## lxml's namespace support — read and write differ

An earlier draft of this issue claimed lxml offers "no way to bind a default namespace". **That is wrong for reads.** Verified:

```
find('str:Codelist', namespaces=NS)     -> works
findall('.//com:Name', namespaces=NS)   -> works
xpath('//str:Codelist', namespaces=NS)  -> works
```

`find` / `findall` / `iterfind` / `xpath` all take a prefix map, so a plain module-level `NSMAP` constant per version is enough — **no closure is needed for lookups at all**.

Writes are different. `SubElement` has an `nsmap` parameter, but it *declares* namespaces on the element rather than resolving a prefixed tag:

```
SubElement(parent, "str:Name", nsmap=NS)  -> ValueError: Invalid tag name 'str:Name'
SubElement(parent, "{uri}Name")           -> ok
```

Element construction requires Clark notation, so the writer genuinely needs the URI at each call site.

**This splits the issue in two**, and the reader half is the larger prize:

* **Reader** — the namespace helpers can be removed outright, replaced by prefixed paths against a module `NSMAP`. That is the idiom lxml is designed for, and it eliminates `c()`/`s()`/`m()` rather than relocating them.
* **Writer** — still needs per-namespace tag building, so the class conversion below is the relevant option there.

## The performance rationale does not survive measurement

The code carries a perf comment, and it is accurate — but about a *different* optimisation:

> Pre-built clark-notation tags for the hot read paths. ~4x faster than the f-string-building `c()`/`s()` calls at ~10 ns vs ~43 ns per access.

That is pre-built constants vs rebuilding f-strings per call, and a class preserves it exactly (`self._c_name`, built once in `__init__`).

For the closure-vs-class question specifically, measured over 2M iterations:

```
closure cell access :  12.5 ns/call
instance attribute  :  12.4 ns/call
difference          :   -0.1 ns  (-1 %, noise)
```

**No measurable difference.** The factory's shape is not buying speed.

## The complexity scores are largely an artifact

Ruff sums nested `def` complexity into the enclosing function. Probed directly — a factory with three trivial nested functions (each complexity 2) scores **7**, where a flat function with the same three branches scores 4.

So `make_reader_helpers`' 88 is not one unreadable function; it is ~24 individually-simple closures counted as one. **As methods on a class each would be scored separately, and essentially all would pass** — which means the suppressions disappear as a *side effect* of a better structure, not as the goal.

## Correction: the reader half does **not** hold up

An earlier revision argued the reader could drop `c()`/`s()`/`m()` entirely in favour of prefixed paths, calling it "the larger prize". Checking what the call sites become:

```python
cl_el.find(_s("Codelist"))                      # current
cl_el.find("str:Codelist", namespaces=_NS)      # prefixed path
```

**314 call sites would each gain `, namespaces=_NS`.** lxml's namespace support is per-call — there is no way to bind the map to an element, a tree or a parser — so "use lxml's built-in support" trades one terse helper for a repeated keyword argument at every lookup.

Surveyed first, so the shape is not in doubt: 273 helper calls across the three readers are **100 %** inside `find`/`findall`, plus 39 in `_common`, with exactly one dynamic case (`read_istring`'s `tag = c(child_tag)`). The conversion is mechanical — it is just not an improvement.

I concluded from this that `c()`/`s()`/`m()` were justified after all, and withdrew the proposal. **The maintainer disagreed, and is right:**

> the lxml with keyword reads clearer, and what it is doing is obvious, the `_s` requires someone to read that function

That is the better trade. `find("str:Codelist", namespaces=NS)` is standard lxml — any Python reader knows what it does without leaving the line. `_s("Codelist")` requires knowing what `_s` builds. Explicit standard idiom beats a project-specific abbreviation, particularly in a library other people read; weighing line length above that was the wrong instinct.

**So the conversion is back in scope**, on clarity grounds rather than the "delete the helper" framing I first used. The verbosity is real and is the price.

## Proposal

Convert both factories to classes: namespaces and pre-built tags stored in `__init__`, nested `def`s become methods.

**Call sites are unchanged.** The readers already bind once at module level:

```python
_helpers = make_reader_helpers(com=COM, str_=STR, mes=MES)
_c = _helpers.c
_s = _helpers.s
```

With a class, `_helpers` is an instance and `_helpers.c` a bound method — the same expression.

## Why this is worth doing beyond the lint

* Two 670/335-line functions become navigable classes; jump-to-definition lands on a method rather than scrolling a closure body.
* Individual helpers become independently testable.
* 4 of 12 complexity suppressions go away without a single line written to satisfy a linter.

## Risks, honestly

* ~1000 lines of restructuring in a well-tested, heavily-exercised area. Regression risk is real even though the transformation is mechanical.
* The frozen-dataclass bundles (`ReaderHelpers` / `WriterHelpers`) currently give a typed surface with `_ResolveRef`-style Protocols for the generic members. A class must keep those generic signatures working — the `resolve_ref[T]` / `resolve_ref_text[T]` / `read_representation[T]` members are the ones to watch.
* Should be its own MR, and ideally split reader and writer so each is reviewable.

## Suggested sequencing

Prototype the **writer** factory first — it is the smaller of the two (22 defs, 335 lines), has no generic Protocol members, and is the half where Clark-notation building is genuinely unavoidable. It tests the class shape at lower risk.

The **reader** needs no prefixed-path conversion — see the correction above. If the class change is adopted, its tag builders simply become methods like everything else.

## Also in scope: the `_helpers.x` rebinding scaffolding

Each reader and writer rebinds every helper to a module-level underscore name:

```python
_helpers = make_reader_helpers(com=COM, str_=STR, mes=MES)
_c = _helpers.c
_s = _helpers.s
...  # 24 of them
```

The comment says why, and says it is temporary:

> bound here under their **legacy** underscore names so the rest of this module (which uses them extensively) can keep its existing call sites

That is migration scaffolding from when the helpers were extracted into `_common`, never removed once the extraction settled. It costs:

| file | rebindings | call sites |
| --- | --- | --- |
| ml21 reader | 23 | 219 |
| ml30 reader | 24 | 268 |
| ml31 reader | 24 | 264 |
| ml21 writer | 21 | 206 |
| ml30 writer | 11 | 275 |
| ml31 writer | 11 | 250 |

**114 rebinding lines**, and — more importantly — every call site reads `_s("Codelist")`, which looks like a module-private function but is a shared helper bound to this module's namespaces. `_helpers.s("Codelist")` says where it comes from.

**No performance reason to keep it.** Measured over 3M iterations:

```
module-level rebound name : 13.0 ns/call
helpers.s(...)            : 12.4 ns/call   (-4%, noise)
```

Attribute access is if anything marginally faster.

**Folded in here rather than done separately**, because these are the same call sites the factory change touches: if the reader moves to prefixed `find`/`findall` the `_c`/`_s`/`_m` bindings disappear outright rather than being renamed, and if the factories become classes `_helpers` becomes an instance. Doing the rename first would touch ~1500 call sites twice.

## Not in scope

The other 8 complexity suppressions (#199). Seven of them are 1–3 points over a threshold of 10 and are inherent dispatch shapes; splitting those to satisfy the lint would make them worse. This issue is only about the two outliers.

## Comments

### 2026-08-05

Both factory conversions are done — !204 (writer) and !205 (reader). The de-aliasing landed earlier in !202.

**Complexity suppressions in `src/`: 12 → 5.** Remaining: `write_text_format`, the two `read` functions, `_resolve_urns`, `_emit_predicate` — all #199's business.

## The framing in this issue was wrong, and is corrected

This issue argued the C901 scores were "largely an artifact of ruff summing nested `def`s", drawing a parallel to SLF001 — a rule that flags correct code it cannot structurally understand. **That parallel was false.** C901 was flagging genuine convolutedness and was right to.

The reader half made it plain. The closure-plus-dataclass form needed **three Protocol classes that existed only to work around itself**:

```
_ResolveRef
_ResolveRefText
_ReadRepresentation
```

each documenting the reason in its own docstring — *"a plain `Callable` annotation cannot carry a free type parameter"*. A method is generic for free. All three are deleted, and `PYI046` reported them unused the moment the methods existed.

The writer half showed the same in a different currency: three fields typed `Callable[..., None]`, erasing arity and parameter types that methods carry for nothing.

So the accurate summary of #209 is not "the metric was measuring the wrong thing". It is: **the closure factory was the more complex design, the linter said so, and this replaced it.**

> the lxml with keyword reads clearer, and what it is doing is obvious, the `_s` requires someone to read that function

Worth converting one file first and looking at it before committing to all six.

## Outcome

* `make_reader_helpers` (670 lines, 24 nested defs) and `make_writer_helpers` (335 lines, 22) are classes.
* **Three Protocol classes deleted** — `_ResolveRef`, `_ResolveRefText`, `_ReadRepresentation` existed only because a dataclass field cannot carry a free type parameter. `PYI046` reported them unused the moment the methods existed.
* **Three `Callable[..., None]` fields** that erased arity and parameter types now carry real method signatures.
* **114 legacy alias lines** removed; two of them were dead, shadowed by a local `def` in the 3.0 and 3.1 writers.
* **322 reader lookups** converted to lxml prefixed paths; `ReaderHelpers.c`/`.s`/`.m` and the eight pre-built `com:` Clark constants deleted as a consequence.
* Complexity suppressions in `src/`: **12 → 5**.

## Two things this issue got wrong

**The C901 framing.** It argued the scores were "largely an artifact of ruff summing nested `def`s", drawing a parallel to SLF001 — a rule that flags correct code it cannot structurally understand. That was false, and it excused a bad design. C901 was flagging genuine convolutedness; the three workaround Protocols and the erased signatures are what 88 and 76 were pointing at.

**The prefixed-path verdict, twice.** First proposed as "the larger prize", then withdrawn on call-site brevity grounds, then reinstated when the maintainer pointed out that brevity is the wrong axis: `find("str:Codelist", namespaces=NS)` is standard lxml a reader knows on sight, where `_s("Codelist")` has to be looked up.

Both errors were the same habit — pattern-matching a new case onto a previous one instead of judging it fresh.
