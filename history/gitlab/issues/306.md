# Issue #306: One query language over the SDMX information model

| | |
| --- | --- |
| State | closed |

Subsumes #280, #297, #304.

## What this is

A single query language over the SDMX IM, replacing the four hand-written SQL
DSLs, with **where a query runs** a property of the backend rather than of the
language. Paths are typed expressions over a declared edge graph; the surface
borrows polars' *expression* layer while keeping this library's own composition
laws.

The design is settled. Five documents carry it, and every spelling below is a
type-checked prototype:

| document | holds |
| --- | --- |
| `docs/design/query-language.md` | the design — rules, arguments, open questions |
| `docs/design/query-language-evidence.md` | what was **run** — surveys, benchmarks, prototype log |
| `docs/design/query-language-examples.md` | the surface, construct by construct |
| `docs/design/query-language-cookbook.md` | the surface **applied** — consumer shapes, REST |
| `docs/design/query-language-explorations.md` | branches prototyped and rejected |

## Why

The %15 consumer survey found **113 hand-written SQL sites** across six
applications. They exist because the DSLs cannot express what callers need. The
worst shape — "every dataflow × dimension × codelist as one frame", 21 sites —
costs **265 ms by resolution against 1 ms as one statement**, a 331× gap, and
`FrameQuery[R]` is parameterised on a single `RowKind` so it cannot be
expressed at all.

Two backends now exist (DuckDB and SDMX REST), which is the need the #273
no-IR decision was waiting for: that decision was about what a query can *say*,
and this is about where it *runs*.

## The shape, in brief

```python
q = sl.q

(reg.query(q.dataflow)                                  # generic entry, any accessor
   .filter(q.dataflow.agency == "ESTAT",
           q.dataflow.dsd.dimensions.concept.id == "REF_AREA")
   .select(q.dataflow.id,
           label=q.dataflow.name["en"].fill_null(q.dataflow.id),
           dims=q.dataflow.dsd.dimensions.id.list())
   .collect())                                          # the only executing call
```

**Rules that are settled** (full argument in the design doc):

- **A path appears exactly where there is a decision.** The 1:1 identity split
  with `sdmx.artefact` is physical layout, so the maintainable surface is
  hoisted; a reference edge is a real choice and is always named.
- **The root fixes the output grain.** Downward edges nest, upward edges
  denormalise; the two directions are one edge declared once with an inverse
  name.
- **Accessors are lowercase singletons**, matching `sl.code` + `CodeRow`, with
  the law `sl.q.` compiles, everything else resolves.
- **Paths are JPQL-style path expressions, not XPath-style patterns** — no
  wildcards, no alternation, no recursion in path syntax. Recursion is a named
  domain verb backed by the baked `depth` / `ancestor_ids` columns.
- **The query family is strictly lazy.** `[]` may refine, never extract.
- **Composition laws are ours, not polars'** — `filter` ANDs, `limit` mins,
  filter-after-slice is refused. polars' *expression* layer is borrowed; its
  *frame pipeline* is not.

## Work breakdown

### 1. Edge model and compiler — the actual work

- [ ] Declare the edge graph: name, direction, **cardinality**, inverse name,
      optionality. One declaration per storage edge, read both ways.
- [ ] Accessor classes generic over the row kind; `edge()` threads the
      **root's** row kind, not the target's.
- [ ] Compiler: paths → join tree, **shared-prefix deduplication**, alias
      assignment, `EXISTS` / `list(...)` / join kind chosen by context.
- [ ] Drift guard, three obligations: declared cardinality against the schema's
      key constraints; each identity split still PK-to-PK and mandatory;
      column coverage policy (report or fail — see open Q5).

### 2. Expression surface

- [ ] Column types `Str[R]`, `Num[R]`, `Win[R]`; `Cols[R]` common base.
- [ ] Namespaces: `.str` (**including the `caseless` / `unaccented` / `folded`
      ladder — a must-keep, see below**), `.hier`, `.ann`, `["lang"]`.
- [ ] Fan-out: dot-through, `.any(*preds)` / `.every(*preds)` as the same-child
      binder, `.list(*cols)` returning **structs**.
- [ ] Expression features: `sl.union()` (free function), `.intersect()`,
      `.difference()`, `.unique()` (full row only), arithmetic, window
      functions, `.qualify()`, `fill_null` / `when-then-otherwise`, `.over()`.
- [ ] Terminals: `collect` `ids` `urns` `count` `exists` `first` `one`
      `one_or_none` `preview` `explain` `to_sql`.

### 3. Entry points and migration

- [ ] `reg.query(<accessor>)` as the generic entry; named roots become ordinary
      convenience functions.
- [ ] Keep `reg.artefacts(T)` and `reg.artefacts()` — generic helpers and
      "any maintainable" have no named-root equivalent.
- [ ] Retire `Query[T]`: its only distinguishing feature is the Python-side
      `filter(lambda)` that strict laziness bans.
- [ ] Remove `__iter__` / `__len__` / `__contains__` from `CodeQuery`,
      `NodeQuery`, `ArtefactQuery`; re-point `__getitem__` from extract to
      refine; **add the terminals that replace them**.
- [ ] Migrate the four DSLs (~1,400 statements) and consumer call sites.

### 4. Backends

- [ ] IR: `Scan | Filter | Project | Join(edge) | Nest/Explode | Aggregate |
      Sort | Limit`.
- [ ] Capability declaration per backend; pushdown with a local residual.
- [ ] `explain()` showing what pushes and what does not.
- [ ] **Refuse rather than silently fetch**, with both escapes named in the
      message.
- [ ] REST structure plane (`references=` *is* the fan-out node); data plane
      (`c[...]` is near 1:1, and `sdmxlib-rest` already implements the
      translation).
- [ ] Federation planner over `FederatedCatalog.from_parts` +
      `Session.value_set`.

### 5. Escape hatch and extension

- [ ] `reg.sql(...)` as a terminal **and** as a one-column `SqlRelation`
      spliceable via `is_in`. Parameterised values only; a different method on
      a different object, so the structural DSL still never accepts text.
- [ ] Schema constants (`sl.schema.dsd_component.codelist_urn`) so raw SQL
      couples to the layout and a drift guard can check it.
- [ ] Cross-schema: document that a downstream library declares its own
      accessor with an edge into the sdmx graph. **No sdmxlib change needed** —
      verified typed. Caller→us only.
- [ ] Cross-plane: `.labelled(lang=)` and `q.obs[dim].code.name[lang]`, moving
      `sl.polars.label` inside the query language. `lang` stays required.

## Must not regress

- **`caseless` / `unaccented` / `folded`.** These exist today and were paid for
  by #222 and #255. Preserve the ladder exactly: `caseless` carries `==` / `!=`
  and the other rungs do not; `caseless` applies to **ids**, not only labels;
  they stay properties.
- The differential oracles and their four rules. A new predicate kind without a
  property fails `test_every_predicate_kind_is_covered`.
- `query-composition.md`'s three laws. Every new clause is checked against them
  **first** — that is how `qualify` and the `unique(subset)` exclusion were
  found, at design time.

## Known risks

- **The compiler is the whole design and none of it is prototyped.** Everything
  so far is type-level. The 331× figure is hand-written SQL in the shape we
  hope to emit.
- **Correlated subqueries are linear in fan-out columns** (~10 ms each over
  100k child rows), and the alignment-safe struct form is the slowest. Shared-
  prefix coalescing is a **requirement**, not an optimisation.
- **Pushdown correctness is safety-critical.** Erring permissive silently
  restores the 800-resolution problem the design exists to prevent.
- **Migration blast radius** is four DSLs plus three shipped classes losing
  dunders.
- **Predicates cannot be reused across roots** — the row kind binds each to
  one, so a shared predicate library is impossible by construction.

## Out of scope

`PIVOT` (polars does it in one call, by the rule that killed server-side
`explode`), reverse cross-schema edges (ours→theirs, which would mean mutating
a class we own from outside), and streaming results larger than memory —
currently unnamed anywhere, and worth its own issue.
