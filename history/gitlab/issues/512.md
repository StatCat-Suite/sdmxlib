# Issue #512: Exceptions the docs name are not importable from sl

| | |
| --- | --- |
| State | closed |
| Opened | 2026-10-20 |
| Closed | 2026-10-20 |
| Milestone | %26 Found by the docs audit: correctness and refusals |

Several exception types that the docs and docstrings tell users to catch can't be imported from `sl`:

- `PushdownError`: `RestRegistry.query` documents it under Raises, and `llms-dsl.txt` names it.
- `SliceError`, `CrossSourceError`, `PathError`.
- `SdmxConformanceError`: default `parse` raises it, but callers can only catch it as `sl.SdmxParseError`.

```python
[n for n in ("PushdownError","SliceError","CrossSourceError","PathError","SdmxConformanceError") if not hasattr(sl, n)]
# all five
```

The rule CLAUDE.md states ("everything in a signature is importable", upgrading.md) should cover what a documented `Raises:` names too.

**Fix:** export them, add them to `docs/api.md`, and extend `test_public_surface` so a `Raises:` entry naming an unexported sdmxlib type fails.
