# Issue #397: LocalRegistry.get declares Codelist/Hierarchy but returns the lazy classes, so h.codes type-checks and raises

| | |
| --- | --- |
| State | closed |
| Opened | 2026-09-07 |
| Closed | 2026-09-08 |

Found while measuring what is left for #347's `tests/unit` pass, after #396
made the query terminals typed.

## The defect

```python
h = reg.get(sl.Hierarchy.urn_for(agency="AG", id="H", version="1.0"))
h.codes          # type-checks as Hierarchy.codes — AttributeError at runtime
h.tree           # same
h.descendants    # same
```

`LocalRegistry.get` is declared `get[T](target: SdmxUrn[T] | Ref[T]) -> T | None`,
so the URN's phantom decides the return type: a `SdmxUrn[Hierarchy]` gives
`Hierarchy | None`. What comes back is a `LazyHierarchy`, which **does not have
`codes`, `tree` or `descendants` at all** — it has `nodes`. Measured, not
inferred:

| | shared attributes | only on the real class | only on the lazy one |
| --- | --- | --- | --- |
| `Codelist` / `LazyCodelist` | 29 | `add`, `drop`, `msg_field`, `parse_rest_ref`, `urn_for` | `code_map`, `materialize` |
| `Hierarchy` / `LazyHierarchy` | 29 | `codes`, `tree`, `descendants`, `msg_field`, `parse_rest_ref`, `urn_for` | `nodes`, `ancestor_at`, `materialize` |

The codelist case is milder but the same shape — `codes` exists on both and is a
different type, so `len(cl.codes)` type-checks and raises
`TypeError: a query has no len() — it is a plan, not a collect`.

## `eager=` changes the class and not the declaration

```python
reveal_type(reg.get(urn))              # Codelist | None   -> LazyCodelist
reveal_type(reg.get(urn, eager=True))  # Codelist | None   -> Codelist
```

Same declared type for both, and the flag that decides is invisible to the
checker. So neither branch is right: one is a lie and the other is accidentally
correct.

## Same shape as #370

`LocalRegistry` is the only one of the four `get`s that diverges — and the only
one with `eager=`. `RestRegistry`, `InMemoryRegistry` and `FederatedRegistry`
hand back the real classes. #370 fixed what the four `get`s **accept**; this is
what one of them **returns**.

## Scope

30 findings in `tests/unit` name `ItemList[Code]` from this, out of 1,116 total
(second-largest single cause; the largest is 75 `MetadataMessage` attribute
errors, which are just `parse()`'s union going un-narrowed — mechanical #347
work, not a design question).

`docs/upgrading.md` and `tests/docs/test_upgrading.py` already document the
codelist half as a trap readers must know about. That is the tell: a trap that
needs documenting is usually a declaration that could have said so.

## Options

1. **Overloads on the two lazy roots.** Verified to work — three overloads, and
   every other artefact type is untouched:

   ```python
   @overload
   def get(self, t: SdmxUrn[Codelist] | Ref[Codelist], *, eager: Literal[False] = False) -> LazyCodelist | None: ...
   @overload
   def get(self, t: SdmxUrn[Hierarchy] | Ref[Hierarchy], *, eager: Literal[False] = False) -> LazyHierarchy | None: ...
   @overload
   def get[T](self, t: SdmxUrn[T] | Ref[T], *, eager: bool = False) -> T | None: ...
   ```

   Gives `LazyCodelist | None`, `Codelist | None` under `eager=True`,
   `LazyHierarchy | None`, and `T | None` for everything else. The declaration
   becomes true in both branches and the `AttributeError` becomes a type error.
   Cost: the lazy classes enter the public signature, and callers who were
   relying on the (false) `Codelist` annotation get errors — which is the point,
   but it is a visible break.

2. **Give the lazy classes the missing members.** `LazyHierarchy.codes` /
   `tree` / `descendants` either materialise or raise with a message naming
   `nodes`. Closes the `AttributeError` without touching signatures, but leaves
   the declaration untrue and `len(cl.codes)` still failing at runtime.

3. **Declare the union** — `Codelist | LazyCodelist`. Honest, and forces
   narrowing at every call site including the many that only touch the shared
   29 attributes, where narrowing buys nothing.

4. **Return the real artefacts always.** Removes the divergence and the reason
   the lazy classes exist; #378's measurements are the argument against.

(1) is where the value is, and it is the only option that makes both branches
of `eager=` true. Worth deciding before the `tests/unit` pass rather than
after: whichever way it goes, those 30 sites get written twice otherwise.
