# Issue #472: A bad XML character in SDMX-JSON fails the whole read instead of refusing one artefact (#435)

| | |
| --- | --- |
| State | closed |
| Opened | 2026-10-16 |
| Closed | 2026-10-19 |
| Milestone | %21 Conformance evidence: what the green checks do not prove |
| Labels | `conformance`, `sdmx-json` |

## Problem

A JSON name holding a character XML cannot represent (U+0000, most other C0 control characters, lone surrogates, U+FFFE/U+FFFF) is caught twice on a read, with **two different outcomes**:

1. **The SDMX-JSON reader** (`formats/sdmx_json/_dto.py: ingest_istr`) raises `SdmxConformanceError` straight away, **failing the whole `parse()`**, even with `strict=False`. Nothing is read, and there is no message.
2. **Read-time validation** (`formats/_refuse.refuse_invalid` → `model/validation._check_name`) **refuses just that artefact**: it goes into `StructureMessage.refused` with its reason, and the rest of the document is read. That's the per-artefact behaviour #435 set for every other problem a document can have. On a JSON read it never runs for this case, because step 1 has already failed the read.

So a bad character in JSON is the one problem that still fails a whole document. Example: a 500-codelist JSON document with one bad character in one code:

| | today | with only the validation check |
| --- | --- | --- |
| `parse(doc)` | raises "contains U+0000" | raises `SdmxConformanceError` naming the refused codelist and why |
| `parse(doc, strict=False)` | raises; nothing is read | returns 499 codelists; the bad one is in `msg.refused` |

## Proposal

Remove the reader's check, and let read-time validation refuse the artefact, as #435 does for everything else. The check in validation stays, and is what still catches the character before anything is written as XML.

Found while working on #466: the reader's check is also the second of two scans of every name. That cost is small once #466's ASCII fast path lands, about 4 ms per 68,000 codes. This issue is about the behaviour, not the time.

## Done when

- A bad character in SDMX-JSON refuses only its artefact. `strict=False` returns the rest.
- `test_validation_xml_charset` and the JSON reader tests assert the new outcome, and an SDMX-ML read is unchanged.
