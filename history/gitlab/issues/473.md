## Comments

### 2026-10-16

**Bar for this issue (from the maintainer):** memory increases are acceptable. What isn't is memory that explodes, or that makes the library work badly on smaller-memory machines.

Measured against that bar:
- **The retention is bounded,** at one copy of the source document per message. It doesn't grow beyond that.
- **On a large model it's moderate:** +84 MB on `CL_GEOGRAPHY`'s 345 MB.
- **On a small model it's large:** UNSD's 8 MB model holds 38 MB, 4.7×.

The case worth fixing is the one that does squeeze small machines: a process that keeps many parsed JSON messages alive, each holding its document. Prioritise accordingly; this isn't urgent in itself.
