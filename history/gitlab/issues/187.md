# Issue #187: Metadata JSON: MetadataSet MSD-direct ref emits non-conformant `metadataStructure` key

| | |
| --- | --- |
| State | closed |
| Opened | 2026-07-22 |
| Closed | 2026-07-22 |

## Context

Surfaced during #182 (MR !172, metadata msgspec migration).

Our model's `MetadataSet.structure` may be a `Ref[MetadataStructure]` **or** a `Ref[Metadataflow]`. The SDMX-JSON 2.1 metadata schema's `MetadataSetType`, however, only defines two structure-ref keys:

- `metadataflow`
- `metadataProvisionAgreement`

There is **no** `metadataStructure` (direct-MSD) key in the schema. For the MSD-direct case our writer emits `"metadataStructure": "<urn>"`, which:

- is not a schema-defined property (tolerated today only because `MetadataSetType` doesn't set `additionalProperties: false`, but it's still off-spec), and
- means a strict validator / conformant consumer won't pick up the structure ref.

The reader accepts both keys, so our own round-trip is fine — the gap is **interop with conformant producers/consumers**.

## Questions to resolve

1. Does SDMX 3.0 actually permit a MetadataSet to reference an MSD directly, or must it always go through a Metadataflow / MetadataProvisionAgreement? (Check the IM + `pysdmx` / `sdmx1`.)
2. If MSD-direct is not a real wire case, should the model still allow `Ref[MetadataStructure]` on `MetadataSet.structure`, or should construction require a Metadataflow ref (resolving the MSD via the flow)?
3. We don't model `MetadataProvisionAgreement` at all yet — worth adding, since it's one of the two conformant attachment options.

## Acceptance (once decided)

- Metadata writer emits only schema-conformant structure-ref keys, OR the model is constrained so the MSD-direct case can't arise.
- A conformity test covers the chosen shape.

Relevant: `src/sdmxlib/formats/sdmx_json/metadata.py` (`_to_metadata_set` / `_structure_ref`), `src/sdmxlib/model/metadataset.py` (`_to_structure_ref`), `tests/schemas/sdmx_json/2.1/sdmx-json-metadata-schema.json` (`MetadataSetType`).
