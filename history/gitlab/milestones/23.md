# Milestone %23: Full information-model coverage: every maintainable artefact type

| | |
| --- | --- |
| State | closed |
| Opened | 2026-10-15 |
| Due | — |

Model every maintainable artefact type the SDMX information model defines. Each one is read and written in every format that has it, stored, and covered by the censuses.

## Where we are (measured 2026-10-15)

The SDMX-ML schemas define 41 maintainable artefact types: 37 in 3.1, plus 4 that exist only in 2.1.

| | types with a class (of 41) | strong where |
| --- | --- | --- |
| sdmxlib | 29 | mapping, constraints (all variants but `MetadataConstraint`), reference-metadata provision, 2.1 containers |
| sdmx1 2.27 | 30 | VTL, organisation schemes; 2.1 only on write; no structure JSON |
| pysdmx 1.20 | 28 | VTL, `AvailabilityConstraint`; no geographic codelists or 2.1 containers |

The sdmx1 and pysdmx counts are of classes. Whether their readers handle each type wasn't checked.

**sdmxlib's 12 gaps**, each refused on read by name, never dropped silently:
- VTL: Transformation, Ruleset, UserDefinedOperator, VtlMapping, CustomType and NamePersonalisation schemes;
- `MetadataConstraint`;
- `DataConsumerScheme` and `OrganisationUnitScheme`;
- `ReportingTaxonomy` and `ReportingTaxonomyMap`;
- `Process` (#361).

## Per artefact, done means

- Modelled in `sdmxlib.model`. Check the shape against sdmx1 and pysdmx where they have it, per CLAUDE.md.
- Read and written in SDMX-ML 2.1, 3.0, 3.1 and SDMX-JSON wherever the format has the type. Where it doesn't, a declared gap in `formats/gaps.py`.
- Stored by `LocalRegistry` and reachable from the query language.
- In the maximal fixture, so the element, attribute and JSON censuses and the round trips cover it.
- `docs/upgrading.md` notes the type is no longer refused.
