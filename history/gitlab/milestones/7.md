# Milestone %7: Typing hardening: eliminate needless Any

| | |
| --- | --- |
| State | closed |
| Opened | 2026-07-22 |
| Due | — |

Structured follow-up to the `Any` design audit. basedpyright runs in `standard`
mode (no `reportAny` pressure), so every `Any` in the tree is a *design choice*.
The audit found the codebase is mostly **honest boundary typing** (JSON/XML/SQL
wire data, phantom-`T` URN parsing) with **one** true structural variance issue
(`Ref[T]` invariance) plus a tier of cheap "Any where a named type already
exists".

This milestone sequences the fixes from **safe & self-contained** to
**experimental & structural**, so we tighten the model core first and only take
on the risky covariant-`Ref` refactor once the cheap wins are banked and we can
measure its payoff.

Tiers (work top-down):
- **T1 — model-core checked seams.** Tiny, isolated, immediate correctness.
- **T2 — mechanical formats/storage narrowings.** Low design risk, wider surface.
- **T3 — structural / experimental.** The one real variance fix (covariant Ref),
  prototyped-and-measured before committing.

Leave-alone (out of scope, honest `Any`): `SdmxUrn.parse -> SdmxUrn[Any]`
(genuine phantom bivariance), SERIAL_DICT JSON trees, EXT_UNTYPED
(duckdb/pyarrow/orjson/lxml), `Ref.__getattr__` proxy, and the `model/expr.py`
predicate DSL.
