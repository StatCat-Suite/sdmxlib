# Milestone %24: Large reads: GC and streaming

| | |
| --- | --- |
| State | closed |
| Opened | 2026-10-19 |
| Due | — |

Make large reads cost what sdmxlib's own work costs, and no more. On a large read, most of the time now goes to the runtime and the parser, not to sdmxlib.

## Where we are (measured 2026-10-18)

- **Garbage collection (#493):** CPython's cyclic GC takes 35% (Python 3.13) to 58% (3.14) of a large read. A reader builds hundreds of thousands of objects that are not cycles, and the collector keeps rescanning them. 3.14 is now the required version, so this is the default case.
- **The whole tree in memory (#132):** SDMX-ML reads build lxml's whole document tree before walking it, so peak memory is about twice the document. `iterparse` would stream instead.

## Done means

- Each change is measured A/B/A interleaved against the scale tier (`just bench-compete-scale`) and the bundle tier, and reports retained and peak memory as well as time.
- Each fix is guarded by a count (objects, collections, round-trips), not by wall-clock.
