## Security

**Do not report a security issue in a public GitHub issue, pull request or
discussion.** Email it to Gabriel Gellner, the maintainer, at
`gabriel.gellner@statcan.gc.ca`.

### Supported versions

sdmxlib is pre-1.0. Fixes go into the next release, and only the latest
release receives them.

### What to include

- The sdmxlib version, and the Python version and operating system.
- What an attacker can do, and what they need to do it: a crafted SDMX file,
  a response from a hostile registry, a query string, a bundle.
- The smallest input or script that shows it.

### What happens next

1. You receive a reply within five business days.
2. The issue is confirmed or ruled out, and you are told which.
3. A confirmed issue is fixed in a release. The release notes describe it once
   the release is out, and credit you unless you ask not to be named.

## Sécurité

**Ne signalez aucun problème de sécurité dans un enjeu (issue), une demande de
tirage (pull request) ou une discussion publique sur GitHub.** Envoyez-le par
courriel à Gabriel Gellner, le responsable du projet, à
`gabriel.gellner@statcan.gc.ca`.

### Versions prises en charge

sdmxlib est en version préliminaire (avant 1.0). Les correctifs sont intégrés à
la prochaine version, et seule la dernière version les reçoit.

### Quoi inclure

- La version de sdmxlib, ainsi que la version de Python et le système
  d'exploitation.
- Ce qu'un attaquant peut faire, et ce dont il a besoin pour le faire : un
  fichier SDMX contrefait, une réponse d'un registre malveillant, une chaîne de
  requête, un paquet (bundle).
- La plus petite entrée ou le plus petit script qui le démontre.

### Étapes suivantes

1. Vous recevez une réponse dans un délai de cinq jours ouvrables.
2. Le problème est confirmé ou écarté, et vous en êtes informé.
3. Un problème confirmé est corrigé dans une version. Les notes de version le
   décrivent une fois la version publiée, et vous en attribuent le mérite, à
   moins que vous ne demandiez à ne pas être nommé.
